# WebSocket

شاشة [[ui:nav.ws]] عميل WebSocket: تفتح اتصالًا واحدًا بخدمة — بالترويسات والبروتوكولات الفرعية
التي تتوقعها الخدمة — وترسل نصًا أو بايتات، وتسرد كل رسالة تأتي وتذهب، والأحدث في الآخر. وتُستعمل
لتجربة واجهة API حية أو سطح تحكم أو جهاز يتكلم WebSocket قبل برمجته في تجربة.

## الاتصال {#connect}

1. فتح شاشة [[ui:nav.ws]].
2. في الحقل [[ui:field.url]]، كتابة العنوان: `ws://127.0.0.1:9001/` أو
   `wss://example.com/socket`.
3. إن طلبتها الخدمة، إدخال [[ui:exp.wsProtocols]] وإضافة [[ui:http.headers]] (ترويسة
   `Authorization` برمز، أو ملف تعريف ارتباط).
4. الضغط على [[ui:ws.connect]]. وفي أثناء الترقية يقول الزر [[ui:ws.connecting]]؛ وما إن تنتهي
   تُقفل الحقول ويصبح الزر [[ui:ws.disconnect]].

| الحقل | ما هو | الافتراضي |
| --- | --- | --- |
| [[ui:field.url]] | `ws://` أو `wss://`، ومضيف، ومنفذ اختياري (80 لـ `ws`، و443 لـ `wss`)، ومسار | `ws://127.0.0.1:9001/` |
| [[ui:exp.wsProtocols]] | البروتوكولات الفرعية المعروضة، مفصولة بفواصل، بترتيب التفضيل؛ ويختار الخادم واحدًا. ولا يحوي الاسم مسافات ولا فواصل ولا شرطات مائلة. | لا شيء |
| [[ui:http.headers]] | ترويسات إضافية لطلب الترقية؛ ويضيف الزر [[ui:http.addHeader]] صفًّا. والصف بلا اسم يُترك. و`Host` (أو ترويسة أخرى تكتبها الترقية نفسها، مثل `Sec-WebSocket-Version`) يحل محل ما كانت الترقية سترسله. | لا شيء |

للاتصال — بحث الاسم، واتصال TCP، وTLS مع `wss://`، والترقية — 10 ثوانٍ. ويُحتفظ بـ URL عند التنقل
بين الشاشات وعند إعادة تشغيل التطبيق؛ أما الترويسات والبروتوكولات الفرعية فلا.

وعند الاتصال، تعرض اللوحة:

| العنصر | ما فيه |
| --- | --- |
| [[ui:ws.state]] | [[ui:ws.open]]، أو عند انتهائه: أغلقه المستخدم أو الخادم، مع رمز الإغلاق، أو [[ui:ws.lost]] حين انقطع الخط دون إغلاق |
| [[ui:field.reason]] | السبب الذي ذكره الطرف المُغلِق، إن ذكر |
| [[ui:ws.subprotocol]] | البروتوكول الفرعي الذي اختاره الخادم، أو — |
| [[ui:ws.peer]] | `IP:port` الخادم |
| [[ui:ws.upgradeTime]] | المدة التي استغرقها الاتصال والترقية، بالمللي ثانية |

والاتصال مهمة: يظهر في شريط وحدة التحكم ويمكن إيقافه من هناك أيضًا.

### الاتصالات الآمنة {#wss}

يثق `wss://` بالشهادات نفسها التي يثق بها HTTPS على هذا النظام: والخادم الذي لا يثق هذا النظام
بشهادته (موقّعة ذاتيًا، أو منتهية، أو باسم آخر) يُرفض بالرسالة «تعذّر إنشاء اتصال آمن بـ …». ولا
يوجد إعداد لتخطي الفحص.

## إرسال رسالة {#send}

1. تحت [[ui:ws.message]]، اختيار [[ui:exp.wsText]] أو [[ui:exp.wsBinary]].
2. كتابة الرسالة. وللثنائي، تُكتب البايتات أزواجًا من أرقام hex: `de ad be ef`.
3. الضغط على [[ui:common.send]]، أو على <kbd>Ctrl</kbd>+<kbd>Enter</kbd> في الرسالة.

حجم الرسالة 16 MiB على الأكثر (16 777 216 بايتًا، تُعدّ بايتات في الثنائي لا أرقام hex)، وهو الحد
نفسه للرسالة التي تصل ولخطوة [[ui:exp.node.ws_send]]. وتُرفض الأطول بالرسالة `Too long: at most
16777216` قبل إرسال أي شيء، ويبقى الاتصال مفتوحًا.

وحين تكون الرسالة النصية JSON، يرتّبها الزر [[ui:http.formatJson]] بمسافات بادئة قبل إرسالها.
ويُحتفظ بالرسالة عند التنقل بين الشاشات وعند إعادة تشغيل التطبيق.

## قراءة الرسائل {#messages}

تسرد [[ui:ws.messages]] ما استُقبل (↓) وما أُرسل (↑)، والأحدث في الآخر، مع الوقت وبداية الرسالة
(300 محرف) وحجمها؛ وتعرض الرسالة الثنائية بايتاتها بصيغة hex وتُوسم بـ [[ui:ws.binary]]. وفوق
القائمة عدد ما استُقبل وما أُرسل. وتتبع القائمة الرسائل الجديدة ما دامت مُمرَّرة إلى نهايتها؛
وبالتمرير إلى أعلى تبقى حيث هي.

النقر على رسالة يعرضها كاملة تحت القائمة: JSON مرتبًا، والثنائي بصيغة hex. والزر
[[ui:ws.editHere]] ينسخها إلى حقل الرسالة، لإعادة إرسالها أو تغييرها. وتُعرض الرسالة الطويلة جدًا
جزئيًا — النص حتى 64 KiB، والثنائي حتى 4096 بايتًا — ولا يمكن نسخها حينئذ، لأنها كانت ستُرسل
مقطوعة.

تحتفظ الشاشة بآخر 2000 رسالة، وأقل منها حين تطول (8 ملايين محرف في المجموع)؛ ويفرغ الزر
[[ui:common.clear]] القائمة. وعدّادا المستقبَل والمرسَل فوقها خاصان بالاتصال، وفيهما كل رسالة. وإن
أرسلت خدمة أسرع مما تتحمله الشاشة — أكثر من 2000 رسالة، أو 1 MB من النص، في عُشر ثانية — تُترك
أقدم تلك الرسائل خارج القائمة وتُحسب «غير معروضة». ويظل الفاحص محتفظًا بها ما دام الالتقاط
مفعّلًا. ومهما أغرقت الخدمة، فإن [[ui:ws.disconnect]] والإيقاف يسريان فورًا.

## الإغلاق {#close}

يرسل [[ui:ws.disconnect]] إطار إغلاق برمز 1000 (عادي) وينتظر حتى ثانيتين جواب الخادم قبل أن يقطع
الاتصال. وتقرأ الحالة حينئذ مغلقًا بالرمز 1000. وحين يغلق الخادم، تعرض الحالة رمزه وسببه؛ وحين
ينقطع الاتصال دون إطار إغلاق، تقرأ [[ui:ws.lost]] وتذكر وحدة التحكم السبب.

يجيب Signal Lab على pings الخادم بنفسه؛ ولا تُسرد pings وpongs. وينتهي الاتصال أيضًا حين تصل رسالة
فوق 16 MiB، أو حين يستغرق إرسال رسالة أكثر من 10 ثوانٍ لأن الخادم توقف عن القراءة. (أما إرسال
رسالة فوق 16 MiB من المستخدم نفسه فيُرفض ولا ينهي شيئًا.)

## في الفاحص {#inspector}

مع تفعيل الالتقاط، تظهر حركة الاتصال بالبروتوكول `ws` والمصدر `websocket`:

| الملخص | ما هو |
| --- | --- |
| `CONNECT ws://… (subprotocol)` | فُتح الاتصال |
| `TEXT …` | رسالة نصية وبدايتها |
| `BINARY n B …` | رسالة ثنائية، وحجمها وأول 16 بايتًا منها |
| `CLOSE code reason` | إطار إغلاق، مُرسل أو مستقبَل |

يحتفظ كل إطار رسالة ببايتاته. وما دامت الحركة خفيفة تُلتقط كل رسالة؛ والاتصال المزدحم يُقيَّد بـ 200
إطار في الثانية، ويذكر الإطار التالي الملتقط كم تُرك (`+n not shown`). انظر
[الفاحص](../tools/inspector.md).

## في التجارب {#experiments}

أربع خطوات تبرمج محادثة WebSocket. وتفتح خطوة واحدة اتصالًا وتسمّيه الخطوات الأخرى:

| الخطوة | ما تفعله |
| --- | --- |
| [[ui:exp.node.ws_connect]] | تفتح اتصالًا لبقية التشغيل. ويقبل URL والترويسات فيها `{{templates}}`، فيمكن وضع رمز استُخرج سابقًا فيها. [التفاصيل](../experiments/nodes.md#node-ws_connect) |
| [[ui:exp.node.ws_send]] | ترسل رسالة نصية أو ثنائية عبر اتصال. [التفاصيل](../experiments/nodes.md#node-ws_send) |
| [[ui:exp.node.wait_ws]] | تنتظر رسالة تطابق حمولتها، كما تفعل [[ui:exp.node.wait_udp]]؛ ويمكن قراءة رسائل JSON حقلًا حقلًا بعدها. [التفاصيل](../experiments/nodes.md#node-wait_ws) |
| [[ui:exp.node.ws_close]] | تغلق اتصالًا بمصافحة إغلاق: الرمز 1000، أو 3000–4999 لرمز خاص بتطبيق، وسبب حتى 123 بايتًا. [التفاصيل](../experiments/nodes.md#node-ws_close) |

والاتصال الذي ما زال مفتوحًا حين ينتهي التشغيل — أو يُوقف — يُغلق إغلاقًا سليمًا. والقالب
[[ui:exp.templateWsEcho]] مثال عملي.

## من سطر الأوامر {#cli}

يجري `signallab send ws` تبادلًا واحدًا: اتصال، وإرسال رسالة، وانتظار الجواب إن طُلب، وإغلاق.

```bash
signallab send ws ws://127.0.0.1:9001/ --text '{"type":"ping"}' --expect pong
```

تذهب المصافحة وما أُرسل إلى الخطأ القياسي، والجواب إلى الخرج القياسي:

```text
Connected to ws://127.0.0.1:9001/ in 4 ms
Sent 15 bytes
{"type":"pong"}
```

يرسل `--hex` رسالة ثنائية؛ ويضيف `-H` ترويسة ويعرض `--protocol` بروتوكولًا فرعيًا (ويتكرر
كلاهما). ويحدد `--expect TEXT` أو `--expect-regex RE` أو `--wait` (أي رسالة) أي جواب يُنتظر، مدة
`--timeout` من المللي ثواني (2000 افتراضيًا). ويخرج برمز 1 حين لا يأتي الجواب أو يفشل الاتصال.
انظر [سطر الأوامر](../automation/cli.md#cli-send-ws).

## المشكلات {#troubleshooting}

| ما يظهر | السبب المعتاد |
| --- | --- |
| `… is not a WebSocket address` | URL لا يبدأ بـ `ws://` أو `wss://`، أو بلا مضيف. |
| `… answered HTTP n instead of switching to WebSocket` | رفض الخادم الترقية: مسار خاطئ (404)، أو رمز مفقود أو خاطئ (401، 403). وبداية متن جوابه (عبر `ws://`، ما يصل خلال 0.3 ث) تحت التفاصيل التقنية. |
| `… did not take any of the subprotocols offered` | عُرضت بروتوكولات فرعية ولم يختر الخادم أيًّا منها، أو أجاب بواحد لم يُعرض. |
| `… is not a subprotocol name` | اسم فيه مسافة أو فاصلة أو شرطة مائلة. |
| `The header … cannot be sent with the upgrade` | اسم ترويسة أو قيمتها فيها محارف لا يسمح بها HTTP. |
| `… refused the connection` | لا أحد يستمع على ذلك المنفذ. |
| `A secure connection to … could not be made` | الشهادة غير موثوقة هنا، أو فشل TLS. انظر [الاتصالات الآمنة](#wss). |
| `The connection with … broke: the server did not keep to the WebSocket protocol` | أرسل الخادم ما ليس WebSocket صالحًا. |
| `A WebSocket message is limited to … bytes` | أرسل الخادم رسالة فوق 16 MiB، وهذا ينهي الاتصال. |
| `Too long: at most 16777216` | الرسالة التي حُوول إرسالها فوق 16 MiB. لم يُرسل شيء؛ والاتصال مفتوح. |

كل رسائل الأخطاء مسرودة في [رسائل الأخطاء](../reference/errors.md#ws).
