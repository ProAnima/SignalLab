# المحاكيات

المحاكي هو Signal Lab في دور الـ API أو الجهاز أو الخدمة التي يتحدث إليها النظام. يستمع على
عنوان واحد ويجيب وفق قواعد: واجهة HTTP API حسب المسارات، وجهاز OSC أو UDP أو TCP وفق «عند هذا،
يُرد بذاك»، ووسيط MQTT كما يفعل أي وسيط إضافةً إلى قواعد خاصة به. ويمكن أن يكون بطيئًا، أو
يفشل، أو يتعطل من حين لآخر، لاختبار ما يفعله النظام حين تسيء تبعيته التصرف. ويُعدّ كل تبادل
ويُسرد ويُرسل إلى [الفاحص](inspector.md).

المحاكي مستند واحد. تحتفظ شاشة [[ui:nav.emulators]] بمكتبة منها؛ ويعمل المستند نفسه داخل تجربة
بوصفه عقدة [[ui:exp.node.emulator]]، ومن سطر الأوامر بـ `signallab emulate`، وعبر
[واجهة API](../api/commands.md) و[MCP](../automation/mcp.md)، ويجيب بالطريقة نفسها في كل مكان.

## الشاشة {#screen}

على اليمين المكتبة ([[ui:emu.library]]): كل محاكٍ مع بروتوكوله وعنوانه، ونقطة نابضة وعدد
الطلبات على المحاكيات الجارية. وعلى اليسار إعدادات المحاكي المحدد وقواعده، وتحتها ما استقبله
([[ui:emu.live]]).

## إنشاء محاكٍ {#create}

1. الضغط على أحد الأزرار أعلى المكتبة:

   | الزر | ما ينشئه | يستمع على | مع قاعدة واحدة تعمل كما هي |
   | --- | --- | --- | --- |
   | ＋ [[ui:emu.new.http]] | واجهة HTTP API | `127.0.0.1:18080` | `GET /health` ← 200 `{"status":"ok"}` |
   | ＋ [[ui:emu.new.osc]] | جهاز OSC | `127.0.0.1:9100` | `/ping` ← `/pong` مع العدد بنوع int |
   | ＋ [[ui:emu.new.udp]] | جهاز UDP | `127.0.0.1:7100` | مخطط بيانات يحتوي على `PING` ← `PONG 1`، `PONG 2`، … |
   | ＋ [[ui:emu.new.tcp]] | جهاز TCP | `127.0.0.1:7200` | سطر يحتوي على `PING` ← `PONG` |
   | ＋ [[ui:emu.new.mqtt]] | وسيط MQTT | `127.0.0.1:1883` | نشر إلى `lab/<name>/set` ← الحمولة نفسها، محتفظًا بها، على `lab/<name>/state` |

   وإذا كان محاكٍ آخر في المكتبة يستخدم ذلك المنفذ، يؤخذ المنفذ الحر التالي.
2. تعيين الحقل [[ui:emu.name]] (120 حرفًا على الأكثر).
3. تعيين الحقل [[ui:emu.bind]]: `IP:port`. العنوان `127.0.0.1` يجيب هذا الكمبيوتر فقط؛
   و`0.0.0.0` يجيب الشبكة أيضًا.
4. تغيير القواعد (أدناه)، وذكر ما يقوم المحاكي مقامه في الحقل [[ui:emu.note]].

تُحفظ التغييرات تلقائيًا. وينشئ الزر [[ui:emu.duplicate]] نسخة على المنفذ الحر التالي. ويطلب
الزر [[ui:emu.delete]] تأكيدًا مرة أخرى ([[ui:emu.confirmDelete]])، ويوقف المحاكي إن كان يعمل،
ويزيله من المكتبة.

تُجرَّب القواعد بالترتيب، من الأولى إلى الأخيرة؛ وأول قاعدة تطابق هي التي تجيب. يعرض رأس كل
قاعدة ملخصًا في سطر واحد؛ وبالنقر عليه تُفتح القاعدة أو تُطوى. ويحرّك الزران ↑ و↓ القاعدة،
ويزيلها ×.

## تشغيله {#run}

1. تحديد المحاكي والضغط على [[ui:emu.start]]. يُفتح منفذه قبل أن يعود الزر: والمنفذ المشغول،
   أو المحاكي الذي فيه مشكلة، يُرفض هناك مع ذكر السبب.
2. توجيه النظام إليه. لواجهة HTTP API، ينسخ الزر [[ui:emu.copyUrl]] عنوانها
   (`http://127.0.0.1:18080`)، ولكل مسار زر [[ui:emu.copyRouteUrl]] لعنوانه الخاص (إلا إذا
   تضمّن مساره قالب `{{…}}`).
3. متابعة قائمة [[ui:emu.received]] وهي تمتلئ.
4. الضغط على [[ui:emu.stop]]، أو إيقاف مهمته من شريط وحدة التحكم.

تعرض الحالة بجانب الأزرار [[ui:emu.notRunning]]، أو أين يجيب المحاكي، أو أنه متعطل.

يواصل المحاكي الإجابة بالقواعد التي بدأ بها. وعند تغييره أثناء عمله، يظهر الزر
[[ui:emu.restart]]: والضغط عليه يعيد التشغيل بالقواعد كما هي الآن. وحتى ذلك الحين تُخفى أعداد
المطابقات على القواعد، لأنها تخص القواعد القديمة.

ويجعل الزر [[ui:emu.takeDown]] المحاكي الجاري غير متاح حتى يُضغط [[ui:emu.bringUp]]: يتلقى طلب
HTTP الرمز 503، ويُسقط جهاز TCP ووسيط MQTT اتصالاتهما ويرفضان الجديدة، ولا يجيب جهاز OSC أو
UDP بشيء. انظر [التعطل](#outage).

لا يمكن لمحاكيين من بروتوكول نقل واحد أن يتشاركا منفذًا: محاكيات HTTP وTCP وMQTT تستمع على
منافذ TCP، ومحاكيات OSC وUDP على منافذ UDP. فيمكن لواجهة HTTP API ولجهاز OSC أن يستخدما المنفذ
8080 معًا؛ أما واجهتا HTTP API فلا. والثاني على منفذ مشغول يُرفض عند بدئه.

::: tip
في متصفح متصل [بخادم](../server/index.md)، يعمل المحاكي على الخادم. فالمحاكي الذي يستمع على
`0.0.0.0` يُوصل إليه باسم الخادم، وينسخ الزر [[ui:emu.copyUrl]] ذلك العنوان؛ أما الذي على
`127.0.0.1` فلا يجيب إلا البرامج الموجودة على الخادم نفسه.
:::

## ما وصل {#received}

تعدّ لوحة [[ui:emu.live]] أثناء عمله:

| العدد | ما يعدّه |
| --- | --- |
| [[ui:emu.total]] | كل ما وصل: الطلبات، والرسائل، والأسطر. |
| [[ui:emu.unmatched]] | ما لم تأخذه أي قاعدة. وطلب HTTP الذي لا مسار له يتلقى رده مع ذلك (انظر [الطلبات التي لا يأخذها أي مسار](#fallback))؛ أما غيره فلا يتلقى شيئًا. |
| [[ui:emu.failed]] | التبادلات التي تعذّر فيها إعداد رد أو إرساله. |
| [[ui:emu.down]] | ما وصل والمحاكي متعطل. يظهر حين يكون للمحاكي انقطاع مضبوط أو حين يصل إليه شيء وهو متعطل. ولا يُعدّ أبدًا ضمن [[ui:emu.unmatched]]. |
| [[ui:emu.missed]] | لـ MQTT فقط، عند حدوثه: رسائل تأخر العميل عنها كثيرًا فلم يأخذها. |

يعرض رأس كل قاعدة عدد مرات مطابقتها منذ البدء.

تسرد قائمة [[ui:emu.received]] أحدث 300 تبادل، الأحدث أولًا:

| العمود | ما فيه |
| --- | --- |
| [[ui:emu.col.time]] | وقت الوصول. |
| [[ui:emu.col.from]] | عنوان العميل. |
| [[ui:emu.col.request]] | ما وصل، بصيغة البروتوكول: `GET /users/7`، `/ping 1`، `POWER?`. |
| [[ui:emu.col.rule]] | القاعدة التي أخذته (`#2`)، أو `—`. |
| [[ui:emu.col.reply]] | ما عاد: `200 OK · 37 B`، `/pong 3`، حمولة؛ أو [[ui:emu.held]] أو [[ui:emu.closed]] عند العطل؛ أو الخطأ حين فشل الرد؛ أو [[ui:emu.wasDown]] حين وصل والمحاكي متعطل. |
| [[ui:emu.col.ms]] | من الوصول حتى خروج الرد، بما في ذلك التأخير. |

يفتح الزر ⌕ في الصف ([[ui:emu.inspectFrame]]) ذلك التبادل في الفاحص، إن كان الالتقاط مفعّلًا.
وحين يصل أكثر من 200 تبادل خلال خُمس ثانية، تتخطى القائمة بعضها وتذكر عددها. ويحتفظ المحرك
بأحدث 500 تبادل لكل محاكٍ جارٍ، مع ما وصل، لسطر الأوامر وواجهة API وMCP.

## واجهة HTTP API {#http}

خادم HTTP/1.1. يُجاب كل طلب بأول مسار يأخذه.

### المسارات {#routes}

يأخذ المسارُ طلبًا حين تتطابق طريقته ومسار URL الخاص به وكل شروطه.

| الحقل | ما هو |
| --- | --- |
| [[ui:emu.method]] | `GET`، `POST`، `PUT`، `PATCH`، `DELETE`، `HEAD`، `OPTIONS`، أو [[ui:emu.methodAny]]. ومسار `GET` يجيب `HEAD` أيضًا. |
| [[ui:emu.path]] | يبدأ بـ `/`. المقطع `:name` يأخذ أي مقطع واحد، ويُقرأ بـ `{{request.params.name}}`؛ والمقطع الأخير `*` يأخذ كل ما تحته. ولا فرق تُحدثه الشرطة `/` في النهاية؛ وسلسلة الاستعلام ليست جزءًا من مسار URL. |
| [[ui:emu.conditions]] | يجب أن يتحقق كلٌّ منها. ويُضاف شرط بالزر ＋ [[ui:emu.addCondition]]. |

أمثلة على مسار URL:

| مسار URL | يأخذ | لا يأخذ |
| --- | --- | --- |
| `/health` | `/health`، `/health/` | `/health/db`، `/Health` |
| `/users/:id` | `/users/7` (`params.id` هو `7`)، `/users/a%20b` (`a b`) | `/users`، `/users/7/orders` |
| `/files/*` | `/files`، `/files/a`، `/files/a/b/c` | `/file`، `/other/files/a` |

يقرأ الشرط جزءًا واحدًا من الطلب ([[ui:emu.on]]) ويقارنه:

| [[ui:emu.on]] | الاسم | ما يقرؤه |
| --- | --- | --- |
| [[ui:emu.on.header]] | اسم ترويسة، بأي حالة أحرف | قيمة الترويسة؛ والترويسة المرسلة عدة مرات تُضم قيمها بـ `, `. |
| [[ui:emu.on.query]] | معامل استعلام | قيمته، بعد فك ترميزها؛ والأولى إن تكرر. |
| [[ui:emu.on.body]] | — | المتن كاملًا نصًا. |
| [[ui:emu.on.json]] | مسار JSON، مثل `$.user.id` | ذلك الحقل من متن JSON. |

المقارنات هي [[ui:exp.op.eq]]، و[[ui:exp.op.ne]]، و[[ui:exp.op.lt]]، و[[ui:exp.op.le]]،
و[[ui:exp.op.gt]]، و[[ui:exp.op.ge]]، و[[ui:exp.op.contains]]، و[[ui:exp.op.matches]]،
و[[ui:exp.op.empty]]، و[[ui:exp.op.not_empty]]. تُقارن الأرقام بوصفها أرقامًا، والنصوص حرفيًا.
والترويسة أو المعامل أو الحقل غير الموجود فارغ. والمقارنة التي لا يمكن إجراؤها — نص مقابل رقم
— لا تتحقق.

### الاستجابات {#responses}

للمسار من استجابة واحدة إلى 16 استجابة ([[ui:emu.responses]]).

| الحقل | ما هو | الافتراضي |
| --- | --- | --- |
| [[ui:emu.status]] | بين 100 و599. | 200 |
| [[ui:emu.fault]] | شيء آخر غير الرد؛ انظر [الأعطال](#faults). | [[ui:emu.fault.none]] |
| [[ui:emu.delay]] | مدة الانتظار قبل الرد، بين 0 و60,000 ms. | 0 |
| [[ui:emu.jitter]] | زيادة عشوائية حتى هذا المقدار، بين 0 و60,000 ms. | 0 |
| [[ui:emu.weight]] | حصتها حين يجيب المسار عشوائيًا. لا يظهر إلا عندئذٍ. | 1 |
| [[ui:emu.headers]] | حتى 32. يمكن أن تستخدم الأسماء المعاملات؛ والقيم [قوالب](#templates). | لا شيء |
| [[ui:emu.body]] | [قالب](#templates)، حتى 256 KiB كما كُتب. | فارغ |

من دون ترويسة `Content-Type`، يُرسل المتن الذي هو JSON صالح بنوع `application/json`، وأي متن
آخر بنوع `text/plain; charset=utf-8`.

مع استجابتين أو أكثر، يحدد الحقل [[ui:emu.order]] الاستجابة التي يتلقاها الطلب:

| [[ui:emu.order]] | ما تتلقاه الطلبات | الاستخدام |
| --- | --- | --- |
| [[ui:emu.order.sequence]] | الأولى، ثم الثانية، …، ثم الأخيرة من ذلك الحين: 500، 500، 200، 200، 200… | إعادة المحاولة: فشل مرتين، ثم نجاح. |
| [[ui:emu.order.cycle]] | الأولى مجددًا بعد الأخيرة: 200، 500، 200، 500… | تبعية تفشل من حين لآخر، بانتظام. |
| [[ui:emu.order.random]] | تُسحب كلٌّ منها حسب وزنها. الوزنان 8 و2 يعطيان الأولى نحو 80% من المرات. ويجب أن يكون وزن واحد على الأقل أكبر من 0. | نسبة واقعية من الإخفاقات. |

يضيف الزر [[ui:emu.preset]] استجابة جاهزة إلى المسار:

| الإعداد المسبق | ما يضيفه |
| --- | --- |
| [[ui:emu.preset.ok]] | 200، `{"ok":true}` |
| [[ui:emu.preset.created]] | 201، `{"id":"{{uuid}}"}`، والترويسة `Location: {{request.path}}/{{counter}}` |
| [[ui:emu.preset.notFound]] | 404، `{"error":"not found"}` |
| [[ui:emu.preset.error]] | 500، `{"error":"internal"}` |
| [[ui:emu.preset.unavailable]] | 503، `{"error":"unavailable"}`، والترويسة `Retry-After: 1` |
| [[ui:emu.preset.slow]] | 200، `{"ok":true}` بعد 2000 ms |
| [[ui:emu.preset.timeout]] | العطل [[ui:emu.fault.timeout]] |
| [[ui:emu.preset.reset]] | العطل [[ui:emu.fault.reset]] |
| [[ui:emu.preset.malformed]] | 200، `{"items":[{"id":1},{"id":2}]}` مع العطل [[ui:emu.fault.malformed]] |

### الأعطال {#faults}

| [[ui:emu.fault]] | ما يواجهه العميل |
| --- | --- |
| [[ui:emu.fault.none]] | الاستجابة. |
| [[ui:emu.fault.timeout]] | لا شيء. يُحتجز الطلب حتى دقيقتين، ثم يُغلق الاتصال — فتُختبر بذلك مهلة العميل نفسه. ولا ينطبق التأخير. |
| [[ui:emu.fault.reset]] | يُغلق الاتصال دون رد، بعد التأخير. |
| [[ui:emu.fault.malformed]] | رد HTTP كامل بالحالة والترويسات المضبوطة، لكن متنه يتوقف في منتصفه: JSON لا يمكن تحليله. وحين يكون المتن كله JSON، يظل نوع المحتوى `application/json`. |

### الطلبات التي لا يأخذها أي مسار {#fallback}

يحدد الحقل [[ui:emu.fallback]] ما يتلقاه الطلب الذي لا يطابق أي مسار:

- [[ui:emu.fallbackDefault]] — الرمز 404 بالمتن `{"error":"no_route"}`؛
- [[ui:emu.fallbackCustom]] — استجابة تُضبط يدويًا، بكل ما في استجابة المسار. ويعدّ `{{counter}}`
  فيها الطلبات التي لم يأخذها أي مسار.

وفي الحالتين يُعدّ الطلب ضمن [[ui:emu.unmatched]].

### ما يمكن أن يقرأه رد HTTP {#http-request}

| القالب | ما هو |
| --- | --- |
| `{{request.method}}` | `GET`، `POST`، … |
| `{{request.path}}` | مسار URL، دون الاستعلام. |
| `{{request.params.id}}` | مقطع مسار URL المسمّى `:id`. |
| `{{request.query.page}}` | معامل استعلام، بعد فك ترميزه. |
| `{{request.headers.x-key}}` | ترويسة؛ والأسماء بأحرف صغيرة. |
| `{{request.body}}` | المتن نصًا: أول 64 KiB منه. |
| `{{request.json.name}}` | حقل من متن JSON، حين يكون المتن JSON وفي حدود 64 KiB. |
| `{{request.from}}` | `IP:port` الخاص بالعميل. |

الطلب الذي يتجاوز متنه 1 MiB يتلقى 413 ويُعدّ ضمن [[ui:emu.failed]]. والرد الذي يتعذّر إعداده —
قالب يسمّي شيئًا ليس في الطلب — يتلقى 500 مع الخطأ في متنه، ويُعدّ ضمن [[ui:emu.failed]].

## جهاز OSC {#osc}

كل رسالة تصل — وكل رسالة من رسائل الـ bundle على حدة — يُجاب عنها بأول قاعدة تطابقها. ومخطط
البيانات الذي ليس OSC يُعدّ ضمن [[ui:emu.unmatched]].

| الحقل | ما هو |
| --- | --- |
| [[ui:emu.address]] | نمط عنوان OSC 1.0: `*` أي أحرف، و`?` حرف واحد، و`[a-z]` مجموعة، و`{a,b}` أيٌّ منهما، كلٌّ منها ضمن مقطع واحد (انظر [OSC](../protocols/osc.md#patterns)). |
| [[ui:exp.argRules]] | حتى 16 شرطًا على الوسائط، كما في [[ui:exp.node.wait_osc]] (انظر [العقد](../experiments/nodes.md#node-wait_osc)). |
| [[ui:emu.replyOn]] | إن كان معطّلًا: تؤخذ الرسالة ولا يُجاب بشيء. |
| [[ui:emu.replyAddress]] | عنوان الرد، [قالب](#templates). |
| [[ui:emu.replyArgs]] | حتى 16 وسيطة، لكلٍّ منها [[ui:emu.argType]] (`int`، `float`، `str`، `long`، `double`، `bool`، `blob`، `nil`) وقالب [[ui:emu.argValue]]. |
| [[ui:emu.to]] | فارغ: يعود الرد إلى عنوان المرسل ومنفذه. وإلا `IP:port`. |
| [[ui:emu.delay]]، [[ui:emu.jitter]] | بين 0 و60,000 ms لكلٍّ منهما. |

تُقرأ قيمة الوسيطة حسب نوعها بعد ملء القالب: `{{request.args[0]}}` يعيد الوسيطة الأولى رقمًا حين
يكون النوع رقميًا. ويقبل `bool` القيم `true` و`1` و`yes` و`on` أو `false` و`0` و`no` و`off`؛
ويقبل `blob` بايتات hex؛ والقيمة الفارغة هي صفر النوع.

تخرج الردود من منفذ المحاكي نفسه، فيسمعها العميل الذي يستمع على المنفذ الذي أرسل منه.

يمكن لرد OSC أن يقرأ `{{request.address}}` و`{{request.args[0]}}` و`{{request.from}}`.

## جهاز UDP {#udp}

يُجاب كل مخطط بيانات بأول قاعدة يطابقها.

| الحقل | ما هو |
| --- | --- |
| [[ui:emu.match]] | [[ui:exp.mode.any]]، أو [[ui:exp.mode.contains]]، أو [[ui:exp.mode.regex]]، أو [[ui:exp.mode.hex]]. |
| [[ui:emu.pattern]] | النص أو التعبير النمطي أو البايتات المبحوث عنها. |
| [[ui:emu.reply]] | [[ui:emu.replyOff]]، أو [[ui:emu.replyText]]، أو [[ui:emu.replyHex]]، ثم الرد نفسه [قالبًا](#templates). |
| [[ui:emu.to]] | فارغ: يعود الرد إلى المرسل. وإلا `IP:port`. |
| [[ui:emu.delay]]، [[ui:emu.jitter]] | بين 0 و60,000 ms لكلٍّ منهما. |

يمكن لرد UDP أو TCP أن يقرأ:

| القالب | ما هو |
| --- | --- |
| `{{request.text}}` | الحمولة نصًا. |
| `{{request.match}}` | ما طابق: النص، أو المجموعة الأولى في التعبير النمطي (أو المطابقة كاملة)، أو البايتات. |
| `{{request.hex}}` | الحمولة بايتاتِ hex، أول 1024 منها. |
| `{{request.bytes}}` | حجم الحمولة. |
| `{{request.from}}` | `IP:port` الخاص بالمرسل. |

الرد النصي 65,507 بايت على الأكثر.

## جهاز TCP {#tcp}

جهاز يتخاطب بالأسطر على اتصال TCP، كما يفعل جهاز العرض أو المحوّل المصفوفي. يُجاب كل رسالة
يرسلها العميل بأول قاعدة تطابقها؛ ويعود الرد على الاتصال نفسه.

| الحقل | ما هو |
| --- | --- |
| [[ui:emu.delimiter]] | ما يُنهي الرسالة، ويُضاف بعد كل رد وبعد التحية: [[ui:emu.delimiter.lf]] (ويُحذف `\r` الذي يسبقه)، أو [[ui:emu.delimiter.crlf]]، أو [[ui:emu.delimiter.cr]]، أو [[ui:emu.delimiter.none]]. وتُتخطى الأسطر الفارغة. |
| [[ui:emu.greeting]] | تُرسل عند اتصال العميل؛ وتُترك فارغة إن لم تُرد تحية. ويمكن أن تقرأ `{{request.from}}`. |
| [[ui:emu.match]]، [[ui:emu.pattern]]، [[ui:emu.reply]] | كما في [جهاز UDP](#udp). |
| [[ui:emu.close]] | إغلاق الاتصال بعد رد هذه القاعدة — عند `QUIT` مثلًا. |
| [[ui:emu.delay]]، [[ui:emu.jitter]] | بين 0 و60,000 ms لكلٍّ منهما. |

الرسالة التي تتجاوز 64 KiB دون فاصلها تؤخذ كما هي.

## وسيط MQTT {#mqtt}

وسيط MQTT 3.1.1 صغير على TCP عادي. يفعل ما يفعله الوسيط: يتصل العملاء، ويشتركون بـ `+` و`#`،
وينشرون بـ QoS 0 و1 و2، وتعمل الرسائل المحتفظ بها ورسائل الوصية الأخيرة، والاتصال الثاني
بمعرّف العميل نفسه يحل محل الأول. والجلسات نظيفة دائمًا: العميل الذي يطلب الاحتفاظ بجلسته يحصل
على جلسة جديدة، ولا يُصَفّ شيء في انتظار عميل غائب.

وفوق ذلك، تُفحص كل رسالة تُنشر إليه مقابل القواعد: وأول قاعدة تطابق تنشر ردًا أيضًا — كجهاز يبلغ
عمّا فعله.

| الحقل | ما هو |
| --- | --- |
| [[ui:emu.username]]، [[ui:emu.password]] | حين يُعيَّن اسم مستخدم، يجب أن يتصل العميل به وبكلمة المرور؛ وإن كان فارغًا: يمكن لأي أحد الاتصال. وتُرفض كلمة المرور دون اسم مستخدم، إذ لا يستطيع MQTT 3.1.1 حملها. |
| [[ui:emu.retained]] | حتى 64 رسالة ([[ui:emu.topic]]، [[ui:emu.payload]]، [[ui:emu.qos]]) محفوظة منذ البدء، كأنها نُشرت مع retain: العميل الذي يشترك يتلقاها أولًا. |
| [[ui:emu.topicFilter]] | المواضيع التي تأخذها القاعدة: `+` مستوى واحد، و`#` الباقي — `lab/+/set`. |
| [[ui:emu.match]]، [[ui:emu.pattern]] | شرط على الحمولة، كما في [جهاز UDP](#udp). |
| [[ui:emu.replyOn]] | إن كان معطّلًا: تؤخذ الرسالة ولا يُنشر شيء آخر. |
| [[ui:emu.replyTopic]]، [[ui:emu.replyPayload]] | [قوالب](#templates). ولا يمكن أن يتضمن الموضوع `+` أو `#`. |
| [[ui:emu.qos]]، [[ui:emu.retain]] | للرد. |
| [[ui:emu.delay]]، [[ui:emu.jitter]] | بين 0 و60,000 ms لكلٍّ منهما. |

يمكن لرد MQTT أن يقرأ `{{request.topic}}`، و`{{request.levels[1]}}` (مستويات الموضوع، بدءًا من
0)، و`{{request.payload}}`، و`{{request.json.state}}`، و`{{request.match}}`، و`{{request.qos}}`،
و`{{request.retain}}`، و`{{request.client}}` (معرّف العميل)، و`{{request.from}}`.

## القوالب في الردود {#templates}

تُكتب الردود [بلغة القوالب](../experiments/data.md#templates) نفسها التي في التجارب، فيعني الحقل
الشيء نفسه هنا وهناك. ويمكن للرد أن يقرأ:

- `request` — ما وصل، كما هو مسرود لكل بروتوكول أعلاه؛
- `{{counter}}` — عدد الرسائل التي أخذتها هذه القاعدة منذ بدء المحاكي، بما فيها هذه الرسالة؛
- [المولّدات](../experiments/data.md#generators) — `{{uuid}}`، و`{{now.iso}}`، والقيم العشوائية
  وغيرها؛ وتُسحب القيم العشوائية من بذرة المحاكي؛
- المعاملات، حين يعمل المحاكي في تجربة أو يبدأ بـ `signallab emulate --param`.

ولا يقرأ الرد الأسرار أبدًا، والاسم غير المعروف خطأ، لا نص فارغ.

بعض الحقول تُثبَّت عند بدء المحاكي، قبل أن يصل أي شيء: مسار URL، والشرط، ونمط العنوان، ونمط
الحمولة، ومرشّح المواضيع، والحقل [[ui:emu.to]]، واسم الترويسة، والرسائل المحتفظ بها، وبيانات
الدخول إلى الوسيط. وهي تقبل النص والمعاملات فقط، دون `request` ودون مولّدات.

تتحكم البذرة في الترتيب العشوائي للاستجابات، وفي التذبذب، وفي المولّدات العشوائية. وفي شاشة
[[ui:nav.emulators]] يأخذ كل بدء بذرة جديدة؛ وتستخدم التجربة بذرة التشغيل، ويأخذ
`signallab emulate --seed` البذرة المعطاة له.

## التعطل {#outage}

لاختبار ما يفعله النظام حين تتقلب إحدى تبعياته بين العمل والتعطل، يُحدَّد الخيار
[[ui:emu.outage]]:

| الحقل | ما هو | الافتراضي |
| --- | --- | --- |
| [[ui:emu.outageUp]] | مدة الإجابة، بين 10 و3,600,000 ms. | 10,000 |
| [[ui:emu.outageDown]] | مدة التعطل، بين 10 و3,600,000 ms. | 3000 |
| [[ui:emu.outageFault]] | لـ HTTP فقط: ما يواجهه الطلب والمحاكي متعطل. | [[ui:emu.outageFault.unavailable]] |

يبدأ الجدول مع بدء المحاكي ويتكرر: عمل، تعطل، عمل، تعطل… وأثناء التعطل:

| المحاكي | ما يُواجَه |
| --- | --- |
| HTTP | [[ui:emu.outageFault.unavailable]]: الرمز 503 مع `Retry-After` مضبوطًا على عدد الثواني حتى عودته (ثانية واحدة على الأقل). [[ui:emu.outageFault.reset]]: يُغلق الاتصال دون رد. [[ui:emu.outageFault.timeout]]: يُحتجز الطلب حتى دقيقتين، ثم يُغلق. |
| جهاز TCP | تُسقط الاتصالات المفتوحة خلال 0.1 ث؛ وتُغلق الجديدة فور وصولها. |
| وسيط MQTT | يُسقط كل اتصال؛ وتُرفض الاتصالات الجديدة (رمز الإرجاع 3 في CONNACK، الخادم غير متاح). |
| جهاز OSC أو UDP | لا يُجاب عن شيء. |

ما يصل أثناء التعطل يُعدّ ضمن [[ui:emu.down]]، لا ضمن [[ui:emu.unmatched]]، ولا تُسأل قواعده.

ويفعل الزر [[ui:emu.takeDown]] الشيء نفسه عند الطلب، أيًّا كان ما يقوله الجدول، حتى يُضغط
[[ui:emu.bringUp]]؛ وعندئذٍ يواجه HTTP الرمز 503 دون `Retry-After`. وفي التجربة، تفعل العقدة
[[ui:exp.node.emulator_state]] ذلك عند خطوة من التشغيل (انظر
[العقد](../experiments/nodes.md#node-emulator_state) و[الأعطال](../experiments/faults.md)).

## المشكلات {#problems}

أثناء التعديل، يُفحص المحاكي بعد كل تغيير بلحظة، وتظهر المشكلة تحت أزراره قبل الضغط على
[[ui:emu.start]]. وتسمّي المشكلة موضعها — القاعدة، أو الاستجابة، أو الرسالة المحتفظ بها، والحقل
— وما الخطأ فيها: مسار URL بلا `/`، أو تعبير نمطي غير صالح، أو قالب رد يسمّي شيئًا غير `request`
والمعاملات والمولّدات، أو قيمة خارج النطاق. ويرفض الزر [[ui:emu.start]] المحاكي الذي فيه مشكلة.

## محاكاة استجابة {#mock-this}

لإنشاء محاكٍ من استجابة نجحت:

1. في شاشة [[ui:nav.http]]، إرسال طلب والحصول على استجابة — أو استخدام [[ui:exp.sendNow]] على
   عقدة HTTP في تجربة.
2. الضغط على ⧉ [[ui:http.mockThis]] بجانب الاستجابة. تعرض نافذة [[ui:http.mockTitle]] المسار الذي
   ستنشئه.
3. في الحقل [[ui:http.mockInto]]، اختيار أحد محاكيات HTTP، أو [[ui:http.mockNew]].
4. الضغط على [[ui:http.mockAdd]]. تُفتح شاشة [[ui:nav.emulators]] على ذلك المحاكي.

يجيب المسار طريقةَ الطلب ومسار URL الخاص به (دون الاستعلام) بحالة الاستجابة وترويساتها ومتنها.
وتُستبعد الترويسات التي تخص ذلك التبادل وحده (`Content-Length`، و`Date`، و`Server`، و`ETag` وما
شابهها)، ويُرسل المتن كما كان، حتى لو تضمّن `{{`. والمحاكي الجديد لا يضم إلا هذا المسار. وإذا
أُضيف المسار إلى محاكٍ موجود، يأتي أولًا، فيجيب قبل أي مسار أعم؛ ويلتقطه المحاكي الجاري عند
الضغط على [[ui:emu.restart]].

ومن تجربة، يصبح URL المكتوب بالقوالب نمطًا: يُحذف جزؤه الأساسي (`{{api}}`)، ويصبح المقطع الذي هو
قالب واحد (`/orders/{{order_id}}`) `:order_id`، والمقطع الذي فيه قالب جزئي يُنهي مسار URL بـ
`*`.

## المجموعة الأولية {#starter-set}

في أول مرة لا يجد فيها Signal Lab مكتبة محاكيات، يكتب خمسة محاكيات، كلها على هذا الكمبيوتر.
وتُكتب أسماؤها وملاحظاتها بلغة الواجهة في تلك اللحظة.

| المحاكي | يستمع على | ما يفعله |
| --- | --- | --- |
| [[ui:seed.emu.demo-api.name]] | `127.0.0.1:8080` | `GET /health` ← `{"status":"ok","time":…}`؛ `GET /users/:id` ← مستخدم بذلك المعرّف؛ `POST /users` ← 201 مع `Location`؛ `GET /slow` ← بعد 1500 ms؛ `/flaky` ← 503، 503، ثم 200 من بعدها. |
| [[ui:seed.emu.osc-device.name]] | `127.0.0.1:9100` | `/ping` ← `/pong` مع العدد؛ `/fader/*` ← `/ack` مع العنوان الذي استقبله؛ `/cue/*` يُؤخذ دون رد. |
| [[ui:seed.emu.udp-device.name]] | `127.0.0.1:7100` | `PING` ← `PONG` والعدد؛ وأي شيء آخر ← `ACK` وحجمه بالبايت. |
| [[ui:seed.emu.tcp-device.name]] | `127.0.0.1:7200` | أسطر تنتهي بـ CR LF. يرحّب بـ `READY`؛ `POWER?` ← `POWER=ON`؛ `POWER ON` أو `POWER OFF` ← `OK ON` / `OK OFF`؛ `QUIT` ← `BYE`، ثم ينهي الاتصال. |
| [[ui:seed.emu.mqtt-broker.name]] | `127.0.0.1:1883` | يحتفظ بـ `online` على `lab/status`؛ `ON` أو `OFF` منشورة إلى `lab/<name>/set` ← القيمة نفسها، محتفظًا بها، على `lab/<name>/state`. |

والإشارة الأولية [[ui:seed.http-reachable.name]] في [مكتبة الإشارات](signals.md#starter-set)
تسأل `http://127.0.0.1:8080/`، وهو عنوان المحاكي [[ui:seed.emu.demo-api.name]]: وليس فيه مسار
لـ `/`، فتتلقى 404.

## ملف المكتبة {#file}

المكتبة هي `emulators.json` في مجلد البيانات (انظر [الملفات](../reference/files.md))؛ ويظهر
مساره بتمرير المؤشر فوق العدد تحت القائمة. يُكتب الملف كاملًا بعد 0.7 ث من آخر تغيير، عبر ملف
مؤقت، فالكتابة الفاشلة تُبقي الملف السابق. وإن تعذّرت قراءة الملف، تعرض القائمة الخطأ مع المسار
والسطر والعمود، ويُترك الملف كما هو: يُصلَح ثم يُضغط [[ui:emu.reload]]. ويُضغط [[ui:emu.reload]]
أيضًا بعد تعديله يدويًا. وإن لم يوجد ملف، تُكتب المجموعة الأولية مجددًا.

```json
{
  "version": 1,
  "emulators": [
    {
      "id": "orders-api",
      "note": "Stands in for the orders service.",
      "emulator": {
        "name": "Orders API",
        "bind": "127.0.0.1:18080",
        "protocol": "http",
        "routes": [
          { "method": "GET", "path": "/orders/:id",
            "responses": [{ "body": "{\"id\":\"{{request.params.id}}\",\"state\":\"open\"}" }] },
          { "method": "POST", "path": "/orders", "order": "sequence",
            "responses": [{ "status": 503 }, { "status": 201, "body": "{\"id\":\"{{uuid}}\"}" }] }
        ],
        "outage": { "up_ms": 20000, "down_ms": 2000, "fault": "unavailable" }
      }
    }
  ]
}
```

كائن `emulator` وحده مستند يقرؤه `signallab emulate` أيضًا.

## في التجارب والسكربتات {#elsewhere}

- في التجربة، تفتح عقدة [[ui:exp.node.emulator]] محاكيها قبل الخطوة الأولى وتجيب حتى ينتهي
  التشغيل؛ ويُعدّ ما استقبلته في التقرير. ومحاكي HTTP هناك هو أيضًا ما تستمع إليه العقدة
  [[ui:exp.node.wait_http]] ([العقد](../experiments/nodes.md#node-wait_http))، ومحاكي OSC أو UDP
  يتشارك منفذه مع عقد الانتظار في التشغيل. ولا يمكن لمحاكيين من بروتوكول نقل واحد في تجربة واحدة
  أن يتشاركا منفذًا. انظر [العقد](../experiments/nodes.md#node-emulator) و[الأعطال](../experiments/faults.md).
- يشغّل `signallab emulate` المحاكيات من ملفات أو من هذه المكتبة حتى <kbd>Ctrl</kbd>+<kbd>C</kbd>
  أو `--for`، طابعًا ما تجيب به؛ انظر [سطر الأوامر](../automation/cli.md#cli-emulate).
