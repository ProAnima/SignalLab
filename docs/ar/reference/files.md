# الملفات والمجلدات

كل ما يحتفظ به Signal Lab ملفات JSON عادية (أو نصوص) في مجلد واحد هو مجلد البيانات. وقيم الأسرار
ليست فيه أبدًا.

## مجلد البيانات {#data-folder}

| أين يعمل Signal Lab | مجلد البيانات |
| --- | --- |
| التطبيق المكتبي، Windows | `Documents\SignalLab` في مجلد المستخدم: `C:\Users\<you>\Documents\SignalLab` |
| التطبيق المكتبي، Linux | `~/Documents/SignalLab` |
| الخادم | `--data-dir`، أو `SIGNALLAB_DATA_DIR`؛ وبلا أي منهما، `Documents/SignalLab` في المجلد الشخصي للمستخدم الذي يعمل بحسابه |
| الخادم، صورة Docker | `/data`، وهو وحدة تخزين (`signallab-data` في ملف compose) |
| `signallab run` | مجلد مؤقت يُزال عند الخروج — ما لم يسمّ `--data-dir` مجلدًا |

ويأخذ التطبيق المكتبي أيضًا `SIGNALLAB_DATA_DIR` من بيئته إن عُيّن. وينشأ المجلد حين يُكتب فيه
شيء أول مرة.

::: tip
على Windows يستعمل التطبيق المجلد `Documents` داخل مجلد المستخدم مباشرة، حتى لو كان Windows يحفظ
المستندات في مكان آخر (OneDrive).
:::

وعلى الخادم، تُكتب الملفات على جهاز الخادم لا على جهاز المستخدم. وتذكر شارة [[ui:app.server]] في
الشريط العلوي أين، في تلميحها؛ وتعطيه واجهة API بوصفه `data_dir` في
[`app_info`](../api/commands.md#app_info)، وينزّل [`/api/files`](../api/index.md#files) ما فيه.

وتقرأ الأوامر `signallab emulate` و`signallab send` و`signallab mcp` في سطر الأوامر مكتبتي
التطبيق من المجلد نفسه الذي يستعمله التطبيق المكتبي.

## ما فيه {#contents}

| الملف | ما هو | متى يُكتب |
| --- | --- | --- |
| `experiment.json` | التجربة المفتوحة في المحرر | بعد كل تغيير بقليل |
| `signals.json` | مكتبة الإشارات ([[ui:nav.signals]]) | بعد كل تغيير بقليل |
| `emulators.json` | مكتبة المحاكيات ([[ui:nav.emulators]]) | بعد كل تغيير بقليل |
| `runs/run-<ms>-<job>.json` | تقرير لكل تشغيل انتهى من تلقاء نفسه | عند انتهاء التشغيل |
| `exports/experiment-<ms>-<16 hex digits>.json` | لقطة من التجربة | [[ui:exp.exportJson]] |
| `capture-<ms>.jsonl`، `capture-<ms>.txt` | إطارات الفاحص | [[ui:ins.exportJsonl]]، [[ui:ins.exportTxt]] |
| `token` | رمز وصول الخادم، لا يقرؤه إلا مستخدمه | `--generate-token`، عند أول تشغيل |
| `.experiment-<hex>.tmp`، `.signals-<hex>.tmp`، `.emulators-<hex>.tmp` | حفظ في طريقه | للحظة، ثم يُعاد تسميته |

و`<ms>` وقت بالمللي ثانية منذ 1970؛ و`<job>` رقم مهمة التشغيل. وعلى الخادم يعمل كل متصفح على
`experiment.json` نفسه والمكتبات نفسها والتقارير نفسها.

## الصيغ {#formats}

كلها JSON بترميز UTF-8، تُكتب بمسافات بادئة لتُقرأ وتُقارن جيدًا. ويحمل كل منها `version`؛ والملف
بإصدار أقدم يُقرأ ويُرحَّل عند فتحه، ويُكتب بالإصدار الحالي عند حفظه التالي — وبعد ذلك لا يستطيع
Signal Lab أقدم فتحه. والملف بإصدار أحدث مما يعرفه هذا Signal Lab يُرفض (`doc.version_unsupported`) ويُترك كما
هو: فلو قُرئ على أي حال لضاع عند الحفظ التالي ما أضافه الإصدار الأحدث. وهذا يسري على التجربة والمكتبتين.

### experiment.json {#experiment-json}

مستند التجربة، الإصدار 9 — وهو JSON نفسه الذي يكتبه [[ui:exp.exportJson]] ويقرؤه
[[ui:exp.importJson]]:

```json
{
  "version": 9,
  "name": "HTTP check",
  "params": [],
  "profiles": [],
  "profile": null,
  "seed": null,
  "cookies": true,
  "nodes": [ { "id": "start", "type": "start", "x": 40, "y": 80 }, … ],
  "edges": [ { "from": "start", "to": "request", "port": "next" }, … ]
}
```

- 4 MiB على الأكثر، ومن 1 إلى 64 عقدة (`doc.node_count`).
- تُرحَّل الإصدارات من 1 إلى 8 عند الفتح. والملف السابق للإصدار 8 يُفتح والخيار `cookies`
  متوقف، فيعمل كما كان؛ وما أضافه كل إصدار من إعدادات أخرى (المعاملات في 2، وملفات التعريف في 3،
  وإعادة المحاولة في 4، والتكرار والحلقات في 5، والمحاكيات في 6، والإضعافات في 7، وWebSocket
  ومصادقة HTTP في 8، والحمل في 9) تبدأ فارغة.
- والإصدار الأحدث مما يعرفه هذا Signal Lab يُرفض (`doc.version_unsupported`) بدلًا من فتحه دون ما
  لا يستطيع قراءته.
- والملف الذي لا يمكن تحليله يُبلَّغ عنه بمساره وسطره وعموده، ولا يُستبدل أبدًا.
- ويُكتب إلى ملف مؤقت ثم يُعاد تسميته، فتترك الكتابة الفاشلة الملف السابق.

وما العقد والمعاملات وملفات التعريف: [التجارب](../experiments/index.md)
و[العقد](../experiments/nodes.md) و[البيانات](../experiments/data.md).

### signals.json {#signals-json}

مكتبة الإشارات، الإصدار 2:

```json
{
  "version": 2,
  "signals": [
    {
      "id": "…",
      "name": "Go cue",
      "group": "Stage/Cues",
      "note": "",
      "body": { "transport": "osc", "target": "127.0.0.1:9000", "address": "/cue/go", "args": [ { "type": "int", "value": 1 } ] }
    }
  ],
  "folders": [ "Stage", "Stage/Cues" ]
}
```

- `group` مجلد الإشارة بصيغة مسار `/`؛ وفارغًا هو المستوى الأعلى. و`folders` (أُضيف في الإصدار 2)
  يسرد كل مجلد، ومنه الفارغ، ويُترك حين لا توجد مجلدات. والملف بالإصدار 1 يُقرأ بالطريقة نفسها،
  بلا مجلدات فارغة.
- `body` واحد من `osc` أو `udp` أو `http` أو `mqtt`؛ وحقولها في
  [`signals_save`](../api/commands.md#signals_save).
- حين لا يوجد الملف، تُكتب المجموعة الابتدائية — كل هدف فيها على `127.0.0.1` — وتُعاد تسميتها
  بلغة الواجهة.
- والملف الذي لا يمكن تحليله يُبلَّغ عنه بمساره وسطره وعموده (`signals.json_invalid`) ولا تحل
  محله المجموعة الابتدائية أبدًا: يُصلح أو يُحذف. ولا يكتب شيء المكتبة ما دامت لا تُقرأ — فالحفظ
  يُرفض بالخطأ نفسه ويبقى الملف كما هو — حتى يقرأها [[ui:sig.reload]] من جديد. ويمر الحفظ عبر ملف
  مؤقت في المجلد نفسه، فتترك الكتابة المقطوعة الملف السابق.

### emulators.json {#emulators-json}

مكتبة المحاكيات، الإصدار 1:

```json
{
  "version": 1,
  "emulators": [
    { "id": "demo-api", "note": "…", "emulator": { "name": "Demo API", "bind": "127.0.0.1:8080", "protocol": "http", "routes": [ … ] } }
  ]
}
```

كل مدخل مستند محاكٍ مع `id` و`note`؛ والمستند موصوف في [المحاكيات](../tools/emulators.md). وكما في
الإشارات، الملف المفقود تُكتب له المجموعة الابتدائية (كل محاكٍ فيها مربوط بـ `127.0.0.1`)، والمعطوب
يُبلَّغ عنه (`emulators.json_invalid`) ولا يُستبدل أبدًا. ويُكتب عبر ملف مؤقت. ويقرأ
`signallab emulate` كذلك ملفًا خاصًا به فيه محاكٍ واحد، أو قائمة منها، أو مكتبة كهذه.

### تقارير التشغيل {#run-reports}

`runs/run-<started ms>-<job>.json`، إصدار التقرير 6: ملف لكل تشغيل نجح أو فشل، لا يُكتب فوقه أبدًا
(والتشغيل الثاني بالاسم نفسه تُضاف إليه `-2` و`-3`…). والتشغيل الذي أُوقف لا يحفظ شيئًا.

| الحقل | ما هو |
| --- | --- |
| `version` | 6 |
| `experiment` | اسم التجربة |
| `document_version` | إصدار المستند الذي عمل |
| `seed`، `profile` | ما عمل به |
| `overrides` | قيم أُعطيت لهذا التشغيل وحده |
| `params` | كل قيمة معامل استعملها |
| `started_ms`، `ended_ms` | مللي ثانية منذ 1970 |
| `outcome` | `passed` أو `failed` |
| `error` | أول فشل له، أو null |
| `steps` | الخطوات، بصيغة [`experiment://step`](../api/events.md#event-experiment-step): وبعد أول 5 000 تُحفظ واحدة في الثانية وآخر 500، وتُعدّ الفجوة في `omitted` (منذ الإصدار 6) |
| `emulators` | ما استقبلته كل عقدة [[ui:exp.node.emulator]] وأجابت به (منذ الإصدار 3)؛ ويُترك حين لا توجد |
| `impairments` | ما فعله مرحّل كل عقدة [[ui:exp.node.impairment]]، مرحلةً مرحلة (منذ الإصدار 4)؛ ويُترك حين لا توجد |

وقياسات خطوة الحمل في آخر خطوة لها (منذ الإصدار 5). ويقرأ سجل التشغيلات في الخط الزمني والزر
[[ui:exp.compare]] هذه الملفات؛ والتقرير الذي لا يمكن قراءته يُترك خارج القائمة. انظر
[التشغيلات والتقارير](../experiments/runs.md).

### الصادرات {#exports}

- `exports/experiment-…json`: مستند التجربة، كما سبق. وكل تصدير ملف جديد.
- `capture-….jsonl`: إطار واحد من الفاحص في كل سطر، مع البايتات التي يحتفظ بها في `data`، بصيغة
  base64.
- `capture-….txt`: الإطارات للقراءة، لكل منها تفريغ hex.

وعلى الخادم، يُنزَّل تصدير الفاحص إلى جهاز المستخدم فور إنشائه؛ ويعرض تصدير التجربة الزر
[[ui:common.download]]، وعبارة [[ui:exp.reportSaved]] الخاصة بتشغيل في الخط الزمني رابط ينزّل
تقريره.

## الأسرار ليست في هذه الملفات {#secrets}

تسمّي التجربة سرًّا — `{{secret.API_TOKEN}}` — ولا يُكتب إلا الاسم. وتُحفظ القيمة:

| أين يعمل Signal Lab | أين قيم الأسرار |
| --- | --- |
| التطبيق المكتبي، Windows | مدير بيانات الاعتماد في Windows، تحت `SignalLab` ([[ui:exp.secrets]] في المحرر) |
| التطبيق المكتبي، Linux | لا مكان: لا يمكن تخزين الأسرار (`secret.unsupported`) |
| الخادم | للقراءة فقط: متغير البيئة `SIGNALLAB_SECRET_<NAME>`، أو الملف `<NAME>` في `--secrets-dir` (الافتراضي `/run/secrets/signallab`) |
| `signallab` | الملفات والمتغيرات نفسها، أو مخزن النظام مع `--secrets system` |

::: warning
ما يُكتب مباشرة في حقل يُحفظ كما كُتب. فكلمة مرور في بيانات اعتماد إشارة HTTP، أو كلمة مرور محاكي
وسيط MQTT، أو رمز ألصق في ترويسة — كلها نص عادي في `signals.json` أو `emulators.json` أو
`experiment.json`، وفي صادراتها. ويُستعمل `{{secret.NAME}}` في التجربة لكل ما لا يوضع في مجلد
مشترك.
:::

## إعدادات الواجهة {#settings}

ما تتذكره الواجهة — لغتها، والقيم المكتوبة آخر مرة في كل شاشة، وأي لوحة مفتوحة وبأي حجم،
و[[ui:http.keepCookies]]، ومتى فُحصت التحديثات آخر مرة، والرقم العشوائي للتثبيت المستعمل في
التحديثات — تحفظه الواجهة نفسها، لا مجلد البيانات: في تخزين التطبيق نفسه على سطح المكتب، وفي
تخزين الموقع في المتصفح لصفحة الخادم (لكل متصفح). وبيانات اعتماد شاشة [[ui:nav.http]] لا تُحفظ
هناك.

ولا يكتب Signal Lab ملفات سجل؛ انظر [استكشاف الأخطاء](troubleshooting.md#logs).

## النسخ الاحتياطي والتعديل والنقل {#backup}

- **النسخ الاحتياطي** بنسخ المجلد كله. وكل ما فيه JSON قائم بذاته؛ وقيم الأسرار ليست فيه، فتُعيَّن
  من جديد على جهاز جديد.
- **التعديل** في `signals.json` و`emulators.json` و`experiment.json` يدويًا ما دام Signal Lab
  مغلقًا (أو، على خادم، ما دامت لا صفحة مفتوحة): فالتطبيق يكتب الملف كله مما يحتفظ به، ففي `signals.json` و`emulators.json` يُرفض (`file.changed`) الحفظ فوق ملف تغيّر
  منذ قرأه التطبيق ويُبقى تغييرك — يُضغط Reload لقراءته؛ أما `experiment.json` فيُكتب فوقه عند الحفظ التالي
  من المحرر. والخطأ يُبلَّغ عنه بالسطر والعمود عند قراءة الملف التالية، ولا يُستبدل بصمت — وفي
  `signals.json` و`emulators.json` كذلك حين يحفظ التطبيق فيه: يُرفض ذلك الحفظ ويبقى الملف كما تُرك.
- **الحذف** لـ `runs/` و`exports/` وملفات `capture-*` في أي وقت. وحذف `signals.json` أو
  `emulators.json` يعيد المجموعة الابتدائية؛ وحذف `experiment.json` يعيد التجربة الابتدائية.
- **النقل** بنسخ المجلد وتوجيه Signal Lab إلى المكان الجديد: `--data-dir` للخادم،
  و`SIGNALLAB_DATA_DIR` للتطبيق المكتبي.
- **المشاركة** لتجربة بتصديرها، أو بحفظ JSON الخاص بها بجوار المشروع الذي تختبره؛ ويشغّلها
  [`signallab run`](../automation/cli.md#cli-run) من هناك.
