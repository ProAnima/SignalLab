# 実験のデータ

実行の中では値が動いていきます。パラメーターが宛先を決め、あるレスポンスのフィールドが次のリクエストのヘッダーになり、生成された ID がコマンドに乗って送られ、チェックで戻ってきます。このページでは、それらの値がどこから来るのか、フィールドがそれをどう使うのかを説明します。

| 出どころ | 書き方 | 設定する場所 |
| --- | --- | --- |
| パラメーター | `{{api}}` または `{{params.api}}` | [[ui:exp.params]] パネル、プロファイル、[[ui:exp.runWith]] |
| 変数 | `{{token}}` または `{{vars.token}}` | 実行中のノード: [[ui:exp.node.extract]]、待機ノード、応答を待つ送信 |
| シークレット | `{{secret.API_TOKEN}}` | コンピューターの資格情報ストア、またはサーバーの環境変数とファイル |
| 組み込みの値 | `{{run.seed}}`、`{{now.iso}}`、`{{counter}}` | 実行そのもの |
| ジェネレーター | `{{uuid}}`、`{{random_int(1, 100)}}` | 実行のシードから生成されます |

## パラメーター {#parameters}

パラメーターは名前の付いたテキスト値で、テンプレートを受け付けるどのフィールドからも使えます。宛先はパラメーターに入れておくと、アドレスを変えるときにノードごとではなく 1 か所の編集で済みます。

### パラメーターの追加 {#add-parameter}

1. エディターのツールバーで [[ui:exp.params]]（`{ }`）を押します。
2. [[ui:exp.noProfile]] タブで [[ui:exp.addParam]] を押します。
3. [[ui:exp.paramName]] と [[ui:exp.paramValue]] を入力します。たとえば `api` と `http://127.0.0.1:8080` です。
4. ノードのフィールドに `{{api}}/login` と書きます。

パネルでの変更はすべて実験の編集として扱われ、実験と一緒に保存され、ほかの編集と同じように <kbd>Ctrl</kbd>+<kbd>Z</kbd> で元に戻せます。

### ルール {#parameter-rules}

| ルール | 制限 |
| --- | --- |
| 名前 | 英字または `_` で始まり、その後は英字、数字、`_` |
| 予約名 | `vars`、`params`、`secret`、`run`、`node`、`now`、`uuid`、`counter`、`random_int`、`random_float`、`pick` |
| 1 つの実験のパラメーター数 | 64 |
| 1 つの値のサイズ | 64 KiB |
| 名前 | 一意であること。変数にパラメーターと同じ名前は付けられません |

値はプレーンテキストで、書かれたまま挿入されます。値の中の `{{…}}` は解決されません。フィールドがパラメーターの一部（`{{config.ports[0]}}`）を求めるときは、値が JSON として読まれます。JSON でない値には、一部というものがありません。

名前が不正、予約済み、または重複しているパラメーターがあっても、実験の保存はできるので、そのまま入力を続けられます。ただし、名前が直されるまで実験は実行されません。

## プロファイル {#profiles}

プロファイルは、*Laptop*、*Stage*、*Venue* のように名前を付けたパラメーター値の組です。宛先の切り替えが、すべてのノードの編集ではなく、1 回の選択で済みます。プロファイルが変更するのは一部のパラメーターで、それ以外は既定値のままです。

### プロファイルの作成 {#make-profile}

1. [[ui:exp.params]] を開き、[[ui:exp.addProfile]] を押します。新しいタブが開きます。
2. [[ui:exp.profileName]] で名前を変更します。
3. そのプロファイルで変更するパラメーターごとに、値を入力します。空のフィールドは既定値のままで、フィールドの中にグレーで表示されます。[[ui:exp.resetToDefault]]（↺）で値をクリアできます。
4. [[ui:exp.makeActive]] を押すと、そのプロファイルで実行されます。有効なプロファイルのタブには ● [[ui:exp.activeProfile]] と表示されます。[[ui:exp.noProfile]] タブで [[ui:exp.makeActive]] を押すと、既定値に戻ります。

実験にプロファイルができると、ツールバーに [[ui:exp.profile]] リストが表示され、切り替えられるようになります。有効なプロファイルは、実行、プレビュー、[[ui:exp.sendNow]] で使われ、実験に保存されるので、エクスポートしたファイルは同じ宛先で開きます。[[ui:exp.removeProfile]] は、画面に表示しているプロファイルを削除します。

| ルール | 制限 |
| --- | --- |
| 1 つの実験のプロファイル数 | 32 |
| 名前 | 1〜64 文字。一意（両端の空白は数えません） |
| 値 | 存在するパラメーターのみ。最大 64 |

パラメーターの名前を変更したり削除したりすると、すべてのプロファイルで同時に変わります。

### 実行が使う値 {#precedence}

後のものが優先されます。

1. [[ui:exp.noProfile]] タブにある、パラメーターの既定値。
2. 有効なプロファイルの値（設定されている場合）。
3. [[ui:exp.runWith]] に入力した値（この実行だけに使われます）。[別の値での実行](runs.md#run-with)を参照してください。

[[ui:exp.runWith]] で設定できるのは、実験が持っているパラメーターだけです。実行レポートには、プロファイル、その実行のために入力した値、使われたすべての値が記録されます。

### 実行できないプロファイル {#profile-issues}

実験がチェックされるたびに、ほかのプロファイルと既定値もチェックされます。失敗するもの（たとえば `http://` でも `https://` でもない URL）には、タブとツールバーのリストに ⚠ が付き、ツールチップに理由が表示されます。使用中のプロファイルでの実行が、これで止まることはありません。

## テンプレート {#templates}

`{{ }}` の中のテキストは式です。フィールドのそれ以外の部分は、書かれたとおりに保たれます。

```text
{{api}}/users/{{user.id}}?trace={{uuid}}
Bearer {{secret.API_TOKEN}}
```

- 波括弧の中の空白は関係ありません。`{{ token }}` は `{{token}}` と同じです。
- `\{{` は、文字どおりの `{{` を書きます。
- 単独の `}}` はプレーンテキストです。
- 値は、引用符なしで、そのまま挿入されます。JSON のボディでは、引用符は自分で書いてください。`"id": "{{uuid}}"` のようにします。

### 名前 {#names}

| 式 | 値 |
| --- | --- |
| `{{name}}` | この経路で変数 `name` が設定されていればその変数、なければパラメーター `name` |
| `{{vars.name}}` | 変数のみ |
| `{{params.name}}` | パラメーターのみ |
| `{{secret.NAME}}` | 保存されているシークレット `NAME`（[シークレット](#secrets)を参照） |
| `{{name.field}}` | JSON の値のフィールド |
| `{{name[0]}}` | JSON の配列の要素 |
| `{{name["a b"]}}`、`{{name['a b']}}` | 名前にほかの文字が含まれるフィールド |

`.` の後のフィールド名には、英字、数字、`_`、`-` を使えます。ステップは連鎖できます。`{{reply.args[0]}}`、`{{order.items[2].sku}}` のようにします。

### 値の書き出し方 {#value-text}

| 値 | 書き出し方 |
| --- | --- |
| テキスト | そのテキスト |
| 数値 | 最も短い形: `42`、`0.5` |
| `true`、`false` | `true`、`false` |
| `null` | `null` |
| オブジェクト、配列 | コンパクトな JSON: `["x","y"]` |

値を埋め込んだあとのフィールドは最大 16 MiB です。それを超えるとステップは `template.too_large` で失敗します。大きな値を何度も使い回して、際限なく大きなフィールドが作られることはありません。

### 組み込みの値 {#built-ins}

| 式 | 値 |
| --- | --- |
| `{{run.id}}` | 実行のジョブ番号。プレビューと [[ui:exp.sendNow]] では `0` |
| `{{run.seed}}` | この実行のシード |
| `{{node.id}}` | 実行中のノードの ID |
| `{{now}}` | 現在の時刻（Unix ミリ秒） |
| `{{now.iso}}` | UTC の現在時刻（ミリ秒付きの ISO 8601）: `2026-09-30T12:34:56.789Z` |
| `{{counter}}` | この実行の中で、このノードが何回実行されたか（今回を含み、1 から数えます） |

`{{counter}}` はノードごとに数えます。[ループ](flow.md#loop)の本体では反復の番号、[繰り返す](flow.md#repeat)ノードでは送信の番号です。`run`、`node`、`now` には、挙げたフィールドしかありません。それ以外はエラーになります。

### ジェネレーター {#generators}

| 式 | 値 |
| --- | --- |
| `{{uuid}}` または `{{uuid()}}` | バージョン 4 の UUID |
| `{{random_int(min, max)}}` | `min` から `max` までの整数（両端を含む）。引数は整数で、`min` ≤ `max` |
| `{{random_float(min, max)}}` | `min` 以上 `max` 未満の数値（小数点以下 3 桁）。`min` < `max` |
| `{{random_float(min, max, digits)}}` | 同じものを、小数点以下 `digits` 桁（0〜9）で |
| `{{pick(a, b, c)}}` | 引数のうちの 1 つ。引数は 1 つ以上 |

引数はカンマで区切ります。引用符で囲んだ引数（`"dark blue"` や `'a, b'`）には、その引用符自身以外なら何でも入れられます。引用符なしの引数には、英字、数字、`_ - . : / +` を使えます。空の引数はエラーです。

すべてのジェネレーターは、実行のシードから値を引きます。ノードの 1 回の実行で得られる値は、シード、ノードの ID、そのノードが何回実行されたかだけで決まります。そのため、並列ブランチが互いの値を変えることはなく、同じシードの実行は同じ値を再び生成します。1 つのノードの中での引きは、フィールドの順に行われます。`{{now}}` と `{{run.id}}` は再現できません。[シード](runs.md#seeds)を参照してください。

### 候補表示 {#suggestions}

テンプレートを受け付けるフィールドで `{{` を入力するか <kbd>Ctrl</kbd>+<kbd>Space</kbd> を押すと、4 つのグループのリストが開きます。値付きの [[ui:exp.suggest.params]]、このノードより上流で設定される [[ui:exp.suggest.vars]]（設定するノード付き。応答のフィールドも含み、たとえば `reply.args[0]` です）、[[ui:exp.suggest.secrets]]、[[ui:exp.suggest.generators]] です。<kbd>↑</kbd> と <kbd>↓</kbd> で選び、<kbd>Enter</kbd> または <kbd>Tab</kbd> で挿入し、<kbd>Esc</kbd> でリストを閉じてフィールドはそのままにします。

### 不明な名前はエラー {#unknown-names}

値のない名前が空の文字列になることはありません。実行の前に、フィールドが使うすべての名前は、パラメーター、有効なシークレット名、またはそのノードに至る**すべて**の経路で設定される変数のいずれかでなければなりません。エディターは、そのノードとフィールドを示します。

| 問題 | 実行前 | 実行中 |
| --- | --- | --- |
| 誰も設定しない名前 | `name.unknown` | — |
| 一部の経路でしか設定されない変数 | `name.not_on_every_path` | — |
| パラメーター `x` がないのに `{{params.x}}` | `param.unknown` | — |
| 値が持っていないフィールド | — | `template.no_field` |
| 閉じられていない `{{`、空の `{{}}`、不正な引数 | `template.*`（位置付き） | — |

これらのコードの文言は[エラー](../reference/errors.md)にあります。

## テンプレートを受け付けるフィールド {#templated-fields}

| ノード | テンプレートを受け付けるフィールド |
| --- | --- |
| [[ui:exp.node.http]] | URL、ヘッダーの名前と値、ボディ、Basic と Digest のユーザー名とパスワード、Bearer トークン |
| [[ui:exp.node.osc]] | 宛先、アドレス、テキストの引数。応答を待つ場合は、そのアドレスパターンとルールの値 |
| [[ui:exp.node.udp]] | 宛先、ペイロード。応答を待つ場合は、そのパターン |
| [[ui:exp.node.tcp]] | ホスト、ペイロード |
| [[ui:exp.node.mqtt]] | ブローカーのホスト、トピック、ペイロード |
| [[ui:exp.node.log]] | メッセージ |
| [[ui:exp.node.assert_body]] | 期待するテキスト |
| [[ui:exp.node.assert_header]] | ヘッダー名、期待するテキスト |
| [[ui:exp.node.assert_value]]、[[ui:exp.node.branch_value]]、[[ui:exp.node.loop]] の終了条件 | 値、期待値 |
| [[ui:exp.node.wait_osc]] | アドレスパターン、ルールの値 |
| [[ui:exp.node.wait_udp]]、[[ui:exp.node.wait_ws]] | パターン |
| [[ui:exp.node.wait_mqtt]] | ブローカーとトピック（パラメーターのみ）、パターン |
| [[ui:exp.node.wait_http]] | パスパターン、条件 |
| [[ui:exp.node.impairment]] | 待ち受けと宛先（パラメーターのみ） |
| [[ui:exp.node.ws_connect]] | URL、ヘッダーの名前と値 |
| [[ui:exp.node.ws_send]] | ペイロード |
| [[ui:exp.node.ws_close]] | 理由 |

数値（ポート、タイムアウト、遅延、ステータス、型付きの OSC の数値）と、待機ノードの待ち受けアドレスは、リテラルです。[[ui:exp.node.emulator]] は、届いたもの（`{{request.…}}`）とパラメーターを使って自分の応答を組み立てます。[障害](faults.md#emulator)を参照してください。

**パラメーターのみ。** 一部のフィールドは、まだ変数が存在しない最初のステップの前に開かれます。[[ui:exp.node.wait_mqtt]] のブローカーとトピック、[[ui:exp.node.impairment]] の待ち受けと宛先です。これらが受け付けるのは、テキストとパラメーターだけです（`node.params_only`）。

**リテラルのようにチェックされます。** パラメーターだけを使うフィールドは、実行の前に解決され、実行が送信するテキストとしてチェックされます。URL は `http://` または `https://`、OSC の宛先は `IP:port` または `host:port`、ヘッダー名は有効なものでなければなりません。変数やジェネレーターを使うフィールドは、実行時にチェックされます。

## プレビュー {#preview}

選択したノードにテンプレートがあると、そのプロパティには、いま分かっている値でそのノードが何をするかが表示されます。送信には [[ui:exp.preview]]、待機には [[ui:exp.previewWait]]、比較には [[ui:exp.previewCheck]] です。解決はエンジンが、実行と同じコードで行うので、プレビューと実行が食い違うことはありません。

- パラメーターは、有効なプロファイルから取られます。
- 変数は、このセッションでエディターが見たもの、つまり最後の実行のステップと [[ui:exp.sendNow]] から取られます。
- 保存済みのシークレットは `••••` と表示されます。
- まだ値のない名前は、書かれたままの形で残り、プレビューはそれを一覧にします。保存されていないシークレットは、別に一覧されます。
- ジェネレーターは、ノードの最初の実行として、実験の固定されたシードを使います。固定されていなければ `0` です。シードを固定すると、プレビューには、実行でそのノードの最初の実行が送信する生成値が表示されます。

## 値の抽出 {#extract}

[[ui:exp.node.extract]] は、その経路上の直近の HTTP レスポンスから 1 つの値を読み、変数に書き込みます。

| フィールド | 内容 |
| --- | --- |
| [[ui:exp.variable]] | 書き込む変数。パラメーターの命名規則が適用されます |
| [[ui:exp.extractFrom]] | 値の取得元（下表） |
| [[ui:exp.jsonPath]]、[[ui:exp.headerName]]、[[ui:exp.pattern]] | 読み取る対象。取得元によって変わります |

| [[ui:exp.extractFrom]] | 読み取るもの | 値 |
| --- | --- | --- |
| [[ui:exp.from.json]] | ボディを JSON として、あるパスで | JSON の値: テキスト、数値、オブジェクト、配列 |
| [[ui:exp.from.header]] | その名前の最初のヘッダー（大文字と小文字は区別しません） | テキスト |
| [[ui:exp.from.status]] | ステータスコード | 数値 |
| [[ui:exp.from.body]] | ボディ全体 | テキスト |
| [[ui:exp.from.regex]] | ボディ内の最初の一致 | パターンにあればキャプチャグループ 1、なければ一致全体 |

**JSON パス。** `$.token`、`$.items[0].id`、`$["a b"]`、`$['a b']['c-d']` のように書きます。先頭の `$.` は省略でき（`token`、`items[0].id`）、`$` だけならボディ全体です。

**正規表現**は Rust の `regex` エンジンの構文を使い、先読み・後読みや後方参照はありません。一致はボディのどこででも探されるので、必要なら `^` と `$` で固定してください。

次の場合、ステップは、何が足りないかを示して失敗します。

- この経路で、その前に HTTP リクエストが実行されていない場合（`check.no_response`。どの経路でもそうならない場合は、エディターがすでにそのグラフを拒否します。`graph.needs_http`）。
- ボディが JSON でない、またはパスがその中にない場合。
- ヘッダーがない、またはパターンが一致しない場合。
- ボディが、レスポンスが保持する 256 KiB を超えている場合。JSON パスやボディ全体の場合と、保持された部分でパターンが何にも一致しなかった場合です（`extract.truncated`）。

タイムラインには、書き込まれた値が `token = abc123` のように表示されます。

::: tip クリックで抽出
[[ui:exp.node.http]] の [[ui:exp.sendNow]] は、その JSON レスポンスを表示します。その中の値をクリックすると、リクエストの後ろに [[ui:exp.node.extract]] ノードが追加され、パスが入力され、キーから取った名前が付き、その値はすぐにプレビューで使えるようになります。
:::

## 変数 {#variables}

変数は JSON の値を保持します。次のノードが変数を書き込みます。

| ノード | 書き込むもの | どの出力で |
| --- | --- | --- |
| [[ui:exp.node.extract]] | 抽出した値 | その出力 |
| [[ui:exp.node.wait_osc]]、[[ui:exp.node.wait_udp]]、[[ui:exp.node.wait_mqtt]]、[[ui:exp.node.wait_http]]、[[ui:exp.node.wait_ws]] | 届いたもの。既定の名前は `reply`（HTTP は `request`） | [[ui:exp.portMatched]] のみ |
| [[ui:exp.expectReply]] を設定した [[ui:exp.node.osc]]、[[ui:exp.node.udp]] | 応答。既定の名前は `reply` | その出力 |

待機ノードが書き込むのはオブジェクトで、後のフィールドがその一部を読みます。

| 待機 | フィールド |
| --- | --- |
| OSC | `address`、`args`、`from`、`ms` |
| UDP | `text`、`hex`、`bytes`、`from`、`ms`、パターンがある場合は `match` |
| MQTT | `topic` と、UDP のフィールド |
| WebSocket | UDP のフィールドと、メッセージが JSON の場合は `json` |
| HTTP リクエスト | `method`、`path`、`query`、`headers`、`body`、`json`、`params`、`from`、`ms` |

`ms` は、ブランチの直近のアクションから到着までの時間です。正確な内容は[ノードのリファレンス](nodes.md)にあります。

### 変数が分かる範囲 {#visibility}

変数は、それを書き込む出力から先に、その出力を通る経路上で存在します。

- 代替の経路が合流した後（分岐の [[ui:exp.yes]] と [[ui:exp.no]] が再び出会う場合）では、**すべての**経路が設定したものだけが分かります。
- [[ui:exp.node.join]] の後では、そこに入る**どれか**のブランチが設定したものが分かります。すべてのブランチが実行されたからです。
- [[ui:exp.node.loop]] の [[ui:exp.portDone]] または [[ui:exp.portLimit]] の後と、その終了条件では、本体のすべての反復が設定するものが分かります。
- 待機ノードの変数は、その [[ui:exp.portTimeout]] 出力の後では分かりません。

並列ブランチは、それぞれが変数の独自のコピーで動きます。Join は、入ってくる接続線の順にコピーをマージし、両方が設定した名前は後の接続線が優先されるので、どのブランチが先に終わったかによって結果が変わることはありません。[実行の進み方](flow.md#parallel)を参照してください。

## 値の比較 {#compare}

[[ui:exp.node.assert_value]] は、比較が成り立たないと実行を失敗させます。[[ui:exp.node.branch_value]] は [[ui:exp.yes]] または [[ui:exp.no]] から出ます。[[ui:exp.node.loop]] は同じ比較を終了条件として使います。どれも、[[ui:exp.value]]、[[ui:exp.operator]]、[[ui:exp.expected]] 値を持ち、2 つのテキストはどちらもテンプレートです。

| [[ui:exp.value]] | [[ui:exp.operator]] | [[ui:exp.expected]] |
| --- | --- | --- |
| `{{status}}` | [[ui:exp.op.lt]] | `300` |
| `{{reply.args[0]}}` | [[ui:exp.op.eq]] | `{{nonce}}` |

| [[ui:exp.operator]] | 成り立つ条件 |
| --- | --- |
| [[ui:exp.op.eq]]、[[ui:exp.op.ne]] | 2 つが等しい（等しくない）。両方が数値なら数値として（`200` と `200.0` は等しい）、そうでなければ大文字と小文字も含めてテキストとして比較します |
| [[ui:exp.op.lt]]、[[ui:exp.op.le]]、[[ui:exp.op.gt]]、[[ui:exp.op.ge]] | 数値として。数値でない側があると、黙って*いいえ*になるのではなく、ステップが失敗します（`compare.not_numbers`） |
| [[ui:exp.op.contains]] | 値が、期待するテキストを大文字と小文字も含めて含む |
| [[ui:exp.op.matches]] | 期待値の正規表現が、値のどこかに一致する |
| [[ui:exp.op.empty]]、[[ui:exp.op.not_empty]] | 空白を取り除いた後の値が空である、または空でない。期待値は使われません |

数値とは、空白を取り除いた後に数値として読めるテキストです。`42`、`-1.5`、`1e3` などです。タイムラインには、行われた比較が `401 = 200` のように、各辺を 120 文字までに切り詰めて表示されます。

## シークレット {#secrets}

トークンやパスワードは、`{{secret.NAME}}` としてフィールドに入れます。実験ファイルには名前だけが保存され、値は保存先にとどまって、インターフェイスに届くことはありません。

### シークレットの保存先 {#secret-stores}

| Signal Lab の動作環境 | ストア | インターフェイスから |
| --- | --- | --- |
| Windows のデスクトップアプリ | Windows の資格情報マネージャー。サービス名 `SignalLab` の下に、名前ごとに 1 エントリ | 設定、置き換え、削除 |
| Linux のデスクトップアプリ | なし: シークレットが必要な実行は `secret.unsupported` で失敗します | — |
| サーバー | 環境変数 `SIGNALLAB_SECRET_<NAME>`、なければシークレットフォルダー内のファイル `<NAME>`（別に指定しなければ `/run/secrets/signallab`） | 読み取り専用 |
| コマンドラインの `signallab` | サーバーと同じ、または `--secrets system` を付けた Windows の資格情報マネージャー | — |

[[ui:exp.secrets]] セクションの見出しにはツールチップがあり、いまの環境でどれが当てはまるかを示します。Windows のストア、サーバーの環境変数とファイル、または Linux のデスクトップアプリではストアがないことです。Linux のデスクトップアプリでは、`secret.unsupported` は、シークレットが Windows の資格情報マネージャーに保存される仕組みであり、そのシステムにはそれがないことを表します。

シークレットは 1 つの実験ではなく、コンピューターまたはサーバーに属します。`{{secret.API_TOKEN}}` を使う 2 つの実験は、同じ値を使います。

サーバーでは、環境変数がファイルより優先されます。ファイルの末尾の改行は値に含まれず、空のファイルはシークレットなしとみなされます。サーバーのフォルダーは `--secrets-dir` または `SIGNALLAB_SECRETS_DIR` で設定します。[サーバー](../server/index.md)を参照してください。コマンドラインについては、[`signallab run`](../automation/cli.md#cli-run)を参照してください。

| ルール | 制限 |
| --- | --- |
| 名前 | 英字または `_` で始まり、その後は英字、数字、`_`。最大 128 文字 |
| 値 | 空でないこと。最大 16 KiB |

### シークレットの設定 {#set-secret}

Windows では次のようにします。

1. [[ui:exp.params]] を開きます。[[ui:exp.secrets]] セクションには、実験のフィールドが使うすべてのシークレットが、[[ui:exp.secretStored]] または [[ui:exp.secretMissing]] として一覧されます。
2. 名前の横の [[ui:exp.secretSet]] を押します。まだどのフィールドも使っていない名前なら [[ui:exp.addSecret]] を押します。
3. 値を入力し（フィールドにはドットが表示されます）、[[ui:exp.secretSave]] または <kbd>Enter</kbd> を押します。フィールドはクリアされ、値を読み返す手段はありません。

[[ui:exp.secretReplace]] は新しい値を保存し、[[ui:exp.secretRemove]] は資格情報ストアから削除します。このセッションで保存した名前は、候補にも表示されます。

サーバーに接続したブラウザーでは、このセクションには [[ui:exp.secretOnServer]] または [[ui:exp.secretNotOnServer]] とだけ表示されます。値はサーバーが動いている場所で、次の 2 つのどちらかの方法で設定してください。

```bash
# in the server's environment
SIGNALLAB_SECRET_API_TOKEN='…'
# or as a file in its secrets folder
printf '%s' '…' > /run/secrets/signallab/API_TOKEN
```

ファイルは実行が始まるたびに読まれるので、ファイルを変更すれば次の実行から反映されます。環境変数を変更した場合は、サーバーの再起動が必要です。

### 実行の前 {#secret-check}

実行のフィールドが使うシークレットは、すべて保存されている必要があります。足りないものがあると、それを使う最初のノードとフィールドで、トラフィックが発生する前に実行が止まります（`secret.missing`）。[[ui:exp.sendNow]] も、そのノードについて同じチェックを行います。

### マスク {#masking}

実行または [[ui:exp.sendNow]] がシークレットを使っている間、エンジンの外へ出るあらゆるものの中で、その値のすべての出現が `••••` に置き換えられます。

- ステップのテキスト、エラー、ステップが書き込んだ変数。
- 実行レポート。
- [[ui:exp.sendNow]] の結果（表示される HTTP レスポンスを含む）。
- 実行中にキャプチャされた[[ui:dock.inspector]]のフレーム。hex ダンプでは、値の各バイトが `*` になるので、オフセットは正しいままです。

Basic 認証は `name:password` を base64 で送ります。どちらかの部分にシークレットが含まれる場合は、その base64 のテキストもマスクされます。リクエストと、それをそのまま返すサーバーが値に与える形も同様です。URL やフォームのようにパーセントエンコードされたもの (クエリの `+` はスペースとして読み戻されます)、JSON の中でエスケープされたものです。実際の通信には、本物の値が載ります。プレビューには、保存済みのシークレットが `••••` と表示されます。[[ui:exp.node.emulator]] の応答では、シークレットは使えません。

## コマンド {#commands}

プレビューは [`experiment_resolve`](../api/commands.md#experiment_resolve) です。シークレットの一覧表示、設定、削除は、[`secret_status`](../api/commands.md#secret_status)、[`secret_set`](../api/commands.md#secret_set)、[`secret_delete`](../api/commands.md#secret_delete) で行います。シークレットの値を返すコマンドはありません。
