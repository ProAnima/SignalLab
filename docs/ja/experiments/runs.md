# 実行と結果

## 実行の開始 {#start}

エディターのツールバーで [[ui:exp.run]] を押します。何かが送信される前に、次のことが行われます。

1. 実験が、エディターと同じ基準でチェックされます。グラフ、フィールド、名前、値が対象で（[チェックされるもの](flow.md#validation)）、使われるすべてのシークレットが保存されている必要があります（[シークレット](data.md#secret-check)）。
2. 実験が保存されます。
3. 実行が、全期間にわたって必要なものを開きます。エミュレーター、劣化リレー、待機ノードが待ち受けるソケット、MQTT のサブスクリプションです。

これらのどれかが失敗すると、何も実行されません。問題が表示され、その対象のノードが選択されます。成功すると、キャンバスの下でタイムラインが開き、ステップが起こるたびにそこに表示されます。実行中は、[[ui:exp.run]] が [[ui:common.stop]] になり、実験は編集できません。

実行には、有効なプロファイルの値と、実験に固定されたシード（なければ新しいシード）が使われます。別の値で 1 回だけ実行するには、[[ui:exp.runWith]] を使います。

### 別の値での実行 {#run-with}

[[ui:exp.run]] の隣の ▾ は、[[ui:exp.runWith]] を開きます。実験を変更せずに、1 回の実行のために別の値を指定できます。

| フィールド | 内容 | 空のとき |
| --- | --- | --- |
| [[ui:exp.profile]] | この実行のプロファイル。実験にプロファイルがあるときに表示されます | 有効なもの |
| 各パラメーター | この実行だけの値 | 選択したプロファイルの値（グレーで表示されます） |
| [[ui:exp.seed]] | この実行のシード。0〜9,007,199,254,740,991 です。横のボタンは、直前の実行のシードを入力します | 固定されたシード、または新しいシード |

フォームの [[ui:exp.run]] が実行を開始し、[[ui:exp.resetOverrides]] はフォームを空にします。入力した内容はセッションの間フォームに残るので、同じ変更は次回ワンクリックで行えます。実行できないプロファイルには ⚠ が付きます。値の優先順位は[データ](data.md#precedence)にあります。

実験にプロファイルがある場合、または実行のために値を入力した場合、タイムラインには、その実行が使ったプロファイル（または [[ui:exp.runDefaults]]）が表示され、値を入力したときは [[ui:exp.overridden]] も表示されます。

## タイムライン {#timeline}

[[ui:exp.timeline]] はキャンバスの下にあります。▸ と ▾ で折りたたみ、縁でサイズを変えます。ステップのイベントごとに 1 行、古いものから順に、時刻、ノード、状態、何が起きたかが表示されます。たとえば `HTTP 200 · 41 ms`、`token = abc123`、`/pong 42 ← 127.0.0.1:9000 · 12 ms` です。失敗には理由が書かれ、技術的な詳細はツールチップにあります。行をクリックすると、キャンバス上でそのノードが選択されます。

| 状態 | ステップの状況 |
| --- | --- |
| [[ui:exp.running]] | 開始した |
| [[ui:exp.passed]] | 正常に終了し、出力を選んだ |
| [[ui:exp.failed]] | 失敗した。最初の失敗が実行の失敗になる |
| [[ui:exp.retry]] | 試行に失敗し、もう一度試す（[再試行](flow.md#retry)） |
| [[ui:exp.repeating]] | 繰り返し送信している。1 秒に最大 1 行（[繰り返し](flow.md#repeat)） |
| [[ui:exp.load]] | 負荷をかけている。1 秒に 1 行（[負荷](load.md#progress)） |

キャンバス上では、各ノードに最新の状態を示すバッジが付きます。

**長い実行。** 実行は、最初の 5,000 ステップを 1 つずつ表示します。それを超えると（1,000 回の反復を持つループが長い本体を実行すれば、10 万を超えることもあります）、1 秒に 1 ステップとすべての失敗を表示し、実行が終わると最後の 500 ステップを表示します。琥珀色の行は、2 つの行の間で何件が省略されたかを示し、折りたたんだタイムラインの数は、実行が行ったすべてのステップの数です。レポートにも同じステップが保存されます。

タイムラインのヘッダーには次のものがあります。

- 結果: [[ui:exp.running]]、[[ui:exp.passed]]、理由付きの [[ui:exp.failed]]、または [[ui:exp.stopped]]。
- レポートが書き込まれると [[ui:exp.reportSaved]]。ブラウザーではダウンロードするリンク、デスクトップアプリではツールチップにそのパスが表示されます。
- [[ui:exp.compare]]。この実行を過去の実行と並べます（[実行の比較](load.md#compare)）。
- 上で述べたプロファイルと変更した値。
- 実行のシードと [[ui:exp.pinSeed]]。実験にシードが固定されている場合は、そのシードと [[ui:exp.unpinSeed]] です（[シード](#seeds)）。

**フレーム。** [[ui:dock.inspector]]がキャプチャしている間、メッセージに一致した待機ノード（または応答を待つ送信）は、そのメッセージのフレームの番号を保持します。行の下のボタンにノードとフレームが示され、押すと、下部パネルでインスペクターがそのフレームを選択した状態で開きます。[インスペクター](../tools/inspector.md)を参照してください。

タイムラインに表示されるのは、このセッションでのその実験の最後の実行で、別の実験を開くと空になります。

## 停止 {#stop}

[[ui:common.stop]] を押すか、ヘッダーの [[ui:app.stopAll]] ですべてのジョブを一度に停止します。実行は直ちに終了し（[何が止まるか](flow.md#stop)）、タイムラインには [[ui:exp.stopped]] が表示され、**レポートは保存されません**。サーバー上でコマンドラインまたは API から開始した実行も、ほかのジョブと同じジョブです。そのサーバーで [[ui:app.stopAll]] を押せば停止し、呼び出し元には停止されたことが伝わります。

## 結果 {#result}

| 結果 | 意味 | レポート |
| --- | --- | --- |
| [[ui:exp.passed]] | すべてのブランチが終了し、失敗したステップがなく、終了に到達した | 保存される |
| [[ui:exp.failed]] | ステップが失敗した（チェック、[[ui:exp.portTimeout]] の接続線がない待機、ネットワークエラー、しきい値）、または実行が時間切れになった（`run.timeout`）、Join が無駄に待った（`run.join_waiting`）、どのブランチも終了に到達しなかった（`run.no_end`） | 保存される（最初の失敗付き） |
| [[ui:exp.stopped]] | 誰かが停止した | なし |
| 開始しなかった | 実験が無効、シークレットがない、またはポートを開けなかった | なし |

失敗した実行は、最初の失敗のノードとフィールドを示します。すべてのコードは[エラーリファレンス](../reference/errors.md)に一覧されています。コマンドラインは、同じことを終了コードで伝えます。`0` は成功、`1` は失敗、`2` は実験または呼び出しが無効（シークレットの不足もこれに含まれます）、`3` は実験の外にある何かが実行を妨げたこと（たとえばポートを開けなかった場合）です。[`signallab run`](../automation/cli.md#cli-run)を参照してください。

## 実行レポート {#report}

自力で終了した実行は、成功でも失敗でも、データフォルダーの `runs` フォルダーに JSON のレポートを書き込みます。デスクトップでは `Documents/SignalLab/runs`、サーバーではサーバー自身のデータフォルダーです（[ファイル](../reference/files.md)）。ファイル名は `run-<start time in ms>-<job number>.json` で、レポートが別のレポートに上書きされることはありません。書き込めない場合は、エディターがその理由を表示します。

| キー | 内容 |
| --- | --- |
| `version` | レポートの形式。現在は 6 |
| `experiment` | 実験の名前 |
| `document_version` | 実験のバージョン。現在は 9 |
| `seed` | 実行が使ったシード |
| `profile` | 実行に使ったプロファイル。既定値では `null` |
| `overrides` | [[ui:exp.runWith]] で入力した値 |
| `params` | 実行が使ったすべてのパラメーター値 |
| `started_ms`、`ended_ms` | Unix ミリ秒 |
| `outcome` | `passed` または `failed` |
| `error` | 最初の失敗。なければ `null` |
| `steps` | ステップのイベント（順番どおり。下表）: 最初の 5,000 件、その後は 1 秒に 1 件とすべての失敗、最後の 500 件 |
| `emulators` | 各エミュレーターノードの件数。ある場合のみ（[エミュレーター](faults.md#emulator)） |
| `impairments` | 各劣化ノードの件数とフェーズ。ある場合のみ（[フェーズ](faults.md#change-impairment)） |

各ステップのイベントには、次のものがあります。

| キー | 内容 |
| --- | --- |
| `job_id`、`node_id` | 実行とノード |
| `ts` | Unix ミリ秒 |
| `state` | `running`、`passed`、`failed`、`retry`、`repeating`、`load` |
| `detail` | 何が起きたか（英語） |
| `message_key`、`message_params` | インターフェイスの文言とその値。ステップをどの言語でも表示できます |
| `vars` | ステップが書き込んだ変数（ある場合） |
| `error` | 失敗の理由: `code`、`params`、`node`、`field`、`detail` |
| `frame` | 待機ノードが一致したインスペクターのフレーム（キャプチャがオンだった場合） |
| `load` | 負荷が測定したもの（[メトリクス](load.md#metrics)）。最後のイベントに付きます |
| `omitted` | このステップの直前に省略されたステップの数（ある場合） |

シークレットの値がレポートに現れることはありません。`••••` でマスクされます（[マスク](data.md#masking)）。

レポートの形式は、機能とともに拡張されてきました。バージョン 3 でエミュレーターの件数、バージョン 4 で劣化のフェーズ、バージョン 5 で負荷の測定値、バージョン 6 で長い実行のステップのサンプリング（`omitted` 付き）が加わりました。

レポートは実行の履歴です。[[ui:exp.compare]] はこれを読み、[`experiment_runs`](../api/commands.md#experiment_runs) も同様です。コマンドラインの `--report` は、実行のレポートを好きな場所にコピーします。

## シード {#seeds}

すべての実行にはシードがあります。0 から 9,007,199,254,740,991 までの整数です。次の順に決まります。

1. この実行に、[[ui:exp.runWith]]、コマンドライン（`--seed`）、または API で与えられたシード。
2. 実験に固定されたシード。
3. 新しいランダムなシード。

タイムラインの最初の行にそれが表示され、レポートにも保存されます。

シードは、実行が行うランダムなことのすべてを決めます。テンプレートの[ジェネレーター](data.md#generators)、[繰り返し](flow.md#repeat)のジッター、[ランダムな負荷](load.md#schedule)の到着、[劣化リレー](faults.md#seed)でのすべてのパケットの運命、エミュレーターのランダムな選択です。それぞれが独自のストリームから値を引くので、並列ブランチが互いの値をずらすことはありません。

実行を再現するには、次のようにします。

1. タイムラインでシードの横にある [[ui:exp.pinSeed]] を押します。シードは実験に保存され、[[ui:exp.unpinSeed]] を押すまで、すべての実行がそれを使います。[[ui:exp.params]] の [[ui:exp.seed]] には、固定されたシードが表示され、編集できます。空のときは [[ui:exp.seedRandom]] です。
2. 同じプロファイルと値で実行します。それらはレポートに記録されています。

シードで再現できないもの: 時刻（`{{now}}`）、`{{run.id}}`、そしてデバイスやネットワークが応答するタイミングです。

## 1 つのノードの試行 {#send-now}

実験を実行せずに 1 つのノードを試すには、そのノードを選択して [[ui:exp.sendNow]]（プロパティの中なら <kbd>Ctrl</kbd>+<kbd>Enter</kbd> でも）を押します。対象は、[[ui:exp.node.http]]、[[ui:exp.node.tcp]]、[[ui:exp.node.osc]]、[[ui:exp.node.udp]]、[[ui:exp.node.mqtt]]、[[ui:exp.node.ws_connect]]、[[ui:exp.node.ws_send]] のノードです。待機ノードでは [[ui:exp.listenNow]] になり、メッセージが一致するかタイムアウトになるまで、その場から待ち受けます。

エンジンは、実行と同じコードで、ノードを 1 回だけ実行します。

- 有効なプロファイルの値、このセッションで分かっている変数の値（最後の実行とこれまでの試行によるもの）、保存済みのシークレットを使います。
- 固定されたシード、なければ新しいシードを使います。`{{run.id}}` は `0`、`{{counter}}` は `1` です。
- 再試行、繰り返し、負荷はなく、送信は 1 回だけです。
- **Cookie なし**: リクエストは 1 つだけで、それより前に送り返すべきものが設定されていません。
- 実行のリレーとエミュレーターはなしです。[[ui:exp.node.wait_http]] は自分専用のリスナーで待ち受け、WebSocket の送信や待機は、その 1 回の試行のために、対応する [[ui:exp.node.ws_connect]] が記述する接続を開きます。

ノードが使う名前にまだ値がない場合、何も送信されず、結果には不足している名前が示されます。先に、実験を実行するか、それらを設定するノードで [[ui:exp.sendNow]] を使ってください。

結果には ✓ または ✕ と、何が起きたかが表示されます。HTTP リクエストでは、ステータス、時間、サイズ、[[ui:http.response]] も表示されます。JSON レスポンスでは、各値をクリックして[抽出](data.md#extract)でき、[[ui:http.mockThis]] はレスポンスをエミュレーターのルートにします。待機ノードが受け取った値や、リクエストの直後にある [[ui:exp.node.extract]] ノードがそのレスポンスから取る値は、プレビューと次の [[ui:exp.sendNow]] で使えるようになります。実行中は、[[ui:exp.sendNow]] は使えません。

テンプレートを持つノードのプレビュー（[送信する内容](data.md#preview)）も、何も送信せずに、エンジンが解決します。

## 実験ファイル {#files}

### 作業中の実験 {#working-file}

エディターが扱う実験は 1 つで、変更の 0.7 秒後に、データフォルダーの `experiment.json` へ自動的に保存されます。ツールバーには [[ui:exp.saving]]、[[ui:exp.saved]]、[[ui:exp.saveError]] のいずれかが表示されます。未完成のグラフも保存されます。読み取れないファイルは、そのパスとともに報告され、置き換えられることはありません。実験ファイルは最大 4 MiB です。

サーバーでは、ファイルはサーバーのデータフォルダーにあるので、そこでエディターを開くすべてのブラウザーが、同じ実験を扱います。

### 開く、テンプレート、エクスポート {#open-export}

ツールバーの ☰ ボタンは [[ui:exp.documents]] を開きます。

- [[ui:exp.templates]]: [[ui:exp.templateEmpty]]、[[ui:exp.templateHttp]]、[[ui:exp.templateBranch]]、[[ui:exp.templateParallel]]、[[ui:exp.templatePingReply]]、[[ui:exp.templatePoll]]、[[ui:exp.templateFlaky]]、[[ui:exp.templateFaults]]、[[ui:exp.templateOutage]]、[[ui:exp.templateWsEcho]]。宛先は `127.0.0.1` です。
- [[ui:exp.importJson]] は、最大 4 MiB のファイルを読み込みます。この版、または以前の版の実験形式のファイルで、以前の版のものは開くときに最新の形式に更新されます。名前とノード数、接続数を表示する前に、ファイルをチェックします。ファイルは、エディターが書き出す形（インデント付き）でも 4 MiB に収まらなければならないので、上限に近いコンパクトなファイルは拒否されることがあります。壊れたファイルは、問題の行と列とともに拒否され、新しい Signal Lab のファイルは `doc.version_unsupported` で拒否され、現在の実験はそのまま残ります。
- [[ui:exp.openDocument]] は、現在の実験を選んだものに置き換えます。<kbd>Ctrl</kbd>+<kbd>Z</kbd> で、このセッションの間は前の実験に戻せます。実験を開いても、実行はされません。
- [[ui:exp.exportJson]] は、データフォルダーの `exports` フォルダーに `experiment-<time in ms>-<random>.json` という名前でコピーを書き出します。別のコピーを上書きすることはありません。ブラウザーでは、[[ui:common.download]] で取得します。

コマンドラインと API も同じファイルを受け付け、テンプレートは名前で指定できます。`empty`、`http-check`、`status-branch`、`parallel-flows`、`osc-ping-reply`、`poll-until-ready`、`flaky-api`、`fault-phases`、`dependency-outage`、`websocket-echo` です。

### ドキュメントのバージョン {#versions}

実験ファイルには `version` があります。この Signal Lab はバージョン 9 を書き出し、それ以前のすべてのバージョンを開き、古いファイルが持てなかったものを補います。バージョン 9 より新しいファイルは、持っているものなしに開くのではなく、拒否されます（`doc.version_unsupported`）。

| バージョン | 追加されたもの |
| --- | --- |
| 2 | パラメーターとシード |
| 3 | プロファイル |
| 4 | 再試行、OSC または UDP の送信で待つ応答 |
| 5 | 繰り返しと [[ui:exp.node.loop]] |
| 6 | [[ui:exp.node.emulator]] と [[ui:exp.node.wait_http]] |
| 7 | [[ui:exp.node.impairment]]、[[ui:exp.node.impairment_change]]、[[ui:exp.node.emulator_state]] |
| 8 | WebSocket ノード、HTTP 認証、Cookie ジャー |
| 9 | HTTP リクエストの負荷、TCP での劣化 |

バージョン 8 より前のファイルは [[ui:exp.cookies]] がオフの状態で開くので、以前と同じように実行されます。新しいファイルは、自身の設定を保ちます。再び保存すると、どのファイルもバージョン 9 になります。

## コマンドラインまたはサーバーから {#automation}

実行はどこでも同じです。コマンドラインとサーバーの API は、エディターと同じ実行を、同じステップ、結果、レポートで開始します。

```bash
signallab run checkout.json --profile Stage -p api=http://192.0.2.10:8080 --seed 42 --report report.json
```

- [`signallab run`](../automation/cli.md#cli-run) は、実験ファイルまたはテンプレートを、このプロセスまたはサーバー上で実行し、タイムラインのようにステップを出力して、結果のコードで終了します。
- [`POST /api/run`](../api/run.md) は、サーバー上で実験を実行し、結果を返すか、ステップを発生するたびにストリームします。クライアントが去っても実行は止まらず、最後まで実行されてレポートが保存されます。
- CI では: [GitHub Actions など](../automation/ci.md)。
