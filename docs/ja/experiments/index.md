# 実験エディター

実験とは、グラフとして書いたテストです。HTTP リクエストや OSC メッセージ、MQTT パブリッシュなどを送るノード、応答を待つノード、返ってきた内容をチェックするノード、相手側を演じたりネットワークを意図したタイミングで壊したりするノードを、次に何が実行されるかを示す接続線でつなぎます。実行は [[ui:exp.node.start]] から始まり、接続線をたどって、すべてのステップが成功した状態で [[ui:exp.node.end]] に到達すると成功になります。実験は [[ui:nav.experiment]] 画面で組み立てて実行します。同じファイルをコマンドラインやサーバーからも実行できます。

エディターが一度に扱える実験は 1 つで、作業に合わせて自動的に保存されます。複数の実験を残したいときは、スナップショットをエクスポートするか、ファイルから別の実験を開いてください（[保存とファイル](#files)を参照）。

ノードの種類ごとのフィールドと出力は[ノードリファレンス](nodes.md)にあります。ノード間で値がどう流れるかは[データとテンプレート](data.md)、並列ブランチ、ループ、再試行、繰り返しは[フロー](flow.md)で説明しています。

## キャンバスの操作 {#canvas}

- **パン**: 何もない場所をドラッグするか、スクロールします。
- **ズーム**: <kbd>Ctrl</kbd> を押しながらマウスホイールを回すと、ポインターを中心に拡大縮小します。キャンバスバーの − と ＋ は 10% ずつ変わります。ズームの範囲は 15% から 200% で、ボタンの間のパーセント表示が現在の倍率です。
- **1:1**（[[ui:exp.resetZoom]]、<kbd>Ctrl</kbd>+<kbd>1</kbd>）は 100% に戻します。
- ⊡ [[ui:exp.fit]]（<kbd>Ctrl</kbd>+<kbd>0</kbd>）はグラフ全体を表示します。倍率は最大でも 100% です。
- **ノードを探す**: キャンバスバーの [[ui:exp.nodes]]（ノード数も表示されます）または <kbd>Ctrl</kbd>+<kbd>F</kbd> を使います。ノードの名前、概要（URL、アドレス、トピック）、ID に含まれる語を入力してください。<kbd>↑</kbd> <kbd>↓</kbd> で選び、<kbd>Enter</kbd> でそのノードを選択して表示位置に移動し（ズームは少なくとも 80% になります）、<kbd>Esc</kbd> で閉じます。

ミニマップはありません。その役割は [[ui:exp.fit]] と検索が果たします。

## ノードと接続線 {#nodes-and-wires}

ノードには、種類、動作を 1 行にまとめた概要、設定を示すバッジが表示されます。バッジは、再試行が ↻ と数字、繰り返しが × と回数（または時間）、負荷が ⚡ です。入力は左側にあり（[[ui:exp.node.start]] 以外のすべてのノードにあります）、出力は右側にあります。

| 出力 | 対象 | たどられる条件 |
| --- | --- | --- |
| [[ui:exp.outputPort]] | ほとんどのノード | ステップが成功したとき |
| [[ui:exp.yes]] / [[ui:exp.no]] | [[ui:exp.node.branch_status]]、[[ui:exp.node.branch_value]] | 比較が成り立ったとき／成り立たなかったとき |
| [[ui:exp.branch1]] / [[ui:exp.branch2]] | [[ui:exp.node.fork]] | 常に、両方が同時に |
| [[ui:exp.portMatched]] / [[ui:exp.portTimeout]] | 待機ノード | 一致するメッセージが届いたとき／時間内に届かなかったとき |
| [[ui:exp.portBody]] / [[ui:exp.portDone]] / [[ui:exp.portLimit]] | [[ui:exp.node.loop]] | 次の反復に入るとき／ループが終わったとき／反復回数が尽きたとき |

**1 つの出力に複数の接続線を引けます。** 最初の接続線は現在のブランチを続け、2 本目以降の接続線は、その時点で分かっている変数のコピーを持つ並列ブランチを開始します。[[[ui:exp.node.join]]](nodes.md#node-join)ノードは、自分に入るすべての接続線を待ちます。詳しくは[フロー](flow.md)を参照してください。

[[ui:exp.portTimeout]] と [[ui:exp.portLimit]] は任意です。接続しなかった場合、タイムアウトや反復回数の超過はそのステップを失敗にします。それ以外の出力は、実験を実行する前にすべて接続されている必要があります。

[[ui:exp.node.loop]] の本体からループ自身へ戻る接続線は、本体の上を通る弧として描かれます。後ろへ戻れる接続線はこれだけです。

## ノードの追加 {#adding}

### 追加メニュー {#add-menu}

追加メニューには、すべての種類のノードがグループごとに並びます。[[ui:exp.group.action]]、[[ui:exp.group.observe]]、[[ui:exp.group.emulate]]、[[ui:exp.group.fault]]、[[ui:exp.group.data]]、[[ui:exp.group.check]]、[[ui:exp.group.flow]] の順で、最後に [[ui:exp.group.signals]] が続きます。これは[ライブラリ](../tools/signals.md)のシグナルのうちノードにできるもの（OSC、HTTP、テキストペイロードの UDP、MQTT）で、フィールドはあらかじめ入力されています。

開くと、検索欄にフォーカスがあります。数文字入力してください。入力したすべての語が、ノードの名前、説明、種類（`http`、`wait_osc`）のいずれかに含まれている必要があります。シグナルは、名前、フォルダー、トランスポート、宛先で見つかります。<kbd>↑</kbd> <kbd>↓</kbd> で選び、<kbd>Enter</kbd> で追加し、<kbd>Esc</kbd> で閉じます。上部の行には、ノードがどこに入るか（あるノードの後ろか、あるノードと並列か）が表示されます。

新しいノードは選択状態になり、プロパティペインが開いて、主要なフィールド（URL、アドレス、トピック、遅延）にテキストが選択された状態でフォーカスが移ります。そのまま入力できます。フィールドで <kbd>Esc</kbd> を押すとキャンバス上のノードに戻り、次の <kbd>A</kbd> を押せる状態になります。

### 選択中のノードの後ろ {#add-after}

<kbd>A</kbd>、ツールバーの ＋ [[ui:exp.addNode]]、プロパティペインの ＋ [[ui:exp.addNext]] は、選択中のノードの次のステップを追加します。

- まだ接続線のない最初の出力（たとえば [[ui:exp.node.branch_status]] の空いている [[ui:exp.no]]）に接続されます。なければ最初の出力に接続されます。
- その出力にすでに接続線がある場合（複数あるときは最初の接続線）、新しいノードはその接続線の途中に挿入されます。接続線は新しいノードを経由するようになり、その後ろのものはすべて右へずれて場所を空けます。
- [[ui:exp.node.end]] を選択していて、そこに入る接続線が 1 本だけの場合、ノードはその直前に入ります。
- 何も選択していない場合、ノードは表示領域の中央に、接続線なしで置かれます。

[[ui:exp.node.loop]] の空の [[ui:exp.portBody]] に出力が 1 つだけのノードを置くと（この方法でも、[新しい接続線](#add-branch)でも）、そのノードはループへも接続されるので、本体はすぐに完成します。

### 接続線の途中へ {#insert}

すべての接続線の中央には ＋（[[ui:exp.insertNode]]）があります。これで追加メニューが開き、選んだノードがその接続線の途中に挿入されます。この方法で挿入した [[ui:exp.node.loop]] は、フローを [[ui:exp.portDone]] から続けます。

### 新しい接続線へ {#add-branch}

出力から接続線をドラッグして、何もないキャンバスで離すと、その場所に追加メニューが開き、新しいノードはその出力の新しい接続線に置かれます。すでにある接続線の横に並ぶので、それらと並列に実行されます。出力をクリックしてから何もないキャンバスをクリックする場合や、出力をダブルクリックする場合も同じです。

### 任意の場所へ {#add-anywhere}

何もないキャンバスをダブルクリックすると、その場所に接続線なしでノードを追加します。

### ほかの画面から {#from-screens}

- [OSC](../protocols/osc.md) 画面と [HTTP](../protocols/http.md) 画面の [[ui:common.toExperiment]] は、いま試したものを次のステップとして追加し（[[ui:exp.node.end]] に入る接続線が 1 本なら、その直前に追加します）、エディターに切り替えます。
- OSC モニターのメッセージの横にある [[ui:osc.waitForThis]] は、そのメッセージを認識する [[ui:exp.node.wait_osc]] を追加します。アドレスと、テキスト、整数、真偽値の引数が対象です（浮動小数点数は変化する計測値なので除外されます）。実行前にモニターを停止してください。実行は、そのポートを自分で待ち受けます。
- [MQTT](../protocols/mqtt.md) ツリーのトピックにある [[ui:mq.waitForThis]] は、そのブローカーのそのトピックに対する [[ui:exp.node.wait_mqtt]] を追加します。

実行中はノードを追加できません。コンソールにその旨が表示されます。

## ノードの接続 {#connecting}

- 出力からノードへ**ドラッグ**します。ノードから 24 ピクセル以内で離せば十分です。
- 出力を**クリック**します（またはフォーカスして <kbd>Enter</kbd> か <kbd>Space</kbd> を押します）。キャンバスバーに [[ui:exp.chooseInput]] と表示されます。ノードまたはその入力をクリックすると接続されます。何もないキャンバスをクリックすると、その場所に新しい接続線でノードが追加されます。[[ui:exp.cancelLink]] または <kbd>Esc</kbd> で中止します。

サイクルになる接続線（[[ui:exp.node.loop]] の戻り線を除く）、[[ui:exp.node.start]] に入る接続線、[[ui:exp.node.end]] から出る接続線、ノード自身への接続線は拒否され、エディターがその旨を表示します。すでに存在する接続線をもう一度引いても、何も変わりません。

**接続線を削除する**には、接続線をクリックして（プロパティペインに接続先が表示されます）<kbd>Delete</kbd> を押すか、ペインの [[ui:exp.removeWire]] を使います。接続線にポインターを重ねると、＋ の上に × も表示されます。ノードのプロパティには、出ていく接続線が一覧され、それぞれに × があります（[[ui:exp.disconnect]]）。

## 複数ノードの選択 {#selection}

| 目的 | 操作 |
| --- | --- |
| ノードを選択する | クリックするか、<kbd>Tab</kbd> で移動します |
| 選択にノードを加える、または外す | <kbd>Shift</kbd> または <kbd>Ctrl</kbd> を押しながらクリックします |
| 枠で選択する | 何もないキャンバスで <kbd>Shift</kbd> を押しながらドラッグします。枠に触れたすべてのノードが選択に加わります |
| すべてのノードを選択する | <kbd>Ctrl</kbd>+<kbd>A</kbd> |
| 選択を解除する | 何もないキャンバスをクリックします。複数選択中は <kbd>Esc</kbd> でも解除できます |
| 動かす | どれか 1 つをドラッグすると、すべてが動きます |
| 少しずつ動かす | ノードにフォーカスがある状態で、矢印キーで選択を 5 ピクセル、<kbd>Shift</kbd> を押すと 20 ピクセル動かします |

プロパティペインには最後に選んだノードが表示されます。複数選択している場合は選択数が表示され、[[ui:exp.copy]]、[[ui:exp.duplicate]]、[[ui:exp.deleteSelected]] が使えます。

### コピー、切り取り、貼り付け {#copy-paste}

<kbd>Ctrl</kbd>+<kbd>C</kbd> は、選択したノードとその間の接続線をテキストとしてコピーします。<kbd>Ctrl</kbd>+<kbd>X</kbd> はさらにそれらを削除します。<kbd>Ctrl</kbd>+<kbd>V</kbd> で貼り付けられ、貼り付け先はこの実験、後で開く別の実験、別の Signal Lab ウィンドウのいずれでも構いません。テキストは JSON なので、ファイルやメッセージに保管することもできます。

- [[ui:exp.node.start]] と [[ui:exp.node.end]] は 1 つしかないノードなので、コピーされることはありません。
- コピーしたノードとグラフのほかの部分との間の接続線はコピーされません。コピーしたノードの接続は自分で行ってください。
- 貼り付けたノードには、すべて新しい ID が付きます。
- 別のノードを名前で指すノード（[[ui:exp.node.impairment_change]]、[[ui:exp.node.emulator_state]]、[[ui:exp.node.ws_send]]、[[ui:exp.node.wait_ws]]、[[ui:exp.node.ws_close]]）は、指す先も一緒にコピーされていれば、そのコピーを指します。そうでなければ、元のノードがこの実験にあれば引き続きそれを指し、なければこの実験にある同じ種類の最初のノードを指します。
- 貼り付けた [[ui:exp.node.emulator]] または [[ui:exp.node.impairment]] のポートをこの実験がすでに待ち受けている場合は、次に空いているポートに移ります。元のノードに送信しているものは、そのまま元のノードに送り続けます。
- コピーは、元の位置から右へ 32 ピクセル、1 行下に置かれ、どのノードとも重ならなくなるまでさらに下へずれて、選択状態になります。

<kbd>Ctrl</kbd>+<kbd>D</kbd>（[[ui:exp.duplicate]]）は、クリップボードを使わずに同じことを行います。

### 削除 {#deleting}

<kbd>Delete</kbd> または <kbd>Backspace</kbd>（[[ui:exp.delete]]、[[ui:exp.deleteSelected]]）で、選択したノードとその接続線を削除します。入る接続線と出る接続線がちょうど 1 本ずつだったノードを削除すると、その位置に、前のノードから後ろのノードへの接続線が残るので、連なりはつながったままです。[[ui:exp.node.start]] と [[ui:exp.node.end]] は削除できません。

## 元に戻す／やり直し {#undo}

<kbd>Ctrl</kbd>+<kbd>Z</kbd> で元に戻し、<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Z</kbd> または <kbd>Ctrl</kbd>+<kbd>Y</kbd> でやり直します（キャンバスバーの ↶ ↷）。1 回のドラッグ、矢印キーによる一連の移動、1 つのフィールドへの入力は、それぞれ 1 ステップです。直近の 100 ステップが、アプリを開いている間、画面を切り替えても保持されます。別の実験を開く操作も 1 ステップなので、<kbd>Ctrl</kbd>+<kbd>Z</kbd> で前の実験が戻ります。元に戻す／やり直しは、実行中は使えません。

## 整列 {#arrange}

[[ui:exp.arrange]] は、グラフを左から右へ配置します。各ノードは、そこへ続く最後のノードの次の列に置かれ、[[ui:exp.node.loop]] の本体は専用の行に置かれます。その後、表示をグラフ全体に合わせます。履歴上は 1 ステップです。ループのものではないサイクルを含む下書きは、そのまま変更されません。

## プロパティペイン {#properties}

ノードを 1 つ選択すると、ペインには上から順に次のものが表示されます。

1. ノードの名前（ツールチップにその動作が表示されます）。このノードが原因で実験を実行できない場合は、何が問題かも表示されます。
2. フィールド。[テンプレート](data.md)を受け付けるフィールドでは、`{{` を入力するか <kbd>Ctrl</kbd>+<kbd>Space</kbd> を押すと、パラメーター、変数、シークレット、ジェネレーターが候補として表示されます。
3. 設定。HTTP リクエストの [[ui:exp.loadOn]]、送信するノードの [[ui:exp.repeatOn]]、送信または待ち受けするノードの [[ui:exp.retryOn]]、OSC メッセージと UDP メッセージの [[ui:exp.expectReply]] です（[ノードの設定](nodes.md#settings)を参照）。負荷が有効な間は、繰り返しと再試行の代わりに負荷が使われます。
4. 負荷をかけて実行した HTTP ノードでは、最後の実行の負荷の結果。
5. ノードにテンプレートがある場合は、プレビュー（[[ui:exp.preview]]、[[ui:exp.previewWait]]、[[ui:exp.previewCheck]]）。現在のパラメーターとこれまでに分かっている値で解決した、送信する内容、待機する内容、比較する内容です（[今すぐ送信とプレビュー](#send-now)）。
6. [[ui:exp.sendNow]] または [[ui:exp.listenNow]] と、その直前の結果。
7. 出ていく接続線。それぞれに × があります。
8. OSC メッセージまたは UDP メッセージでは、⚡ [[ui:exp.routeThrough]]。ノードの前に [[ui:exp.node.impairment]] ノードが置かれ（9010 以降の空いているループバックポートで待ち受け、ノードの宛先へ転送します）、ノードの宛先がそちらに向け直されるので、次の実行では送信内容が劣化します（[障害](faults.md)）。
9. ＋ [[ui:exp.addNext]]、[[ui:exp.copy]]、[[ui:exp.duplicate]]、[[ui:exp.delete]]。

ノードをダブルクリックすると、ペインが開いて主要なフィールドにカーソルが入ります。複数のノードを選択しているときは、ペインにすべてに対して行える操作が表示されます。接続線を選択しているときは、その接続先と [[ui:exp.removeWire]] が表示されます。実行中は、フィールドはロックされます。

## 今すぐ送信とプレビュー {#send-now}

[[ui:exp.sendNow]]（<kbd>Ctrl</kbd>+<kbd>Enter</kbd>。ノードのフィールドの中からも使えます）は、実験を実行せずに、選択したノードだけを、実行と同じコードで送信します。対象は [[ui:exp.node.http]]、[[ui:exp.node.tcp]]、[[ui:exp.node.osc]]、[[ui:exp.node.udp]]、[[ui:exp.node.mqtt]]、[[ui:exp.node.ws_connect]]、[[ui:exp.node.ws_send]] です。待機ノードでは [[ui:exp.listenNow]] になり、メッセージが一致するかタイムアウトになるまで、その場から待ち受けます。

- ノードは、有効なプロファイル、保存済みのシークレット、これまでに分かっている変数の値（最後の実行と、これまでの [[ui:exp.sendNow]] の結果によるもの）を使います。テンプレートがまだ誰も設定していない値を指している場合は、何も送信されず、その名前が一覧されます。
- 送信は 1 回だけです。再試行、繰り返し、負荷は適用されず、Cookie も保持されず、実験のエミュレーターとリレーも起動しません。
- [[ui:exp.node.ws_send]] または [[ui:exp.node.wait_ws]] は、その 1 回のテストのために、対応する [[ui:exp.node.ws_connect]] が記述する接続を開きます。
- HTTP リクエストでは、レスポンスが表示されます。ステータス、時間、サイズ、そして JSON 整形されたボディです。リクエストの後ろにある [[ui:exp.node.extract]] ノードが取得する値は、すぐに入力されます。JSON レスポンスの値をクリックすると、リクエストの直後にその値の [[ui:exp.node.extract]] ノードが追加され、変数名が付き、値も分かった状態になります。[[ui:http.mockThis]] は、レスポンスを[エミュレーター](../tools/emulators.md)のルートにします。
- 結果はコンソールにも書き込まれます。

プレビューもエンジンが解決します。変更の約 4 分の 1 秒後です。シークレットの値は、ここでも他の場所でも表示されません。

## 検証 {#validation}

エディターは編集中に実験をチェックし、[[ui:exp.run]] を押したときにもう一度チェックします。

- まだ接続線が必要な出力は、琥珀色で点滅します。
- [[ui:exp.node.start]] からの接続線が届かないノードは、破線で描かれます。ツールチップにその旨が表示されます。
- 問題の対象となるノードには枠線が付き、問題の内容がそのフィールドの上に書かれます。
- ツールバーの ⚠ [[ui:exp.needsLinks]] に問題が表示され、クリックするとそのノードが選択されます。

実験が実行できるのは、とりわけ次の条件を満たすときです。

- 名前があり、[[ui:exp.node.start]] と [[ui:exp.node.end]] がちょうど 1 つずつあり、ノードが 64 個以内であること。エディターはこれを超える追加、貼り付け、複製を行わず、その旨を表示します。
- すべてのノードが [[ui:exp.node.start]] から到達でき、必要な出力すべてに接続線があること。
- 存在するサイクルが、[[ui:exp.node.loop]] ノードの本体からそのループへ戻るものだけであること。
- すべてのチェックと [[ui:exp.node.extract]] について、すべての経路でその前に HTTP リクエストがあること（負荷をかけたリクエストは、レスポンスが残らないので数えません）。
- [[ui:exp.node.ws_send]]、[[ui:exp.node.wait_ws]]、[[ui:exp.node.ws_close]] が、それが使う [[ui:exp.node.ws_connect]] より後にあること。
- すべてのフィールドが入力済みで範囲内にあり、すべてのテンプレートが、その時点で分かっているものを指していること。

未完成の下書きも保存されます。実行に必要なシークレットが保存されていない場合、トラフィックが発生する前に実行が拒否されます。すべてのメッセージは[エラーリファレンス](../reference/errors.md)に一覧されています。

## 実行 {#running}

[[ui:exp.run]] は、実験をチェックし、保存して、開始します。実行できない場合は、問題が表示され、そのノードが選択されます。実行できる場合はタイムラインが開き、実行が到達したノードが順に点灯します。● は実行中、✓ は成功、✕ は失敗、↻ は再試行中、⟳ は繰り返し中、⚡ は負荷送信中です。フローが通った接続線も色が付きます。

- 待機、エミュレーター、劣化リレーは、最初のステップの前にポートを開くので、早く届いたものを取りこぼすことはありません。開けないポート（たとえば別のプログラムが使用中）があると実行は開始されず、そのポートを必要とするノードが表示されます。
- [[ui:common.stop]] は、一時停止、待機、負荷を含めて、実行を直ちに終了します。実行はコンソールのジョブストリップにもジョブとして表示され、そこから停止することもできます。
- 300 秒を超える実行は、停止されて失敗になります。
- 実行中は実験を編集できません。パン、ズーム、選択は引き続き使えます。

ボタンの隣の ▾ [[ui:exp.runWith]] は、別のプロファイル、別のパラメーター値、指定したシードで 1 回だけ実行します。実験自体は変更されず、入力した内容は、アプリを閉じるまでフォームに保持されます（[データとテンプレート](data.md)）。

### 実行タイムライン {#timeline}

[[ui:exp.timeline]] には、ステップごとに 1 行が表示されます。時刻、ノード、何が起きたか（成功、失敗とその理由、再試行、繰り返しの進行状況、1 秒ごとの負荷の数値）です。行をクリックすると、キャンバス上でそのノードが選択されます。

タイトル行には次のものが表示されます。

- 結果: [[ui:exp.passed]]、理由付きの [[ui:exp.failed]]、または [[ui:exp.stopped]]。
- [[ui:exp.reportSaved]] — 実行のレポートファイル（サーバーではダウンロード）。
- [[ui:exp.compare]] — この実行を、同じ実験の過去の実行と並べて表示します。
- 実行で使ったプロファイルと変更した値（ある場合）。
- 実行のシード。[[ui:exp.pinSeed]] で実験に保存して以降の実行で同じ乱数値が使われるようにでき、固定した後は [[ui:exp.unpinSeed]] が表示されます。

[インスペクター](../tools/inspector.md)がキャプチャ中だった場合、一致した待機（または期待した応答）には、一致したフレームへのリンクが付きます。クリックすると、インスペクターでそのフレームが開きます。レポート、シード、実行の比較は[実行とレポート](runs.md)で説明しています。

## フォーカスモードと全画面表示 {#focus}

▢ [[ui:exp.focus]] は、サイドバー、ヘッダー、下部パネル（コンソールとインスペクター）を隠し、画面をエディターに明け渡します。⛶ [[ui:exp.fullscreen]] はウィンドウを全画面にして、フォーカスモードを有効にします。全画面を終了すると、フォーカスモードは元の状態に戻ります。別の画面に切り替えると、フォーカスモードは終了します。

キャンバスで <kbd>Esc</kbd> を押すと（ほかに閉じるものがない場合）、全画面が終了し、続けてフォーカスモードが終了します。

## 保存とファイル {#files}

実験は、変更の少し後に自動で保存されます。保存先は、データフォルダー内の `experiment.json` です（デスクトップでは `Documents/SignalLab`、サーバーには独自のフォルダーがあります。[ファイルとフォルダー](../reference/files.md)を参照）。まだ実行できない下書きも保存されます。実行の前にも保存されるので、実行されたものがそのままディスクにあります。

このファイルを読み取れない場合（たとえば手作業の編集で JSON が壊れた場合）、エディターはどのファイルでなぜ読めないかを表示し、そのファイルには手を付けません。その後 ☰ [[ui:exp.documents]] から別の実験を開くと、次の保存でそのファイルが置き換えられます。

☰ [[ui:exp.documents]] は、実験のダイアログを開きます。

- [[ui:exp.templates]]: 1 つを選んで [[ui:exp.openDocument]] を押します。すべてループバックアドレスを使っています。
- [[ui:exp.importJson]] は、実験ファイルを読み込みます。この版または以前の版の Signal Lab が書き出した、4 MiB までのファイルです。開く前に、名前とノード数、接続数が表示されます。以前の版のファイルは、開くときに最新の形式に更新されます。解析できないファイルや、有効な実験にならないファイルは、理由とともに拒否され、現在の実験はそのまま残ります。
- [[ui:exp.exportJson]] は、現在の実験のスナップショット（ノード、接続線、位置、パラメーター、プロファイル。シークレットの値は含まれません）を、データフォルダー内の `exports` に新しいファイルとして書き出し、そのパスを表示します。サーバーでは [[ui:common.download]] リンクが表示されます。
- [[ui:exp.openDocument]] は、現在の実験をテンプレートまたはファイルで置き換えます。実行はされず、<kbd>Ctrl</kbd>+<kbd>Z</kbd> で前の実験に戻せます。

| テンプレート | 内容 |
| --- | --- |
| [[ui:exp.templateEmpty]] | [[ui:exp.node.start]] と [[ui:exp.node.end]] だけです。自分のフローを組み立てるためのものです |
| [[ui:exp.templateHttp]] | `http://127.0.0.1:8080/` への GET と、ステータス 200 のチェックです。最初に使う実験です |
| [[ui:exp.templateBranch]] | 同じリクエストを送り、200 なら `127.0.0.1:9000` への OSC メッセージ、それ以外なら 500 ms の遅延です |
| [[ui:exp.templateParallel]] | 同時に走る 2 つのブランチ（リクエストとログ行）を、[[ui:exp.node.end]] の前で合流させます |
| [[ui:exp.templatePingReply]] | 実行の ID を付けた `/ping` を `127.0.0.1:9000` へ送り、それを載せた `/pong` を `127.0.0.1:9001` で待ちます |
| [[ui:exp.templatePoll]] | デバイスに `/status` を 0.3 秒ごとに尋ね、`ready` と答えるまで、最大 10 回繰り返します |
| [[ui:exp.templateFlaky]] | 2 回失敗してから応答するエミュレートされた API と、応答するまで尋ね続けるループです |
| [[ui:exp.templateFaults]] | 劣化リレーを通してエミュレートされたデバイスへデータグラムを送り、その間に並列ブランチがネットワークを、正常、ロスあり、オフライン、正常の順に切り替えます |
| [[ui:exp.templateOutage]] | 並列ブランチが 2 秒間ダウンさせるエミュレートされた API と、再び応答するまで尋ね続けるクライアントです |
| [[ui:exp.templateWsEcho]] | `ws://127.0.0.1:9001/echo` のエコーサービスに接続し、JSON の ping を送って、そのまま返ってくることを確認し、クローズします |

同じファイルは、エディターなしでも実行できます。`signallab run experiment.json` です（[コマンドライン](../automation/cli.md)を参照）。

## キーボードショートカット {#shortcuts}

単独のキーはキャンバスに作用し、フィールドに入力している間は無視されます。Mac のブラウザーでは、<kbd>Ctrl</kbd> と書かれている箇所で <kbd>Cmd</kbd> が使えます。

| キー | 動作 |
| --- | --- |
| <kbd>A</kbd> | 選択中のノードの後ろ、何も選択していなければ表示領域の中央にノードを追加します |
| <kbd>Ctrl</kbd>+<kbd>Enter</kbd> | 選択中のノードに対する [[ui:exp.sendNow]]、または [[ui:exp.listenNow]] |
| <kbd>Ctrl</kbd>+<kbd>Z</kbd> | 元に戻す |
| <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>Z</kbd>、<kbd>Ctrl</kbd>+<kbd>Y</kbd> | やり直し |
| <kbd>Ctrl</kbd>+<kbd>A</kbd> | すべてのノードを選択します |
| <kbd>Ctrl</kbd>+<kbd>C</kbd> / <kbd>Ctrl</kbd>+<kbd>X</kbd> / <kbd>Ctrl</kbd>+<kbd>V</kbd> | 選択したノードとその間の接続線をコピー／切り取り／貼り付けします |
| <kbd>Ctrl</kbd>+<kbd>D</kbd> | 選択したノードを複製します |
| <kbd>Delete</kbd>、<kbd>Backspace</kbd> | 選択した接続線、または選択したノードを削除します |
| 矢印キー (ノードにフォーカスがあるとき) | 選択したノードを 5 ピクセル動かします。<kbd>Shift</kbd> を押すと 20 ピクセルです |
| <kbd>Ctrl</kbd>+<kbd>F</kbd> | ノードを探します |
| <kbd>Ctrl</kbd>+<kbd>0</kbd> | グラフ全体を表示します |
| <kbd>Ctrl</kbd>+<kbd>1</kbd> | 100% にズームします |
| <kbd>Ctrl</kbd> + マウスホイール | ポインターを中心にズームします |
| <kbd>Shift</kbd> + クリック、<kbd>Ctrl</kbd> + クリック | 選択にノードを加える、または外します |
| 何もないキャンバスで <kbd>Shift</kbd> + ドラッグ | 枠で選択します |
| ノードをダブルクリック | フィールドを編集します |
| 何もないキャンバスをダブルクリック | その場所にノードを追加します |
| フォーカスした出力で <kbd>Enter</kbd>、<kbd>Space</kbd> | そこから接続線を引き始めます |
| フィールドで `{{` または <kbd>Ctrl</kbd>+<kbd>Space</kbd> | パラメーター、変数、シークレット、ジェネレーターを候補表示します |
| フィールドで <kbd>Esc</kbd> | キャンバス上のノードに戻ります |
| キャンバスで <kbd>Esc</kbd> | 追加メニューを閉じます。閉じるものがなければ、引いている接続線を取り消し、なければ選択した接続線を解除し、なければ複数選択を解除し、なければ全画面を終了し、なければフォーカスモードを終了します |

追加メニューと検索では、<kbd>↑</kbd> <kbd>↓</kbd> で選び、<kbd>Enter</kbd> で決定し、<kbd>Esc</kbd> で閉じます。アプリのすべてのショートカットは[キーボードショートカット](../reference/shortcuts.md)にあります。
