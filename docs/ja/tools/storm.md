# ストーム

[[ui:nav.storm]] 画面は負荷源です。1 つの宛先に、指定した速さで、指定した時間だけ、UDP データグラムを送信するか、TCP 接続を開き、実際に送信できた量を計測します。自分のサーバー、デバイス、回線が、大量の通信にどこまで耐えるか、つまり応答し続けるか、パケットを落とすか、機能しなくなるかを確認するのに使います。

::: danger 責任ある使用
ストームは、実在のホストに実際の通信を送ります。所有しているか、テストを許可されているホストとネットワークにだけ向けてください。高いレートは、同じ回線を使うすべての人にとって回線を飽和させ、侵入検知に引っかかることがあります。エンジンはストームのレートに上限を設けていません。0 は、このコンピューターが送信できる最高の速さを意味します。
:::

## ストームを開始する {#start}

1. [[ui:common.target]] を設定します。送信先の `IP:port` または `host:port` で、`127.0.0.1:9000` や `test-rig.local:9000` のようにします。ホスト名は、開始時に名前解決され、IPv4 アドレスがあればそれが使われます。
2. [[ui:common.protocol]] を選びます。[[ui:st.udp]] または [[ui:st.tcp]] です。
3. [[ui:st.payloadSize]]、[[ui:st.rate]]、[[ui:st.duration]] を設定します。
4. [[ui:st.launch]] を押します。

ストームはジョブとして動作します。コンソールの帯に表示され、継続時間が終わったとき、[[ui:st.stop]] を押したとき、または [[ui:app.stopAll]] で停止します。動作中は、フィールドは固定されます。

| フィールド | 内容 | 既定値 |
| --- | --- | --- |
| [[ui:common.target]] | 宛先の `IP:port` または `host:port`。 | `127.0.0.1:9000` |
| [[ui:common.protocol]] | [[ui:st.udp]]: 個別のデータグラム。[[ui:st.tcp]]: 「パケット」ごとに新しい TCP 接続。 | [[ui:st.udp]] |
| [[ui:st.payloadSize]] | 各データグラムまたは接続のバイト数。1〜65,507。範囲外の値は、その範囲に収められます。 | 512 |
| [[ui:st.rate]] | 目標とする 1 秒あたりのパケット (または接続) 数。0 は可能な限り速く。 | 1000 |
| [[ui:st.duration]] | 実行する秒数。0 は、停止するまで。 | 10 |

### UDP フラッド {#udp}

Signal Lab は、ペイロードサイズのデータグラムを、すべてのバイトを `0x55` にして、自分のポート 1 つから宛先に送信します。システムが拒否した送信はエラーとして数えられます。たとえば、宛先がそのポートで待ち受けているものがないと応答したあとなどです。

### TCP 接続フラッド {#tcp}

「パケット」ごとに、Signal Lab は宛先への TCP 接続を開き、ペイロードを書き込んで、閉じます。接続は同時ではなく、1 つずつ順に作られるため、TCP ストームが到達するレートは、宛先が接続を受け付ける速さに制限されます。拒否された接続や、500 ms 以内に受け付けられなかった接続はエラーとして数えられ、ペイロードを受け取った接続はパケットとして数えられます。

### レートの維持方法 {#pacing}

レートはスケジュールです。最初のパケットはすぐに送信され、*n* 番目のパケットは、開始から *n* ÷ [[ui:st.rate]] 秒後が期限になります。ストームは、起きるたびに期限が来ているものを送信し、次のパケットの期限まで眠ります。そのため、毎秒 50 なら毎秒 50、250 なら 250 になり、1 秒間の実行でほぼその数が送信されます。システムのタイマーの粒度には左右されません。[[ui:st.duration]] は、次のパケットの期限がそれより後であっても、時間どおりにストームを終了します。

ストームは、遅れを取り戻すためにレートを超えて送信することはありません。このコンピューターや、受け付けの遅い TCP 宛先が 256 パケットを超えて遅れた場合、古いものはスケジュールから除かれ、まとめて遅れて送信されることはありません。到達したレートは [[ui:st.pps]] に表示されます。

[[ui:st.rate]] が 0 の場合はスケジュールがなく、ストームは 256 パケットを送信したら、ほかの処理を実行させてから次の 256 パケットを送信する、ということを、このコンピューターが可能な限り速く繰り返します。

## スループットを読む {#metrics}

[[ui:st.throughput]] は 1 秒に 4 回更新されます。

| 指標 | 内容 |
| --- | --- |
| [[ui:common.packets]] | 開始からの、送信したデータグラム数、またはペイロードを受け取った接続数。 |
| [[ui:st.pps]] | 直近の 4 分の 1 秒間の、1 秒あたりのパケット数。 |
| [[ui:st.rateLabel]] | 直近の 4 分の 1 秒間の、ペイロードのメガビット毎秒。ヘッダー (IP、UDP、TCP) は数えません。 |
| [[ui:common.volume]] | 開始からの、送信したペイロードのバイト数。 |
| [[ui:common.errors]] | 失敗した送信または接続の数。 |

その下のグラフには、直近 1 分間の [[ui:st.pps]] が描かれます。

ストームが終了すると、カウンターには最終的な合計が表示され、[[ui:st.pps]] と [[ui:st.rateLabel]] は 0 になります。

数値からわかることは次のとおりです。

- UDP で [[ui:st.pps]] が [[ui:st.rate]] を大きく下回る場合: このコンピューターがそれ以上速く送信できません。レートかペイロードサイズを下げてください。
- UDP で [[ui:common.errors]] が増える場合: 宛先のポートが閉じているか、ネットワークが通信を拒否しています。
- TCP で [[ui:common.errors]] が増える場合: 宛先が接続を拒否しているか、受け付けに 500 ms を超えてかかっています。上限に達している可能性があります。

ストームがわかるのは、どれだけ送信したかであり、どれだけ届いたかではありません。宛先が何を受信したかは、宛先側で確認してください。宛先自身のログ、[[ui:nav.osc]] のモニター、または代わりに置いた[エミュレーター](emulators.md)です。

## インスペクターでの表示 {#inspector}

キャプチャがオンのときは、UDP ストームは、データグラムを 1 秒に 1 件だけ[インスペクター](inspector.md)に入れ、`sampled 1/s` と表示します。すべて同一だからです。判定には、前の 1 件から除外された件数も、`sampled 1/s · +999 not shown` のように表示されます。TCP ストームは、何も入れません。
