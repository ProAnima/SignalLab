# インスペクター

インスペクターは、すべてのツールをまとめた 1 つのタイムラインです。OSC メッセージ、データグラム、HTTP のやり取り、MQTT のパブリッシュ、WebSocket メッセージ、リレーされたパケット、エミュレーターのやり取りは、すべてここに、デコードされた状態で、元になったバイト列とともに表示されます。実際に回線上を何が、どの順序で流れ、それがどうなったかを確認するのに使います。

インスペクターは下部パネルにあり、コンソールの隣の [[ui:dock.inspector]] タブとして、どの画面からでも使えます。タブをクリックすると開き、パネルは数行とフレームの詳細が見える高さで開きます。⤢ ボタン ([[ui:dock.maximise]]) を押すと、パネルがウィンドウの高さいっぱいに広がります。パネルを閉じたり画面を切り替えたりしても、インスペクターは一覧と選択を保持します。

## キャプチャする {#capture}

キャプチャは Signal Lab の起動時にはオフで、オフの間は負荷がかかりません。ツールはフレームを作ることさえしません。

1. [[ui:dock.inspector]] タブを開きます。
2. [[ui:ins.arm]] を押します。タブの点が赤くなり、点滅します。
3. 任意のツールを使います。フレームは、新しいものを上にして一覧に表示されます。
4. 必要なものが取れたら、[[ui:ins.disarm]] を押します。

タブには、どの画面からでも、キャプチャされたフレームの数が表示されます。

フレームがキャプチャされるのは、キャプチャを開始した時点からで、それより前のものは取れません。先にキャプチャを開始してから、送信してください。

[サーバー](../server/index.md)では、キャプチャはサーバーに属します。サインインしているすべてのページに同じフレームが表示され、1 つのページでキャプチャを開始したりクリアしたりすると、すべてのページに反映されます。

### キャプチャされるもの {#sources}

| ツール | フレーム | 件数 |
| --- | --- | --- |
| [OSC](../protocols/osc.md): 送信 | 送信した各メッセージ | すべて |
| [OSC](../protocols/osc.md): モニター | 受信した各パケット。デコードできないものには、デコードエラーが付きます | すべて |
| [OSC](../protocols/osc.md): シグナルジェネレーター | 送信したメッセージ | 100 ms に最大 1 件。`sampled` と表示 |
| [ブロードキャスト](../protocols/broadcast.md): 1 回送信 | 各データグラム (宛先ごとに 1 つ)。失敗した送信はそのエラー付き | すべて |
| [ブロードキャスト](../protocols/broadcast.md): ビーコン | 送信したデータグラム | 50 ms に最大 1 件 |
| [ブロードキャスト](../protocols/broadcast.md): ディスカバリーリスナー | 受信したプローブ | 40 ms に最大 1 件 |
| [ブロードキャスト](../protocols/broadcast.md): ディスカバリーリスナー | その応答 (`auto-reply`) | すべて |
| [HTTP](../protocols/http.md): 送信、シグナル、実験のリクエスト | 各やり取り。リクエスト行、ステータスと時間、レスポンスヘッダー、ボディの先頭 | すべて |
| [HTTP](../protocols/http.md): 負荷バースト、負荷をかけたリクエスト | やり取り | 100 ms に最大 1 件 |
| [MQTT](../protocols/mqtt.md): 接続 | 送信したパブリッシュ | すべて |
| [MQTT](../protocols/mqtt.md): 接続 | 受信したメッセージ | 200 ms に最大 1 件 |
| [MQTT](../protocols/mqtt.md): 画面がそのブローカーに接続していないときに送信した MQTT シグナル | パブリッシュ | すべて |
| [WebSocket](../protocols/websocket.md) | 送受信したメッセージ | 通信量が少ないうちはすべて。最大で 1 秒に 200 件 |
| [エミュレーター](emulators.md) | 届いたものと応答を合わせて 1 件 | 10 ms に最大 1 件のやり取り |
| [劣化](impairment.md) | リレーされたすべてのデータグラムまたはチャンク。両方向、その運命付き | 両方向を合わせて 25 ms に最大 1 件 |
| [ストーム](storm.md) (UDP) | フラッドのパケット。すべて同一 | 1 秒に 1 件。`sampled 1/s` と表示。TCP のストームは何もキャプチャしません | 
| [スキャナー](scanner.md) | 開いている各ポートとそのバナー | すべて |
| [実験](../experiments/index.md) | 実行のステップが送信するもの (TCP メッセージの場合は、書き込んだペイロードと読み取った応答)、待機が受信するもの | 使われるツールと同じ |

サンプリングするツールは、残りを意図的に除外し、その数を数えます。次に描画されるフレームの判定に、保留した件数が `+n not shown` として付きます (`sampled · +5 not shown`)。この件数は、ツールが描画するはずだったものの数で、キャプチャ自身が間引いた分ではありません ([件数と欠落](#counts)を参照)。

## フレームの一覧 {#list}

| 列 | 内容 |
| --- | --- |
| [[ui:common.time]] | キャプチャされた時刻。ミリ秒単位。 |
| [[ui:ins.dir]] | → は送信 (`tx`)、← は受信 (`rx`)。リレーでは、→ がクライアントから宛先へ、← が宛先からクライアントへの向きです。 |
| [[ui:bc.proto]] | `osc`、`udp`、`tcp`、`http`、`mqtt`、`ws` のいずれか。 |
| [[ui:bc.peer]] | 相手側。`IP:port`、URL、ブローカーなど。 |
| [[ui:common.bytes]] | フレームのサイズ。 |
| [[ui:ins.summary]] | そのプロトコル固有の表記による 1 行。`/fader/1 0.75` や `GET http://127.0.0.1:8080/ → 200 in 3ms` など。 |
| [[ui:ins.verdict]] | そのフレームがどうなったか。伝えることがある場合のみ。 |

判定は、緑、琥珀色、赤のいずれかです。赤はロスまたは失敗 (`dropped (loss)`、`failed`、`error: …`)、琥珀色は変更されたフレームか、多数のうちのサンプルにすぎないフレーム (`corrupted`、`copy 2/2`、`sampled`、`+n not shown`)、それ以外は緑です。次のような判定が表示されます。

| 判定 | 出どころ | 意味 |
| --- | --- | --- |
| `forwarded +42ms` | 劣化 | その遅延のあとに転送された。`· corrupted`、`· reordered`、`· copy 1/2` が続くことがあります。 |
| `dropped (loss)`、`dropped (burst)`、`dropped (offline)` | 劣化 | 意図的に失われた。その理由も示されます。 |
| `throttled` | 劣化 | 帯域制限によって破棄された。 |
| `· client→target`、`· target→client` | 劣化 | リレーされたすべてのフレームの判定の末尾 (`+n not shown` の前) に付き、フレームがどちら向きだったかを示します。 |
| `#2 → 200 OK · 37 B`、`— → 404 …` | エミュレーター | どのルールが応答したか (`—` は該当なし) と、その応答。 |
| `down`、`down → 503` | エミュレーター | エミュレーターがダウンしている間に届いた。 |
| `200 OK`、`failed` | HTTP | レスポンスのステータス、またはレスポンスなし。 |
| `open` | スキャナー | 開いているポート。 |
| `auto-reply` | ディスカバリー | リスナーがプローブに送信した応答。 |
| `clears retained` | MQTT | 空の保持パブリッシュ。 |
| `+n not shown` | サンプリングするすべてのツール | 前のフレームから、その数のフレームが除外された。フレームのほかの判定のあとに `·` を挟んで付きます。 |

一覧は、最新の 4000 フレームを保持し、絞り込み条件に一致する最新の 300 フレームを描画します。絞り込み条件の下には、一致する数のうち、いくつ表示しているかが示されます。

### 絞り込み {#filter}

- テキストフィールド ([[ui:ins.filterPlaceholder]]) に入力すると、概要、ピア、ソース、プロトコル、判定にそのテキストを含むフレームだけが残ります。
- プロトコルのチップ (`osc`、`udp`、`tcp`、`http`、`mqtt`、`ws`) をクリックすると、そのプロトコルだけが表示されます。チップがどれもオンでなければ、すべてのプロトコルが表示されます。
- `tx` または `rx` をクリックすると、送信または受信したフレームだけが表示されます。
- [[ui:common.reset]] を押すと、3 つすべてが解除されます。

絞り込みは、一覧の表示だけを変えます。キャプチャ、件数、エクスポートは、常にすべてを対象とします。

### 一時停止とクリア {#pause}

[[ui:ins.pause]] を押すと、通信が続いている間も一覧が止まり、読み取れます。キャプチャは続きます。[[ui:ins.resume]] を押すと、新しいフレームが再び入ってきます。表示を一時停止している間に届いたフレームは、一覧には追加されませんが、キャプチャとエクスポートには含まれます。

[[ui:common.clear]] を押すと、一覧とキャプチャが空になり、件数もリセットされます。

### 件数と欠落 {#counts}

上部のバーには、キャプチャしたフレームの数とそのバイト数、キャプチャの使用状況 (8192 のうち保持しているフレーム数) が表示されます。

フレームが一覧の処理能力より速く届くと (約 8 分の 1 秒間に 250 件を超えると)、一覧は、そのうち最も古いものを飛ばします。すると、琥珀色のチップに表示されなかったフレームの数が表示され、一覧には欠落した位置を示す行が入ります。そのフレームは、より新しいフレームに押し出されていない限り、キャプチャにはまだ残っています。エクスポートすれば見られます。

## フレームの詳細 {#detail}

行をクリックすると、右側にそのフレームが表示されます。

| フィールド | 内容 |
| --- | --- |
| [[ui:ins.seq]] | フレームの番号。番号はキャプチャの順に増え、再利用されません。 |
| [[ui:common.time]] | キャプチャされた時刻。 |
| [[ui:ins.direction]] | 送信か受信か。 |
| [[ui:common.protocol]] | 一覧と同じ。 |
| [[ui:ins.source]] | キャプチャしたツール (`osc-send`、`osc-monitor`、`netsim`、`emulator`、`experiment-wait`、…)。ジョブに属している場合は、そのジョブ番号も表示されます。 |
| [[ui:ins.local]] | こちら側のアドレス (ある場合)。リレーされたフレームでは、リレーが待ち受けているアドレス。 |
| [[ui:bc.peer]] | 相手側。リレーされたフレームでは、向かっていた先。宛先、または応答が戻されたクライアント。 |
| [[ui:ins.size]] | バイト単位のサイズ。 |
| [[ui:ins.verdict]] | 一覧と同じ。 |

[[ui:ins.decoded]] には、そのプロトコルとして読み取ったフレームが表示されます。OSC バンドルのすべてのメッセージとその引数、HTTP レスポンスのヘッダーとボディの先頭、エミュレーターのリクエストとその応答などです。

[[ui:ins.rawBytes]] には、hex ダンプが表示されます。オフセット、16 バイトの hex、同じバイト列のテキスト表示です。一覧には、各フレームの先頭 256 バイトが入っています。フレームがそれより長い場合は、ダンプの下のボタンで全体を読み込めます。

### フレームが保持するもの {#limits}

| 上限 | 値 | 上限に達したとき |
| --- | --- | --- |
| 1 フレームが保持するバイト数 | 256 KiB | それより長いフレームは先頭の 256 KiB だけを保持し、全体のうちどれだけ保持したかが表示されます。 |
| キャプチャ内のフレーム数 | 8192 | 最も古いフレームが押し出されます。 |
| キャプチャ全体が保持するバイト数 | 64 MiB | 最も古いフレームが押し出されます。 |

バイト列を保持しないフレームもあります。HTTP のやり取り (サイズは記録され、レスポンスヘッダーとボディの先頭は、代わりにデコード結果のテキストに含まれます) と、スキャナーの開いているポートです。

MQTT のフレームが保持するのは、メッセージのペイロードで、その周りのプロトコルのパケットではありません。トピック、QoS、retain フラグは、概要に含まれます。

### シークレット {#secrets}

実験の実行や [[ui:exp.sendNow]] が[シークレット](../experiments/data.md#secrets)を使っている間は、その値は、キャプチャされる前にすべてのフレームでマスクされます。概要、デコード結果、アドレス、判定では `••••`、ペイロードではバイトごとに `*` になり、ダンプのオフセットは正しいままです。HTTP 画面の認証情報も表示されません。HTTP のフレームが保持するのは、レスポンスであり、送信した `Authorization` ヘッダーではありません。

## フレームをシグナルとして保存する {#save-as-signal}

キャプチャしたパケットを保存して、あとで、送信元のデバイスがなくなっていても再送信できるようにするには、次のようにします。

1. フレームを選択します。
2. [[ui:sig.fromFrame]] を押します。

シグナルは、[シグナルライブラリ](signals.md)の [[ui:sig.capturedFolder]] フォルダーに、フレームのすべてのバイト列とともに保存されます。バイト列は、デコード結果のテキストではなく、キャプチャが保持していたものから取られます。名前はフレームの概要から付けられ、メモには、どのフレームから作られたかが書かれます。

作られるものは、フレームによって異なります。

| フレーム | シグナル |
| --- | --- |
| OSC または UDP のデータグラム | フレームのバイト列 (hex) を持つ生の UDP シグナル。 |
| MQTT のパブリッシュ (送信、受信、またはエミュレーターのもの) | フレームのブローカー、トピック、QoS、retain フラグと、テキストとして元のままのペイロードを持つ MQTT シグナル。空のペイロードも保持されるので、保持値の消去も保存できます。 |
| それ以外。TCP ストリーム (リレーが運んだものや TCP ノードのものを含む)、HTTP のやり取り、WebSocket メッセージ、パブリッシュではない MQTT パケット (エミュレーターに対するクライアントのサブスクライブなど) | なし。ボタンはオフになり、ツールチップに理由が表示されます。シグナルが送信するのは 1 つのデータグラムか 1 件のパブリッシュで、これらは元のままでは再送信できません。 |

データグラムの送信先は次のとおりです。

- 受信したフレーム: それを受け取ったアドレス ([[ui:ins.local]] 側)。シグナルが送信元の代わりになります。
- 送信したフレーム: 送信先のピア。
- リレーされたフレーム (どちら向きでも): 向かっていた先のアドレス。クライアントから来たフレームなら宛先、応答ならクライアントです。

そのアドレスが、このコンピューターのすべてのアドレス (`0.0.0.0:9000` や `[::]:9000` で待ち受けているモニターなど) の場合は、代わりにこのコンピューターを宛先とします。`127.0.0.1:9000` や `[::1]:9000` です。別のアドレスにしたい場合は、シグナルを開いて宛先を変更してください。

MQTT シグナルは、フレームが示すブローカーに送信されます。すべてのアドレスで待ち受けているブローカーには、同様に `127.0.0.1` で到達します。

次の場合も、ボタンはオフになります。

- 完全には保持されていないフレーム。256 KiB を超えるもの、またはバイト列を保持していないもの。
- ペイロードがテキストでない MQTT メッセージ。シグナルのペイロードはテキストなので、そのバイト列を元のままでは再送信できません。
- こちら側のソケットを持たない受信フレーム。送信先となるアドレスがありません。

キャプチャがすでに手放したフレームも保存できず、コンソールにそう表示されます。ライブラリファイルを読み取れない間も、[[ui:sig.fromFrame]] はオフになり、ツールチップにファイルのエラーが表示されます ([シグナル](signals.md#file)を参照)。

## エクスポート {#export}

[[ui:ins.exportJsonl]] と [[ui:ins.exportTxt]] は、キャプチャ全体を書き出します。絞り込みの表示にかかわらず、最大 8192 フレームと、各フレームが保持するすべてのバイト列です。出力先は、データフォルダー内の `capture-<time>.jsonl` または `capture-<time>.txt` ファイルです ([ファイル](../reference/files.md)を参照)。場所はコンソールに表示されます。サーバーに接続したブラウザーでは、ファイルはサーバー上に書き込まれ、ブラウザーがダウンロードします。

空のキャプチャは書き込まれません。コンソールに、保存するものがないと表示されます。

- **`.jsonl`**: 1 行に 1 つの JSON オブジェクトで、フレームごとに 1 行です。`seq`、`ts` (1970 年からのミリ秒)、`proto`、`dir`、`source`、`job_id`、`local`、`remote`、`bytes`、`kept`、`summary`、`detail`、`hex` (先頭 256 バイトのダンプ)、`verdict`、そして保持したバイト列を base64 にした `data` が含まれます。
- **`.txt`**: 読むためのものです。フレームごとに、番号、時刻、方向、プロトコル、ピア、サイズ、判定を含む 1 行があり、続けて概要、デコード結果、保持したすべてのバイト列の hex ダンプが入ります。

```json
{"seq":12,"ts":1767225600123,"proto":"osc","dir":"rx","source":"osc-monitor","job_id":3,"local":"0.0.0.0:9000","remote":"127.0.0.1:53211","bytes":20,"summary":"/fader/1 0.75","detail":"/fader/1 0.75","hex":"0000  2f 66 61 64 65 72 2f 31  00 00 00 00 2c 66 00 00  |/fader/1....,f..|\n0010  3f 40 00 00                                       |?@..|\n","verdict":null,"kept":20,"data":"L2ZhZGVyLzEAAAAALGYAAD9AAAA="}
```

## ほかの場所から来る {#reveal}

ほかの画面からも、フレームを指すリンクがあります。実験のタイムラインの待機は、一致したフレームへのリンクを持ち、エミュレーターの受信一覧には、やり取りごとに ⌕ ボタン ([[ui:emu.inspectFrame]]) があります。これらを辿ると、そのフレームが選択され、絞り込みが解除され、表示が再開された状態で、インスペクターが開きます。
