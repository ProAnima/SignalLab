# スキャナー

[[ui:nav.scan]] 画面は、1 つのホストの範囲内のすべてのポートに TCP 接続を試み、接続を受け付けたポートを一覧にします。デバイスで実際にどのサービスが待ち受けているか、つまりプロジェクターの制御ポート、スイッチの Web インターフェイス、自分のサービスが開くはずだったポートなどを確認するのに使います。最初に挨拶を送るサービスについては、その内容も確認できます。

::: danger 責任ある使用
スキャンは、範囲内のすべてのポートに接続します。所有しているか、テストを許可されているホストだけをスキャンしてください。ほかのネットワークでは、スキャンが侵入検知に引っかかることがあり、規則に反する場合も少なくありません。
:::

## ホストをスキャンする {#scan}

1. [[ui:sc.host]] を入力します。1 つのホストで、IP アドレスまたは名前です。名前は、スキャンの開始時に一度だけ名前解決されます。解決できない場合は、その時点で理由を表示して止まります。
2. [[ui:sc.fromPort]] と [[ui:sc.toPort]] を設定するか、[[ui:sc.preset]] を選びます。
3. 必要に応じて、[[ui:common.concurrency]] と [[ui:common.timeoutMs]] を調整します。
4. 各サービスが最初に送信する内容を読み取るには、[[ui:sc.grabBanner]] をオンのままにします。
5. [[ui:sc.startScan]] を押します。

ボタンの下のバーには、全体のうち何ポートを試したか、そのうちいくつが開いているかが表示されます。開いているポートは、見つかるたびに右側に表示されます。スキャンは、すべてのポートを試したときに終了します。[[ui:sc.stopScan]] を押すと早めに終了し、まだ試していないポートは試されません。動作中は、フィールドは固定されます。

| フィールド | 内容 | 既定値 |
| --- | --- | --- |
| [[ui:sc.host]] | スキャンするホスト。 | `127.0.0.1` |
| [[ui:sc.fromPort]]、[[ui:sc.toPort]] | 範囲。両端を含み、1〜65,535。どちらかの端を超えて入力した数は、そこで止まります。最初のほうが大きい場合は、入れ替えられます。 | 1〜1024 |
| [[ui:common.concurrency]] | 同時に開く接続試行の数。1〜1024。 | 400 |
| [[ui:common.timeoutMs]] | 各接続を待つ時間。50〜10,000 ms。 | 500 |
| [[ui:sc.grabBanner]] | 接続後、サービスが何かを送信するのを最大 400 ms 待ち、最初の 256 バイトを保持します。 | オン |

範囲外の [[ui:common.concurrency]] や [[ui:common.timeoutMs]] は、スキャンの開始時にその範囲に収められます。

[[ui:sc.preset]] は、範囲を入力します。

| プリセット | ポート |
| --- | --- |
| [[ui:sc.preset.wellKnown]] | 1〜1024 |
| [[ui:sc.preset.common]] | 1〜10,000 |
| [[ui:sc.preset.osc]] | 8000〜9100 |
| [[ui:sc.preset.full]] | 1〜65,535 |

## スキャンにかかる時間 {#duration}

接続を受け付けるポートは、すぐに応答します。受け付けないポートでは、タイムアウト全体の時間がかかることがあります。接続の試行を破棄するファイアウォールは、まったく応答せず、Windows では、拒否でさえ既定のタイムアウトより長くかかることがあります。そのため、何も応答しないホストのスキャンには、おおよそ次の時間がかかります (Windows では、拒否されたポートに約 2 秒かかります。Windows が再試行するためで、その場合はタイムアウトによって決まります)。

```text
ports ÷ concurrency × timeout
```

既定値での全範囲は、65,535 ÷ 400 × 0.5 秒 ≈ 82 秒です。速くするには、[[ui:common.concurrency]] を上げるか、[[ui:common.timeoutMs]] を下げてください。タイムアウトを下げすぎると、応答の遅いホストの開いているポートを見逃します。

## 結果を読む {#results}

[[ui:sc.openPorts]] には、接続を受け付けたすべてのポートが、ポート番号順に一覧表示されます。

| 列 | 内容 |
| --- | --- |
| [[ui:sc.port]] | 開いているポート。 |
| [[ui:common.time]] | 見つかった時刻。 |
| [[ui:sc.banner]] | サービスが最初に送信した内容。改行はスペースに置き換えられます。なければ `—`。 |

接続を拒否したポートと、タイムアウト内に応答しなかったポートは、どちらも一覧に含まれません。スキャナーは、閉じているポートとフィルターされているポートを区別しません。一覧は、いくつあっても、開いているすべてのポートを保持します。

開いているポートが少ないのが普通です。Windows の PC は、最初の 1000 ポートのうち、通常 135 と 445 (ネットワークアドレスでは 139 も) で待ち受けており、ほとんどのデバイスは、ごく少数のポートです。比較するには、`netstat -an` (PowerShell では `Get-NetTCPConnection -State Listen`) で、このコンピューターが待ち受けているポートを一覧にしてみてください。

### チェックしなかったポート {#unchecked}

接続のたびに、このコンピューター自身のポートが 1 つ使われます。ポートやソケットが足りなくなると、試行はホストに届く前にここで失敗します。スキャナーは待って再試行し、それでも試せないポートは、閉じているものとしてではなく、*チェックしなかった*ポートとして数え、開いている数の隣に琥珀色で表示します。これが表示されたら、[[ui:common.concurrency]] を下げて、もう一度スキャンしてください。

バナーを持つのは、最初に自分から話すサービスだけです。SSH、SMTP、FTP、多くのデバイス制御プロトコルなどです。Web サーバーはリクエストを待つので、そのポートには `—` が表示されます。バナーの取得を有効にすると、開いているポートごとに最大 400 ms 余計にかかります。

スキャナーが開いた接続は、すぐにリセットで閉じられるので、このコンピューターのポートを、そのあと何分も保持し続けることはありません。スキャナーは、その接続上では何も送信しません。

キャプチャがオンのときは、開いているポートはすべて、バナーと判定 `open` とともに[インスペクター](inspector.md)にも表示されます。
