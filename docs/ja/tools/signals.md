# シグナル

シグナルは、名前を付けて保存したメッセージです。OSC メッセージ、生の UDP データグラム、HTTP リクエスト、MQTT のパブリッシュのいずれかで、宛先も含みます。一度作れば、[[ui:nav.signals]] 画面で作成するか、ほかの画面で送信したものを保存することで、必要なときにいつでも、バイト単位でまったく同じものを再送信できます。

ライブラリは JSON ファイルで、読んだり、手で編集したり、別のマシンにコピーしたり、プロジェクトと並べてコミットしたりできます。[[ui:nav.signals]] 画面では、左側にフォルダーのツリー、右側に選択中のシグナルのフィールドが表示されます。

## シグナルが送信できるもの {#transports}

[[ui:sig.transport]] で種類を選びます。種類ごとに、専用のフィールドがあります。

| [[ui:sig.transport]] | フィールド | 送信される内容 |
| --- | --- | --- |
| [[ui:sig.tr.osc]] | [[ui:common.target]]、[[ui:common.address]]、[[ui:common.arguments]] | 1 つの `IP:port` または `host:port` への 1 件の OSC メッセージ。新しい UDP ポートから送信します。引数の型については [OSC](../protocols/osc.md#types) を参照してください。 |
| [[ui:sig.tr.udp]] | [[ui:common.target]]、[[ui:sig.payloadKind]] ([[ui:sig.payloadText]] または [[ui:sig.payloadHex]])、[[ui:sig.payload]] | ちょうどこのバイト列を持つ 1 つのデータグラム。テキストは書いたとおりに、終端文字なしで送信されます。hex は `de ad be ef` のような 16 進数 2 桁の組です (スペースと `0x` の接頭辞は使えます)。 |
| [[ui:sig.tr.http]] | [[ui:sig.method]]、[[ui:sig.url]]、[[ui:sig.timeout]]、[[ui:sig.headers]]、[[ui:field.auth]]、[[ui:sig.body]] | 1 件の HTTP リクエスト。[HTTP](../protocols/http.md) を参照してください。 |
| [[ui:sig.tr.mqtt]] | [[ui:mq.broker]]、[[ui:mq.topic]]、[[ui:mq.qos]]、[[ui:mq.retain]]、[[ui:sig.payload]] | 1 件のパブリッシュ。[MQTT](../protocols/mqtt.md) を参照してください。 |

どのシグナルにも、[[ui:sig.name]]、[[ui:sig.group]]、[[ui:sig.note]] があります。メモには、何を起こすためのものか、相手側で何が一致している必要があるかを書きます。

OSC と UDP シグナルの宛先は `IP:port` または `host:port` (たとえば `127.0.0.1:9000`) です。ホスト名は、シグナルを送信するたびに名前解決されます。MQTT シグナルのブローカーは `host:port` で、ポートがなければ `1883` です。

シグナルの種類を変更すると、メッセージはその種類の既定値からやり直しになります。引き継がれるのは宛先だけで、宛先が同じ意味を持つ [[ui:sig.tr.osc]] と [[ui:sig.tr.udp]] の間の切り替えに限られます。

## シグナルを送信する {#send}

[[ui:nav.signals]] 画面からシグナルを送信するには、次のいずれかを行います。

- シグナルを選択して [[ui:sig.fire]] を押します。
- フィールドで作業中に <kbd>Ctrl</kbd>+<kbd>Enter</kbd> を押します。
- ツリーでシグナルをダブルクリックします。

送信のたびに、コンソールに 1 行が書き込まれます。何がどこへ送られたか、送信したバイト数、HTTP ならステータスとかかった時間です。失敗 (接続の拒否、到達できないホスト) は、理由付きの赤い行になります。最後に送信した時刻は、ボタンの横に表示されます。

シグナルは、そのプロトコルの画面と同じコマンドを通して送信されます。そのため、[インスペクター](inspector.md)には、送信したツールの名前で表示され、相手側には、手で入力したものと区別がつきません。

種類ごとの送信方法は次のとおりです。

| 種類 | 送信方法 |
| --- | --- |
| [[ui:sig.tr.osc]] | [[ui:nav.osc]] 画面がメッセージを送信するのと同じです。 |
| [[ui:sig.tr.udp]] | 宛先に 1 つのデータグラムを送信します。 |
| [[ui:sig.tr.http]] | [[ui:nav.http]] 画面がリクエストを送信するのと同じです。そちらで [[ui:http.keepCookies]] がオンの間は、その Cookie ジャーも使います。接続の拒否やタイムアウトは、ステータスではなく失敗として扱われます。 |
| [[ui:sig.tr.mqtt]] | [[ui:nav.mqtt]] 画面がシグナルのブローカーに接続している間は、その接続を通して、その接続のクライアント ID と認証情報で送信します。そうでない場合 (未接続、または別のブローカーに接続中) は、この 1 回のパブリッシュのために、Signal Lab がシグナルのブローカーに独自のクライアント ID、ユーザー名なし、クリーンセッションで接続し、そのあと切断します。 |

シグナルのブローカーへの接続とみなされるのは、ホストが (大文字と小文字を区別せずに) 同じで、ポートも同じ場合です。ポートなしで書かれたブローカーは `1883` として扱います。名前は解決されません。ここでは `localhost` と `127.0.0.1` は別のブローカーなので、一方の名前を指すシグナルは、もう一方に張った接続では送信されません。

::: tip
MQTT シグナルはパスワードを保存しません。パスワードを求めるブローカーにパブリッシュするには、先に [[ui:nav.mqtt]] 画面でそのブローカーに接続してください。シグナルは、その接続を通して送信されます。
:::

## どの画面からでも送信する {#palette}

どの画面でも <kbd>Ctrl</kbd>+<kbd>K</kbd> を押すとパレットが開きます。シグナルの名前、フォルダー、宛先、メッセージの数文字を入力して、<kbd>Enter</kbd> を押します。パレットが閉じてシグナルが送信され、見ていた画面にそのままとどまります。

| キー | 動作 |
| --- | --- |
| <kbd>Ctrl</kbd>+<kbd>K</kbd> | パレットを開く、または閉じる。 |
| <kbd>↑</kbd> <kbd>↓</kbd> | 選択を移動する。 |
| <kbd>Enter</kbd> | 選んだシグナルを送信する。 |
| <kbd>Esc</kbd> | 送信せずにパレットを閉じる。 |

パレットに表示されるシグナルは最大 12 件です。何も入力していないときはライブラリの先頭 12 件、入力後は一致した先頭 12 件です。行をクリックすると送信され、外側をクリックするとパレットが閉じます。

## シグナルを作る {#create}

### シグナル画面で {#create-here}

1. シグナルを入れるフォルダーを選びます ([現在のフォルダー](#current-folder)を参照)。
2. [[ui:sig.new]] を押します。宛先 `127.0.0.1:9000`、アドレス `/hello` の新しい OSC シグナルが、そのフォルダーに選択された状態で作られます。
3. [[ui:sig.name]]、[[ui:sig.transport]]、メッセージのフィールドを変更します。

変更はすべて自動で保存されます。この画面に保存ボタンはありません。ライブラリファイルを読み取れない間は、何も保存されず、フィールドは読み取り専用になります ([ライブラリファイル](#file)を参照)。

[[ui:sig.duplicate]] を押すと、選択中のシグナルの直後にコピーが作られ、名前の後ろに `·` が付きます。[[ui:sig.delete]] はもう一度確認を求め ([[ui:sig.confirmDelete]])、2 回目のクリックでファイルから削除されます。そのフォルダーは、空になっても残ります。

### HTTP・OSC・MQTT 画面から {#save-from-screens}

3 つの画面の送信部分、つまり [[ui:nav.http]] の [[ui:http.request]]、[[ui:nav.osc]] の [[ui:osc.sender]]、[[ui:nav.mqtt]] の [[ui:mq.publish]] では、送信する内容をシグナルとして保存できます。

1. メッセージを設定し、思いどおりに動作するまで送信します。
2. [[ui:sig.saveNew]] を押します (または画面のその部分で <kbd>Ctrl</kbd>+<kbd>S</kbd>)。[[ui:sig.saveTitle]] ダイアログが開きます。
3. [[ui:sig.name]] を確認します。送信する内容から提案されます。
4. [[ui:sig.group]] を選ぶか、入力します。前回使ったフォルダーが入力済みになっています。`Venue/Stage` のようにまだ存在しないパスは、新しく作られます。
5. [[ui:sig.saveConfirm]] を押します。

以降、その画面はそのシグナルと結び付きます。ボタンの横のチップに保存場所が表示されます (`❖ Folder / Name`)。チップをクリックすると、[[ui:nav.signals]] 画面でそのシグナルが表示されます。

| 表示 | 意味 | できること |
| --- | --- | --- |
| ✓ [[ui:sig.savedState]] (グレー) | ライブラリには、画面が送信するものとまったく同じ内容があります。 | 保存するものはありません。 |
| [[ui:sig.save]] と、チップの [[ui:sig.changed]] | 画面のメッセージが、シグナルと異なります。 | [[ui:sig.save]] または <kbd>Ctrl</kbd>+<kbd>S</kbd> で、画面のメッセージがそのシグナルに書き込まれます。名前、フォルダー、メモは変わりません。 |
| [[ui:sig.saveAs]] | — | シグナルの名前とフォルダーが入力された状態でダイアログをもう一度開き、新しいシグナルとして保存します。そのあと、画面は新しいほうと結び付きます。 |

比較の対象は、書き方ではなくメッセージの内容です。JSON のキーの順序や、32 ビット精度を超える OSC の float の末尾の桁は、変更として扱われません。

[[ui:nav.http]] 画面と [[ui:nav.osc]] 画面は、Signal Lab を再起動しても結び付きを保ちます。[[ui:nav.mqtt]] 画面は、アプリを閉じるまで保ちます。

::: warning
HTTP シグナルは、[[ui:field.auth]] (ユーザー名とパスワード、またはトークン) を、ライブラリファイルにプレーンテキストで保存します。ファイルを読める人は誰でも、それを読み取れます。
:::

### シグナルをその画面で開く {#open-in-screen}

選択した HTTP、OSC、MQTT のシグナルには、そのプロトコルの画面 ([[ui:nav.http]]、[[ui:nav.osc]]、[[ui:nav.mqtt]]) で開くボタンがあります。画面のフィールドにはシグナルの内容が入力され、上記のとおり画面はそのシグナルと結び付きます。そこで編集して送信し、[[ui:sig.save]] で保存してください。生の UDP シグナルには、専用の画面はありません。

### フレームやトピックから {#capture}

- [インスペクター](inspector.md#save-as-signal)でフレームを選んで [[ui:sig.fromFrame]] を押します。データグラムは、そのフレームとまったく同じバイト列を持つ生の UDP シグナルになります。MQTT のパブリッシュは、同じブローカー、トピック、QoS、retain フラグ、ペイロードを持つ MQTT シグナルになります。それ以外のフレームは保存できません。
- [[ui:nav.mqtt]] 画面でトピックを選んで [[ui:sig.fromFrame]] を押します。接続中のブローカーに、そのトピックの最後の値を、QoS と retain フラグも含めてパブリッシュする MQTT シグナルが作られます。

どちらも [[ui:sig.capturedFolder]] フォルダーに保存され、キャプチャした内容にちなんだ名前が付きます。

### 実験で {#in-experiments}

実験にノードを追加するとき、[[ui:exp.addNode]] メニューの [[ui:exp.group.signals]] にも、シグナルが一覧表示されます。1 つ選ぶと、同じメッセージを持つ OSC、HTTP、MQTT、または UDP ノードが追加されます。hex ペイロードの生の UDP シグナルは表示されません。UDP ノードはテキストを送信するためです。[ノード](../experiments/nodes.md)を参照してください。

## フォルダー {#folders}

フォルダーは、`/` でつないだ名前のパスです。`API/Auth` は、`API` の中の `Auth` フォルダーです。シグナルの [[ui:sig.group]] フィールドには、そのフォルダーのパスが入ります。空の場合は最上位 ([[ui:sig.topLevel]]) です。フィールドを離れると、名前は前後の空白が取り除かれ、空のパートは除かれるので、` API / Auth/ ` は `API/Auth` になります。

フォルダーは名前順に並び、数字は数値の順になります (`Cue 2` が `Cue 10` より前)。シグナルは、ファイルの順序のままです。各フォルダーには、サブフォルダーを含め、保持しているシグナルの数が表示されます。空のフォルダーは、削除するまで残ります。

### 現在のフォルダー {#current-folder}

最後にクリックしたフォルダー、または選択したシグナルのフォルダーが、現在のフォルダーです。[[ui:sig.new]] と [[ui:sig.newFolder]] は、そこに作成します。ツリーの上のチップにその名前が表示され、チップをクリックすると最上位に戻ります。

### フォルダーを操作する {#folder-tasks}

| やりたいこと | 操作 |
| --- | --- |
| フォルダーを作る | ＋ [[ui:sig.newFolder]] を押します。現在のフォルダーの中に、[[ui:sig.newFolderName]] という名前で作られ (その名前がすでにあれば、後ろに数字が付きます)、すぐに名前を変更できます。 |
| フォルダーを開閉する | フォルダーをクリックするか、フォーカスがある状態で <kbd>→</kbd> / <kbd>←</kbd> を押します。Signal Lab は、閉じているフォルダーを記憶します。 |
| すべてを開閉する | ツリーの上の ⊞ と ⊟ のボタン ([[ui:sig.expandAll]]、[[ui:sig.collapseAll]])。 |
| フォルダー名を変更する | フォルダー上で ✎ ([[ui:sig.renameFolder]]) または <kbd>F2</kbd> を押し、入力して <kbd>Enter</kbd> を押します。<kbd>Esc</kbd> でキャンセルします。 |
| シグナルやフォルダーを移動する | フォルダーにドラッグします。最上位にするには、ツリーの空白部分にドラッグします。 |
| 入力でシグナルを移動する | [[ui:sig.group]] フィールドを変更します。 |
| フォルダーを削除する | × ([[ui:sig.removeFolder]]) を押してから [[ui:sig.confirmRemoveFolder]] を押すか、フォルダー上で <kbd>Delete</kbd> を 2 回押します。 |

名前の変更で 2 つのフォルダーが統合されることはありません。`/` を含む名前や、同じ階層のフォルダーにすでにある名前は拒否され、コンソールに表示されます。フォルダーを自分自身や、その中のフォルダーにドラッグすることはできません。同じ名前のフォルダーがすでにあるフォルダーにドラッグすると、2 つは統合されます。

フォルダーの削除では、フォルダーだけが削除されます。そのシグナルとサブフォルダーは、1 階層上に移動します。何も削除されません。

### シグナルを探す {#filter}

ツリーの上の [[ui:sig.search]] に入力します。名前、フォルダー、メモ、宛先、メッセージが対象です。絞り込んでいる間は、一致があるフォルダーはすべて開き、それ以外は非表示になります。

## 初期セット {#starter-set}

Signal Lab は、ライブラリファイルが見つからない最初の機会に、9 つの例を書き込みます。それぞれ、間違えやすい点に焦点を当てたものです。名前とメモは、その時点のインターフェイスの言語で書かれます。以降は、自由に変更できます。すべて、このコンピューターを宛先としています。

| フォルダー | シグナル | 送信内容 |
| --- | --- | --- |
| `OSC` | [[ui:seed.osc-fader.name]] | `127.0.0.1:9000` への、float `0.75` を持つ `/fader/1` |
| `OSC` | [[ui:seed.osc-types.name]] | int `-7`、float `1.5`、文字列 `hi`、bool true、int64 `4294967296`、double `0.125`、nil を持つ `/types` |
| `OSC` | [[ui:seed.osc-id-and-value.name]] | 文字列 `reader-1` と `04a1b2c3` を持つ `/tag` |
| `OSC` | [[ui:seed.osc-trigger.name]] | 引数なしの `/cue/go` |
| `MQTT` | [[ui:seed.mqtt-publish.name]] | `127.0.0.1:1883` の `lab/example/value` への `1`。QoS 0 |
| `MQTT` | [[ui:seed.mqtt-retained.name]] | `lab/example/config` への `night`。QoS 1、retain 付き |
| `MQTT` | [[ui:seed.mqtt-clear-retained.name]] | `lab/example/config` への、空で retain 付きのペイロード。QoS 1 |
| `HTTP` | [[ui:seed.http-reachable.name]] | `GET http://127.0.0.1:8080/`。タイムアウト 4000 ms |
| [[ui:seed.folder.Raw]] | [[ui:seed.udp-raw.name]] | `127.0.0.1:9000` へのバイト列 `de ad be ef` |

初期セットを元に戻すには、`signals.json` を移動するか名前を変更して、[[ui:sig.reload]] を押します。ファイルがなければ、もう一度書き込まれます。

## ライブラリファイル {#file}

ライブラリは、データフォルダーにある `signals.json` です。デスクトップではホームフォルダーの `Documents/SignalLab`、サーバーではサーバーのデータフォルダーです ([ファイル](../reference/files.md)を参照)。ツリーの下のシグナル数にカーソルを合わせると、完全なパスが表示されます。

- **自動で保存されます。** 変更は、最後の変更から 0.7 秒後に、ファイル全体がまとめて書き込まれます。同じフォルダー内の一時ファイルに書いてから、それがファイルと入れ替わるので、書き込みが途中で切れても、前のファイルが残ります。書き込みの待機中は、ツリーの下部に [[ui:sig.saving]] と表示され、完了すると [[ui:sig.saved]] になります。待機中の書き込みは、アップデートでアプリが再起動する前に実行されます。
- **手で編集できます。** Signal Lab は、ファイルが外部で変更されても気づきません。編集したあとや、別のマシンのファイルに置き換えたあとは、[[ui:sig.reload]] を押してください。再読み込みはファイルをもう一度読み込み、書き込み待ちだった変更を破棄します。
- **ほかで変更された場合。** 保存のたびに、どのファイルを読み込んだかが記録されます。そのあとファイルが変更されていた場合 (自分で編集した、または同じサーバーの別のページが自分の変更を保存した) は、保存が拒否され、ファイルはその変更を保ったまま残り、ツリーにエラーが表示されて、以下の壊れたファイルの場合と同様に書き込みが止まります。[[ui:sig.reload]] を押して、いまの内容を確認してください。このページが保存できなかった変更は再読み込みで失われるので、もう一度行ってください。
- **壊れている間は上書きされません。** ファイルが有効な JSON でない場合や、シグナルライブラリでない場合は、ツリーにファイルのパス、行、列とともにエラーが表示され、コンソールにも同じ内容が表示されます。ファイルはそのまま残り、再び読み込めるまで、何もライブラリに書き込みません。[[ui:sig.new]]、シグナルやフォルダーの名前変更、移動、削除、ドラッグ、シグナルのフィールド、HTTP・OSC・MQTT 画面の [[ui:sig.saveNew]]、[[ui:sig.save]]、[[ui:sig.saveAs]]、インスペクターと MQTT 画面の [[ui:sig.fromFrame]] は、すべて無効になり、ツールチップに何が問題かが表示されます。ファイルを修正するか削除して、[[ui:sig.reload]] を押してください。読み込めるようになれば、すべてが再び使えます。
- **アプリの動作中にファイルが壊れた場合。** ファイルを読み取れないものに編集し、そのあとアプリが変更を保存しようとすると、同じエラーで保存が拒否されます。ファイルは編集したとおりに残り、アプリは、修正して [[ui:sig.reload]] を押すまで書き込みを止めます。編集して有効なままにしたファイルも置き換えられません。次回の保存は、ほかで変更されたものとして拒否され、[[ui:sig.reload]] でその編集が読み込まれます。

ファイルの短い例です。

```json
{
  "version": 2,
  "signals": [
    {
      "id": "fader-value",
      "name": "Fader value",
      "group": "Venue/Stage",
      "note": "Main fader of desk A.",
      "body": {
        "transport": "osc",
        "target": "127.0.0.1:9000",
        "address": "/fader/1",
        "args": [{ "type": "float", "value": 0.75 }]
      }
    }
  ],
  "folders": ["Venue/Stage", "Venue/Empty for now"]
}
```

| キー | 内容 |
| --- | --- |
| `version` | `2`。バージョン 1 のファイル (フォルダー機能の前) も同じように読み込まれますが、空のフォルダーはありません。 |
| `signals[].id` | シグナルの作成時に名前から作られます (`fader-value`、`fader-value-2`、…)。名前を変更しても変わりません。`signallab fire` は、これでシグナルを探します。 |
| `signals[].group` | フォルダーのパス。`""` は最上位です。 |
| `signals[].body` | メッセージ。`transport` は `osc`、`udp`、`http`、`mqtt` のいずれかで、そのほかのキーはその種類のフィールドです。 |
| `folders` | すべてのフォルダー。空のフォルダーも保持できます。フォルダーがない場合は省略されます。どのエントリにも挙げられていない `group` も、フォルダーとして扱われます。 |

## コマンドラインから {#cli}

`signallab fire` は、アプリと同じコマンドを通して、ライブラリのシグナルを送信します。

```bash
signallab fire "Fader value"
signallab fire fader-value --library ./show/signals.json
```

まず ID で、次に (大文字と小文字を区別せずに) 名前でシグナルを探します。同じ名前のシグナルが複数ある場合は、それらの ID を表示し、何も送信しません。`--library` がなければ、アプリ自身の `signals.json` を読み込みます。ファイルに書き込むことはありません。[コマンドライン](../automation/cli.md#cli-fire)を参照してください。
