# インストールと更新

Signal Lab は GitHub でリリースされています。各リリースには、Windows と Linux 用のデスクトップアプリ、単体の `signallab` コマンドライン、チェックサムの一覧が含まれます。サーバー上で動かしてブラウザーから使う場合は、[サーバー](../server/index.md)を参照してください。

## ダウンロードするもの {#downloads}

[最新のリリース](https://github.com/ProAnima/SignalLab/releases/latest)を開き、自分のシステム用のファイルを選びます。`<version>` はリリースのバージョンで、たとえば `[[version]]` です。

| ファイル | 対象 |
| --- | --- |
| `Signal.Lab_<version>_x64-setup.exe` | Windows 10 と 11、x64 — ほとんどの人に適したセットアップ |
| `Signal.Lab_<version>_x64_en-US.msi` | Windows、IT 部門による展開 (Intune、グループ ポリシー) 用: すべてのユーザーにインストールします |
| `Signal.Lab_<version>_amd64.deb` | Linux x86_64: Debian、Ubuntu とその派生ディストリビューション |
| `Signal.Lab-<version>-1.x86_64.rpm` | Linux x86_64: Fedora、RHEL、openSUSE とその派生ディストリビューション |
| `Signal.Lab_<version>_amd64.AppImage` | Linux x86_64、任意のディストリビューション、インストール不要 |
| `signallab-<version>-windows-x64.zip` | Windows 用のコマンドライン単体 |
| `signallab-<version>-linux-x64.tar.gz` | Linux 用のコマンドライン単体 |
| `SHA256SUMS.txt` | 上記すべてのファイルの SHA-256 チェックサム |

その横にある `.sig` ファイルと `latest.json` はアプリ自身の更新機能が使うもので、ダウンロードする必要はありません。

## Windows {#windows}

Signal Lab は Windows 10 と 11 (x64) で動作します。どちらにも含まれている WebView2 ランタイムを使用します。

### セットアップでインストールする {#windows-setup}

1. `Signal.Lab_<version>_x64-setup.exe` を実行します。
2. Windows SmartScreen が PC を保護したと表示した場合は、**詳細情報**を選んでから**実行**を選びます (下の [SmartScreen](#smartscreen) を参照)。
3. セットアップの言語を選びます。アプリと同じ 11 の言語から選べます。
4. 誰のためにインストールするかを選びます。
   - 自分だけ: `%LOCALAPPDATA%\Signal Lab` にインストールされ、管理者権限は不要です。
   - このコンピューターを使うすべてのユーザー: `C:\Program Files\Signal Lab` にインストールされ、管理者権限を求められます。
5. フォルダーを確認してインストールします。
6. 最後のページでは、Signal Lab をすぐに起動することと、デスクトップにショートカットを作成することを選べます。

インストール済みのバージョンの上から新しいバージョンのセットアップを実行すると、そのままアップグレードされます。

### セットアップが追加するもの {#windows-setup-adds}

セットアップはアプリのほかに 2 つのものを配置し、アンインストーラーはその両方を削除します。

- **コマンドライン。** `signallab.exe` がアプリの横に置かれ、そのフォルダーが `PATH` に追加されます。自分だけのインストールでは自分の `PATH` に、すべてのユーザーへのインストールではコンピューター全体のものに追加されるので、その後に開くどのターミナルでも `signallab` が使えます。[コマンドライン](../automation/cli.md)を参照してください。
- **ファイアウォールのルール** (すべてのユーザーへのインストールの場合のみ)。Windows Defender ファイアウォールは、ルールが許可している場合にだけ他のマシンからプログラムへの接続を通し、プログラムが初めて待ち受けるときに画面の前にいる人に確認します。そこで *キャンセル* を選ぶと、他のマシンから送られたものは何の通知もなく破棄されます。管理者権限を持つすべてのユーザーへのインストールは、`signal-lab.exe` (アプリ) と `signallab.exe` (コマンドライン) のそれぞれに、プライベート ネットワークとドメイン ネットワークでの受信許可ルールを追加します。自分だけのインストールではファイアウォールを変更できません。その場合は、何かが初めて待ち受けるときに、アプリが Windows 自身の管理者確認を使って変更を提案します。[ファイアウォールの通知](interface.md#firewall-notice)を参照してください。

このコンピューター自身の通信 (`127.0.0.1`) はフィルターされないため、ループバックで行うことはすべて、ルールがなくても動作します。

### 無人インストール {#windows-unattended}

セットアップは、コマンドラインで次のスイッチを受け付けます。

| スイッチ | 動作 |
| --- | --- |
| `/S` | 何も確認せずにサイレントでインストールします。 |
| `/P` | 確認なしで、進行状況バーを表示してインストールします。 |
| `/ALLUSERS` | すべてのユーザーにインストールします (管理者として実行したプロンプトが必要です)。 |
| `/CURRENTUSER` | 現在のユーザーだけにインストールします。 |
| `/NS` | ショートカットを作成しません。 |
| `/D=C:\Tools\Signal Lab` | このフォルダーにインストールします。最後に指定し、引用符で囲みません。 |
| `/NOPATH` | `PATH` を変更しません。`signallab` はインストールされますが、`PATH` には追加されません。 |
| `/NOFIREWALL` | ファイアウォールのルールを追加しません。 |

たとえば、管理者として実行したプロンプトから、ファイアウォールのルールなしで、すべてのユーザーにサイレントでインストールするには次のようにします。

```powershell
.\Signal.Lab_[[version]]_x64-setup.exe /S /ALLUSERS /NOFIREWALL
```

### MSI {#windows-msi}

`Signal.Lab_<version>_x64_en-US.msi` は IT 部門による展開用です。すべてのユーザーにインストールし、`signallab.exe` をアプリの横に置いてそのフォルダーをコンピューターの `PATH` に追加しますが、ファイアウォールのルールは追加しません。それは展開する側 (たとえばグループ ポリシー) に任されます。アプリは、初めて待ち受けるときにやはりルールの追加を提案します。サイレントでインストールするには次のようにします。

```powershell
msiexec /i "Signal.Lab_[[version]]_x64_en-US.msi" /qn
```

### SmartScreen {#smartscreen}

インストーラーはまだコード署名されていないため、Windows SmartScreen は発行元を認識できず、警告を表示してセットアップを止めることがあります。**詳細情報**を選び、そのファイルがリリースページからダウンロードしたものであることを確認してから、**実行**を選んでください。ファイルが改変されていないことを確かめるには、先に[`SHA256SUMS.txt` と照合](#checksums)してください。

アプリ自身の更新は署名されており、別途検証されます。[更新](#updates)を参照してください。

## ダウンロードの検証 {#checksums}

`SHA256SUMS.txt` には、リリースの各ファイルの SHA-256 チェックサムが 1 行に 1 つずつ、ファイル名とともに記載されています。対象のファイルと同じ場所にダウンロードして比較します。

Windows では、PowerShell で次のようにします。

```powershell
Get-FileHash .\Signal.Lab_[[version]]_x64-setup.exe -Algorithm SHA256
Select-String "Signal.Lab_[[version]]_x64-setup.exe" .\SHA256SUMS.txt
```

2 つのハッシュが一致している必要があります (`Get-FileHash` は大文字で表示しますが、大文字と小文字の違いは関係ありません)。

Linux では、両方のファイルがあるフォルダーで次のようにします。

```bash
sha256sum --check --ignore-missing SHA256SUMS.txt
```

見つかった各ファイルの後に `OK` と表示されます。それ以外の表示は、ダウンロードしたものがリリースされたファイルではないことを意味します。ダウンロードし直してください。

## Linux {#linux}

Linux 版のアプリは x86_64 向けに (Ubuntu 22.04 上で) ビルドされており、ウィンドウの描画に使う Web ビュー、WebKitGTK 4.1 が必要です。Arm プロセッサー向けのビルドはありません。Arm マシンでは、代わりに[サーバー](../server/index.md)を実行してください。

### .deb パッケージ {#linux-deb}

```bash
sudo apt install ./Signal.Lab_[[version]]_amd64.deb
```

`apt` は、パッケージが必要とするものも一緒にインストールします。このパッケージは、コマンドラインも `/usr/bin/signallab` に配置します。

### .rpm パッケージ {#linux-rpm}

```bash
sudo dnf install ./Signal.Lab-[[version]]-1.x86_64.rpm
```

openSUSE では、同じファイルで `sudo zypper install` を使います。`.deb` と同様に、このパッケージはコマンドラインを `/usr/bin/signallab` に配置します。

### AppImage {#linux-appimage}

AppImage はインストールせずに実行できます。

```bash
chmod +x Signal.Lab_[[version]]_amd64.AppImage
./Signal.Lab_[[version]]_amd64.AppImage
```

`signallab` コマンドラインは含まれていません。必要な場合は、[コマンドラインのアーカイブ](#cli-archives)から入手してください。

### Linux のファイアウォール {#linux-firewall}

Linux では、アプリはファイアウォールの通知を表示しません。`ufw` と `firewalld` は、プログラム単位ではなくポート単位で動作するからです。どちらかが有効で、他のマシンからモニター、リスナー、エミュレーター、リレーに接続する必要がある場合は、そのファイアウォールでポートを開いてください。たとえば次のようにします。

```bash
sudo ufw allow 9000/udp
```

ループバックの通信には影響しません。

## 単体のコマンドライン {#cli-archives}

デスクトップ版のインストーラーには `signallab` が付属しています。アプリのないマシン (ビルドエージェント、サーバー、ラボの PC) 向けに、各リリースにはコマンドライン単体も含まれています。

- `signallab-<version>-windows-x64.zip` には `signallab.exe` とライセンスが入っています。
- `signallab-<version>-linux-x64.tar.gz` には `signallab` とライセンスが入っています。

`PATH` 上のフォルダーに展開してください。Linux では次のようにします。

```bash
tar -xzf signallab-[[version]]-linux-x64.tar.gz signallab
sudo install signallab /usr/local/bin/
signallab version
```

サーバーの Docker イメージにも含まれています。使い方は[コマンドライン](../automation/cli.md)を参照してください。

## 更新 {#updates}

### デスクトップアプリ {#updates-desktop}

デスクトップアプリは、公開済みのリリースからのみ、指示したときにだけ自身を更新します。

- **1 日 1 回確認します。** [[ui:update.auto]] がオンのとき (既定ではオンです)、アプリは起動後、前回の確認から 1 日以上たっていればすぐに新しいリリースを探し、実行中にさらに 1 日が過ぎるたびにもう一度探します。自動で探さないようにするには、「Signal Lab について」でこのチェックを外します。
- **今すぐ確認することもできます。** 「Signal Lab について」(ヘッダーの **?**) を開き、[[ui:update.title]] の下にある [[ui:update.check]] を押します。
- **確認で送信される内容。** スタジオの更新サービス (`hub.proanima.net`) に、このインストールがどのリリースを受け取るべきかを問い合わせ、そのサービスに接続できない場合にだけ GitHub の最新リリースを参照します。リクエストには、アプリのバージョン、システムとプロセッサーの種類、このインストール用に生成されたランダムな番号が含まれます。この番号によって、新しいリリースをまず一部のインストールにだけ届けることができます。あなたやこのコンピューターを特定できる情報は送信されません。
- **リリースが見つかると**、コンソールにその旨が表示され、ヘッダーに「Signal Lab について」を開く更新ボタンが現れます。そこでは [[ui:update.notes]] にリリースノートが表示されます。
- **クリックするまで何もインストールされません。** [[ui:update.install]] を押します (ジョブが実行中の場合は、それらを停止することがボタンに表示されます)。Signal Lab は保存待ちのものをすべて保存し、実行中のジョブをすべて停止し、更新をダウンロードして、アプリに組み込まれた鍵でその署名を検証します。リリース工程で署名されていない更新は拒否されます。その後、更新をインストールし、新しいバージョンとして再起動します。

Windows では、更新はセットアップを確認なしで実行し、フォルダー、`PATH`、ファイアウォールのルールはそのまま保たれます。Linux では、AppImage を置き換えるか、新しい `.deb` または `.rpm` パッケージをインストールします。パッケージの場合は、先にシステムがパスワードを求めます。

プレリリースと下書きが提示されることはありません。マシン上のすべてのインストールで自動確認を止めるには (たとえば IT 部門が自ら更新を展開する場合)、環境変数 `SIGNALLAB_NO_UPDATE_CHECK` に任意の値を設定します。その場合も [[ui:update.check]] は押せば動作します。開発ビルドが自動で確認することはありません。

### サーバー {#updates-server}

サーバーと、ブラウザーに表示されるそのページは、Docker イメージとともに更新され、自動で更新されることはありません。「Signal Lab について」にもそう表示されます。更新方法は[サーバー](../server/index.md)を参照してください。

## アンインストール {#uninstall}

**Windows。** *設定 → アプリ → インストールされているアプリ* を開き、Signal Lab を見つけて *アンインストール* を選びます。セットアップのアンインストーラーは `signallab.exe` を `PATH` から外し、管理者権限で実行された場合 (すべてのユーザーへのインストールではそうなります) は、Windows の確認で作成されたものも含め、アプリとコマンドラインに対する受信ファイアウォールルールをすべて削除します。アプリケーションデータも削除するためのチェックボックスが表示されます。これはアプリ自身の設定 (言語、ペインのサイズ、開いていた画面、各画面に最後に入力した値) であり、あなたのファイルではありません。MSI でのインストールも同じ方法で削除できます。その場合は `PATH` のエントリーも一緒に削除され、ファイアウォールは展開した側に任されます。

**Linux。** インストールに使ったパッケージマネージャーでパッケージを削除するか、AppImage ファイルを削除します。

どちらの場合も、**データフォルダー**には手を付けません。実験、シグナルライブラリとエミュレーターライブラリ、実行レポート、エクスポートは、ホームフォルダーの `Documents/SignalLab` に残ります。不要な場合は、そのフォルダーを自分で削除してください。

## データの保存場所 {#data}

作成したものはすべて、Windows でも Linux でも、ホームフォルダーの `Documents/SignalLab` という 1 つのフォルダーにプレーンなファイルとして保存されます。現在の実験、シグナルライブラリ、エミュレーターライブラリ、実行レポート、エクスポート、インスペクターのキャプチャがここに入ります。各ファイルとその形式は[ファイルとフォルダー](../reference/files.md)で説明しています。

## サーバーとして実行する {#server}

ブラウザーから Signal Lab を使うには (機器のそばのラボ PC、Linux マシン、Docker などで)、[サーバー](../server/index.md)を参照してください。Docker のある Linux マシンなら、1 つのコマンドでインストールして起動できます。
