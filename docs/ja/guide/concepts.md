# 基本概念

このページでは、Signal Lab の土台になっている考え方を説明します。ここを押さえておくと、ほかのドキュメントが読みやすくなります。各セクションからは、その話題を詳しく扱うページにリンクしています。

## 画面と実験 {#screens-and-experiments}

Signal Lab には 2 つの使い方があり、どちらも使うことになります。

- **画面**は、今すぐ手作業で行う作業のためのツールです。このメッセージを送る、そのポートで待ち受ける、このエミュレーターを起動する、ブローカーが何を保持しているか確認する、といった作業です。試して、確認して、何かを変えて、また試します。プロトコルやツールごとに画面があります。[ウィンドウ](interface.md)を参照してください。
- **実験**は、一度組み立てれば毎回同じ方法で繰り返し実行できるフローです。リクエストを送り、応答を待ち、チェックし、続行または分岐します。実行のたびにステップごとのレポートが作られ、保存されます。[実験](../experiments/index.md)を参照してください。

この 2 つは、いくつかの場所でつながっています。HTTP 画面と OSC 画面では、[[ui:common.toExperiment]] を使うと、送信したばかりの内容が実験の次のステップになります。OSC モニターと MQTT 画面では、[[ui:osc.waitForThis]] を使うと、受信したメッセージを待機するステップになります。ライブラリのシグナルもステップにできます。ただし、hex で書いた生の UDP バイト列は除きます。

## シグナルとライブラリ {#signals}

**シグナル**は、保存しておくメッセージです。名前、フォルダー、何を起こすためのものかというメモ、そして送信する内容 (OSC メッセージ、生の UDP バイト列、HTTP リクエスト、MQTT のパブリッシュのいずれか) で構成されます。**シグナルライブラリ**は、シグナルをフォルダーにまとめて保持します。フォルダーは入れ子にでき、名前を変えたり、ドラッグして移動したりできます。

- シグナルは、OSC・HTTP・MQTT の各画面から保存するか ([[ui:sig.saveNew]])、[[ui:nav.signals]] 画面で作成するか、インスペクターがキャプチャしたフレームを保存して ([[ui:sig.fromFrame]]) 作ります。フレームから作ったシグナルは、バイト単位でそのまま再生されます。
- 送信は、[[ui:nav.signals]] 画面、どこからでも <kbd>Ctrl</kbd>+<kbd>K</kbd>、実験のステップ、またはターミナルからの `signallab fire` で行います。
- シグナルは、元の画面が送るものとまったく同じ内容を、同じ経路で送ります。インスペクターには、本来のプロトコルで表示されます。

ライブラリは[データフォルダー](#data-folder)にある `signals.json` という 1 つのファイルです。プレーンな JSON なので、読んだり編集したり、別のマシンにコピーしたり、リポジトリで管理したりできます。最初は、すべて `127.0.0.1` 宛ての例のシグナルのセットが入っています。[シグナル](../tools/signals.md)を参照してください。

## ジョブ {#jobs}

ボタンを押したあとも動き続けるものは、すべて**ジョブ**です。OSC モニターやジェネレーター、ブローカーや WebSocket の接続、ビーコンやディスカバリーのリスナー、HTTP 負荷バースト、エミュレーター、劣化リレー、ストーム、スキャン、実験の実行が該当します。

- ジョブごとに、下部パネルの帯にピル型の表示があり、番号、種類、停止ボタンが付いています。サイドバーには、各画面で動いているジョブの数が表示されます。
- ヘッダーの [[ui:app.stopAll]] を押すと、すべてのジョブが一度に停止します。
- 終了したスキャン、成功した実行、ポートの確保に失敗したモニターなど、自然に終わったジョブは帯から消え、どのように終わったかがコンソールに表示されます。
- ジョブは、ほかの画面で作業している間も動き続けます。
- アップデートをインストールするときは、先にすべてのジョブが停止します。

サーバーでは、ジョブはサーバーに属します。サーバーにサインインしているすべてのページに同じジョブが表示され、どのページからでも停止できます。

## キャプチャとインスペクター {#capture}

送信側、モニター、リスナー、エミュレーター、リレー、実験の実行など、すべてのツールは、送受信するフレームを 1 つの**キャプチャ**に渡します。[インスペクター](../tools/inspector.md)は、それを 1 つのタイムラインに表示します。

- キャプチャは、[[ui:ins.arm]] で開始するまで**オフ**で、オフの間は負荷がかかりません。開始すると、どの画面にいても、停止するまでオンのままです。
- 最大 8192 フレーム、バイト数で 64 MiB まで保持し、古いフレームから順に新しいフレームに置き換えられます。1 フレームにつき最大 256 KiB のバイトを保持し、一覧には先頭の 256 バイトが表示されます。
- [[ui:ins.pause]] を押すと、一覧の動きが止まって読みやすくなります。キャプチャ自体は裏で続きます。
- 実行で使われたシークレットの値は、すべてのフレームでマスクされます。
- キャプチャ全体は、すべてのバイトを保ったまま `.jsonl` または `.txt` ファイルにエクスポートできます。

## エミュレーター {#emulators}

**エミュレーター**は、システムが通信する相手側の API、デバイス、サービスを演じます。エミュレーターは 1 つのドキュメントで、プロトコル、待ち受けるアドレス、何を応答するかを定めるルールを持ちます。

| プロトコル | エミュレートするもの |
| --- | --- |
| HTTP | API。メソッドとパスによるルート、順番・交互・ランダムのレスポンス、遅延、障害 |
| OSC | アドレスと引数に応じて OSC メッセージに応答するデバイス |
| UDP | ペイロードに応じてデータグラムに応答するデバイス |
| TCP | TCP 接続上の行に応答するデバイス。接続時の挨拶つき |
| MQTT | クライアントがパブリッシュしたものをルーティングし、デバイスのようにルールで応答するブローカー |

エミュレーターは、応答を遅らせたり、失敗したり、接続を閉じたり、不正な形式の本体を送ったり、スケジュールに従ってダウンしたりできます。やり取りはすべて数えられ、その画面に一覧表示され、インスペクターにキャプチャされます。

エミュレーターは、[[ui:nav.emulators]] 画面からジョブとして起動するか、実験の [[ui:exp.node.emulator]] ノードから実行全体のために起動するか、`signallab emulate` で起動します。**エミュレーターライブラリ**は、データフォルダーの `emulators.json` です。最初は、種類ごとに 1 つずつエミュレーターが入っていて、すべて `127.0.0.1` で動作します。

| エミュレーター | 待ち受け先 | 動作 |
| --- | --- | --- |
| [[ui:seed.emu.demo-api.name]] | `127.0.0.1:8080` (HTTP) | ヘルスチェック、ID によるユーザーの取得、作成、遅い応答、2 回失敗してから成功するルート |
| [[ui:seed.emu.osc-device.name]] | `127.0.0.1:9100` (OSC) | `/ping` に `/pong` とカウントで応答し、`/fader/…` に `/ack` で応答し、`/cue/…` は何も返さずに受け取る |
| [[ui:seed.emu.udp-device.name]] | `127.0.0.1:7100` (UDP) | `PING` に `PONG` とカウントで応答し、それ以外には受け取ったバイト数で応答する |
| [[ui:seed.emu.tcp-device.name]] | `127.0.0.1:7200` (TCP) | プロジェクターのような行プロトコル。接続時に `READY` と挨拶し、電源の状態を報告・切り替え、`QUIT` には `BYE` を返して切断する |
| [[ui:seed.emu.mqtt-broker.name]] | `127.0.0.1:1883` (MQTT) | 保持された `lab/status` と照明。`lab/<name>/set` に `ON` または `OFF` をパブリッシュすると、`lab/<name>/state` に応答が返る |

[エミュレーター](../tools/emulators.md)を参照してください。

## 劣化リレー {#impairment}

**劣化リレー**は、クライアントとその宛先の間に入ります。クライアントの向き先を本来の宛先ではなくリレーの待ち受けアドレスにすると、リレーは双方向に転送しながら、通過するものを**プロファイル**に従って劣化させます。

- **UDP** では、データグラムごとに運命が決まります。レイテンシとジッター、ロスとロスのバースト、重複、破損、順序の入れ替え、帯域制限、あるいは何も通さない (オフライン) といった具合です。
- **TCP** では、接続ごとに宛先への専用の接続が結ばれ、両方向のストリームが遅延されたり、帯域制限をかけられたり、リセットされたり、ハーフオープンのまま放置されたりします。

プリセットを使うと、有線回線から衛星回線まで、プロファイルをワンクリックで設定できます。変更はリレーの動作中に反映され、ポートが切断されることはありません。すべての判断はシードから導かれるので、同じ通信なら同じ運命が再現されます。

[[ui:nav.netsim]] 画面では、リレーはジョブとして動作します。実験では、[[ui:exp.node.impairment]] ノードが実行のためにリレーを開き、[[ui:exp.node.impairment_change]] が実行の途中でプロファイルを切り替えます。[劣化](../tools/impairment.md)と[障害](../experiments/faults.md)を参照してください。

## 実験 {#experiments}

### ノードと接続線 {#nodes-and-wires}

実験は、**接続線**でつながれた**ノード**のグラフです。ノードは 1 つのステップで、何かを送る、何かを待つ、値をチェックする、値を抽出する、フローを変える、エミュレーターや劣化リレーなど実行の準備をする、のいずれかを行います。どの実験にも [[ui:exp.node.start]] と [[ui:exp.node.end]] がちょうど 1 つずつあり、ノードは最大 64 個までです。エディターで開いている実験は、編集するたびに保存されます。[ノード](../experiments/nodes.md)を参照してください。

### 出力 {#outputs}

接続線は、あるノードの**出力**から別のノードの入力へつながります。ほとんどのノードには出力が 1 つありますが、複数の出力から選ぶノードもあります。分岐では [[ui:exp.yes]] と [[ui:exp.no]]、待機では [[ui:exp.portMatched]] と [[ui:exp.portTimeout]]、ループでは [[ui:exp.portBody]]、[[ui:exp.portDone]]、[[ui:exp.portLimit]]、並列ブランチでは [[ui:exp.branch1]] と [[ui:exp.branch2]] です。

1 つの出力に複数の接続線をつなぐこともできます。その場合、それぞれが独立したブランチとして並列に実行され、[[ui:exp.node.join]] は、そこに入るすべての接続線を待ちます。接続線を戻せるのは [[ui:exp.node.loop]] の本体だけで、それ以外の循環はエラーです。[フロー](../experiments/flow.md)を参照してください。

### パラメーターとプロファイル {#parameters}

**パラメーター**は、ホスト、ポート、ユーザー名などの名前付きの値です。[[ui:exp.params]] で一度書いておけば、どのフィールドでも `{{name}}` として使えます。**プロファイル**は、いくつかのパラメーターをまとめて切り替えます。ノート PC 用、ステージ用、会場用、といった具合です。実行に使うプロファイルを選ぶか、[[ui:exp.runWith]] で、プロファイル、別の値、シードを 1 回の実行にだけ指定できます。実験自体は変わりません。1 つの実験に、パラメーターは最大 64 個、プロファイルは最大 32 個まで持てます。[データ](../experiments/data.md)を参照してください。

### テンプレート {#templates}

ノードのテキストフィールドの多くは**テンプレート**です。二重の波括弧で式を囲んだプレーンテキストで、ステップの実行時に値が埋め込まれます。

- `{{host}}`: パラメーター、または実行の中でそれまでに設定された変数。たとえば [[ui:exp.node.extract]] ノードがレスポンスから取り出した値や、待機が受信した応答 (`{{reply.args[0]}}`) です。
- `{{secret.API_TOKEN}}`: シークレット。
- `{{run.id}}`、`{{run.seed}}`、`{{now}}`、`{{now.iso}}`、`{{counter}}`: 実行とその時点。
- `{{uuid}}`、`{{random_int(1, 10)}}`、`{{random_float(0, 1, 2)}}`、`{{pick("a", "b")}}`: 生成される値。

テンプレートを展開するのはエンジンだけです。そのため、フィールドの意味は、実行でも、エディターのプレビューでも、[[ui:exp.sendNow]] でも同じです。未知の名前は、空文字列になるのではなくエラーになります。[データ](../experiments/data.md)を参照してください。

### シークレット {#secrets}

**シークレット**は、実験が使うものの保存はしない値です。トークンやパスワードなどが該当します。実験が保持するのは名前だけで、フィールドでは `{{secret.NAME}}` として使います。実行が報告するすべてのテキスト、つまりすべてのステップ、レポート、すべてのインスペクターのフレームで、値はマスクされて表示されます。シークレットの値を返すコマンドはありません。

値の保存場所は、Signal Lab をどこで動かすかによって異なります。

- **Windows のデスクトップアプリ**は、Windows 資格情報マネージャーに保存します。値は [[ui:exp.params]] → [[ui:exp.secrets]] で設定します。
- **Linux のデスクトップアプリ**には、保存先となる資格情報ストアがないため、シークレットを使う実験は、Linux ではコマンドラインまたはサーバーから実行します。
- **サーバー**は、環境変数 (`SIGNALLAB_SECRET_<NAME>`) か、シークレットフォルダー内の名前ごとのファイル (既定では `/run/secrets/signallab/<NAME>`) から、読み取り専用で読み込みます。ブラウザーからは設定できません。
- **コマンドライン**は、サーバーと同じ方法で読み込むか、指定すればシステムの資格情報ストアから読み込みます。[コマンドライン](../automation/cli.md)を参照してください。

### シード {#seeds}

実行ごとに**シード**があります。実行の中でランダムになるものすべてを決める数値です。生成される値、繰り返しのジッター、エミュレーターが応答をランダムに選ぶ処理、劣化リレーのすべての判断が対象です。同じシードと同じ通信なら、同じ実行になります。実験でシードを固定しない限り、実行のたびに新しいシードが選ばれます。実行タイムラインの [[ui:exp.pinSeed]] は直前の実行のシードを固定し、[[ui:exp.params]] の [[ui:exp.seed]] ではシードを指定できます。

### 実行とレポート {#reports}

**実行**は [[ui:exp.node.start]] から始まり、接続線をたどり、失敗したステップがないまま [[ui:exp.node.end]] に達すると成功です。300 秒を超えると停止されます。各ステップは、開始と終了のたびに実行タイムラインに表示されます。

成功でも失敗でも、実行が終わると、データフォルダーの `runs` フォルダーに**レポート**が書き込まれます。レポートには、実験の名前、シード、プロファイルと使用した値、開始と終了の時刻、結果とそのエラー、すべてのステップ、エミュレーターとリレーが数えた内容が入ります。同じ実験の 2 つの実行は比較できます。[実行とレポート](../experiments/runs.md)を参照してください。

## データフォルダー {#data-folder}

Signal Lab が保持するものは、すべて 1 つのフォルダーにあるファイルです。Windows でも Linux でも、ホームフォルダーの `Documents/SignalLab` です。サーバーは、起動時に指定した独自のフォルダーを使います (Docker イメージでは `/data`)。

| ファイルまたはフォルダー | 内容 |
| --- | --- |
| `experiment.json` | エディターで開いている実験 |
| `signals.json` | シグナルライブラリ |
| `emulators.json` | エミュレーターライブラリ |
| `runs/` | 実行ごとのレポート |
| `exports/` | 実験ダイアログからエクスポートした実験 |
| `capture-….jsonl`、`capture-….txt` | インスペクターのエクスポート |

ファイルは JSON で、まるごと書き込まれます。読み込めないファイルがあると、Signal Lab はどのファイルのどこにエラーがあるかを伝え、最初からやり直さずにそのまま残します。[ファイルとフォルダー](../reference/files.md)を参照してください。

## デスクトップとサーバー {#desktop-and-server}

デスクトップアプリとサーバーは、同じエンジンを同じインターフェイスの背後で動かします。違いは次のとおりです。

| | デスクトップアプリ | ブラウザーで使うサーバー |
| --- | --- | --- |
| 通信の出発点、モニターが待ち受ける場所 | このコンピューター | サーバー |
| データフォルダー | `Documents/SignalLab` | サーバー側のフォルダー。ヘッダーの [[ui:app.server]] にカーソルを合わせると表示されます |
| シークレット | Windows 資格情報マネージャー。アプリで設定。Linux では使えません | サーバーの環境変数またはシークレットファイルから読み取り専用で読み込み |
| レポート、エクスポート、キャプチャ | データフォルダーに書き込まれ、パスが表示される | ブラウザーでダウンロードされる |
| サインイン | なし | アクセストークンがある場合は、そのトークンを使う |
| ジョブ、HTTP 画面の Cookie ジャー | このアプリのもの | サーバーのもので、サインインしているすべてのページで共有 |
| ファイアウォール | Signal Lab を許可するための通知が出る (Windows) | Signal Lab が変更することはない |
| アップデート | クリックすると署名済みのリリースをインストール | イメージの更新で行う |

[サーバー](../server/index.md)と[サーバーのセキュリティ](../server/security.md)を参照してください。

## Signal Lab が勝手には行わないこと {#on-its-own}

- **操作したときだけ送信します。** 送信先も、入力したアドレスだけです。アプリを起動しただけでは何も送信しません。ただし、デスクトップアプリの 1 日 1 回のアップデート確認は例外で、オフにできます。フィードバックは、フォームを送信したときにだけ送られます。
- **付属の例は、このコンピューターの中で完結します。** 初期のシグナル、初期のエミュレーター、新規のエミュレーター、実験のテンプレートは、すべて `127.0.0.1` を使います。自分で起動するリスナー (OSC モニター、ディスカバリーリスナー、劣化リレー) の既定は、ほかのマシンから到達できるように、すべてのネットワークカードを意味する `0.0.0.0` です。このコンピューターの中にとどめるには、`127.0.0.1` を入力します。
- **ファイアウォールは、[[ui:fw.allow]] をクリックして Windows の管理者権限の確認を承認したとき、または `signallab firewall allow` を実行したときにだけ変更します。** サーバーがホストのファイアウォールを変更することはありません。
- **アクセストークンのないサーバー**は `127.0.0.1` でしか待ち受けず、それ以外のアドレスでは起動を拒否します。
- **安全上の上限を守ります。** ブロードキャストのスイープは最大 1024 ホストまで、ビーコンは全宛先の合計で毎秒最大 50,000 パケットまでです。

安全上の上限は、許可ではありません。[ストーム](../tools/storm.md)、[スキャナー](../tools/scanner.md)、[ブロードキャスト](../protocols/broadcast.md)は実際の通信を送ります。所有しているか、テストを許可されているネットワークとホストにだけ使ってください。
