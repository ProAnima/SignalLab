# ウィンドウ

Signal Lab のウィンドウは 4 つの部分から成ります。左側の**サイドバー**には画面の一覧、上部の**ヘッダー**にはどこでも使うもの、中央にはそのとき選んだ**画面**、そして**下部パネル**にはコンソール、実行中のジョブ、インスペクターが表示されます。デスクトップアプリと、ブラウザーで開くサーバーのページは見た目が同じです。わずかな違いは[ブラウザーで使う場合](#browser)にまとめてあります。

## サイドバー {#sidebar}

各画面はそれぞれ独立したツールです。クリックすると開きます。

| 画面 | 用途 |
| --- | --- |
| [[ui:nav.experiment]] | キャンバス上にテストフローを組み立てて実行し、各実行をステップごとに確認します。[実験](../experiments/index.md) |
| [[ui:nav.signals]] | シグナルライブラリ: フォルダーに整理された名前付きのメッセージを編集し、再送信します。[シグナル](../tools/signals.md) |
| [[ui:nav.emulators]] | ルールに従って応答するモックの HTTP API、OSC・UDP・TCP デバイス、MQTT ブローカー。[エミュレーター](../tools/emulators.md) |
| [[ui:nav.osc]] | OSC メッセージの送信、ポートのモニター、エンドポイントへの波形の送り込み。[OSC](../protocols/osc.md) |
| [[ui:nav.mqtt]] | ブローカーに接続し、保持されているすべてのトピックを確認し、パブリッシュや保持された値の消去を行います。[MQTT](../protocols/mqtt.md) |
| [[ui:nav.broadcast]] | 多数のホストに一度に送信し (リスト、ブロードキャスト、マルチキャスト、サブネットスイープ)、どこが応答するかを待ち受けます。[ブロードキャストとディスカバリー](../protocols/broadcast.md) |
| [[ui:nav.http]] | 1 つのリクエストとその完全なレスポンス、続いて同じエンドポイントへの負荷バースト。[HTTP](../protocols/http.md) |
| [[ui:nav.ws]] | WebSocket サービスに接続し、テキストやバイト列を送信し、すべてのメッセージを読み取ります。[WebSocket](../protocols/websocket.md) |
| [[ui:nav.netsim]] | クライアントと宛先の間の UDP または TCP の通信を劣化させるリレー。[ネットワーク劣化](../tools/impairment.md) |
| [[ui:nav.storm]] | 自分のサーバーや回線に向けた、生の UDP または TCP の負荷。[ストーム](../tools/storm.md) |
| [[ui:nav.scan]] | ホストのどの TCP ポートが開いているか、そしてサービスが最初に送ってくる内容。[スキャナー](../tools/scanner.md) |

サイドバーは最初、各画面の記号と短い名前だけの細いレールとして表示されます。項目にポインターを合わせると正式な名前が表示されます。ヘッダー左端の **☰** ([[ui:app.expandNav]] / [[ui:app.collapseNav]]) でレールと完全な一覧を切り替えられ、Signal Lab はどちらを選んだかを覚えています。

画面の項目に表示される数字は、その画面から実行中のジョブ (モニターやエミュレーターなど) の数です。画面を開かなくても、まだ動いているものがわかります。サイドバーの下部にあるバージョンをクリックすると「Signal Lab について」が開き、その下の行には実行中のすべてのジョブの数が表示されます。

Signal Lab は、最後に使った画面で開きます。

## ヘッダー {#header}

左から右へ、次の項目が並んでいます。

| 項目 | 機能 |
| --- | --- |
| **☰** | サイドバーをレールまたは完全な一覧として表示します。 |
| ホスト | [[ui:app.host]] の後に、エンジンが動作しているコンピューターの名前とネットワークアドレスが表示されます。デスクトップアプリではこのコンピューター、ブラウザーではサーバーです。ブラウザーでは [[ui:app.server]] とも表示され (ポインターを合わせると、サーバーがファイルを保存している場所がわかります)、ページの接続が切れるとその横の点が変化します。 |
| 更新ボタン | 新しいリリースが見つかったときにデスクトップアプリに現れ、インストールのために「Signal Lab について」を開きます。[更新](install.md#updates)を参照してください。 |
| 本のアイコン | [[ui:app.docs]]: このドキュメントを、今いる画面のページで開きます。どこからでも <kbd>F1</kbd> で同じことができます。 |
| **✉** | [[ui:feedback.open]]: 開発者へのメッセージです。[開発者への連絡](#feedback)を参照してください。 |
| **?** | [[ui:about.open]]: バージョン、Signal Lab の開発元、その連絡先、更新。 |
| 国旗 | [[ui:app.language]]: インターフェイスの言語。[言語](#languages)を参照してください。 |
| [[ui:app.signOut]] | ブラウザーで、サーバーがアクセストークンを求める場合: このブラウザーのセッションを終了します。 |
| [[ui:app.stopAll]] | 実行中のすべてのジョブを一度に停止します。モニター、ジェネレーター、ビーコン、エミュレーター、リレー、ストーム、スキャン、実行が対象です。何も実行していない間はグレー表示になります。 |

### ドキュメント {#docs}

ドキュメントはアプリとサーバーに組み込まれているので、インターネットに接続していなくても、インターフェイスの言語で読めます。デスクトップアプリでは専用のウィンドウに表示されます。別の画面からもう一度ボタンを押すと、そのウィンドウはその画面のページに切り替わります。ドキュメントの外へ出るリンクはブラウザーで開きます。ブラウザーでは専用のタブで開きます。「Signal Lab について」にも [[ui:app.docs]] ボタンがあり、[Signal Lab とは](index.md)を開きます。

### Signal Lab について {#about}

このダイアログには、バージョン、開発元、連絡先のアドレス (コピーするボタン付き)、ソースコード、ライセンスが表示されます。デスクトップアプリでは、その [[ui:update.title]] セクションで更新を探し、表示し、インストールします。[更新](install.md#updates)を参照してください。ブラウザーでは [[ui:update.server]] と表示されます。[[ui:about.writeUs]] を押すとフィードバックのフォームが開きます。

### 開発者への連絡 {#feedback}

ヘッダーの **✉** を押すと、開発者に直接届くフォームが開きます。

| フィールド | 入力する内容 |
| --- | --- |
| [[ui:feedback.message]] | 何が起きたか、本来はどうなるはずだったか。必須で、最大 20,000 文字です。 |
| [[ui:feedback.email]] | 任意: 開発者が返信できる宛先です。開発者だけが見ることができます。 |
| [[ui:feedback.screenshots]] | 最大 6 枚の画像 (PNG、JPEG、WebP、GIF)。1 枚あたり 8 MB、合計 15 MB までです。<kbd>Ctrl</kbd>+<kbd>V</kbd> で貼り付けるか、ウィンドウにファイルをドロップするか、[[ui:feedback.addScreenshot]] を押します。 |
| [[ui:feedback.logs]] | コンソールの行と [[ui:feedback.systemInfo]] が、それぞれ別のファイルとして添付されます。[[ui:feedback.show]] で送信される内容を正確に確認でき、チェックを外すとそれを除外できます。 |

添付されるログからは、このコンピューターの名前、そのネットワークアドレス、フォルダーのパスに含まれる名前が除かれます。<kbd>Ctrl</kbd>+<kbd>Enter</kbd> でフォームを送信します。送信されると参照番号が表示され、コンソールにも記録されます。メッセージはスタジオ自身のサービスを経由し、そこからメールで転送されます。アプリはそのためのパスワードを持っていません。

## 下部パネル {#bottom-panel}

どの画面の下にもあるパネルには、[[ui:console.title]] と [[ui:dock.inspector]] の 2 つのタブがあり、タブとパネルのボタンの間には実行中のジョブの帯があります。

- 左端の**山形のボタン** ([[ui:console.collapse]] / [[ui:console.expand]]) で、パネルをバーだけに折りたたんだり、再び開いたりします。折りたたんでいても、バーにはコンソールの最新の行が表示されます。その行をクリックするとパネルが開きます。
- パネルの上端をドラッグすると、高さを変えられます ([ペインのサイズ変更](#panes)を参照)。
- 右端のボタンで、[[ui:dock.maximise]] と [[ui:dock.restore]] を切り替えます。

パネルが開いているかどうか、どのタブを表示しているか、高さはどれくらいかは、次回のために保存されます。

### コンソール {#console}

コンソールには、各ツールが行ったことと発生した問題が、新しいものを下にして表示されます。送信したメッセージとそのサイズ、開始したモニター、レスポンスのステータスと時間、終了したジョブとその理由などです。各行には時刻 (ミリ秒単位)、ツールを示すタグ、メッセージがあり、その種類 (完了、情報、警告、エラー) によって色分けされます。

- [[ui:console.autoscroll]] をオンにすると、行が届くたびに最新の行が表示されたままになります。オフにすると、新しい行が届いている間もさかのぼって読めます。
- [[ui:common.clear]] で空にします。
- 最新の 500 行を保持します。
- 言語を切り替えると、コンソール全体が新しい言語で書き直されます。

### ジョブ {#jobs-strip}

実行中の各ジョブ (モニター、ジェネレーター、ビーコン、ブローカーへの接続、エミュレーター、リレー、ストーム、スキャン、実験の実行) は、帯の中に番号と内容を示すピル型の表示を持ち、それぞれに専用の停止ボタンがあります。何も実行していないときは、帯に [[ui:console.empty]] と表示されます。[ジョブ](concepts.md#jobs)を参照してください。

### インスペクタータブ {#inspector-tab}

[[ui:dock.inspector]] タブには、キャプチャがオンの間に各ツールが送受信したすべてのフレームが、作業中のどの画面の横にも表示されます。キャプチャがオンの間はタブの点が点灯し、数字がキャプチャしたフレームの数を示します。パネルは、インスペクターの一覧とフレームの詳細が収まる高さで開きます。他の場所 (実行のタイムラインやエミュレーターの一覧) にあるフレームへのリンクをクリックすると、このタブがそのフレームを表示した状態で開きます。一度開くと、パネルを閉じている間もインスペクターは一覧と選択を保持します。使い方は[インスペクター](../tools/inspector.md)を参照してください。

## どこからでもシグナルを送信する {#palette}

どの画面でも <kbd>Ctrl</kbd>+<kbd>K</kbd> を押すと [[ui:sig.paletteTitle]] が開きます。シグナルの名前、フォルダー、宛先の数文字を入力し、<kbd>↑</kbd> と <kbd>↓</kbd> で選んで <kbd>Enter</kbd> を押すと送信されます。一度に最大 12 件のシグナルが一覧表示されます。<kbd>Esc</kbd>、パレットの外側のクリック、またはもう一度 <kbd>Ctrl</kbd>+<kbd>K</kbd> を押すと閉じます。コンソールには、何をどこに送信したかが表示されます。[シグナル](../tools/signals.md)を参照してください。

## ペインのサイズ変更 {#panes}

サイズを変更できるペインの間には細いハンドルがあります。下部パネルの上端 ([[ui:layout.console]])、そして実験画面ではプロパティの端 ([[ui:layout.properties]]) と実行タイムラインの上端 ([[ui:layout.timeline]]) です。

- ハンドルをドラッグします。
- または <kbd>Tab</kbd> でハンドルにフォーカスし、矢印キーを使います。1 回押すごとに 16 ピクセル移動し、<kbd>Shift</kbd> を押しながらだとその 4 倍移動します。<kbd>Home</kbd> と <kbd>End</kbd> で最小と最大のサイズになります。
- ダブルクリックするか、ハンドル上で <kbd>Enter</kbd> を押すと、ペインが既定のサイズに戻ります。

サイズは次回のために保存されます。

## ツールチップ {#tooltips}

画面にはラベル、値、状態が表示され、説明はツールチップにまとめられています。フィールドが何を期待するか、そこで `0` が何を意味するか、どのキーで同じことができるか、などです。ツールチップは、要素にポインターを約 0.5 秒置くと表示され、キーボードで移動したときはすぐに表示されます。フィールドではそのラベルのツールチップが表示されます。<kbd>Esc</kbd>、入力、クリック、スクロールで非表示になります。スクリーンリーダーも同じテキストを読み上げます。

エラーメッセージは、どこで何がうまくいかなかったのか、そしてその理由を示します。システム自身の文言は [[ui:err.details]] の中に折りたたまれています。

## 画面は状態を保持する {#state}

画面は初めて開いたときに表示され、その後は別の画面で作業している間もそのまま残ります。入力した内容、最後のレスポンス、モニターが受信したメッセージの一覧とその背後にあるジョブ、スクロール位置まで、戻ってきたときにすべてそのままです。実行中のジョブは、どの画面を見ていても動き続けます。

一部の値は再起動後も保持されます。送信していた OSC メッセージ、HTTP リクエスト、WebSocket のアドレス、ペインのサイズ、開いていた画面です。

## ファイアウォールの通知 {#firewall-notice}

Windows Defender ファイアウォールは、プログラムごとに、他のマシンからの接続を許可するかどうかを決めます。プログラムが初めて待ち受けるとき、Windows は画面の前にいる人に確認します。そこで *キャンセル* を選んだ場合や、Windows がパブリックと見なすネットワークでは、他のマシンから送られたものは何の通知もなく破棄されます。何も表示されないモニターが、その典型的な兆候です。

そこで Windows のデスクトップアプリでは、何かが初めて待ち受けを始めるとき (OSC モニター、ディスカバリーリスナー、劣化リレー、エミュレーター、実験の実行)、Signal Lab がファイアウォールを一度確認します。ファイアウォールが妨げになっている場合は、ヘッダーの下にその旨の通知が表示されます。

- [[ui:fw.allow]] は、Windows 自身の確認画面で管理者権限を求めたうえで、プライベート ネットワークとドメイン ネットワークで他のマシンから Signal Lab に接続できるようにします。
- Windows がパブリックと呼ぶネットワーク (会場の Wi-Fi によくあります) では、ボタンは代わりに [[ui:fw.allowPublic]] になります。
- [[ui:fw.dismiss]] は、このセッションの間だけ通知を非表示にします。

許可すると、Signal Lab の受信ファイアウォールルールが 1 つの許可ルールに置き換えられます。このコンピューター自身の通信 (`127.0.0.1`) は影響を受けないため、ループバックで作業している間は通知を無視してかまいません。すべてのユーザーへのインストールでは、ルールはすでに追加されています。[セットアップが追加するもの](install.md#windows-setup-adds)を参照してください。ターミナルからは `signallab doctor` で同じことを確認でき、`signallab firewall allow` で修正できます。[コマンドライン](../automation/cli.md)を参照してください。Linux やブラウザーでは通知は表示されません。サーバーのファイアウォールはその管理者が管理するものです。

## ブラウザーで使う場合 {#browser}

[サーバー](../server/index.md)のページは同じインターフェイスですが、いくつか違いがあります。

- ヘッダーのホストにはサーバーの名前が表示され、その横に [[ui:app.server]] と表示されます。
- サーバーがアクセストークンを求める場合は一度サインインし、ヘッダーの [[ui:app.signOut]] でセッションを終了します。
- ページとサーバーの接続が切れると、復旧するまで [[ui:app.connectionLost]] というバーが表示されます。コンソールには切断と復旧の両方が記録されます。
- 実行レポート、エクスポート、インスペクターのキャプチャは、パスとして表示される代わりに、ブラウザーでダウンロードされます。
- 「Signal Lab について」に更新はありません。サーバーはそのイメージとともに更新されます。

サーバーのページで行うことは、すべてサーバー上で行われます。通信はサーバーから送信され、モニターはサーバーのポートで待ち受け、ファイルはサーバーのデータフォルダーに保存されます。[概念](concepts.md#desktop-and-server)を参照してください。

## 言語 {#languages}

ヘッダーの国旗は、現在の言語とその 2 文字の略称を示します。クリックするとすべての言語の一覧が開き、それぞれが国旗とその言語自身での名前で表示されるので、1 つを選びます。一覧では、<kbd>↑</kbd>、<kbd>↓</kbd>、<kbd>Home</kbd>、<kbd>End</kbd> で移動し、文字キーを押すとその文字で始まる次の言語に移動します。その言語自身の名前でも英語名でも探せるので、<kbd>g</kbd> で Deutsch が見つかります。<kbd>Enter</kbd> で選択し、<kbd>Esc</kbd> で閉じます。

インターフェイスは再起動なしですぐに切り替わります。すべての画面、ツールチップ、エラー、そしてコンソールのそれまでの行も切り替わります。Signal Lab は初めて起動したとき、システムの言語のうち対応している最初のもの、なければ英語を選び、以後は選んだ言語を保持します。ブラウザーでは、そのブラウザーごとに保持されます。

アラビア語では、ウィンドウ全体が右から左の表示になります。データにあたるもの (アドレス、hex ダンプ、コード、実験のキャンバス) は、書かれたとおり左から右のままです。
