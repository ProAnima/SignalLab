# はじめの一歩

このセッションに必要なのは Signal Lab だけです。すべてこのコンピューター `127.0.0.1` に送るので、デバイスもネットワークもファイアウォールのルールも関係しません。次のことを行います。

1. OSC メッセージを送信し、届くのを確認する。
2. 同じメッセージをインスペクターで見る。
3. それをライブラリに保存し、どこからでも再送信する。
4. エミュレートした HTTP API を起動し、問い合わせる。
5. その API に対して実験を実行し、失敗の理由を読み、修正してチェックを追加する。

Signal Lab をまだインストールしていない場合は、[インストールと更新](install.md)を参照してください。ウィンドウのどこに何があるかわからない場合は、[ウィンドウ](interface.md)を参照してください。

## OSC メッセージを送信して届くのを確認する {#osc}

まず、メッセージを受け取るものを用意します。OSC 画面のモニターです。

1. サイドバーで [[ui:nav.osc]] を開きます。
2. [[ui:osc.monitor]] セクションで [[ui:common.bind]] を `127.0.0.1:9000` に設定し、モニターがこのコンピューターでだけ待ち受けるようにします。
3. [[ui:osc.listen]] を押します。ボタンが [[ui:common.stop]] に変わり、コンソールにモニターが待ち受けていることが表示され、モニターが下部パネルの帯にジョブとして現れます。

次に、その横の送信側からメッセージを送ります。

4. [[ui:osc.sender]] セクションで、[[ui:common.target]] は、モニターが待ち受けているポート `127.0.0.1:9000` のままにします。
5. [[ui:common.address]] は `/hello/avatar/1` のまま、[[ui:common.arguments]] の float 引数 1 つも `1.0` のままにします。独自のアドレスや値を入力してもかまいません。
6. [[ui:common.send]] を押すか、宛先またはアドレスのフィールドで <kbd>Enter</kbd> を押します。

モニターの表に 1 行が表示されます。列は [[ui:common.time]] (届いた時刻)、[[ui:osc.from]] (`127.0.0.1` と送信元のポート)、[[ui:osc.address]]、[[ui:osc.args]] です。送信側の下には、送信した内容とそのバイト数を確認する行が表示されます。もう一度送信すると、繰り返しの回数が数えられます。

::: tip ファイアウォールの通知が出た場合
Windows では、モニターを開始すると、ヘッダーの下に Windows ファイアウォールについての通知が表示されることがあります。これは**他の**マシンからのメッセージに関するもので、`127.0.0.1` の通信がフィルターされることはありません。ひとまず [[ui:fw.dismiss]] を押してください。いつ許可すべきかは[ファイアウォールの通知](interface.md#firewall-notice)で説明しています。
:::

## インスペクターで見る {#inspector}

インスペクターは、すべてのツールが送受信するすべてのフレームを記録します。ただし、記録するのはキャプチャがオンの間だけです。

1. 下部パネルで [[ui:dock.inspector]] タブを開きます。
2. [[ui:ins.arm]] を押します。タブの点が点灯します。
3. 送信側に戻り、もう一度 [[ui:common.send]] を押します。

新しいものを上にして 2 行が表示されます。送信したメッセージ (→) と、モニターが受信したメッセージ (←) で、それぞれプロトコル、相手側のアドレス、サイズ、概要が示されます。1 行をクリックすると、[[ui:ins.detail]] に、どのツールがどのアドレスで送受信したか、メッセージの [[ui:ins.decoded]]、そしてメッセージを構成する [[ui:ins.rawBytes]] が表示されます。

終わったら [[ui:ins.disarm]] を押します。キャプチャがオフの間は負荷がかかりません。詳しくは[インスペクター](../tools/inspector.md)を参照してください。

## シグナルとして保存して再送信する {#signal}

また使いたいメッセージは、シグナルライブラリに入れておきます。

1. OSC 画面で、送信側の下にある [[ui:sig.saveNew]] を押します。
2. [[ui:sig.saveTitle]] ダイアログで、[[ui:sig.name]] を `First message`、[[ui:sig.group]] を `Tutorial` に設定します。新しいフォルダーは、そこに保存するときに作成されます。
3. [[ui:sig.saveConfirm]] を押します。

これで送信側はそのシグナルと結び付きました。ボタンには [[ui:sig.savedState]] と表示され、その横のチップにはシグナルの保存場所が表示されます。引数を変更するとチップに変更が示され、[[ui:sig.save]] (<kbd>Ctrl</kbd>+<kbd>S</kbd>) でシグナルを更新できます。

では、3 つの方法で再送信してみます。

- **ライブラリから。** チップをクリックすると、`Tutorial` フォルダーでそのシグナルが選択された状態で [[ui:nav.signals]] が開きます ([[ui:nav.signals]] を開いて、そこでクリックしてもかまいません)。[[ui:sig.fire]] または <kbd>Ctrl</kbd>+<kbd>Enter</kbd> を押します。一覧でダブルクリックしても送信されます。
- **どこからでも。** どの画面でも <kbd>Ctrl</kbd>+<kbd>K</kbd> を押し、`first` と入力して <kbd>Enter</kbd> を押します。
- **実験から。** ノードを追加するとき、メニューの [[ui:exp.group.signals]] にシグナルが一覧表示され、それを送信するステップとしてすぐに追加できます。

どの方法でも、モニターにはメッセージが届いたことが表示され、コンソールにはシグナルの名前が表示されます。シグナルは、その画面から送った場合とまったく同じものを送信します。詳しくは[シグナル](../tools/signals.md)を参照してください。

OSC の作業が終わったら、モニターの [[ui:common.stop]] を押します。

## エミュレートした API に問い合わせる {#emulator}

Signal Lab には、すべて `127.0.0.1` 上で動作する 5 つのエミュレーターが付属しています。そのひとつ [[ui:seed.emu.demo-api.name]] は `127.0.0.1:8080` 上の HTTP API で、次のルートを持っています。

| リクエスト | 応答 |
| --- | --- |
| `GET /health` | `200` と `{"status":"ok","time":"…"}` (現在時刻) |
| `GET /users/:id` | `200` とその ID のユーザー (例: `{"id":"42","name":"User 42"}`) |
| `POST /users` | `201` と `Location` ヘッダー、新しい ID |
| `GET /slow` | 1.5 秒後に `200` |
| 任意のメソッド、`/flaky` | `503`、`503`、3 回目のリクエスト以降は `200` |
| それ以外 | `404` |

1. [[ui:nav.emulators]] を開きます。[[ui:emu.library]] に 5 つが一覧表示されるので、[[ui:seed.emu.demo-api.name]] を選択します。
2. [[ui:emu.start]] を押します。`127.0.0.1:8080` で応答するようになり、ジョブとして実行されます。
3. [[ui:nav.http]] を開きます。メソッドは `GET` です。URL を `http://127.0.0.1:8080/health` に設定します。
4. [[ui:common.send]] を押すか、URL のフィールドで <kbd>Enter</kbd> を押します。

[[ui:http.response]] に、[[ui:http.status]] `200`、[[ui:http.latency]]、[[ui:http.size]]、レスポンスヘッダー、JSON ボディが表示されます。`http://127.0.0.1:8080/flaky` を 3 回送信してみてください。`503` が 2 回返ってから `200` になります。回復するサービスは、再試行するクライアントからはこのように見えます。

[[ui:nav.emulators]] に戻ると、[[ui:emu.live]] パネルがすべてのリクエストを数え、[[ui:emu.received]] にそれぞれのリクエストが、応答した [[ui:emu.col.rule]] と [[ui:emu.col.reply]] とともに一覧表示されます。[[ui:seed.emu.demo-api.name]] は次のパートのために実行したままにしておきます。詳しくは[エミュレーター](../tools/emulators.md)を参照してください。

## 実験を実行する {#experiment}

実験は、何度でも実行できるステップのフローです。Signal Lab が初回に開く実験 ([[ui:exp.templateHttp]] テンプレート) は、`http://127.0.0.1:8080/` にリクエストを送り、応答が `200` であることをチェックします。

### テンプレートを開く {#open-template}

1. [[ui:nav.experiment]] を開きます。
2. キャンバスに 4 つのノード ([[ui:exp.node.start]]、[[ui:exp.node.http]]、[[ui:exp.node.assert_status]]、[[ui:exp.node.end]]) が表示されていない場合は、ツールバー左端の **☰** ([[ui:exp.documents]]) を押し、テンプレートの一覧で [[ui:exp.templateHttp]] を選んで、[[ui:exp.openDocument]] を押します。開くとキャンバス上の実験が置き換えられます。<kbd>Ctrl</kbd>+<kbd>Z</kbd> で前の実験に戻せます。

ノードをクリックすると、右側の [[ui:exp.properties]] にその設定が表示されます。実験は編集するたびに自動的に保存されます。

### 実行して失敗の理由を読む {#first-run}

3. [[ui:exp.run]] を押します。

キャンバスの下に [[ui:exp.timeline]] が開き、各ステップについて、開始時 ([[ui:exp.running]]) と終了時にそれぞれ 1 行が表示されます。時刻、ノード、そして結果です。この実行は失敗します。

- [[ui:exp.node.start]] は成功し、実行のシードを示します。
- [[ui:exp.node.http]] は成功します。リクエストが送信され、`HTTP 404` という応答が返ってきました。
- [[ui:exp.node.assert_status]] は失敗します。`200` を期待しましたが、`404` を受信しました。

[[ui:seed.emu.demo-api.name]] には `/` のルートがないので `404` を返し、チェックがそれを捉えました。タイムラインの一番上の行には [[ui:exp.failed]] とその理由が表示されます。行をクリックすると、キャンバス上でそのノードが選択されます。

::: tip リクエスト自体が失敗した場合
[[ui:exp.node.http]] ステップが接続拒否で失敗した場合は、`127.0.0.1:8080` で何も待ち受けていません。[[ui:nav.emulators]] で [[ui:seed.emu.demo-api.name]] を起動して、もう一度実行してください。
:::

### リクエストを修正する {#fix}

4. [[ui:exp.node.http]] ノードをクリックします。
5. [[ui:exp.properties]] で、[[ui:sig.url]] を `http://127.0.0.1:8080/health` に変更します。
6. [[ui:exp.run]] を押します。

今度はすべてのステップが成功します。[[ui:exp.node.assert_status]] には [[ui:exp.step.checked]]、[[ui:exp.node.end]] には [[ui:exp.step.complete]] と表示され、タイムラインのタイトルには [[ui:exp.passed]] と表示されます。

### チェックを追加する {#add-check}

ステータス `200` は、サービスが応答したことを示すだけで、何を応答したかは示しません。ボディもチェックしましょう。

7. [[ui:exp.node.assert_status]] ノードをクリックします。
8. [[ui:exp.properties]] で [[ui:exp.addNext]] を押します。キャンバスにフォーカスがある状態で <kbd>A</kbd> を押してもかまいません。検索フィールド付きのノードのメニューが開きます。
9. `assert_body` と入力して <kbd>Enter</kbd> を押します。[[ui:exp.node.assert_status]] と [[ui:exp.node.end]] の間に [[ui:exp.node.assert_body]] ノードが追加されます。接続線はすでにつながっており、[[ui:exp.contains]] フィールドにすぐ入力できる状態になっています。
10. `"status":"ok"` と入力します。
11. [[ui:exp.run]] を押します。

新しいステップは成功します。テキストをボディに含まれていないものに変えてもう一度実行すると、理由とともに失敗するのを確認できます。

### 実行が残すもの {#report}

- **レポート。** 実行が終わると、タイムラインのタイトルに [[ui:exp.reportSaved]] と表示されます。ポインターを合わせると、そのファイルがわかります。終了した実行は、成功でも失敗でも、使った値とすべてのステップを含むレポートを、データフォルダーの `runs` フォルダーに書き込みます。ブラウザーではダウンロードのリンクになります。
- **シード。** タイトルには、実行のシードも [[ui:exp.pinSeed]] とともに表示されます。実行中のランダムな値はそのシードに従うので、シードを固定すればそれらを正確に再現できます。

詳しくは[実行とレポート](../experiments/runs.md)を参照してください。

## 後片付け {#clean-up}

ヘッダーの [[ui:app.stopAll]] を押します。[[ui:seed.emu.demo-api.name]] と、まだ実行中のほかのすべてが停止します。シグナル、実験、そのレポートはデータフォルダーに残ります。
