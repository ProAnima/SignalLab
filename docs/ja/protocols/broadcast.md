# ブロードキャスト

[[ui:nav.broadcast]] 画面 ([[ui:bc.title]]) は、1 つの UDP ペイロードを多数の宛先に一度に送信し、反対側では待ち受けて、誰が応答するかを確認します。ネットワーク上のデバイスを探したり、マルチキャストのストリームが受信側に届くか確認したり、ディスカバリーのプローブに応答するデバイスを演じたりするのに使います。

- [[ui:bc.emitter]] は、ホストのリスト、ブロードキャストアドレス、マルチキャストグループ、またはサブネットのすべてのホストに、1 回、またはビーコンとして繰り返し送信します。
- [[ui:bc.discovery]] は、ポートで待ち受け、マルチキャストグループに参加し、通信してきたすべてのピアを一覧表示し、プローブに応答することもできます。

::: danger
ブロードキャスト、マルチキャスト、スイープは、想定している 1 台だけでなく、そのネットワークセグメント上のすべてのデバイスに届き、ビーコンはそれを繰り返し続けます。まず、どのネットワークにいるかを確認し、所有しているか、テストを許可されているネットワークにだけ送信してください。以下の上限は、安全上の上限であって、許可ではありません。
:::

## 送信する {#send}

1. [[ui:bc.mode]] (後述) を選びます。
2. 宛先を入力します。フィールドの名前はモードによって変わります。IPv4 アドレスを持つネットワークでは、[[ui:bc.useSubnet]] を押すと、このマシンのアドレスから自動で入力されます。
3. [[ui:bc.payload]] を選んで書きます。
4. [[ui:bc.sendOnce]] を押します。各宛先に 1 つずつデータグラムが送信されます。

### モード {#modes}

| [[ui:bc.mode]] | 宛先 | 動作 | 既定値 |
| --- | --- | --- | --- |
| [[ui:bc.mode.list]] | [[ui:bc.targetList]]: カンマ、セミコロン、改行で区切った `IP:port` または `host:port` のエントリ。スペースでは区切れません。名前は名前解決され、IPv4 アドレスがあればそれが使われます。 | 各宛先に 1 つずつデータグラム | `127.0.0.1:9000, 127.0.0.1:9001` |
| [[ui:bc.mode.broadcast]] | [[ui:bc.targetAddress]]: `255.255.255.255:port`、または `.255` で終わるアドレス | ローカルネットワークのすべてのホストが受信する 1 つのデータグラム。ルーターは転送しません。 | `255.255.255.255:9000` |
| [[ui:bc.mode.multicast]] | [[ui:bc.targetAddress]]: `224.0.0.0` から `239.255.255.255` までのグループとポート | グループへの 1 つのデータグラム。参加しているリスナーだけが受信します | `239.1.1.1:9000` |
| [[ui:bc.mode.sweep]] | [[ui:bc.targetCidr]] (`a.b.c.d/nn`) と [[ui:bc.port]] | ブロックの使用可能なすべてのホストに、ユニキャストで 1 つずつデータグラムを送信します。ブロードキャストを無視するデバイス向けです | `192.168.1.0/24`、ポート 9000 |

スイープでは、ネットワークアドレスとブロードキャストアドレスはスキップされ (`/31` と `/32` を除く)、ネットワーク自身のアドレスでないベースは、切り捨てられてネットワークアドレスになります。`192.0.2.77/30` なら、`192.0.2.77` と `192.0.2.78` がスイープされます。スイープが届くのは最大 1024 ホストなので、最も広いブロックは `/22` (1022 ホスト) です。それより広いブロックは、絞り込むべきプレフィックスが示されて拒否されます。

ブロードキャスト、マルチキャストグループ、スイープ、ディスカバリーリスナーの参加は、IPv4 のみです。IPv6 にはブロードキャストがないためです。[[ui:bc.mode.list]] には、IPv6 ホストも指定できます ([ソケットオプション](#socket-options)を参照)。

[[ui:bc.useSubnet]] は、このマシンのアドレス `x.y.z.w` から、[[ui:bc.mode.list]] には `x.y.z.10:9000, x.y.z.11:9000`、[[ui:bc.mode.broadcast]] には `x.y.z.255:9000`、[[ui:bc.mode.sweep]] には `x.y.z.0/24` を入力します。`/24` のネットワークを前提としています。

### ペイロード {#payload}

| [[ui:bc.payload]] | 送信される内容 |
| --- | --- |
| [[ui:bc.payload.osc]] | OSC メッセージ。[OSC](osc.md) 画面と同じく、[[ui:common.address]] と型付きの [[ui:common.arguments]] を指定します。既定は `/hello/discover` とテキスト `who-is-there` です。 |
| [[ui:bc.payload.text]] | [[ui:bc.text]] を、入力したとおりに UTF-8 で送信します。終端文字はありません。既定は `HELLO-PROBE` です。 |
| [[ui:bc.payload.hex]] | [[ui:bc.hex]] をバイト単位でそのまま送信します。キャプチャしたフレームを再生したり、バイナリのディスカバリープロトコルを話したりするのに使います。16 進数 2 桁の組で書き、その間にあるほかの文字は無視されます。既定は `48 45 4c 4c 4f` です。 |

### ソケットオプション {#socket-options}

[[ui:bc.socketOptions]] を開くと、3 つの設定が追加されます。

| オプション | 内容 | 既定値 |
| --- | --- | --- |
| [[ui:bc.bindSource]] | データグラムの送信元となるローカルの `IP:port`。ネットワークカードや、デバイスが応答する送信元ポートを選ぶために固定します。`0.0.0.0:0` は任意です。 | `0.0.0.0:0` |
| [[ui:bc.ttl]] | データグラムが越えられるルーターの数。1〜255。マルチキャストではマルチキャストのホップ制限です。1 ならこのネットワーク内にとどまります。 | `1` |
| [[ui:bc.mcastLoop]] | マルチキャストのみ。グループのデータグラムをこのマシンにも配信し、ここのリスナーが聞き取れるようにします | オン |

[[ui:bc.bindSource]] が既定のままの場合、データグラムは IPv4 ソケットから送信されます。すべての宛先が IPv6 の場合は、IPv6 ソケットから送信されます。両方が混在するリストは IPv4 ソケットから送信されるため、IPv6 の宛先は失敗します。それらは別のリストとして送信するか、[[ui:bc.bindSource]] を IPv6 アドレスに固定してください。

### 結果 {#result}

[[ui:bc.lastEmit]] には、送信された内容が表示されます。[[ui:bc.targets]]、[[ui:common.packets]]、[[ui:common.volume]]、[[ui:common.errors]]、そして到達した最初の 8 つの宛先です (残りは「… +n more」)。ある宛先へのエラーがほかの宛先を止めることはありません。コンソールの行には、失敗した件数が表示されます。

## ビーコンとして繰り返す {#beacon}

ビーコンは、同じラウンド (各宛先に 1 つずつデータグラム) を、停止するまでスケジュールに従って送信します。定期的な通知を待ち受けるデバイスには、これが必要です。

1. 1 回の送信と同じように、モード、宛先、ペイロードを設定します。
2. [[ui:bc.beacon]] で [[ui:bc.beaconRate]] を設定し、自動で止めたい場合は [[ui:bc.beaconRounds]] または [[ui:bc.beaconSeconds]] も設定します。
3. [[ui:bc.startBeacon]] を押します。[[ui:bc.stopBeacon]] を押すか、コンソールの帯でそのジョブを停止すると、終了します。

| フィールド | 内容 | 既定値 |
| --- | --- | --- |
| [[ui:bc.beaconRate]] | 1 秒あたりのラウンド数。0 より大きい必要があります | `2` |
| [[ui:bc.beaconRounds]] | このラウンド数のあとに停止します。0 は無制限 | `0` |
| [[ui:bc.beaconSeconds]] | この秒数のあとに停止します。0 は無制限 | `0` |

レートと宛先の数の積は、1 秒あたり最大 50,000 データグラムまでです。そのため、`/24` (254 ホスト) のスイープは、1 秒あたり最大で約 196 回しか繰り返せません。ビーコンの動作中、[[ui:bc.lastEmit]] には、[[ui:bc.targets]] (各ラウンドの宛先。最初のレポートから表示)、合計、[[ui:bc.rounds]]、[[ui:bc.pps]] (1 秒あたりのデータグラム数) が 1 秒に 4 回更新されて表示され、[[ui:bc.sendOnce]] は使えなくなります。32 件を超えるデータグラムが失敗し、1 件も送信されていないビーコンは (経路がない、ブロードキャストが許可されていないなど)、自動で停止して理由を表示します。

## デバイスを待ち受ける {#discovery}

[[ui:bc.discovery]] は、UDP ポートをバインドし、そこに送信してきたすべてのピアを記録します。プローブに応答してきたものや、デバイスが自分から通知してくるものです。

1. [[ui:common.bind]] に、デバイスが送信するポートを設定します。
2. マルチキャストの場合は、[[ui:bc.joinGroups]] にグループを列挙します。
3. [[ui:bc.startListen]] を押します。[[ui:bc.stopListen]] を押すまで、設定はロックされます。

| フィールド | 内容 | 既定値 |
| --- | --- | --- |
| [[ui:common.bind]] | 待ち受ける場所 (`IP:port`)。`0.0.0.0` はすべてのネットワークカードで待ち受けます。 | `0.0.0.0:9000` |
| [[ui:bc.joinGroups]] | 参加する IPv4 マルチキャストグループ。カンマ区切り。空の場合は、ユニキャストとブロードキャストだけです | `239.1.1.1` |
| [[ui:bc.interface]] | グループに参加するネットワークカードの IPv4 アドレス。空の場合は、システムが選びます | 空 |
| [[ui:bc.reuse]] | 別のプログラムも使っているポートで待ち受けます (`SO_REUSEADDR`)。相手のプログラムも共有を許可している場合にだけ動作します。 | オン |
| [[ui:bc.respond]] | デバイスのようにプローブに応答する ([後述](#auto-reply)) | オフ |

### ピア {#peers}

[[ui:bc.peers]] には、何かを送信してきた相手が、最新のものを先頭にして一覧表示されます。その上には、確認したピアの数、受信したパケット数、送信した応答の数があります。

| 列 | 内容 |
| --- | --- |
| [[ui:bc.peer]] | 送信元の `IP:port`。ドットは、直近 3 秒以内に受信したかどうかを示します |
| [[ui:bc.proto]] | 最後のデータグラムが OSC としてデコードできた場合は `osc`、それ以外は `udp` |
| [[ui:common.packets]] | 送信してきた数 |
| [[ui:bc.age]] | 最後のデータグラムからの秒数 |
| [[ui:bc.lastMessage]] | 最後のデータグラム。OSC のアドレスと引数、またはテキストの先頭 |

一覧は 1 秒間に数回更新され、最大 512 ピアを保持します。それを超えると、パケットは引き続き数えられますが、新しいピアには行が付きません。

### プローブに応答する {#auto-reply}

[[ui:bc.respond]] をオンにすると、リスナーはデバイスを演じ、受信した各データグラムに、待ち受けているポートから、送信元のアドレスとポートへ応答します。

| フィールド | 内容 | 既定値 |
| --- | --- | --- |
| [[ui:bc.payload]] | 応答の内容。送信時と同じく OSC、テキスト、hex | OSC `/hello/here` とテキスト `signal-lab` |
| [[ui:bc.replyDelay]] | 動作の遅いデバイスのように、この時間だけ待ってから応答します | `0` |
| [[ui:bc.matchContains]] | デコードしたテキスト (OSC のアドレスと引数、またはテキストの先頭) にこの文字列を含むデータグラムにだけ応答します。空の場合はすべてに応答します | 空 |

リスナーは、自分の応答と同一のデータグラムには応答しません。そのため、互いに向き合う 2 つのリスナーが、延々と応答し合うことはありません。

### ファイアウォールと共有ポート {#firewall}

ほかのマシンからのブロードキャストとマルチキャストの通信は、ほとんどの Windows ファイアウォールで既定でブロックされます。アプリが提案したら、プライベートネットワークで Signal Lab を許可してください。ブロードキャストがルーターを越えることはありません。本物のサービスがすでに使っているポートで待ち受けるには、両方が共有を許可する必要があります (ここでは [[ui:bc.reuse]])。共有しない場合、使用中のポートは拒否され、オンにするよう案内が表示されます。[トラブルシューティング](../reference/troubleshooting.md)を参照してください。

## インスペクターでの表示 {#inspector}

キャプチャを開始していると、この画面の通信は、ペイロードに応じてプロトコル `osc` または `udp` として表示されます。

| ソース | 内容 | 件数 |
| --- | --- | --- |
| `broadcast` | [[ui:bc.sendOnce]]: 各データグラム。判定は `fan-out`、`broadcast`、`multicast`、`sweep` のいずれかで、失敗したものは `error: …` | すべて |
| `beacon` | ビーコンのラウンド | 50 ms に最大 1 ラウンド |
| `discovery` | リスナーが受信したデータグラム | 40 ms に最大 1 件 |
| `discovery` | その応答。判定は `auto-reply` | すべて |

ビーコンやリスナーについてインスペクターが除外した分は数えられ、次に描画されるフレームの判定に件数が `+n not shown` として付きます (ビーコンの場合は、除外されたラウンドの宛先ごとに 1 フレーム)。[インスペクター](../tools/inspector.md)を参照してください。

## サーバーまたは Docker で {#server}

[サーバー](../server/index.md)では、画面はサーバーのネットワーク上で送信と待ち受けを行います。Docker では、Linux ホスト上でコンテナがホストのネットワーク (`--network host`) を使う場合にだけ、ブロードキャスト、マルチキャスト、ディスカバリーがローカルネットワークに届きます。Docker の既定のブリッジネットワークや Docker Desktop では、コンテナが到達できるホストへのユニキャストだけが動作します。

## ほかの手段 {#elsewhere}

- [`signallab send udp`](../automation/cli.md#cli-send-udp) は、1 つのホストに 1 件のデータグラムを送信します。コマンドラインからのブロードキャスト、マルチキャスト、スイープはありません。
- [[ui:exp.node.udp]] ステップは、1 つ以上のホストにテキストのデータグラムを送信し、[[ui:exp.node.wait_udp]] ステップはそれを待ちます。[UDP と TCP](udp-tcp.md) を参照してください。
- 複数のルールや、届いた内容から作る応答など、ルールに従って応答するデバイスを演じるには、[[ui:emu.new.udp]] または [[ui:emu.new.osc]] のエミュレーターを使います。[エミュレーター](../tools/emulators.md)を参照してください。

## 問題が起きたとき {#troubleshooting}

| 表示される内容 | よくある原因 |
| --- | --- |
| `… is not a broadcast address` | [[ui:bc.mode.broadcast]] で使えるのは、`255.255.255.255:port` か、`.255` で終わるアドレスです。それ以外のサブネットマスクでは、[[ui:bc.mode.sweep]] を使ってください。 |
| `… is not a multicast group` | アドレスが `224.0.0.0`〜`239.255.255.255` の範囲外です。 |
| `… spans … addresses, and a sweep reaches at most 1024 hosts` | ブロックが `/22` より広いので、絞り込んでください。 |
| `Set the port to sweep` | [[ui:bc.port]] が 0 です。 |
| `… is over the … pps limit` | レートと宛先の数の積が、1 秒あたり 50,000 を超えています。[[ui:bc.beaconRate]] を下げるか、宛先を絞り込んでください。 |
| `… is already in use — turn on “share the port” to listen alongside it` | ほかのプログラムがそのポートを使っています。[[ui:bc.reuse]] にチェックを入れてください。 |
| `Cannot join the multicast group …` | グループまたは [[ui:bc.interface]] が、このマシンでは使えません。そのアドレスを持つネットワークカードがないか、マルチキャストの経路がありません。 |
| 送信はできたが、誰も応答しない | デバイスが別のポートで待ち受けている、ここのファイアウォールが応答を遮断している、間にルーターがある、または Docker でコンテナがホストのネットワーク上にありません。 |
| プローブは送信されるが、ディスカバリーリスナーに応答が届かない | 多くのデバイスは、プローブの送信元のアドレスとポート、つまり送信側自身のソケットに応答しますが、画面はそこを読み取りません。デバイスが応答するポートで待ち受けるか、実験からプローブを送信してください。[[ui:exp.expectReply]] 付きの [[ui:exp.node.udp]] ステップは、同じポートで送信と待ち受けを行います。 |

すべてのエラーメッセージは[エラーメッセージ](../reference/errors.md#broadcast)に一覧があります。
