# HTTP

[[ui:nav.http]] 画面は、リクエストの検査ツールと負荷ツールを兼ねています。

- 1 件のリクエストを送信し、ステータス、かかった時間、ヘッダー、ボディを確認します。
- Basic、Bearer トークン、Digest で認証します。
- ブラウザーと同じように、サーバーが設定した Cookie を保持します。
- 同じリクエストを同時に何度も送信し ([[ui:http.burst]])、スループットとレイテンシのパーセンタイルを読み取ります。

## リクエストを送信する {#request}

1. [[ui:nav.http]] を開きます。
2. メソッドを選び、URL を入力します。たとえば `http://127.0.0.1:8080/health` です。
3. サーバーが必要とするなら [[ui:http.headers]] を追加します。[[ui:http.addHeader]] で行を追加し、✕ で 1 行削除します。名前のない行は送信されません。
4. GET と HEAD 以外のメソッドでは、[[ui:http.body]] を書きます。GET や HEAD に切り替えている間もテキストはフィールドに残り、別のメソッドに戻すと元に戻りますが、その間は送信されません。
5. [[ui:common.send]] を押します。

ボタンの下の行にすぐ結果が表示されます。ステータス、時間、サイズ、またはレスポンスがなかった理由です。残りは [[ui:http.response]] パネルに表示されます。リクエスト (メソッド、URL、ヘッダー、ボディ、タイムアウト、[[ui:http.keepCookies]]) は、画面を切り替えたりアプリを再起動したりしても保持されます。ただし、認証情報は保持されません。

| キー | 場所 | 動作 |
| --- | --- | --- |
| <kbd>Enter</kbd> | URL、ヘッダー、認証情報、タイムアウト | 送信 |
| <kbd>Ctrl</kbd>+<kbd>Enter</kbd> | ボディを含むリクエストのどのフィールドでも | 送信 |
| <kbd>Ctrl</kbd>+<kbd>S</kbd> | リクエストのどのフィールドでも | シグナルとして保存 ([後述](#library)) |

### リクエストのフィールド {#request-fields}

| フィールド | 内容 | 既定値 |
| --- | --- | --- |
| [[ui:exp.method]] | GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS | GET |
| [[ui:field.url]] | `http://` または `https://` の URL | `http://127.0.0.1:8080/` |
| [[ui:http.headers]] | 名前と値のペア。書いたとおりに送信されます。独自の `User-Agent` がなければ、Signal Lab は `SignalLab/0.1` を送信します。 | `Accept: application/json` |
| [[ui:field.auth]] | リクエストの認証方法 ([後述](#auth)) | [[ui:http.auth.none]] |
| [[ui:http.keepCookies]] | サーバーが設定した Cookie を送り返す ([後述](#cookies)) | オン |
| [[ui:http.body]] | 書いたとおりに送信されます。`Content-Type` は追加されないので、内容に合ったヘッダーを自分で追加してください。空のボディは送信されません。GET と HEAD ではこのフィールドは表示されず、そのときリクエストはボディをまったく持ちません。別のメソッドのときに入力していても、送信にも、保存したシグナルにも、[[ui:common.toExperiment]] にも含まれません。 | 空 |
| [[ui:common.timeoutMs]] | 応答とボディを含め、やり取り全体にかけられる時間。HTTP ステップと同じく 1 ms から 120,000 (2 分) | 10,000 |

## 認証 {#auth}

| [[ui:field.auth]] | フィールド | 送信される内容 |
| --- | --- | --- |
| [[ui:http.auth.none]] | — | `Authorization` ヘッダーなし |
| [[ui:http.auth.basic]] | [[ui:field.username]]、[[ui:field.password]] | `Authorization: Basic …`。名前とパスワードを base64 にしたもので、最初のリクエストから付きます |
| [[ui:http.auth.bearer]] | [[ui:field.token]] | `Authorization: Bearer <token>` |
| [[ui:http.auth.digest]] | [[ui:field.username]]、[[ui:field.password]] | 最初は何も送らず、サーバーのチャレンジへの応答を送信します ([後述](#digest)) |

Basic と Digest を切り替えても、名前とパスワードは保持されます。

### Digest {#digest}

Digest では、Signal Lab はまず認証情報なしでリクエストを送信します。サーバーが Digest チャレンジ付きの `401` を返すと、Signal Lab はチャレンジとパスワードから応答を計算し、リクエストを再送します。表示されるレスポンスは、この 2 回目のリクエストに対するもので、[[ui:http.digestAnswered]] と表示されます。レイテンシは 2 回のやり取りの合計で、これはクライアントが実際に待つ時間です。

- アルゴリズム: MD5 と SHA-256、およびその `-sess` 版。サーバーが両方を提示した場合は SHA-256 を使います。
- 保護の品質 (quality of protection): `auth` と `auth-int`、および `qop` のない従来の応答。
- サーバーが nonce の期限切れ (`stale`) を伝えたり、新しい nonce で再度要求したりした場合は、最大 3 回まで追加で応答し直します。直前に出した nonce への応答をサーバーが拒否した場合は、`401` がそのまま結果になります。名前かパスワードが間違っています。
- リダイレクトは Signal Lab 自身がたどるので、チャレンジを要求した URL に応答します。別のオリジンからのチャレンジには応答しません。あるホスト用に入力した認証情報が、別のホストに渡ることはありません。同じホストで、既定のポートのまま `http://` から `https://` に移る場合は、同じホストとして扱います。

チャレンジに応答できない場合は、`401` がそのまま結果になり、パネルに理由が表示されます。

| メッセージ | 意味 |
| --- | --- |
| サーバーは Digest を要求せずに 401 を返しました | サーバーが別の方式を求めています。Basic または Bearer を試してください。 |
| サーバーが … の Digest を要求しましたが、Signal Lab は対応していません | Signal Lab が対応していないアルゴリズムです。対応しているのは MD5 と SHA-256 です。 |
| サーバーが realm または nonce なしで Digest を要求しました | サーバーのチャレンジが不完全です。 |
| リクエストは … に転送され、そこが Digest を要求しました | リダイレクトで別のオリジンに移り、そのチャレンジには応答しません。 |

### 認証情報の行き先 {#credentials}

認証情報は、送信時にリクエストの `Authorization` ヘッダーにだけ入ります。インスペクター、コンソール、実験のレポートには、そのヘッダーは表示されません。この画面では、認証情報はメモリにだけ保持され、再起動すると消えます。ただし、保存したシグナルとリクエストが結び付いている場合は、シグナルから復元されます。

::: warning
シグナルとして保存したリクエストは、認証情報をライブラリファイル `signals.json` にプレーンテキストで保存します。実験では、パスワードの代わりに `{{secret.NAME}}` と書いてください。[データとテンプレート](../experiments/data.md)を参照してください。
:::

## Cookie {#cookies}

[[ui:http.keepCookies]] がオンのときは、サーバーが `Set-Cookie` で設定したものがこの画面の Cookie ジャーに保持され、そのサーバーへの以降のリクエストに、ブラウザーと同じルール (ドメイン、パス、`Secure`、有効期限) で送り返されます。ジャーは、この画面のリクエスト、バースト、ライブラリから送信する HTTP シグナルで使われます。オフにすると、Cookie なしでリクエストを送り、何も保持しません。

リクエストとレスポンスの下の Cookie パネルには、ジャーの中身が一覧表示されます。[[ui:http.cookieName]]、[[ui:http.cookieValue]]、[[ui:http.cookieWhere]] (`.` で始まるドメインはそのサブドメインも対象とします)、[[ui:http.cookieExpires]] (有効期限のない Cookie は [[ui:http.cookieSession]])、[[ui:http.cookieFlags]] (`Secure`、`HttpOnly`、`SameSite`) です。期限切れの Cookie は表示されません。[[ui:common.clear]] を押すと、ジャーが空になります。

ジャーが保持する Cookie は最大 3000 件で、ブラウザーが保持する数とほぼ同じです。応答のたびに新しい Cookie を設定するサーバーがあっても、ジャーがそこまで埋まるだけで、それ以上は増えません。上限に達すると新しい Cookie は保持されませんが、ジャーにすでにあるものの更新や削除は行われます。

ジャーはアプリが動いている間だけ存在し、再起動すると空の状態から始まります。[サーバー](../server/index.md)では、サインインしているすべてのページで 1 つのジャーを共有します。実験の実行には専用のジャーがあり ([実験](../experiments/index.md)を参照)、`signallab send http` は Cookie を使いません。

## レスポンス {#response}

| 部分 | 内容 |
| --- | --- |
| [[ui:http.status]] | ステータスコードとその理由。レスポンスがなければ `ERR` |
| [[ui:http.latency]] | 送信からボディの最後のバイトまで。ミリ秒 |
| [[ui:http.size]] | ボディのサイズ |
| レスポンスヘッダー | 件数が書かれた行をクリックすると、表示と非表示を切り替えます |
| ボディ | JSON の場合は整形されます。[[ui:http.rawBody]] と [[ui:http.formatJson]] で切り替えます。最大 256 KiB まで表示し、それを超えると `… (truncated)` と表示されます。[[ui:http.size]] は、ボディ全体のサイズのままです。 |

ボディは届くそばから読み込まれ、保持されるのは先頭の 256 KiB だけです。そのため、数ギガバイトのボディや、終わらないボディでも、メモリの使用量はその分に収まり、タイムアウトで終了します。途中で止まったボディ (タイムアウト、またはサーバーが切断した場合) は、ほかの失敗と同じ表現で失敗として扱われ、ステータスとそれまでに届いた内容は表示されたままになります。ボディが半分しか届かない `200` は、成功ではありません。

レスポンスがない場合、パネルには、Signal Lab のほかの場所と同じ言葉で理由が表示されます。接続が拒否された、時間内に応答がない、名前を解決できない、証明書の問題、などです。システムからの技術的な詳細は、その下に折りたたまれています。

### リダイレクト {#redirects}

リダイレクト (301、302、303、307、308) は最大 10 回までたどられ、表示されるレスポンスは最後のものです。301、302、303 のあとは、リクエストはボディなしの GET として続行されます (HEAD は HEAD のまま)。307 と 308 のあとは、元のとおりに続行されます。あるホスト用に入力した `Authorization` と Cookie は、別のホストには送られません。

### 安全な接続 {#tls}

`https://` サーバーの証明書は、このシステムが信頼する証明書に照らして検証されます。自己署名や期限切れの証明書は、「… への安全な接続を確立できませんでした」というメッセージで拒否されます。検証を省略する設定はありません。独自の証明書を持つサーバーをテストするには、その証明書をシステムの信頼済み証明書に追加してください。

## 負荷バースト {#burst}

[[ui:http.burst]] は、画面上のリクエストを、その認証と、[[ui:http.keepCookies]] がオンのときは Cookie ジャーも使って、何度も送信して測定します。

1. [[ui:common.concurrency]]、[[ui:http.total]]、[[ui:http.duration]]、[[ui:http.rate]] を設定します。
2. [[ui:http.startBurst]] を押します。バーストはジョブです。[[ui:http.stopBurst]] を押すか、コンソールの帯で停止すると終了します。

| フィールド | 内容 | 既定値 |
| --- | --- | --- |
| [[ui:common.concurrency]] | 同時に処理中のリクエスト数。1〜512 | 20 |
| [[ui:http.total]] | 送信するリクエスト数。0 は、継続時間が終わるまで送り続けます | 500 |
| [[ui:http.duration]] | 実行する秒数。0 は、合計数を送り終えたら停止します | 0 |
| [[ui:http.rate]] | 1 秒あたりに開始するリクエスト数。0.1〜100,000。0 はワーカーが処理できる限りの速さです | 0 |

[[ui:http.total]] と [[ui:http.duration]] がどちらも 0 の場合、バーストは停止するまで続きます。

送信方法は 2 つあります。

- **[[ui:http.rate]] が 0。** 各ワーカーは、応答を受け取るとすぐに次を送信します。サーバーがどこまで処理できるかがわかりますが、サーバーが遅いとバーストも遅くなります。
- **レートを指定。** 応答の遅さにかかわらず、リクエストは固定のスケジュールで開始されます。毎秒 10 件なら、開始から 100 ms ごとに 1 件です。すべてのワーカーが使用中のときにリクエストの時刻が来ると、最大 50 ms はワーカーの空きを待ちます。それを過ぎるとスキップされ、[[ui:http.missed]] として数えられ、遅れて送信されることはありません。取りこぼしがあるのは、このレートに対して同時実行数が少ないか、サーバーがレートの要求より遅いことを意味します。

| 数値 | 内容 |
| --- | --- |
| [[ui:http.sent]] | 応答があったか、失敗したリクエスト |
| [[ui:http.ok]] | 2xx のステータスでボディ全体が届いたもの |
| [[ui:http.failed]] | 応答がない、ボディが途中で切れた、または 200〜299 以外のステータス |
| [[ui:http.local]] | このコンピューターが送信できなかったリクエスト。ソケットまたはローカルポートが足りなくなったものです (Windows では、閉じた接続ごとに最大 2 分間ポートが占有されます)。サーバーには届いていないため、[[ui:http.sent]] には含まれますが、[[ui:http.failed]] やレイテンシには含まれません。該当するものがある場合にのみ表示されます。 |
| [[ui:http.missed]] | 上記のとおりスキップされたもの (レートを指定した場合のみ) |
| [[ui:http.rps]] | 直近 10 分の 1 秒間の 1 秒あたりのリクエスト数。バーストが終了したあとは、バースト全体での値です。レートを指定した場合、ラベルには要求したレートが表示されます。 |
| [[ui:http.p50]]、[[ui:http.p90]]、[[ui:http.p95]]、[[ui:http.p99]] | その割合のリクエストが、失敗も含めて、その時間内に終わったことを示します。誤差は 0.5% 以内です |
| [[ui:http.avg]]、[[ui:http.min]]、[[ui:http.max]] | 平均、最速、最遅 |

数値は 1 秒間に約 10 回更新されます。その横のグラフには、直近約 24 秒間の 1 秒あたりのリクエスト数が描かれます。

Digest の場合、最初のリクエストのチャレンジに一度応答すると、その応答がバーストのすべてのリクエストに使われます。

::: warning
バーストは実際の負荷です。所有しているか、テストを許可されているサーバーにだけ向けてください。
:::

ランプ、段階、スパイク、合否のしきい値が必要な場合は、[実験の負荷](../experiments/load.md)でリクエストを実行してください。

## インスペクターでの表示 {#inspector}

キャプチャを開始していると、やり取りごとに、プロトコル `http`、ソース `http` の 1 つのフレームが表示されます。概要にはメソッド、URL、ステータス、時間が入ります。詳細にはレスポンスヘッダーとボディの先頭 (2000 文字) が入ります。判定にはステータスが入ります (レスポンスがなかった場合は `failed`、チャレンジに応答した場合は `· digest after 401`)。フレームに記録されるのはボディのサイズで、バイト列そのものではありません。リクエストの `Authorization` ヘッダーは含まれません。バーストがキャプチャに入れるのは、100 ms ごとに最大 1 件のやり取りです。[インスペクター](../tools/inspector.md)を参照してください。

## 保存と再利用 {#library}

- **シグナルとして保存する。** [[ui:sig.saveNew]] を押すと、リクエスト (メソッド、URL、ヘッダー、ボディ、タイムアウト、認証) がシグナルライブラリに保存されます。画面はそのシグナルと結び付いたままになり、[[ui:sig.save]] (<kbd>Ctrl</kbd>+<kbd>S</kbd>) で更新、[[ui:sig.saveAs]] でコピーを作成し、チップを押すと [[ui:nav.signals]] で開きます。ライブラリの HTTP シグナルを開くと、認証情報も含めてここに読み込まれます。[シグナル](../tools/signals.md)を参照してください。
- **実験に追加する。** [[ui:common.toExperiment]] を押すと、同じリクエストの [HTTP リクエスト](../experiments/nodes.md#node-http)ステップが、開いている実験の終了の直前か、選択中のステップの後ろに追加され、その実験が開きます。
- **モック化する。** レスポンスの下の [[ui:http.mockThis]] は、このメソッドとパスに、このステータス、ヘッダー、ボディで応答するエミュレーターのルートを作ります。[[ui:http.mockInto]] で HTTP エミュレーターか [[ui:http.mockNew]] を選び、[[ui:http.mockAdd]] を押します。ルートはそのエミュレーターの先頭に追加され、[[ui:nav.emulators]] 画面がそのルートを開いた状態で表示されます。[エミュレーター](../tools/emulators.md)を参照してください。

## コマンドラインから {#cli}

`signallab send http` は、この画面と同じように 1 件のリクエストを送信します。

```bash
signallab send http GET http://127.0.0.1:8080/health --expect-status 200
signallab send http POST http://127.0.0.1:8080/api/items \
  -H 'Content-Type: application/json' --body '{"name":"lamp"}'
signallab send http GET http://127.0.0.1:8080/private -u admin:secret --digest
```

ステータス行は標準エラー出力に、ボディは標準出力に出力されます。

```text
HTTP 200 OK · 3 ms · 15 B
{"status":"ok"}
```

| オプション | 内容 | 既定値 |
| --- | --- | --- |
| `-H`, `--header 'Name: value'` | ヘッダー。複数指定するには繰り返します | — |
| `--body TEXT`, `--body @FILE` | ボディ、またはファイルの内容 | — |
| `--expect-status N` | ステータスが N でなければ終了コード 1 で終了します | — |
| `--timeout MS` | レスポンスを待つ時間 | 10,000 |
| `-u`, `--user NAME:PASSWORD` | Basic 認証 | — |
| `--digest` | `--user` と併用。代わりにサーバーの Digest チャレンジに応答します | — |
| `--bearer TOKEN` | `Authorization: Bearer TOKEN` | — |
| `--json` | レスポンス全体を JSON として標準出力に出力します | — |

終了コードは、レスポンスがあった (かつ期待したステータスだった) ときは 0、レスポンスがなかったとき、期待したステータスでなかったとき、Digest チャレンジに応答できなかったときは 1、オプションが無効なときは 2 です。Cookie は保持しません。[コマンドライン](../automation/cli.md#cli-send-http)を参照してください。

## 問題が起きたとき {#troubleshooting}

| 表示される内容 | よくある原因 |
| --- | --- |
| `… refused the connection — nothing is listening on that port` | サーバーが動いていないか、別のポートまたはアドレスで待ち受けています。 |
| `No answer from … in time` | サーバーが遅いか、到達できません。アドレスを確認するか、[[ui:common.timeoutMs]] を増やしてください。 |
| `Cannot resolve …` | このマシンでホスト名を名前解決できません。入力ミスか、別のネットワークでしか通用しない名前です。 |
| `A secure connection to … could not be made` | ここでは証明書が信頼されていない (自己署名、期限切れ、別の名前) か、TLS が失敗しました。[安全な接続](#tls)を参照してください。 |
| `… is not a valid address` | URL の形式が不正か、`http://` または `https://` で始まっていません。 |
| サーバーが、ボディがない、または型が違うと言う | ボディに合う `Content-Type` ヘッダーがないか、ボディが空です。 |
| Digest での `401` | ステータスの下のメッセージを読んでください。[Digest](#digest) を参照してください。 |
| [[ui:http.missed]] が 0 より大きい | [[ui:common.concurrency]] を増やすか、レートを下げてください。サーバーがレートの要求より遅く応答しています。 |
| サーバーが応答しているのに [[ui:http.failed]] が多い | 200〜299 以外のステータスは、404 や 500 も含め、すべて失敗として数えられます。 |
| [[ui:http.local]] が 0 より大きい | このコンピューターのローカルポートが足りなくなりました。サーバーが接続をすべて閉じるため、リクエストごとに新しい接続が必要です。[[ui:common.concurrency]] かレートを下げるか、ポートが戻るまで 1 分ほど待ってください。 |

サーバーでは、リクエストはサーバーから送信されます。`127.0.0.1` はサーバー自身です。[サーバー](../server/index.md)を参照してください。

すべてのエラーメッセージは[エラーメッセージ](../reference/errors.md#transport)に一覧があります。
