# WebSocket

[[ui:nav.ws]] 画面は WebSocket クライアントです。サービスが求めるヘッダーとサブプロトコルを付けてサービスへの接続を 1 つ開き、テキストまたはバイト列を送信し、行き来するすべてのメッセージを、新しいものを下にして一覧表示します。実験でスクリプト化する前に、ライブ API、コントロールサーフェス、WebSocket を話すデバイスを試すのに使います。

## 接続する {#connect}

1. [[ui:nav.ws]] を開きます。
2. [[ui:field.url]] にアドレスを入力します。`ws://127.0.0.1:9001/` や `wss://example.com/socket` のようにします。
3. サービスが求める場合は、[[ui:exp.wsProtocols]] を入力し、[[ui:http.headers]] (トークン付きの `Authorization` ヘッダーや Cookie) を追加します。
4. [[ui:ws.connect]] を押します。アップグレードの間、ボタンは [[ui:ws.connecting]] になり、完了するとフィールドがロックされ、ボタンは [[ui:ws.disconnect]] に変わります。

| フィールド | 内容 | 既定値 |
| --- | --- | --- |
| [[ui:field.url]] | `ws://` または `wss://`、ホスト、省略可能なポート (`ws` は 80、`wss` は 443)、パス | `ws://127.0.0.1:9001/` |
| [[ui:exp.wsProtocols]] | 提示するサブプロトコル。優先順にカンマで区切ります。サーバーが 1 つを選びます。名前にスペース、カンマ、スラッシュは使えません。 | なし |
| [[ui:http.headers]] | アップグレードのリクエストに付ける追加のヘッダー。[[ui:http.addHeader]] で行を追加します。名前のない行は除外されます。`Host` (または `Sec-WebSocket-Version` のように、アップグレード自体が書き込むほかのヘッダー) は、アップグレードが送るはずだった値を置き換えます。 | なし |

接続 (名前解決、TCP 接続、`wss://` の TLS、アップグレード) には 10 秒かけられます。URL は、画面を切り替えたりアプリを再起動したりしても保持されます。ヘッダーとサブプロトコルは保持されません。

接続すると、パネルに次の内容が表示されます。

| 項目 | 内容 |
| --- | --- |
| [[ui:ws.state]] | [[ui:ws.open]]。終了後は、自分で閉じたか、サーバーが閉じたか (クローズコード付き)、またはクローズなしで回線が切れた場合の [[ui:ws.lost]] |
| [[ui:field.reason]] | 閉じた側が示した理由 (ある場合) |
| [[ui:ws.subprotocol]] | サーバーが選んだサブプロトコル。なければ — |
| [[ui:ws.peer]] | サーバーの `IP:port` |
| [[ui:ws.upgradeTime]] | 接続とアップグレードにかかった時間。ミリ秒 |

接続はジョブです。コンソールの帯に表示され、そこから停止することもできます。

### 安全な接続 {#wss}

`wss://` は、このシステムで HTTPS が信頼するのと同じ証明書を信頼します。このシステムが証明書を信頼しないサーバー (自己署名、期限切れ、別の名前) は、「… への安全な接続を確立できませんでした」というメッセージで拒否されます。検証を省略する設定はありません。

## メッセージを送信する {#send}

1. [[ui:ws.message]] で、[[ui:exp.wsText]] または [[ui:exp.wsBinary]] を選びます。
2. メッセージを書きます。バイナリの場合は、バイト列を 16 進数 2 桁の組で書きます。`de ad be ef` のようにします。
3. [[ui:common.send]] を押すか、メッセージ欄で <kbd>Ctrl</kbd>+<kbd>Enter</kbd> を押します。

メッセージは最大 16 MiB (16,777,216 バイト。バイナリでは 16 進数の桁数ではなくバイト数で数えます) までです。これは、届くメッセージの上限、[[ui:exp.node.ws_send]] ステップの上限と同じです。それより長いメッセージは、何も送信される前に `Too long: at most 16777216` で拒否され、接続は開いたままです。

テキストメッセージが JSON の場合は、[[ui:http.formatJson]] を押すと、送信前にインデント付きで整形されます。メッセージは、画面を切り替えたりアプリを再起動したりしても保持されます。

## メッセージを読む {#messages}

[[ui:ws.messages]] には、受信 (↓) と送信 (↑) したものが、新しいものを下にして、時刻、メッセージの先頭 (300 文字)、サイズとともに一覧表示されます。バイナリメッセージはバイト列が hex で表示され、[[ui:ws.binary]] と表示されます。一覧の上には、受信数と送信数があります。一覧の末尾までスクロールしている間は新しいメッセージに追従し、上にスクロールするとその位置にとどまります。

メッセージをクリックすると、一覧の下に全体が表示されます。JSON は整形され、バイナリは hex です。[[ui:ws.editHere]] を押すと、メッセージ欄にコピーされ、再送信や変更ができます。非常に長いメッセージは一部だけ表示されます。テキストは 64 KiB まで、バイナリは 4096 バイトまでで、その場合は切り詰めたものが送信されてしまうため、コピーできません。

画面が保持するのは最新の 2000 件で、メッセージが長い場合はそれより少なくなります (合計 800 万文字まで)。[[ui:common.clear]] で一覧が空になります。その上の受信数と送信数は接続そのものの数で、すべてのメッセージを含みます。サービスが画面の処理能力を超える速さで送信すると (10 分の 1 秒間に 2000 件、またはテキスト 1 MB を超える場合)、その中で最も古いものは一覧から除かれ、「非表示」として数えられます。キャプチャを開始していれば、インスペクターにはそれらも残ります。サービスがどれだけ大量に送り付けても、[[ui:ws.disconnect]] と停止は即座に効きます。

## 閉じる {#close}

[[ui:ws.disconnect]] は、コード 1000 (正常) のクローズフレームを送信し、サーバーの応答を最大 2 秒待ってから切断します。状態は、1000 で閉じたと表示されます。サーバー側が閉じた場合は、状態にそのコードと理由が表示されます。クローズフレームなしで接続が切れた場合は [[ui:ws.lost]] と表示され、コンソールに理由が表示されます。

Signal Lab は、サーバーの ping に自動で応答します。ping と pong は一覧に表示されません。16 MiB を超えるメッセージが届いたときや、サーバーが読み取りを止めたためにメッセージの送信に 10 秒を超えてかかったときにも、接続は終了します。(自分で 16 MiB を超えるメッセージを送ろうとした場合は、拒否されるだけで、何も終了しません。)

## インスペクターでの表示 {#inspector}

キャプチャを開始していると、接続の通信は、プロトコル `ws`、ソース `websocket` として表示されます。

| 概要 | 内容 |
| --- | --- |
| `CONNECT ws://… (subprotocol)` | 接続が開かれた |
| `TEXT …` | テキストメッセージとその先頭 |
| `BINARY n B …` | バイナリメッセージ、そのサイズ、先頭の 16 バイト |
| `CLOSE code reason` | 送信または受信したクローズフレーム |

メッセージのフレームは、それぞれバイト列を保持します。通信量が少ないうちはすべてのメッセージがキャプチャされます。忙しい接続は 1 秒に 200 フレームまでに抑えられ、そのあとにキャプチャされるフレームに、除外された件数が付きます (`+n not shown`)。[インスペクター](../tools/inspector.md)を参照してください。

## 実験での使い方 {#experiments}

WebSocket のやり取りをスクリプト化するステップは 4 つあります。接続は 1 つのステップで開き、ほかのステップはその接続を名前で指定します。

| ステップ | 動作 |
| --- | --- |
| [[ui:exp.node.ws_connect]] | 実行の残りの間、接続を開きます。URL とヘッダーには `{{templates}}` が使えるので、前に抽出したトークンを入れられます。[詳細](../experiments/nodes.md#node-ws_connect) |
| [[ui:exp.node.ws_send]] | 接続にテキストまたはバイナリのメッセージを送信します。[詳細](../experiments/nodes.md#node-ws_send) |
| [[ui:exp.node.wait_ws]] | [[ui:exp.node.wait_udp]] と同様に、ペイロードが一致するメッセージを待ちます。JSON メッセージは、そのあとでフィールドごとに読み取れます。[詳細](../experiments/nodes.md#node-wait_ws) |
| [[ui:exp.node.ws_close]] | クローズのハンドシェイクで接続を閉じます。コードは 1000、またはアプリケーション独自の 3000〜4999 で、理由は最大 123 バイトです。[詳細](../experiments/nodes.md#node-ws_close) |

実行が終了したとき、または停止されたときに接続がまだ開いていれば、きちんと閉じられます。[[ui:exp.templateWsEcho]] テンプレートが実例です。

## コマンドラインから {#cli}

`signallab send ws` は、接続、メッセージの送信、(指定すれば) 応答の待機、切断という 1 回のやり取りを行います。

```bash
signallab send ws ws://127.0.0.1:9001/ --text '{"type":"ping"}' --expect pong
```

ハンドシェイクと送信内容は標準エラー出力に、応答は標準出力に出力されます。

```text
Connected to ws://127.0.0.1:9001/ in 4 ms
Sent 15 bytes
{"type":"pong"}
```

`--hex` はバイナリメッセージを送信します。`-H` はヘッダーを追加し、`--protocol` はサブプロトコルを提示します (どちらも複数回指定できます)。`--expect TEXT`、`--expect-regex RE`、`--wait` (任意のメッセージ) で、どの応答を待つかを指定し、待つ時間は `--timeout` ミリ秒です (既定は 2000)。応答が来ないとき、または接続に失敗したときは、終了コード 1 で終了します。[コマンドライン](../automation/cli.md#cli-send-ws)を参照してください。

## 問題が起きたとき {#troubleshooting}

| 表示される内容 | よくある原因 |
| --- | --- |
| `… is not a WebSocket address` | URL が `ws://` または `wss://` で始まっていないか、ホストがありません。 |
| `… answered HTTP n instead of switching to WebSocket` | サーバーがアップグレードを拒否しました。パスが違う (404) か、トークンがない、または間違っている (401、403) などです。応答の本文の冒頭 (`ws://` では、0.3 秒以内に届いた分) は、技術的な詳細に表示されます。 |
| `… did not take any of the subprotocols offered` | サブプロトコルを提示したのに、サーバーがどれも選ばなかったか、提示していないものを返しました。 |
| `… is not a subprotocol name` | スペース、カンマ、スラッシュを含む名前です。 |
| `The header … cannot be sent with the upgrade` | ヘッダーの名前または値に、HTTP で許されていない文字が含まれています。 |
| `… refused the connection` | そのポートで待ち受けているものがありません。 |
| `A secure connection to … could not be made` | ここでは証明書が信頼されていないか、TLS が失敗しました。[安全な接続](#wss)を参照してください。 |
| `The connection with … broke: the server did not keep to the WebSocket protocol` | サーバーが、有効な WebSocket ではないものを送信しました。 |
| `A WebSocket message is limited to … bytes` | サーバーが 16 MiB を超えるメッセージを送信したため、接続が終了します。 |
| `Too long: at most 16777216` | 送信しようとしたメッセージが 16 MiB を超えています。何も送信されず、接続は開いたままです。 |

すべてのエラーメッセージは[エラーメッセージ](../reference/errors.md#ws)に一覧があります。
