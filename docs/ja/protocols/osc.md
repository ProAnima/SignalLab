# OSC

[[ui:nav.osc]] 画面は、UDP 上の Open Sound Control (OSC 1.0) を手作業で扱う場所です。次の 3 つのパートがあります。

- [[ui:osc.sender]]: 1 件のメッセージを、型付きの引数とともに、Enter を押したときに送信します。
- [[ui:osc.monitor]]: ポートで待ち受け、届いたパケットをすべてデコードします。
- [[ui:osc.generator]]: 波形に沿って変化する値を 1 秒間に何度も送信し、その波形を描画します。

Signal Lab は OSC のエンコードとデコードを自前で行います。送信した内容は、[インスペクター](../tools/inspector.md)にバイト単位でそのまま表示されます。

## メッセージを送信する {#send}

1. [[ui:nav.osc]] を開きます。
2. [[ui:common.target]] に、デバイスの IP アドレスまたはホスト名とポートを入力します。たとえば `127.0.0.1:9000` や `stage-mixer.local:9000` です。
3. [[ui:common.address]] に、デバイスが待ち受けているアドレスを入力します。たとえば `/mixer/fader/1` です。
4. [[ui:common.arguments]] で、各引数の型と値を設定します。引数を増やすには [[ui:common.addArgument]] を押します。✕ で 1 つ削除できます。
5. [[ui:common.send]] を押すか、送信側のどのフィールドでも <kbd>Enter</kbd> を押します。

ボタンの下の行に、送信した内容が表示されます。アドレス、バイト数、宛先です。同じメッセージをもう一度送信すると、回数 (×2、×3…) が増えるので、繰り返しの送信が行われたことがわかります。失敗した場合は、その行とコンソールに表示されます。

宛先、アドレス、引数は、画面を切り替えたりアプリを再起動したりしても保持されます。

### フィールド {#send-fields}

| フィールド | 内容 | 既定値 |
| --- | --- | --- |
| [[ui:common.target]] | 受信側の `IP:port` または `host:port`。IPv6 アドレスは角括弧で囲みます。`[::1]:9000` のようにします。ホスト名は送信のたびに名前解決され、IPv4 アドレスがあればそれを使い (そのため `localhost` は `127.0.0.1` で待ち受ける受信側に届きます)、なければ IPv6 アドレスを使います。ポートのない宛先は拒否されます。 | `127.0.0.1:9000` |
| [[ui:common.address]] | OSC アドレス。`/` で始まり、各パートは `/` で区切ります。先頭に `/` がないアドレスは、何も送信される前に拒否されます。 | `/hello/avatar/1` |
| [[ui:common.arguments]] | アドレスの後ろに順に並ぶ型付きの値。引数のないメッセージも可能です。 | `float` 1 つ、`1.0` |

### 引数の型 {#types}

各引数の型はメッセージの一部 (型タグ) なので、float を期待するデバイスは、同じ値の int を無視することがあります。

| 一覧での型 | OSC タグ | 値 | 入力方法 |
| --- | --- | --- | --- |
| `int` | `i` | 32 ビット符号付き整数 | 整数 |
| `float` | `f` | 32 ビット浮動小数点数 | 数値。`0.75` など |
| `str` | `s` | テキスト | 任意のテキスト。UTF-8 で送信 |
| `bool` | `T` / `F` | 真または偽 | 一覧から `true` か `false` を選ぶ。バイトは持たず、タグだけ |
| `long` | `h` | 64 ビット符号付き整数 | 整数 |
| `double` | `d` | 64 ビット浮動小数点数 | 数値 |
| `nil` | `N` | 何もなし | 値なし |
| `blob` | `b` | バイト列 | ここでは入力しない。blob を含むシグナルを開くと、読み取り専用で hex 表示される |

数値フィールドに数値でないものが入っていると、`0` が送信されます。

::: tip
OSC の `true` は、テキスト `"true"` ではなくタグ `T` です。bool を待っているデバイスは、文字列を黙って無視します。
:::

## バンドル {#bundles}

送信側が送るのは単一のメッセージで、バンドルではありません。バンドル (`#bundle`) が届いた場合、モニター、実験の待機、エミュレーターはそれを展開します。中の各メッセージは個別に処理され、タイムタグは無視されます。

## ポートを監視する {#monitor}

デバイスやショーコントローラーが何を送っているかを確認するには、次のようにします。

1. [[ui:common.bind]] に、待ち受けるアドレスとポートを入力します。既定の `0.0.0.0:9000` はすべてのネットワークカードで待ち受け、`127.0.0.1:9000` はこのマシンでのみ待ち受けます。
2. [[ui:osc.listen]] を押します。モニターの動作中は、フィールドがロックされます。
3. 送信側の宛先を、このマシンの IP アドレスとそのポートにします。

パケットはそれぞれ 1 行になり、新しいものが上に表示されます。

| 列 | 内容 |
| --- | --- |
| [[ui:common.time]] | 届いた時刻。ミリ秒単位 |
| [[ui:osc.from]] | 送信元の `IP:port` |
| [[ui:osc.address]] | OSC アドレス。パケットが有効な OSC でない場合は [[ui:osc.decodeError]] |
| [[ui:osc.args]] | 引数の値。blob は `blob[n]`、`nil` は `nil`、タイムタグは `t:` と 1900 年からの秒数 (OSC の「今すぐ」は `t:immediate`)、char は `'A'`、色は `#rrggbbaa`、MIDI メッセージは `midi[01 90 3c 7f]`、配列は `[ ]` で囲んで表示されます。デコードできなかったパケットでは、その理由が表示されます。 |

バンドルは、メッセージごとに 1 行になります。一覧には最新の 300 行が保持され、[[ui:common.clear]] で空になります。ポートを閉じるには [[ui:common.stop]] を押します。モニターはコンソールの帯にジョブとしても表示されるので、そこから停止することもできます。

モニターは最大 64 KiB のパケットを読み取ります。OSC 1.0 のすべての型タグ `i f s S b h d T F N I t c r m` と配列 `[ ]` をデコードします (`S` はテキスト、`I` は `impulse` として読み取ります)。型タグ文字列のない古い実装のメッセージは、仕様どおり、引数のないメッセージとして読み取ります。それ以外のタグを含むパケット、途中で切れたパケット、アドレスが `/` で始まらないパケットは、破棄されずにデコードエラーとして表示されます。待機とエミュレーターも同じ型を読み取ります。応答の値では、タイムタグは 64 ビットの数値のテキスト、色は `#rrggbbaa`、MIDI メッセージは 4 バイト、配列はリストになります。

### メッセージを待機に変える {#wait-for-this}

各行には ⇠ ボタン [[ui:osc.waitForThis]] があります。これを押すと、開いている実験に [OSC を待機](../experiments/nodes.md#node-wait_osc)ステップが追加されます。このステップは、モニターの [[ui:common.bind]] でこのアドレスを待ち受け、テキスト、整数、真偽値の引数ごとに「等しい」ルールを持ちます。float、blob、nil にはルールが付きません。ルールは最大 16 個です。タイムアウトは 2000 ms です。エディターが開き、新しいステップが選択された状態になります。

::: warning
その実験を実行する前に、モニターを停止してください。実行は同じポートを自分で開くため、2 つのリスナーが同じポートを共有することはできません。
:::

## 波形を送り込む {#generator}

[[ui:osc.generator]] は、1 つのアドレスにメッセージを次々と送ります。引数は 1 つで、その値が波形に沿って変化します。フェーダー、照明の明るさ、位置などを想定しています。変化する値にデバイスがどう追従するかを確認したり、受信側に一定のストリームで負荷をかけたりするのに使います。

1. [[ui:common.target]] と [[ui:osc.address]] を設定します。どちらも、送信側と同じように、[[ui:osc.startGen]] を押したときにチェックされます。
2. [[ui:osc.waveform]]、その [[ui:osc.freq]]、[[ui:osc.rate]] を選びます。
3. 値の範囲となる [[ui:osc.min]] と [[ui:osc.max]] を設定します。
4. [[ui:osc.startGen]] を押します。[[ui:osc.stopGen]] を押すか、コンソールの帯でそのジョブを停止するまで動き続けます。

| フィールド | 内容 | 既定値 |
| --- | --- | --- |
| [[ui:common.target]] | 受信側の `IP:port` または `host:port`。名前はジェネレーターの開始時に一度だけ解決されます | `127.0.0.1:9000` |
| [[ui:osc.address]] | すべてのメッセージの送信先アドレス。`/` で始まります | `/hello/lfo` |
| [[ui:osc.waveform]] | 時間に対する値の形 (下記) | [[ui:wave.sine]] |
| [[ui:osc.freq]] | 波形の 1 秒あたりのサイクル数 | `1` |
| [[ui:osc.rate]] | 1 秒あたりのメッセージ数。0.1 から 5000 まで。範囲外の値はその範囲に収められます | `60` |
| [[ui:osc.min]]、[[ui:osc.max]] | 最低値と最高値。最大が最小より小さいと、値は動きません。 | `0`、`1` |
| [[ui:osc.asInt]] | 最も近い整数に丸め、`float` ではなく `int` として送信します | オフ |

| 波形 | 1 サイクルでの値の動き |
| --- | --- |
| [[ui:wave.sine]] | 最小と最大の間をなめらかに振れます。中間から始まり、上昇します |
| [[ui:wave.triangle]] | 最小から最大へ上昇し、最小へ下降します。最小から始まります |
| [[ui:wave.saw]] | 下降するのこぎり波。最大から始まり、最小まで下降し、最大に戻ります |
| [[ui:wave.ramp]] | 上昇するのこぎり波。最小から始まり、最大まで上昇し、最小に戻ります |
| [[ui:wave.square]] | 前半は最大、後半は最小 |
| [[ui:wave.random]] | メッセージごとに、最小と最大の間の新しいランダムな値。周波数は使いません |
| [[ui:wave.constant]] | 常に最大。周波数は使いません |

### スコープ {#scope}

フィールドの横のスコープには、送信している値が描画されます。最新の 300 点が、収まるようにスケールされて表示されます。その下には、波形、周波数、レート、最後に送信した値があります。スコープの更新は、ジェネレーターの送信速度にかかわらず 1 秒間に約 30 回なので、高いレートでは、すべてのメッセージではなくその一部のサンプルが表示されます。

送信に失敗すると、ジェネレーターは停止し、コンソールに理由が表示されます。

## インスペクターでの表示 {#inspector}

キャプチャを開始している ([[ui:dock.inspector]] の [[ui:ins.arm]]) と、OSC の通信はプロトコル `osc` として表示されます。

| ソース | 内容 | 備考 |
| --- | --- | --- |
| `osc-send` | 送信側、ライブラリのシグナル、[[ui:exp.node.osc]] ステップ、`signallab send osc` が送信したすべてのメッセージ | 応答を待つステップは `experiment` と表示されます |
| `osc-monitor` | モニターが受信したすべてのパケット | バンドルは、最初のメッセージと `+n more in bundle` で要約されます。不正な形式のパケットの判定は `decode error: …` です |
| `osc-gen` | ジェネレーターのメッセージ | キャプチャされるのは 100 ms に最大 1 件で、判定は `sampled` です。スキップされたメッセージのあとの最初の 1 件には、描画されなかった件数が `sampled · +5 not shown` のように付きます |

各フレームは、作成元のバイト列を保持しています。[インスペクター](../tools/inspector.md)を参照してください。

## 保存と再利用 {#library}

- **シグナルとして保存する。** ボタンの下の [[ui:sig.saveNew]] を押すと、メッセージ (宛先、アドレス、引数) が、選んだフォルダーのシグナルライブラリに保存されます。以降、送信側はそのシグナルと結び付きます。[[ui:sig.save]] (または送信側での <kbd>Ctrl</kbd>+<kbd>S</kbd>) で更新、[[ui:sig.saveAs]] でコピーを作成し、横のチップを押すと [[ui:nav.signals]] で開きます。あとで [[ui:nav.signals]] から、またはどの画面からでも <kbd>Ctrl</kbd>+<kbd>K</kbd> で送信できます。[シグナル](../tools/signals.md)を参照してください。
- **実験に追加する。** [[ui:common.toExperiment]] を押すと、同じ宛先、アドレス、引数の [OSC メッセージ](../experiments/nodes.md#node-osc)ステップが、開いている実験の終了の直前か、選択中のステップの後ろに追加され、その実験が開きます。実験の実行中は何も追加できず、そのことがコンソールに表示されます。

## 実験での使い方 {#experiments}

| ステップ | 動作 |
| --- | --- |
| [[ui:exp.node.osc]] | 1 件のメッセージを送信します。宛先、アドレス、テキスト引数には `{{templates}}` が使えます。[[ui:exp.expectReply]] を使うと、専用のポートから送信し、同じステップ内でそこに届く応答を待ちます。[詳細](../experiments/nodes.md#node-osc) |
| [[ui:exp.node.wait_osc]] | アドレスがパターンに一致し、引数がルールを満たすメッセージを待ちます。[詳細](../experiments/nodes.md#node-wait_osc) |
| [[ui:exp.node.emulator]] | 実行全体を通して、ルールに従って応答する OSC デバイスです。[エミュレーター](../tools/emulators.md)を参照してください。 |

OSC メッセージのステップは、画面と同じように `IP:port` または `host:port` を受け付け、アドレスは `/` で始まる必要があります。ホスト名は、ステップが送信するたびに名前解決されます。

### アドレスパターン {#patterns}

[[ui:exp.node.wait_osc]]、[[ui:exp.node.osc]] の応答、OSC エミュレーターのルールは、OSC 1.0 のパターンでアドレスを照合します。

| パターン | 一致するもの |
| --- | --- |
| `*` | 任意の文字列。空でもかまいません |
| `?` | ちょうど 1 文字 |
| `[0-9]`、`[a-c]` | 集合または範囲に含まれる 1 文字 |
| `[!0-9]` | 集合に含まれない 1 文字 |
| `{ping,pong}` | 列挙した単語のいずれか |

ワイルドカードは、スラッシュで区切られた 1 つのパートの中にとどまります。`/cue/*` は `/cue/7` には一致しますが `/cue/7/go` には一致せず、パターンは同じ数のパートを持つアドレスにだけ一致します。大文字と小文字は区別されます。パターンは `/` で始まり、空のパート (`//`) を含まず、スペースも `#` も ASCII 以外の文字も含まず、512 文字までです。

引数のルールは、0 から 63 番の引数を値と比較します (等しい、より小さい、含む、正規表現に一致する、など)。1 つの待機に付けられるルールは最大 16 個です。バンドルが届いた場合、待機は、中のいずれかのメッセージが一致すればそれを受け取ります。一致したメッセージが後続のステップに何を渡すかは、[データとテンプレート](../experiments/data.md)を参照してください。

## コマンドラインから {#cli}

`signallab send osc` は、送信側と同じように 1 件のメッセージを送信します。

```bash
signallab send osc 127.0.0.1:9000 /cue/go f:0.75 s:main
```

```text
✔ sent /cue/go (24 bytes) → 127.0.0.1:9000
```

各引数は `tag:value` です。`i:3`、`f:0.5`、`d:1.5`、`h:64`、`s:text`、`b:de ad be ef` (hex バイト列)、または単独の `T`、`F`、`N` を使います。タグがない場合、整数は `i`、小数点のある数値は `f`、それ以外は `s` になります。テキストの `7` を送るには `s:7` と書きます。宛先は `IP:port` または `host:port` です。終了コードは、メッセージを送信できたときは 0、送信に失敗したとき (名前解決できないホスト名を含む) は 1、引数、アドレス、宛先のいずれかが無効なときは 2 です。[`signallab fire`](../automation/cli.md#cli-fire) は、保存したシグナルを送信します。[コマンドライン](../automation/cli.md#cli-send-osc)を参照してください。

::: tip
Windows の Git Bash では、`/` で始まる引数は、`signallab` に渡される前にファイルパスに変換されます。コマンドの前に `MSYS_NO_PATHCONV=1` を付けて実行するか、PowerShell または `cmd` を使ってください。
:::

## 問題が起きたとき {#troubleshooting}

| 表示される内容 | よくある原因 |
| --- | --- |
| 送信時の `… is not a valid address` | 宛先にポートがないか、`IP:port` でも `host:port` でもありません。 |
| 送信時の `Cannot resolve …` | このマシンでホスト名を名前解決できません。ホスト名を確認するか、IP アドレスを使ってください。 |
| `OSC addresses start with / (…)` | アドレスの先頭に `/` がありません。 |
| メッセージは送信されるが、デバイスが反応しない | ポートかアドレスが違うか、デバイスが期待する型と異なります (`float` の代わりに `int`、bool の代わりにテキストの `"true"`)。インスペクターで確認するか、宛先をこのマシンのモニターに向けて、何が送信されているか確認してください。 |
| [[ui:osc.listen]] 時の `… is already in use by another program` | ほかのプログラム、または実行中の実験、エミュレーター、2 つ目のモニターがそのポートを使っています。 |
| `… is not an address of this computer` | [[ui:common.bind]] の IP が別のマシンのものです。`0.0.0.0` か、このマシンのアドレスを使ってください。 |
| 他のマシンからのパケットがまったく届かない | Windows では、ファイアウォールが遮断していることがあります。アプリが許可を提案したら、Signal Lab を許可してください。ローカルの通信 (`127.0.0.1`) には影響しません。[トラブルシューティング](../reference/troubleshooting.md)を参照してください。 |
| [[ui:osc.decodeError]] の行 | 送信側がそのポートで OSC 1.0 を話していないか、Signal Lab がデコードしない型タグを使っています。 |

サーバーでは、画面はサーバーのネットワーク上で動作します。`127.0.0.1` はサーバー自身で、モニターはサーバーのポートで待ち受けます。[サーバー](../server/index.md)を参照してください。

すべてのエラーメッセージは[エラーメッセージ](../reference/errors.md#transport)に一覧があります。
