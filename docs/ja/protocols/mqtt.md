# MQTT

[[ui:nav.mqtt]] 画面は、ブローカーの中身を確認し、変更するための MQTT クライアントです。接続すると、既定では `#` をサブスクライブし、ブローカーが保持しているすべてのトピックが、最新の値とともにツリーに積み上がっていきます。そこから、パブリッシュしたり、保持値を消去したり、トピックをシグナルとして保存したり、実験のステップにしたりできます。

Signal Lab が話すのは、**プレーン TCP 上の MQTT 3.1.1** で、サブスクライブ、パブリッシュ、Will メッセージのいずれも QoS 0、1、2 に対応しています。MQTT 5 と TLS には対応していません。`mqtts://` や MQTT 5 のクライアントしか受け付けないブローカーには接続できません。

## 接続する {#connect}

1. [[ui:nav.mqtt]] を開きます。
2. [[ui:mq.host]] と [[ui:common.port]] を入力します。
3. ブローカーが特定の ID を求める場合を除き、[[ui:mq.clientId]] はそのままにします。[[ui:mq.username]] と [[ui:mq.password]] は、ブローカーが求める場合にだけ入力します。
4. [[ui:mq.connect]] を押します。

接続では、まず TCP 接続を開き、MQTT のハンドシェイクを完了します。そのため、パスワードの誤りやポートが閉じていることは、その場で報告されます。接続中は接続のフィールドがロックされ、[[ui:mq.disconnect]] で閉じます。接続はコンソールの帯にジョブとして表示され、そこから停止することもできます。

| フィールド | 内容 | 既定値 |
| --- | --- | --- |
| [[ui:mq.host]] | ブローカーの IP アドレスまたはホスト名 | `127.0.0.1` |
| [[ui:common.port]] | ブローカーのポート | `1883` |
| [[ui:mq.clientId]] | ブローカー上でのこのクライアントの名前。空にはできず、ブローカー内で一意である必要があります。同じ ID の 2 つ目のクライアントが接続すると、最初のクライアントは切断されます。 | `signal-lab-` と 16 進数 6 桁のランダムな値。アプリの起動のたびに新しくなります |
| [[ui:mq.username]]、[[ui:mq.password]] | ブローカーが必要とする場合にだけ送信します。TLS がないので、プレーンテキストです。ユーザー名のないパスワードはまったく送信されません。MQTT 3.1.1 では送れないためです。 | 空 |
| [[ui:mq.keepAlive]] | 接続が無通信のままでいられる秒数。Signal Lab はその半分の間隔でブローカーに ping を送ります。ブローカーは、この 1.5 倍の時間無通信のクライアントを切断し、Signal Lab も、ブローカーが ping に対してさえこの 1.5 倍の時間何も返さなければ、接続を終了します (「No answer from … in time」)。0 にすると ping を送りません。 | `60` |
| [[ui:mq.cleanSession]] | オンの場合、接続のたびに、保存されたサブスクリプションもキューに溜まったメッセージもない状態で始まります。オフの場合は、この ID のために、それらを接続の間も保持するようブローカーに求めます。 | オン |
| [[ui:mq.scanFilter]] とその [[ui:mq.qos]] | 接続が確立した時点ですぐにサブスクライブするフィルター。`#` はすべてのトピックです。空の場合は何もサブスクライブしません。 | `#`、QoS 0 |
| [[ui:mq.willEnable]] | ブローカーに Will メッセージ ([後述](#will)) を預ける | オフ |

ブローカーには、TCP 接続を受け付けるまで 6 秒、ハンドシェイクに応答するまでさらに 6 秒が与えられます。

### Will メッセージ {#will}

Will メッセージは、ブローカーが預かり、接続が正常な別れの挨拶なしに切れたときにブローカー自身がパブリッシュするメッセージです。プレゼンス (存在の通知) は、たいていこの方法で作られます。デバイスが自分のステータスのトピックに `online` をパブリッシュし、その Will メッセージが同じトピックを `off` にします。

[[ui:mq.willEnable]] にチェックを入れたら、[[ui:mq.willTopic]] と [[ui:mq.willPayload]] (既定は `off`) を設定します。Will メッセージは QoS 2 で、retain 付きでパブリッシュされます。トピックがなければ、Will メッセージは送信されません。

## サブスクライブする {#subscribe}

スキャンフィルターは、接続時にサブスクライブされます。さらに追加するには、次のようにします。

1. [[ui:mq.addSubscription]] に、トピックフィルターを入力します。
2. その [[ui:mq.qos]] を選びます。
3. [[ui:mq.subscribe]] を押すか、<kbd>Enter</kbd> を押します。

フィルターは、ワイルドカードを使ったトピックです。

| ワイルドカード | 意味 | 例 |
| --- | --- | --- |
| `+` | ちょうど 1 階層 | `sensors/+/state` は `sensors/door/state` に一致します |
| `#` | 以下のすべての階層。最後の文字にだけ使えます | `sensors/#` は `sensors/door/state` と `sensors` に一致します |

[[ui:mq.subscriptions]] には、各フィルターと、ブローカーが許可した内容が一覧表示されます。`qos0`、`qos1`、`qos2` (ブローカーは、要求より低いレベルを許可することがあります)、または [[ui:mq.refused]] です。[[ui:mq.unsubscribe]] を押すと、そのサブスクリプションが解除されます。

| QoS | 配信 |
| --- | --- |
| 0 | 多くても 1 回。送信したら終わり |
| 1 | 少なくとも 1 回。確認応答があり、2 回届くことがあります |
| 2 | ちょうど 1 回。2 段階のハンドシェイクで、再配信は 2 回表示されません |

## トピックツリー {#topics}

届いたメッセージはすべて [[ui:mq.topics]] に入ります。トピックの階層を表したツリーです。トピックには、最新の値、その値が保持されたものであれば **R**、メッセージが 2 件以上あればその件数が表示されます。階層をクリックすると、開閉します。

- ツリーの上のフィールドに入力すると、パスまたは最新の値にそのテキストを含むトピックだけが一覧表示されます。
- ツリーの上には、トピックの数、保持値を持つトピックの数、接続中であれば待ち受け中のブローカーが表示されます。
- ペイロードはテキストとして表示されます。UTF-8 でないバイトは置換文字で表示されます。4 KB を超えるペイロードは、先頭部分と全体のサイズが表示されます。切り詰めたものが送信されてしまうため、[[ui:mq.publish]] にコピーしたり、シグナルとして保存したりはできません。
- [[ui:common.clear]] を押すと、ツリーが空になります。それ以外の操作では空になりません。画面を切り替えたり切断したりしても、アプリを閉じるまでそのまま残ります。

メッセージは、1 秒に 10 回、まとめて画面に届きます。それぞれのまとめには、メッセージがあったトピックごとの最新のメッセージと、その件数が入ります。そのため、少数のトピックに大量のメッセージが届いても何も失われず、件数はすべて正確です。まとめがいっぱいになると (4000 トピック、またはペイロード 2 MB。`#` をサブスクライブしたときにブローカーの保持値が届く場合がこれにあたります)、接続はそれを送り出してから先を読み込むので、ブローカーが待つことになり、一度しか送られないトピックを取りこぼすことはありません。ツリーが保持できるトピックは最大 100,000 個で、それを超えるトピックのメッセージは、ツリーの上で「非表示」として数えられます。

### トピックのパネル {#topic}

値を持つトピックを選ぶと、ツリーの下にその内容が表示されます。[[ui:mq.value]]、[[ui:mq.qos]]、[[ui:mq.retain]]、[[ui:common.bytes]]、[[ui:mq.messages]]、[[ui:mq.lastAt]] です。ボタンは次のとおりです。

| ボタン | 動作 |
| --- | --- |
| [[ui:mq.editHere]] | トピック、値、QoS、retain フラグを [[ui:mq.publish]] にコピーします |
| [[ui:mq.waitForThis]] | このトピック、このブローカー、任意のペイロード、タイムアウト 2000 ms の [MQTT を待機](../experiments/nodes.md#node-wait_mqtt)ステップを、開いている実験に追加します |
| [[ui:mq.clearRetained]] | 保持値を削除します ([後述](#clear-retained)) |
| [[ui:sig.fromFrame]] | トピックとその最新の値を、[[ui:sig.capturedFolder]] フォルダーのシグナルとして保存します |

## パブリッシュする {#publish}

1. 接続します。
2. [[ui:mq.publish]] で、[[ui:mq.topic]] と [[ui:sig.payload]] を入力します。
3. [[ui:mq.qos]] を選びます。あとからサブスクライブするすべてのクライアントに対して、ブローカーがそのメッセージをトピックの値として保持するようにするには、[[ui:mq.retain]] にチェックを入れます。
4. [[ui:mq.publishBtn]] を押します。

パブリッシュのたびに、コンソールに確認が表示されます。QoS 0 では即座に、QoS 1 と 2 ではブローカーが確認応答を返したときです。パブリッシュ先のトピックは、ワイルドカードを含まず、空でもない必要があります。`+` や `#` を含むトピックは、何も送信される前に、シグナル、ステップ、`signallab send mqtt` と同じメッセージで拒否され、接続はそのままです。ワイルドカード付きのフィルターを受け付けるのは、サブスクリプションだけです。

### 保持値を消去する {#clear-retained}

保持値は、置き換えられるまでブローカーに残り、サブスクライブしたクライアントには必ず最初に配信されます。古い保持値は、デバイスが誤った状態で起動する典型的な原因です。それを削除する方法は、retain を付けて空のペイロードをパブリッシュすることだけです。

トピックのパネルの [[ui:mq.clearRetained]] がそれを行います。押したあとに [[ui:mq.clearConfirm]] を押します。接続を使って、QoS 1 で、retain 付きの空のペイロードをパブリッシュします。これが使えるのは、接続中で、トピックの最新の値が保持値であるときだけです。手動でも同じことができます。[[ui:sig.payload]] を空にして、[[ui:mq.retain]] にチェックを入れます。

::: warning
消去すると、すべてのクライアントに対して一度にブローカーが変更されます。
:::

## インスペクターでの表示 {#inspector}

キャプチャを開始していると、MQTT の通信は、プロトコル `mqtt` として表示されます。

| ソース | 内容 | 件数 |
| --- | --- | --- |
| `mqtt` | この画面の接続がパブリッシュしたもの。空の保持パブリッシュの判定は `clears retained` です | すべて |
| `mqtt` | 接続が受信したメッセージ | 200 ms に最大 1 件 |
| `mqtt-send` | 専用の接続を持ってきたパブリッシュ。この画面がシグナルのブローカーに接続していないときに送信したシグナル、ステップ、`signallab send mqtt` (判定は `one-shot`) | すべて |
| `experiment-wait` | [[ui:exp.node.wait_mqtt]] ステップのサブスクリプションが受信したメッセージ。保持値の再送を除く | すべて |

概要は `topic = payload` の形式で、該当する場合は QoS と `retained` が付きます。[インスペクター](../tools/inspector.md)を参照してください。

## 保存と再利用 {#library}

- **シグナルとして保存する。** [[ui:mq.publish]] の下の [[ui:sig.saveNew]] を押すと、ブローカー (接続の [[ui:mq.host]] と [[ui:common.port]])、トピック、ペイロード、QoS、retain フラグがシグナルライブラリに保存されます。パブリッシュのパネルで <kbd>Ctrl</kbd>+<kbd>S</kbd> を押しても同じで、パネルがシグナルと結び付いていれば、そのシグナルが更新されます。[シグナル](../tools/signals.md)を参照してください。
- **MQTT シグナルを送信する。** この画面が、シグナルの指すブローカー (ホストは大文字と小文字を区別せず、ポートも同じ。シグナルにポートがなければ `1883`) に接続している間は、ライブラリから送信したシグナルは、その接続を通して、その接続のクライアント ID と認証情報で送信されます。そうでない場合 (未接続、または別のブローカーに接続中) は、シグナルのブローカーへの専用の接続を開き (新しいクライアント ID、ユーザー名なし)、パブリッシュし、その QoS が求める確認応答を待ち、切断します。名前の解決は行わないため、`localhost` と `127.0.0.1` は別のブローカーとして扱われます。ライブラリにパスワードは保存されません。
- **実験で使う。** 保存した MQTT シグナルは、実験の [[ui:exp.addNode]] メニューの [[ui:exp.group.signals]] から選べます。選ぶと、[[ui:exp.node.mqtt]] ステップになります。

## 実験での使い方 {#experiments}

| ステップ | 動作 |
| --- | --- |
| [[ui:exp.node.mqtt]] | 接続し、1 件のメッセージをパブリッシュし、切断します。ユーザー名とパスワードなし、クリーンセッション、15 秒以内です。[詳細](../experiments/nodes.md#node-mqtt) |
| [[ui:exp.node.wait_mqtt]] | 実行の開始時にサブスクライブし、トピックフィルターに対して、ペイロードが一致するメッセージを待ちます。サブスクライブ時に再送される保持値は無視されます。[詳細](../experiments/nodes.md#node-wait_mqtt) |
| [[ui:exp.node.emulator]] | 実行専用の MQTT ブローカーです。[詳細](../experiments/nodes.md#node-emulator) |

どちらのステップもログインしないため、ユーザー名なしでクライアントを受け付けるブローカーが必要です。

### ブローカーのエミュレーター {#broker-emulator}

Signal Lab はブローカーにもなれます。[[ui:emu.new.mqtt]] エミュレーターは、クライアントがパブリッシュしたものを、サブスクライブしている相手にルーティングします。3.1.1、プレーン TCP、QoS 0、1、2、保持メッセージ、Will メッセージ、任意のログインに対応し、デバイスのようにルールで応答します。実際のブローカーなしでテストするには、機器とこの画面の向き先をこのエミュレーターにします。[エミュレーター](../tools/emulators.md)を参照してください。

## コマンドラインから {#cli}

`signallab send mqtt` は、専用の接続で 1 件のメッセージをパブリッシュします。

```bash
signallab send mqtt 127.0.0.1:1883 lab/light/1/set on --qos 1
signallab send mqtt 127.0.0.1:1883 lab/light/1/state "" --retain
```

```text
✔ lab/light/1/set → 127.0.0.1:1883 · 2 B · qos1
```

2 行目は、保持値を消去します。ポートを省略すると、ブローカーは 1883 にあるものとして扱われます。認証情報は使いません。終了コードは、ブローカーがメッセージを受け取ったときは 0、ブローカーに到達できなかったとき、または拒否されたときは 1 です。[コマンドライン](../automation/cli.md#cli-send-mqtt)を参照してください。

## 問題が起きたとき {#troubleshooting}

| 表示される内容 | よくある原因 |
| --- | --- |
| `… refused the connection — nothing is listening on that port` | そのアドレスとポートにブローカーがありません。 |
| `… accepted the connection but did not answer in time — is it an MQTT broker?` | そこで待ち受けているものはありますが、MQTT を話していないか、TLS で話しています。 |
| `… answered with something other than MQTT 3.1.1` | MQTT ブローカーではないか、Signal Lab が読み取れないものを送ってきたブローカーです。 |
| `… does not accept MQTT 3.1.1 clients` | そのブローカーは MQTT 5 しか受け付けません。 |
| `… rejected the client ID — choose another one` | ID が長すぎるか、ブローカーが受け付けない文字を含んでいます。 |
| `… rejected the username or password` | 認証情報が間違っているか、ユーザー名のないパスワードです。 |
| `… did not authorize this client — check its access rules` | ブローカーのアクセスルールが、このクライアントを拒否しています。 |
| `… is unavailable right now — try again later` | ブローカーは動いていますが、クライアントを受け付けていません。 |
| `Enter a client ID — brokers refuse an empty one` | [[ui:mq.clientId]] が空です。 |
| `A publish topic cannot contain the wildcards + or #` | パブリッシュ先のトピックに `+` または `#` が含まれています。それらはサブスクライブ用です。パブリッシュは 1 つのトピックずつ行ってください。 |
| フィルターに [[ui:mq.refused]] と表示される | ブローカーのアクセスルールが禁止しています。形式が不正なフィルター (`#` が最後にない、`+` が階層内でほかの文字と同居している) は、送信前に拒否されます。ブローカーはそのようなフィルター 1 つで接続全体を閉じてしまうためです。 |
| 接続した直後に切断される | 同じ [[ui:mq.clientId]] で別のクライアントが接続しました。 |
| ツリーに何も表示されない | スキャンフィルターが空か、ブローカーがこのクライアントに何も見せません。 |

すべてのエラーメッセージは[エラーメッセージ](../reference/errors.md#mqtt)に一覧があります。
