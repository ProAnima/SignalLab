# एमुलेटर

एमुलेटर में Signal Lab उस API, डिवाइस या सेवा की भूमिका निभाता है जिससे आपका सिस्टम बात करता
है। यह एक पते पर सुनता है और नियमों से जवाब देता है: HTTP API रूट के ज़रिए, OSC, UDP या TCP
डिवाइस “यह आए तो वह जवाब दो” के ज़रिए, और MQTT ब्रोकर किसी भी ब्रोकर की तरह, साथ में अपने
नियमों के साथ। यह धीमा हो सकता है, विफल हो सकता है, या बीच-बीच में बंद हो सकता है, ताकि आप टेस्ट
कर सकें कि अपनी डिपेंडेंसी के गड़बड़ करने पर आपका सिस्टम क्या करता है। हर आदान-प्रदान गिना जाता
है, सूची में आता है और [इंस्पेक्टर](inspector.md) में भेजा जाता है।

एमुलेटर एक दस्तावेज़ है। [[ui:nav.emulators]] स्क्रीन इनकी एक लाइब्रेरी रखती है; वही दस्तावेज़
किसी प्रयोग के भीतर [[ui:exp.node.emulator]] नोड के रूप में, कमांड लाइन से `signallab emulate`
के साथ, और [API](../api/commands.md) तथा [MCP](../automation/mcp.md) के ज़रिए चलता है, और हर
जगह एक ही तरह जवाब देता है।

## स्क्रीन {#screen}

बाईं ओर लाइब्रेरी ([[ui:emu.library]]) है: हर एमुलेटर अपने प्रोटोकॉल और पते के साथ, और चल रहे
एमुलेटर पर धड़कता बिंदु और रिक्वेस्ट की गिनती। दाईं ओर चुने गए एमुलेटर की सेटिंग्स और नियम हैं,
और उनके नीचे वह जो उसे प्राप्त हुआ ([[ui:emu.live]])।

## एमुलेटर बनाना {#create}

1. लाइब्रेरी के ऊपर के बटनों में से एक दबाएँ:

   | बटन | क्या बनाता है | कहाँ सुनता है | एक नियम के साथ, जो जैसा है वैसा ही काम करता है |
   | --- | --- | --- | --- |
   | ＋ [[ui:emu.new.http]] | HTTP API | `127.0.0.1:18080` | `GET /health` → 200 `{"status":"ok"}` |
   | ＋ [[ui:emu.new.osc]] | OSC डिवाइस | `127.0.0.1:9100` | `/ping` → `/pong`, गिनती int के रूप में |
   | ＋ [[ui:emu.new.udp]] | UDP डिवाइस | `127.0.0.1:7100` | `PING` वाला डेटाग्राम → `PONG 1`, `PONG 2`, … |
   | ＋ [[ui:emu.new.tcp]] | TCP डिवाइस | `127.0.0.1:7200` | `PING` वाली पंक्ति → `PONG` |
   | ＋ [[ui:emu.new.mqtt]] | MQTT ब्रोकर | `127.0.0.1:1883` | `lab/<name>/set` पर पब्लिश → वही पेलोड, retained, `lab/<name>/state` पर |

   अगर लाइब्रेरी का कोई दूसरा एमुलेटर वह पोर्ट पहले से उपयोग करता है, तो अगला ख़ाली पोर्ट लिया
   जाता है।
2. इसे [[ui:emu.name]] दें (अधिकतम 120 अक्षर)।
3. [[ui:emu.bind]] सेट करें: `IP:port`। `127.0.0.1` केवल इसी कंप्यूटर को जवाब देता है;
   `0.0.0.0` नेटवर्क को भी।
4. नियम बदलें (नीचे देखें), और [[ui:emu.note]] में लिखें कि यह किसकी जगह ले रहा है।

बदलाव अपने आप सहेजे जाते हैं। [[ui:emu.duplicate]] अगले ख़ाली पोर्ट पर एक कॉपी बनाता है।
[[ui:emu.delete]] एक बार और पूछता है ([[ui:emu.confirmDelete]]), एमुलेटर चल रहा हो तो उसे रोकता
है, और उसे लाइब्रेरी से हटा देता है।

नियम क्रम से, पहले से अंतिम तक, आज़माए जाते हैं; जो पहला मेल खाता है, वही जवाब देता है। हर नियम
के हेडर में एक पंक्ति का सारांश दिखता है; नियम खोलने या समेटने के लिए उस पर क्लिक करें। ↑ और ↓
बटन नियम को ऊपर-नीचे करते हैं, × उसे हटाता है।

## इसे चलाना {#run}

1. एमुलेटर चुनें और [[ui:emu.start]] दबाएँ। बटन के लौटने से पहले उसका पोर्ट खुल जाता है: पहले से
   लिया गया पोर्ट, या किसी समस्या वाला एमुलेटर, वहीं वजह के साथ अस्वीकार कर दिया जाता है।
2. अपने सिस्टम को इसकी ओर मोड़ें। HTTP API के लिए [[ui:emu.copyUrl]] उसका पता
   (`http://127.0.0.1:18080`) कॉपी करता है, और हर रूट का अपना पता कॉपी करने के लिए एक
   [[ui:emu.copyRouteUrl]] बटन होता है (तब नहीं, जब उसके पाथ में `{{…}}` टेम्पलेट हो)।
3. [[ui:emu.received]] को भरते देखें।
4. [[ui:emu.stop]] दबाएँ, या कंसोल पट्टी से इसका जॉब रोकें।

बटनों के पास की स्थिति बताती है: [[ui:emu.notRunning]], यह कहाँ जवाब देता है, या यह कि यह बंद है।

एमुलेटर उन्हीं नियमों से जवाब देता रहता है जिनके साथ उसे शुरू किया गया था। चलते समय उसे बदलने पर
[[ui:emu.restart]] दिखता है: नियम अब जैसे हैं, उनके साथ फिर से शुरू करने के लिए इसे दबाएँ। तब तक
नियमों पर मिलान की गिनती छिपी रहती है, क्योंकि वह पुराने नियमों की है।

[[ui:emu.takeDown]] चल रहे एमुलेटर को तब तक अनुपलब्ध कर देता है, जब तक आप [[ui:emu.bringUp]] न
दबाएँ: HTTP रिक्वेस्ट को 503 मिलता है, TCP डिवाइस और MQTT ब्रोकर अपने कनेक्शन तोड़ देते हैं और नए
अस्वीकार करते हैं, OSC या UDP डिवाइस कोई जवाब नहीं देता। देखें [बंद होना](#outage)।

एक ही ट्रांसपोर्ट के दो एमुलेटर एक पोर्ट साझा नहीं कर सकते: HTTP, TCP और MQTT एमुलेटर TCP पोर्ट
पर सुनते हैं, OSC और UDP एमुलेटर UDP पोर्ट पर। HTTP API और OSC डिवाइस दोनों पोर्ट 8080 उपयोग कर
सकते हैं; दो HTTP API नहीं। लिए गए पोर्ट पर दूसरा एमुलेटर शुरू होते समय अस्वीकार कर दिया जाता है।

::: tip
[सर्वर](../server/index.md) से जुड़े ब्राउज़र में एमुलेटर सर्वर पर चलता है। `0.0.0.0` पर सुनने
वाले एमुलेटर तक सर्वर के नाम से पहुँचा जाता है, और [[ui:emu.copyUrl]] वही पता कॉपी करता है;
`127.0.0.1` वाला केवल सर्वर पर ही चल रहे प्रोग्राम को जवाब देता है।
:::

## क्या आया {#received}

चलते समय [[ui:emu.live]] गिनता है:

| गिनती | क्या |
| --- | --- |
| [[ui:emu.total]] | जो कुछ भी आया: रिक्वेस्ट, संदेश, पंक्तियाँ। |
| [[ui:emu.unmatched]] | जिसे किसी नियम ने नहीं लिया। बिना रूट वाली HTTP रिक्वेस्ट को फिर भी जवाब मिलता है (देखें [वे रिक्वेस्ट, जिन्हें कोई रूट नहीं लेता](#fallback)); बाकी को कुछ नहीं मिलता। |
| [[ui:emu.failed]] | वे आदान-प्रदान जिनमें जवाब बनाया या भेजा नहीं जा सका। |
| [[ui:emu.down]] | जो एमुलेटर के बंद रहते आया। तब दिखता है, जब उस पर आउटेज सेट हो या कुछ उसे बंद हालत में मिला हो। इसे कभी [[ui:emu.unmatched]] में नहीं गिना जाता। |
| [[ui:emu.missed]] | केवल MQTT, जब ऐसा हो: वे संदेश जिन्हें लेने में कोई क्लाइंट बहुत पीछे रह गया। |

हर नियम का हेडर दिखाता है कि शुरू से अब तक वह कितनी बार मेल खाया।

[[ui:emu.received]] नवीनतम 300 आदान-प्रदान दिखाता है, सबसे नया सबसे ऊपर:

| कॉलम | क्या |
| --- | --- |
| [[ui:emu.col.time]] | यह कब आया। |
| [[ui:emu.col.from]] | क्लाइंट का पता। |
| [[ui:emu.col.request]] | क्या आया, प्रोटोकॉल नोटेशन में: `GET /users/7`, `/ping 1`, `POWER?`। |
| [[ui:emu.col.rule]] | वह नियम जिसने इसे लिया (`#2`), या `—`। |
| [[ui:emu.col.reply]] | क्या वापस गया: `200 OK · 37 B`, `/pong 3`, कोई पेलोड; फ़ॉल्ट के लिए [[ui:emu.held]] या [[ui:emu.closed]]; जवाब विफल होने पर त्रुटि; बंद रहते आने पर [[ui:emu.wasDown]]। |
| [[ui:emu.col.ms]] | आने से लेकर जवाब निकलने तक, उसका विलंब मिलाकर। |

किसी पंक्ति का ⌕ बटन ([[ui:emu.inspectFrame]]) उस आदान-प्रदान को इंस्पेक्टर में खोलता है, अगर
कैप्चर चालू था। जब सेकंड के पाँचवें हिस्से में 200 से ज़्यादा आदान-प्रदान आते हैं, तो सूची कुछ को
छोड़ देती है और बताती है कि कितने। इंजन हर चल रहे एमुलेटर के नवीनतम 500 आदान-प्रदान, जो आया उसके
साथ, कमांड लाइन, API और MCP के लिए रखता है।

## HTTP API {#http}

एक HTTP/1.1 सर्वर। हर रिक्वेस्ट का जवाब वह पहला रूट देता है जो उसे लेता है।

### रूट {#routes}

रूट किसी रिक्वेस्ट को तब लेता है, जब उसका मेथड, उसका पाथ और उसकी सभी शर्तें मेल खाती हैं।

| फ़ील्ड | क्या |
| --- | --- |
| [[ui:emu.method]] | `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS`, या [[ui:emu.methodAny]]। `GET` रूट `HEAD` का भी जवाब देता है। |
| [[ui:emu.path]] | `/` से शुरू होता है। `:name` सेगमेंट कोई भी एक सेगमेंट लेता है, जिसे `{{request.params.name}}` के रूप में पढ़ा जाता है; अंतिम सेगमेंट `*` उसके नीचे का सब कुछ लेता है। अंत का `/` कोई फ़र्क नहीं डालता; क्वेरी स्ट्रिंग पाथ का हिस्सा नहीं है। |
| [[ui:emu.conditions]] | हर एक पूरी होनी चाहिए। ＋ [[ui:emu.addCondition]] से एक जोड़ें। |

पाथ के उदाहरण:

| पाथ | लेता है | नहीं लेता |
| --- | --- | --- |
| `/health` | `/health`, `/health/` | `/health/db`, `/Health` |
| `/users/:id` | `/users/7` (`params.id` है `7`), `/users/a%20b` (`a b`) | `/users`, `/users/7/orders` |
| `/files/*` | `/files`, `/files/a`, `/files/a/b/c` | `/file`, `/other/files/a` |

शर्त रिक्वेस्ट का एक हिस्सा पढ़ती है ([[ui:emu.on]]) और उसकी तुलना करती है:

| [[ui:emu.on]] | नाम | क्या पढ़ती है |
| --- | --- | --- |
| [[ui:emu.on.header]] | हेडर का नाम, किसी भी केस में | हेडर का मान; कई बार भेजे गए हेडर के मान `, ` से जोड़कर। |
| [[ui:emu.on.query]] | क्वेरी पैरामीटर | उसका मान, डिकोड करके; दोहराए जाने पर पहला। |
| [[ui:emu.on.body]] | — | पूरी बॉडी, टेक्स्ट के रूप में। |
| [[ui:emu.on.json]] | JSON पाथ, जैसे `$.user.id` | JSON बॉडी का वह फ़ील्ड। |

तुलना के विकल्प हैं: [[ui:exp.op.eq]], [[ui:exp.op.ne]], [[ui:exp.op.lt]],
[[ui:exp.op.le]], [[ui:exp.op.gt]], [[ui:exp.op.ge]], [[ui:exp.op.contains]],
[[ui:exp.op.matches]], [[ui:exp.op.empty]] और [[ui:exp.op.not_empty]]। संख्याओं की तुलना संख्या
के रूप में होती है, टेक्स्ट की ठीक-ठीक। जो हेडर, पैरामीटर या फ़ील्ड मौजूद नहीं है, वह ख़ाली माना
जाता है। जो तुलना की ही नहीं जा सकती — टेक्स्ट की संख्या से — वह पूरी नहीं होती।

### रिस्पॉन्स {#responses}

रूट में एक से 16 तक रिस्पॉन्स ([[ui:emu.responses]]) होते हैं।

| फ़ील्ड | क्या | डिफ़ॉल्ट |
| --- | --- | --- |
| [[ui:emu.status]] | 100–599। | 200 |
| [[ui:emu.fault]] | जवाब के बजाय कुछ और; देखें [फ़ॉल्ट](#faults)। | [[ui:emu.fault.none]] |
| [[ui:emu.delay]] | जवाब देने से पहले कितनी देर प्रतीक्षा करनी है, 0–60,000 ms। | 0 |
| [[ui:emu.jitter]] | रैंडम रूप से इतना तक और देर, 0–60,000 ms। | 0 |
| [[ui:emu.weight]] | जब रूट रैंडम रूप से जवाब देता है, तब इसका हिस्सा। केवल तभी दिखता है। | 1 |
| [[ui:emu.headers]] | अधिकतम 32। नामों में पैरामीटर हो सकते हैं; मान [टेम्पलेट](#templates) होते हैं। | कोई नहीं |
| [[ui:emu.body]] | एक [टेम्पलेट](#templates), लिखे गए रूप में अधिकतम 256 KiB। | ख़ाली |

`Content-Type` हेडर के बिना, जो बॉडी वैध JSON है वह `application/json` के रूप में जाती है और बाकी
हर बॉडी `text/plain; charset=utf-8` के रूप में।

दो या अधिक रिस्पॉन्स होने पर [[ui:emu.order]] तय करता है कि रिक्वेस्ट को कौन-सा मिले:

| [[ui:emu.order]] | रिक्वेस्ट को मिलता है | किसके लिए |
| --- | --- | --- |
| [[ui:emu.order.sequence]] | पहला, दूसरा, …, फिर उसके बाद हमेशा अंतिम: 500, 500, 200, 200, 200… | दोबारा प्रयास: दो बार विफल, फिर सफल। |
| [[ui:emu.order.cycle]] | अंतिम के बाद फिर से पहला: 200, 500, 200, 500… | ऐसी डिपेंडेंसी जो नियमित रूप से बीच-बीच में विफल होती है। |
| [[ui:emu.order.random]] | हर एक उसके वज़न के अनुसार चुना जाता है। वज़न 8 और 2 होने पर पहला लगभग 80 % बार मिलता है। कम से कम एक वज़न 0 से अधिक होना चाहिए। | विफलताओं का यथार्थवादी हिस्सा। |

[[ui:emu.preset]] रूट में एक तैयार रिस्पॉन्स जोड़ता है:

| प्रीसेट | क्या जोड़ता है |
| --- | --- |
| [[ui:emu.preset.ok]] | 200, `{"ok":true}` |
| [[ui:emu.preset.created]] | 201, `{"id":"{{uuid}}"}`, हेडर `Location: {{request.path}}/{{counter}}` |
| [[ui:emu.preset.notFound]] | 404, `{"error":"not found"}` |
| [[ui:emu.preset.error]] | 500, `{"error":"internal"}` |
| [[ui:emu.preset.unavailable]] | 503, `{"error":"unavailable"}`, हेडर `Retry-After: 1` |
| [[ui:emu.preset.slow]] | 200, `{"ok":true}`, 2000 ms बाद |
| [[ui:emu.preset.timeout]] | फ़ॉल्ट [[ui:emu.fault.timeout]] |
| [[ui:emu.preset.reset]] | फ़ॉल्ट [[ui:emu.fault.reset]] |
| [[ui:emu.preset.malformed]] | 200, `{"items":[{"id":1},{"id":2}]}`, फ़ॉल्ट [[ui:emu.fault.malformed]] के साथ |

### फ़ॉल्ट {#faults}

| [[ui:emu.fault]] | क्लाइंट को क्या मिलता है |
| --- | --- |
| [[ui:emu.fault.none]] | रिस्पॉन्स। |
| [[ui:emu.fault.timeout]] | कुछ नहीं। रिक्वेस्ट को अधिकतम 2 मिनट तक रोके रखा जाता है, फिर कनेक्शन बंद कर दिया जाता है — इसलिए टेस्ट क्लाइंट के अपने टाइमआउट का होता है। विलंब लागू नहीं होता। |
| [[ui:emu.fault.reset]] | विलंब के बाद, बिना जवाब के कनेक्शन बंद हो जाता है। |
| [[ui:emu.fault.malformed]] | सेट किए गए स्टेटस और हेडर वाला एक पूरा HTTP जवाब, जिसकी बॉडी बीच में रुक जाती है: ऐसा JSON जो पार्स नहीं होता। जब पूरी बॉडी JSON थी, तो कंटेंट टाइप फिर भी `application/json` बताता है। |

### वे रिक्वेस्ट, जिन्हें कोई रूट नहीं लेता {#fallback}

[[ui:emu.fallback]] तय करता है कि किसी रूट से मेल न खाने वाली रिक्वेस्ट को क्या मिले:

- [[ui:emu.fallbackDefault]] — बॉडी `{"error":"no_route"}` के साथ 404;
- [[ui:emu.fallbackCustom]] — आपका सेट किया गया रिस्पॉन्स, उन सभी चीज़ों के साथ जो किसी रूट के
  रिस्पॉन्स में होती हैं। इसका `{{counter}}` उन रिक्वेस्ट को गिनता है जिन्हें किसी रूट ने नहीं लिया।

दोनों ही स्थितियों में रिक्वेस्ट [[ui:emu.unmatched]] में गिनी जाती है।

### HTTP जवाब क्या पढ़ सकता है {#http-request}

| टेम्पलेट | क्या है |
| --- | --- |
| `{{request.method}}` | `GET`, `POST`, … |
| `{{request.path}}` | पाथ, क्वेरी के बिना। |
| `{{request.params.id}}` | `:id` नाम वाला पाथ सेगमेंट। |
| `{{request.query.page}}` | क्वेरी पैरामीटर, डिकोड किया हुआ। |
| `{{request.headers.x-key}}` | कोई हेडर; नाम छोटे अक्षरों में। |
| `{{request.body}}` | बॉडी, टेक्स्ट के रूप में: उसके पहले 64 KiB। |
| `{{request.json.name}}` | JSON बॉडी का कोई फ़ील्ड, जब बॉडी JSON हो और 64 KiB के भीतर हो। |
| `{{request.from}}` | क्लाइंट का `IP:port`। |

1 MiB से बड़ी रिक्वेस्ट बॉडी को 413 मिलता है और उसे [[ui:emu.failed]] में गिना जाता है। जो जवाब
बनाया ही नहीं जा सकता — ऐसा टेम्पलेट जो किसी ऐसी चीज़ का नाम लेता है जो रिक्वेस्ट में नहीं है —
उसे बॉडी में त्रुटि के साथ 500 मिलता है, और उसे [[ui:emu.failed]] में गिना जाता है।

## OSC डिवाइस {#osc}

आने वाले हर संदेश का — बंडल के हर संदेश का अलग से — जवाब वह पहला नियम देता है जिससे वह मेल खाता
है। जो डेटाग्राम OSC नहीं है, उसे [[ui:emu.unmatched]] में गिना जाता है।

| फ़ील्ड | क्या |
| --- | --- |
| [[ui:emu.address]] | OSC 1.0 पता पैटर्न: `*` कोई भी अक्षर, `?` एक अक्षर, `[a-z]` एक समूह, `{a,b}` दोनों में से कोई, हर एक एक ही सेगमेंट के भीतर (देखें [OSC](../protocols/osc.md#patterns))। |
| [[ui:exp.argRules]] | आर्ग्युमेंट पर अधिकतम 16 शर्तें, जैसे [[ui:exp.node.wait_osc]] में (देखें [नोड](../experiments/nodes.md#node-wait_osc))। |
| [[ui:emu.replyOn]] | बंद: संदेश लें और कोई जवाब न दें। |
| [[ui:emu.replyAddress]] | जवाब का पता, एक [टेम्पलेट](#templates)। |
| [[ui:emu.replyArgs]] | अधिकतम 16 आर्ग्युमेंट, हर एक का [[ui:emu.argType]] (`int`, `float`, `str`, `long`, `double`, `bool`, `blob`, `nil`) और [[ui:emu.argValue]] टेम्पलेट। |
| [[ui:emu.to]] | ख़ाली: भेजने वाले के पते और पोर्ट पर वापस। अन्यथा `IP:port`। |
| [[ui:emu.delay]], [[ui:emu.jitter]] | हर एक 0–60,000 ms। |

टेम्पलेट भरने के बाद आर्ग्युमेंट का मान उसके प्रकार के रूप में पढ़ा जाता है: प्रकार संख्या होने पर
`{{request.args[0]}}` पहले आर्ग्युमेंट को संख्या के रूप में लौटाता है। `bool` में `true`, `1`,
`yes`, `on` या `false`, `0`, `no`, `off` चलते हैं; `blob` में hex बाइट; ख़ाली मान उस प्रकार का शून्य
होता है।

जवाब एमुलेटर के अपने पोर्ट से निकलते हैं, इसलिए जो क्लाइंट उसी पोर्ट पर सुनता है जिससे उसने
भेजा था, उसे वे सुनाई देते हैं।

OSC जवाब `{{request.address}}`, `{{request.args[0]}}` और `{{request.from}}` पढ़ सकता है।

## UDP डिवाइस {#udp}

हर डेटाग्राम का जवाब वह पहला नियम देता है जिससे वह मेल खाता है।

| फ़ील्ड | क्या |
| --- | --- |
| [[ui:emu.match]] | [[ui:exp.mode.any]], [[ui:exp.mode.contains]], [[ui:exp.mode.regex]] या [[ui:exp.mode.hex]]। |
| [[ui:emu.pattern]] | खोजा जाने वाला टेक्स्ट, रेगुलर एक्सप्रेशन या बाइट। |
| [[ui:emu.reply]] | [[ui:emu.replyOff]], [[ui:emu.replyText]] या [[ui:emu.replyHex]], फिर ख़ुद जवाब, एक [टेम्पलेट](#templates) के रूप में। |
| [[ui:emu.to]] | ख़ाली: भेजने वाले को वापस। अन्यथा `IP:port`। |
| [[ui:emu.delay]], [[ui:emu.jitter]] | हर एक 0–60,000 ms। |

UDP या TCP जवाब पढ़ सकता है:

| टेम्पलेट | क्या है |
| --- | --- |
| `{{request.text}}` | पेलोड, टेक्स्ट के रूप में। |
| `{{request.match}}` | जो मेल खाया: टेक्स्ट, रेगुलर एक्सप्रेशन का पहला ग्रुप (या पूरा मिलान), बाइट। |
| `{{request.hex}}` | पेलोड, hex बाइट के रूप में, उसके पहले 1024। |
| `{{request.bytes}}` | पेलोड का आकार। |
| `{{request.from}}` | भेजने वाले का `IP:port`। |

टेक्स्ट जवाब अधिकतम 65,507 बाइट का होता है।

## TCP डिवाइस {#tcp}

ऐसा डिवाइस जो TCP कनेक्शन पर पंक्तियों में बात करता है, जैसे प्रोजेक्टर या मैट्रिक्स स्विचर। क्लाइंट
का भेजा हर संदेश उस पहले नियम से जवाब पाता है जिससे वह मेल खाता है; जवाब उसी कनेक्शन पर वापस
जाता है।

| फ़ील्ड | क्या |
| --- | --- |
| [[ui:emu.delimiter]] | संदेश किससे समाप्त होता है, और जो हर जवाब और अभिवादन के बाद जोड़ा जाता है: [[ui:emu.delimiter.lf]] (उससे पहले का `\r` हटा दिया जाता है), [[ui:emu.delimiter.crlf]], [[ui:emu.delimiter.cr]], या [[ui:emu.delimiter.none]]। ख़ाली पंक्तियाँ छोड़ दी जाती हैं। |
| [[ui:emu.greeting]] | क्लाइंट के कनेक्ट होते ही भेजा जाता है; ख़ाली हो तो कुछ नहीं। यह `{{request.from}}` पढ़ सकता है। |
| [[ui:emu.match]], [[ui:emu.pattern]], [[ui:emu.reply]] | जैसे [UDP डिवाइस](#udp) में। |
| [[ui:emu.close]] | इस नियम के जवाब के बाद कनेक्शन बंद करें — जैसे `QUIT` पर। |
| [[ui:emu.delay]], [[ui:emu.jitter]] | हर एक 0–60,000 ms। |

अपने डिलिमिटर के बिना 64 KiB से लंबा संदेश जैसा है वैसा ही लिया जाता है।

## MQTT ब्रोकर {#mqtt}

सादे TCP पर एक छोटा MQTT 3.1.1 ब्रोकर। यह वही करता है जो कोई ब्रोकर करता है: क्लाइंट कनेक्ट
होते हैं, `+` और `#` के साथ सब्सक्राइब करते हैं, QoS 0, 1 और 2 पर पब्लिश करते हैं, retained संदेश
और लास्ट-विल काम करते हैं, और किसी क्लाइंट की id वाला दूसरा कनेक्शन पहले की जगह ले लेता है।
सेशन हमेशा क्लीन होते हैं: अपना सेशन बनाए रखने को कहने वाले क्लाइंट को नया सेशन मिलता है, और
अनुपस्थित क्लाइंट के लिए कुछ भी कतार में नहीं रखा जाता।

इसके ऊपर, इस पर पब्लिश किया गया हर संदेश नियमों से जाँचा जाता है: जो पहला मेल खाता है, वह एक जवाब
भी पब्लिश करता है — जैसे कोई डिवाइस बता रहा हो कि उसने क्या किया।

| फ़ील्ड | क्या |
| --- | --- |
| [[ui:emu.username]], [[ui:emu.password]] | उपयोगकर्ता नाम सेट होने पर क्लाइंट को उसी और पासवर्ड के साथ कनेक्ट करना होगा; ख़ाली: कोई भी कनेक्ट कर सकता है। उपयोगकर्ता नाम के बिना पासवर्ड अस्वीकार किया जाता है, क्योंकि MQTT 3.1.1 उसे नहीं ले जा सकता। |
| [[ui:emu.retained]] | अधिकतम 64 संदेश ([[ui:emu.topic]], [[ui:emu.payload]], [[ui:emu.qos]]), जो शुरू से रखे जाते हैं, मानो retain के साथ पब्लिश किए गए हों: सब्सक्राइब करने वाले क्लाइंट को सबसे पहले ये मिलते हैं। |
| [[ui:emu.topicFilter]] | नियम कौन-से टॉपिक लेता है: `+` एक लेवल, `#` बाकी सब — `lab/+/set`। |
| [[ui:emu.match]], [[ui:emu.pattern]] | पेलोड पर एक शर्त, जैसे [UDP डिवाइस](#udp) में। |
| [[ui:emu.replyOn]] | बंद: संदेश लें और आगे कुछ पब्लिश न करें। |
| [[ui:emu.replyTopic]], [[ui:emu.replyPayload]] | [टेम्पलेट](#templates)। टॉपिक में `+` या `#` नहीं हो सकता। |
| [[ui:emu.qos]], [[ui:emu.retain]] | जवाब के। |
| [[ui:emu.delay]], [[ui:emu.jitter]] | हर एक 0–60,000 ms। |

MQTT जवाब `{{request.topic}}`, `{{request.levels[1]}}` (टॉपिक के लेवल, 0 से), `{{request.payload}}`,
`{{request.json.state}}`, `{{request.match}}`, `{{request.qos}}`, `{{request.retain}}`,
`{{request.client}}` (क्लाइंट id) और `{{request.from}}` पढ़ सकता है।

## जवाबों में टेम्पलेट {#templates}

जवाब उसी [टेम्पलेट भाषा](../experiments/data.md#templates) में लिखे जाते हैं जिसमें प्रयोग, इसलिए
किसी फ़ील्ड का यहाँ और वहाँ एक ही अर्थ होता है। जवाब पढ़ सकता है:

- `request` — जो आया, जैसा ऊपर हर प्रोटोकॉल के लिए बताया गया है;
- `{{counter}}` — एमुलेटर के शुरू होने के बाद से इस नियम ने कितने संदेश लिए, यह वाला मिलाकर;
- [जनरेटर](../experiments/data.md#generators) — `{{uuid}}`, `{{now.iso}}`, रैंडम मान और बाकी;
  रैंडम मान एमुलेटर के सीड से निकाले जाते हैं;
- पैरामीटर, जब एमुलेटर किसी प्रयोग में चलता है या `signallab emulate --param` के साथ शुरू किया
  जाता है।

जवाब कभी सीक्रेट नहीं पढ़ता, और अज्ञात नाम एक त्रुटि है, ख़ाली टेक्स्ट नहीं।

कुछ फ़ील्ड एमुलेटर के शुरू होने पर, कुछ भी आने से पहले, तय हो जाते हैं: पाथ, शर्त, पता पैटर्न,
पेलोड पैटर्न, टॉपिक फ़िल्टर, [[ui:emu.to]], हेडर का नाम, retained संदेश और ब्रोकर का लॉगिन। इनमें
केवल टेक्स्ट और पैरामीटर चलते हैं, न `request` और न जनरेटर।

सीड रिस्पॉन्स के रैंडम क्रम, जिटर और रैंडम जनरेटर को तय करता है। [[ui:nav.emulators]] स्क्रीन पर
हर बार शुरू करने पर नया सीड लिया जाता है; प्रयोग रन के सीड का उपयोग करता है, और
`signallab emulate --seed` आपका दिया हुआ सीड लेता है।

## बंद होना {#outage}

डिपेंडेंसी के बार-बार गिरने-उठने पर आपका सिस्टम क्या करता है, यह टेस्ट करने के लिए
[[ui:emu.outage]] पर टिक करें:

| फ़ील्ड | क्या | डिफ़ॉल्ट |
| --- | --- | --- |
| [[ui:emu.outageUp]] | यह कितनी देर जवाब देता है, 10–36,00,000 ms। | 10,000 |
| [[ui:emu.outageDown]] | यह कितनी देर बंद रहता है, 10–36,00,000 ms। | 3000 |
| [[ui:emu.outageFault]] | केवल HTTP: बंद रहते समय रिक्वेस्ट को क्या मिलता है। | [[ui:emu.outageFault.unavailable]] |

शेड्यूल एमुलेटर के शुरू होने पर शुरू होता है और दोहराता है: चालू, बंद, चालू, बंद… बंद रहते समय:

| एमुलेटर | क्या मिलता है |
| --- | --- |
| HTTP | [[ui:emu.outageFault.unavailable]]: 503, जिसमें `Retry-After` लौटने तक बचे सेकंड पर सेट होता है (कम से कम 1)। [[ui:emu.outageFault.reset]]: कनेक्शन बिना जवाब के बंद हो जाता है। [[ui:emu.outageFault.timeout]]: अधिकतम 2 मिनट तक रोका जाता है, फिर बंद। |
| TCP डिवाइस | खुले कनेक्शन 0.1 s के भीतर तोड़ दिए जाते हैं; नए कनेक्शन आते ही बंद कर दिए जाते हैं। |
| MQTT ब्रोकर | हर कनेक्शन तोड़ दिया जाता है; नए अस्वीकार किए जाते हैं (CONNACK रिटर्न कोड 3, server unavailable)। |
| OSC, UDP डिवाइस | किसी को जवाब नहीं दिया जाता। |

बंद रहते जो आता है, वह [[ui:emu.down]] में गिना जाता है, [[ui:emu.unmatched]] में नहीं, और उसके
लिए नियमों से नहीं पूछा जाता।

[[ui:emu.takeDown]] यही काम माँग पर करता है, शेड्यूल चाहे जो कहे, तब तक जब तक आप
[[ui:emu.bringUp]] न दबाएँ; तब HTTP को `Retry-After` के बिना 503 मिलता है। प्रयोग में
[[ui:exp.node.emulator_state]] नोड यह रन के किसी चरण पर करता है (देखें
[नोड](../experiments/nodes.md#node-emulator_state) और [फ़ॉल्ट](../experiments/faults.md))।

## समस्याएँ {#problems}

संपादन के दौरान हर बदलाव के कुछ क्षण बाद एमुलेटर जाँचा जाता है, और आपके [[ui:emu.start]] दबाने से
पहले ही समस्या उसके बटनों के नीचे दिख जाती है। समस्या बताती है कि वह कहाँ है — नियम, रिस्पॉन्स या
retained संदेश, और फ़ील्ड — और क्या ग़लत है: `/` के बिना पाथ, ऐसा रेगुलर एक्सप्रेशन जो कंपाइल नहीं
होता, ऐसा जवाब टेम्पलेट जो `request`, पैरामीटर और जनरेटर के अलावा किसी और चीज़ का नाम लेता है,
सीमा से बाहर का मान। [[ui:emu.start]] समस्या वाले एमुलेटर को अस्वीकार कर देता है।

## इसका मॉक बनाना {#mock-this}

किसी सफल रिस्पॉन्स से एमुलेटर बनाने के लिए:

1. [[ui:nav.http]] स्क्रीन पर रिक्वेस्ट भेजें और रिस्पॉन्स पाएँ — या किसी प्रयोग के HTTP नोड पर
   [[ui:exp.sendNow]] का उपयोग करें।
2. रिस्पॉन्स के पास ⧉ [[ui:http.mockThis]] दबाएँ। [[ui:http.mockTitle]] डायलॉग दिखाता है कि वह
   कौन-सा रूट बनाएगा।
3. [[ui:http.mockInto]] में अपने HTTP एमुलेटर में से एक चुनें, या [[ui:http.mockNew]]।
4. [[ui:http.mockAdd]] दबाएँ। [[ui:nav.emulators]] स्क्रीन उसी एमुलेटर पर खुलती है।

रूट रिक्वेस्ट के मेथड और पाथ (क्वेरी के बिना) का जवाब रिस्पॉन्स के स्टेटस, हेडर और बॉडी से देता है।
जो हेडर केवल उस एक आदान-प्रदान के होते हैं (`Content-Length`, `Date`, `Server`, `ETag` और इसी तरह
के), वे छोड़ दिए जाते हैं, और बॉडी वैसी ही भेजी जाती है जैसी थी, भले ही उसमें `{{` हो। नए एमुलेटर
में केवल यही रूट होता है। किसी मौजूदा एमुलेटर में जोड़ने पर रूट सबसे पहले आता है, ताकि वह किसी
व्यापक रूट से पहले जवाब दे; चल रहा एमुलेटर इसे तब अपनाता है जब आप [[ui:emu.restart]] दबाते हैं।

प्रयोग से, टेम्पलेट के साथ लिखा URL एक पैटर्न बन जाता है: उसका आधार (`{{api}}`) हटा दिया जाता है,
जो सेगमेंट एक ही टेम्पलेट है (`/orders/{{order_id}}`), वह `:order_id` बन जाता है, और जो सेगमेंट
केवल आंशिक रूप से टेम्पलेट है, वह पाथ को `*` के साथ समाप्त कर देता है।

## शुरुआती सेट {#starter-set}

जब Signal Lab को पहली बार कोई एमुलेटर लाइब्रेरी नहीं मिलती, तो वह पाँच एमुलेटर लिखता है, सभी इसी
कंप्यूटर पर। उनके नाम और नोट उस समय की इंटरफ़ेस भाषा में लिखे जाते हैं।

| एमुलेटर | कहाँ सुनता है | क्या करता है |
| --- | --- | --- |
| [[ui:seed.emu.demo-api.name]] | `127.0.0.1:8080` | `GET /health` → `{"status":"ok","time":…}`; `GET /users/:id` → उस id वाला उपयोगकर्ता; `POST /users` → `Location` के साथ 201; `GET /slow` → 1500 ms बाद; `/flaky` → 503, 503, फिर उसके बाद हमेशा 200। |
| [[ui:seed.emu.osc-device.name]] | `127.0.0.1:9100` | `/ping` → गिनती के साथ `/pong`; `/fader/*` → मिले पते के साथ `/ack`; `/cue/*` बिना जवाब के लिया जाता है। |
| [[ui:seed.emu.udp-device.name]] | `127.0.0.1:7100` | `PING` → `PONG` और गिनती; बाकी कुछ भी → `ACK` और बाइट में उसका आकार। |
| [[ui:seed.emu.tcp-device.name]] | `127.0.0.1:7200` | CR LF से समाप्त होने वाली पंक्तियाँ। `READY` से अभिवादन करता है; `POWER?` → `POWER=ON`; `POWER ON` या `POWER OFF` → `OK ON` / `OK OFF`; `QUIT` → `BYE`, फिर कनेक्शन काट देता है। |
| [[ui:seed.emu.mqtt-broker.name]] | `127.0.0.1:1883` | `lab/status` पर `online` retain करता है; `lab/<name>/set` पर पब्लिश किया गया `ON` या `OFF` → वही, retained, `lab/<name>/state` पर। |

[सिग्नल लाइब्रेरी](signals.md#starter-set) का शुरुआती सिग्नल [[ui:seed.http-reachable.name]]
`http://127.0.0.1:8080/` से पूछता है, जो [[ui:seed.emu.demo-api.name]] का पता है: उसमें `/` के लिए
कोई रूट नहीं है, इसलिए उसे 404 मिलता है।

## लाइब्रेरी फ़ाइल {#file}

लाइब्रेरी डेटा फ़ोल्डर में `emulators.json` है (देखें [फ़ाइलें](../reference/files.md)); उसका पथ
देखने के लिए सूची के नीचे की गिनती पर पॉइंटर रखें। अंतिम बदलाव के 0.7 s बाद यह पूरी की पूरी, एक
अस्थायी फ़ाइल के ज़रिए, लिखी जाती है, इसलिए विफल लेखन पिछली फ़ाइल को बनाए रखता है। अगर फ़ाइल पढ़ी
नहीं जा सकती, तो सूची पथ, पंक्ति और कॉलम के साथ त्रुटि दिखाती है, और फ़ाइल को जैसी है वैसी ही छोड़
दिया जाता है: उसे ठीक करें और [[ui:emu.reload]] दबाएँ। हाथ से संपादित करने के बाद भी
[[ui:emu.reload]] दबाएँ। फ़ाइल न होने पर शुरुआती सेट फिर से लिखा जाता है।

```json
{
  "version": 1,
  "emulators": [
    {
      "id": "orders-api",
      "note": "Stands in for the orders service.",
      "emulator": {
        "name": "Orders API",
        "bind": "127.0.0.1:18080",
        "protocol": "http",
        "routes": [
          { "method": "GET", "path": "/orders/:id",
            "responses": [{ "body": "{\"id\":\"{{request.params.id}}\",\"state\":\"open\"}" }] },
          { "method": "POST", "path": "/orders", "order": "sequence",
            "responses": [{ "status": 503 }, { "status": 201, "body": "{\"id\":\"{{uuid}}\"}" }] }
        ],
        "outage": { "up_ms": 20000, "down_ms": 2000, "fault": "unavailable" }
      }
    }
  ]
}
```

अकेला `emulator` ऑब्जेक्ट भी एक दस्तावेज़ है, जिसे `signallab emulate` पढ़ता है।

## प्रयोगों और स्क्रिप्ट में {#elsewhere}

- प्रयोग में [[ui:exp.node.emulator]] नोड अपना एमुलेटर पहले चरण से पहले खोलता है और रन समाप्त होने
  तक जवाब देता है; उसे जो प्राप्त हुआ, वह रिपोर्ट में गिना जाता है। वहाँ HTTP एमुलेटर वही है जिसे
  [[ui:exp.node.wait_http]] ([नोड](../experiments/nodes.md#node-wait_http)) सुनता है, और OSC या UDP
  एमुलेटर अपना पोर्ट रन की प्रतीक्षाओं के साथ साझा करता है। एक प्रयोग में एक ही ट्रांसपोर्ट के दो
  एमुलेटर एक पोर्ट साझा नहीं कर सकते। देखें [नोड](../experiments/nodes.md#node-emulator) और
  [फ़ॉल्ट](../experiments/faults.md)।
- `signallab emulate` फ़ाइलों से या इस लाइब्रेरी से एमुलेटर <kbd>Ctrl</kbd>+<kbd>C</kbd> या `--for`
  तक चलाता है और बताता है कि वे क्या जवाब देते हैं; देखें
  [कमांड लाइन](../automation/cli.md#cli-emulate)।
