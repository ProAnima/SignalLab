# 창

Signal Lab의 창은 네 부분으로 이루어져 있습니다. 왼쪽의 **사이드바**에는 화면 목록이 있고, 위쪽의
**헤더**에는 모든 화면에 적용되는 항목이 있으며, 가운데는 선택한 **화면**이 차지하고, **하단
패널**에는 콘솔, 실행 중인 작업, 인스펙터가 표시됩니다. 데스크톱 앱과 브라우저에서 보는 서버
페이지는 모양이 같으며, 몇 가지 차이는 [브라우저에서](#browser)에 정리되어 있습니다.

## 사이드바 {#sidebar}

각 화면은 독립된 도구입니다. 클릭해서 엽니다.

| 화면 | 용도 |
| --- | --- |
| [[ui:nav.experiment]] | 캔버스에 테스트 흐름을 만들어 실행하고, 각 실행을 단계별로 읽습니다. [실험](../experiments/index.md) |
| [[ui:nav.signals]] | 신호 라이브러리: 폴더에 정리된 이름 붙은 메시지를 편집하고 다시 보냅니다. [신호](../tools/signals.md) |
| [[ui:nav.emulators]] | 규칙에 따라 응답하는 모의 HTTP API, OSC·UDP·TCP 장치, MQTT 브로커. [에뮬레이터](../tools/emulators.md) |

| [[ui:nav.mqtt]] | 브로커에 연결하고, 브로커의 모든 토픽을 보고, 발행하고, retained 값을 지웁니다. [MQTT](../protocols/mqtt.md) |

| [[ui:nav.storm]] | 직접 관리하는 서버와 링크에 거는 원시 UDP나 TCP 부하. [스톰](../tools/storm.md) |
| [[ui:nav.scan]] | 호스트의 어떤 TCP 포트가 열려 있는지, 서비스가 처음 보내는 내용과 함께 보여 줍니다. [스캐너](../tools/scanner.md) |

사이드바는 처음에 각 화면의 기호와 짧은 이름만 있는 좁은 막대로 표시됩니다. 항목 위에 포인터를
올리면 전체 이름이 보입니다. 헤더 왼쪽의 **☰**([[ui:app.expandNav]] /
[[ui:app.collapseNav]])는 좁은 막대와 전체 목록을 전환하며, Signal Lab은 선택한 방식을
기억합니다.

화면 항목에 표시되는 숫자는 모니터나 에뮬레이터처럼 그 화면에서 실행 중인 작업의 수이므로, 화면을
열지 않아도 무엇이 아직 동작 중인지 알 수 있습니다. 사이드바 맨 아래의 버전을 누르면 Signal Lab
정보가 열리며, 그 아래 줄에는 실행 중인 모든 작업의 수가 표시됩니다.

Signal Lab은 마지막으로 사용한 화면으로 열립니다.

### 문서 {#docs}

문서는 앱과 서버에 내장되어 있으므로 인터넷 연결 없이도 인터페이스 언어로 볼 수 있습니다.
데스크톱 앱은 문서를 별도의 창에 표시하며(다른 화면에서 버튼을 다시 누르면 그 창이 해당 화면의
페이지로 바뀝니다), 문서 밖으로 나가는 링크는 브라우저로 엽니다. 브라우저에서는 별도의 탭으로
열립니다. Signal Lab 정보에도 [[ui:app.docs]] 버튼이 있으며, [Signal Lab 소개](index.md)를 엽니다.

### Signal Lab 정보 {#about}

Signal Lab 정보에는 버전, 개발자, 연락처 주소(복사 버튼 포함), 소스 코드, 라이선스가 표시됩니다.
데스크톱 앱에서는 [[ui:update.title]] 섹션에서 업데이트를 찾고, 보여 주고, 설치합니다.
[업데이트](install.md#updates)를 참고하십시오. 브라우저에서는 [[ui:update.server]] 안내가
표시됩니다. [[ui:about.writeUs]] 버튼은 피드백 양식을 엽니다.

### 개발자에게 문의하기 {#feedback}

헤더의 **✉**를 누르면 개발자에게 바로 전달되는 양식이 열립니다.

| 필드 | 입력할 내용 |
| --- | --- |
| [[ui:feedback.message]] | 무슨 일이 일어났는지, 그리고 원래 무엇을 기대했는지. 필수이며 최대 20,000자입니다. |
| [[ui:feedback.email]] | 선택 사항: 개발자가 답변을 보낼 주소. 개발자만 볼 수 있습니다. |
| [[ui:feedback.screenshots]] | 이미지 최대 6개(PNG, JPEG, WebP, GIF), 각각 8 MB, 합계 15 MB까지. <kbd>Ctrl</kbd>+<kbd>V</kbd>로 붙여 넣거나, 파일을 창에 끌어다 놓거나, [[ui:feedback.addScreenshot]] 버튼을 누르십시오. |
| [[ui:feedback.logs]] | 콘솔의 줄과 [[ui:feedback.systemInfo]] 정보가 각각 별도의 파일로 첨부됩니다. [[ui:feedback.show]] 버튼을 누르면 보낼 내용을 정확히 보여 줍니다. 빼려면 해당 항목의 선택을 해제하십시오. |

첨부되는 로그에서는 이 컴퓨터의 이름, 네트워크 주소, 폴더 경로에 들어 있는 이름이 빠집니다.
<kbd>Ctrl</kbd>+<kbd>Enter</kbd>를 누르면 양식이 전송되며, 전송되면 참조 번호를 받습니다. 이
번호는 콘솔에도 남습니다. 메시지는 스튜디오 자체 서비스를 거쳐 메일로 전달되며, 앱에는 이를 위한
암호가 들어 있지 않습니다.

## 하단 패널 {#bottom-panel}

모든 화면 아래의 패널에는 [[ui:console.title]]과 [[ui:dock.inspector]] 두 탭이 있고, 탭과
패널 버튼 사이에 실행 중인 작업 표시줄이 있습니다.

- 왼쪽의 **갈매기 모양 아이콘**([[ui:console.collapse]] / [[ui:console.expand]])은 패널을
  막대 하나로 접거나 다시 엽니다. 접혀 있어도 막대에 최신 콘솔 줄이 표시되며, 그 줄을 클릭하면
  패널이 열립니다.
- 패널 위쪽 가장자리를 끌어 높이를 조절합니다([창 영역 크기 조절](#panes) 참고).
- 오른쪽 버튼([[ui:dock.maximise]] / [[ui:dock.restore]])은 패널을 창 높이만큼 키우고 다시
  원래대로 돌립니다.

패널이 열려 있는지, 어느 탭을 보여 주는지, 높이가 얼마인지는 다음 실행 때까지 유지됩니다.

### 콘솔 {#console}

콘솔은 각 도구가 무엇을 했는지, 무엇이 잘못되었는지를 최신 줄이 맨 아래에 오도록 보여 줍니다.
보낸 메시지와 그 크기, 시작된 모니터, 응답의 상태와 시간, 종료된 작업과 그 이유 등입니다. 각
줄에는 시각(밀리초 단위), 도구 이름 태그, 메시지가 있으며, 완료, 정보, 경고, 오류 등 종류에 따라
색이 다릅니다.

- [[ui:console.autoscroll]] 옵션을 켜 두면 줄이 들어올 때마다 최신 줄이 계속 보입니다. 새 줄이
  들어오는 동안 앞의 내용을 읽으려면 해제하십시오.
- [[ui:common.clear]] 버튼은 콘솔을 비웁니다.
- 마지막 500줄을 보관합니다.
- 언어를 바꾸면 콘솔 전체가 새 언어로 다시 표시됩니다.

### 작업 {#jobs-strip}

모니터, 발생기, 비컨, 브로커 연결, 에뮬레이터, 릴레이, 스톰, 스캔, 실험 실행 등 실행 중인 각
작업은 표시줄에 번호와 종류가 적힌 알약 모양 항목으로 나타나며, 각각 중지 버튼이 있습니다. 실행
중인 것이 없으면 표시줄에 [[ui:console.empty]] 문구가 표시됩니다. [작업](concepts.md#jobs)을
참고하십시오.

### 인스펙터 탭 {#inspector-tab}

[[ui:dock.inspector]] 탭은 캡처가 켜져 있는 동안 도구가 보내고 받는 모든 프레임을, 작업 중인
화면 옆에 보여 줍니다. 캡처가 켜져 있으면 탭의 점에 불이 들어오고, 캡처한 프레임 수가 표시됩니다.
패널은 인스펙터의 목록과 프레임 세부 정보가 들어갈 만큼 높게 열립니다. 실행 타임라인이나
에뮬레이터 목록처럼 다른 곳에 있는 프레임 링크를 누르면 이 탭이 그 프레임을 보여 주며 열립니다.
한 번 열린 인스펙터는 패널이 닫혀 있는 동안에도 목록과 선택을 유지합니다. 사용 방법은
[인스펙터](../tools/inspector.md)를 참고하십시오.

## 어디서든 신호 보내기 {#palette}

어느 화면에서든 <kbd>Ctrl</kbd>+<kbd>K</kbd>를 누르면 [[ui:sig.paletteTitle]] 창이 열립니다.
신호의 이름, 폴더, 대상 중 몇 글자를 입력하고 <kbd>↑</kbd>와 <kbd>↓</kbd>로 고른 다음
<kbd>Enter</kbd>를 누르면 보냅니다. 한 번에 최대 12개 신호가 목록에 표시됩니다. <kbd>Esc</kbd>를
누르거나, 바깥을 클릭하거나, <kbd>Ctrl</kbd>+<kbd>K</kbd>를 다시 누르면 닫힙니다. 콘솔에 무엇을
어디로 보냈는지 표시됩니다. [신호](../tools/signals.md)를 참고하십시오.

## 창 영역 크기 조절 {#panes}

크기를 조절할 수 있는 창 영역 사이에는 얇은 핸들이 있습니다. 하단 패널의 위쪽 가장자리
([[ui:layout.console]])와, 실험 화면에서는 속성 영역의 가장자리([[ui:layout.properties]]) 및
실행 타임라인의 위쪽([[ui:layout.timeline]])입니다.

- 핸들을 끕니다.
- 또는 <kbd>Tab</kbd>으로 핸들에 포커스를 옮긴 뒤 화살표 키를 사용합니다. 한 번 누를 때마다
  16픽셀씩, <kbd>Shift</kbd>를 함께 누르면 네 배씩 움직이며, <kbd>Home</kbd>과
  <kbd>End</kbd>는 가장 작은 크기와 가장 큰 크기로 이동합니다.
- 핸들을 두 번 클릭하거나 핸들에서 <kbd>Enter</kbd>를 누르면 영역이 기본 크기로 돌아갑니다.

크기는 다음 실행 때까지 유지됩니다.

## 툴팁 {#tooltips}

화면에는 레이블, 값, 상태만 표시되고, 설명은 툴팁에 들어 있습니다. 필드에 무엇을 입력해야 하는지,
거기서 `0`이 무슨 뜻인지, 어떤 키가 같은 일을 하는지 등입니다. 툴팁은 포인터를 무언가에 약 0.5초
올려 두면 나타나고, 키보드로 이동하면 바로 나타납니다. 필드는 레이블의 툴팁을 보여 줍니다.
<kbd>Esc</kbd>를 누르거나, 입력하거나, 클릭하거나, 스크롤하면 사라집니다. 화면 낭독기도 같은
텍스트를 읽습니다.

오류 메시지는 어디서 무엇이 잘못되었고 왜 그런지를 알려 주며, 시스템이 보낸 원래 문구는
[[ui:err.details]] 아래에 접혀 있습니다.

## 화면은 상태를 유지합니다 {#state}

화면은 처음 방문할 때 열리고, 그 뒤로는 다른 화면에서 작업하는 동안에도 그대로 유지됩니다. 입력한
내용, 마지막 응답, 모니터의 메시지 목록과 그 뒤에서 도는 작업, 스크롤 위치까지 돌아왔을 때 모두
그대로 있습니다. 실행 중인 작업은 어느 화면을 보든 계속 실행됩니다.

일부 값은 다시 시작한 뒤에도 유지됩니다. 보내던 OSC 메시지, HTTP 요청, WebSocket 주소, 창 영역
크기, 마지막으로 보던 화면입니다.

## 방화벽 알림 {#firewall-notice}

Windows Defender 방화벽은 프로그램별로 다른 컴퓨터의 접근을 허용할지 결정합니다. 프로그램이 처음
수신을 시작하면 Windows가 화면 앞의 사용자에게 묻는데, 여기서 *취소*를 누르거나 Windows가 공용으로
간주하는 네트워크에 있으면 다른 컴퓨터가 보내는 데이터가 아무 표시 없이 버려집니다. 아무것도
표시하지 않는 모니터가 흔한 징후입니다.

그래서 Windows의 데스크톱 앱에서는 OSC 모니터, 탐색 리스너, 네트워크 장애 릴레이, 에뮬레이터,
실험 실행 등 무언가가 처음 수신을 시작할 때 Signal Lab이 방화벽을 한 번 확인합니다. 방화벽이
가로막고 있으면 헤더 아래에 알림이 표시됩니다.

- [[ui:fw.allow]] 버튼은 Windows 자체의 프롬프트로 관리자 권한을 요청한 다음, 개인 네트워크와
  도메인 네트워크에서 다른 컴퓨터가 Signal Lab에 접근하도록 허용합니다.
- Windows가 공용으로 분류하는 네트워크(공연장 Wi-Fi가 흔히 그렇습니다)에서는 버튼이 대신
  [[ui:fw.allowPublic]]으로 표시됩니다.
- [[ui:fw.dismiss]] 버튼은 이번 세션 동안 알림을 숨깁니다.

허용하면 Signal Lab의 인바운드 방화벽 규칙이 하나의 허용 규칙으로 바뀝니다. 이 컴퓨터 안의
트래픽(`127.0.0.1`)은 영향을 받지 않으므로, 루프백에서 작업하는 동안에는 알림을 무시해도 됩니다.
모든 사람용 설치에는 이미 규칙이 있습니다. [설치 프로그램이 추가하는 것](install.md#windows-setup-adds)을
참고하십시오. 터미널에서는 `signallab doctor`가 같은 내용을 알려 주고 `signallab firewall allow`가
문제를 해결합니다. [명령줄](../automation/cli.md)을 참고하십시오. Linux나 브라우저에서는 알림이
없습니다. 서버의 방화벽은 그 관리자가 관리합니다.

## 브라우저에서 {#browser}

[서버](../server/index.md)의 페이지는 같은 인터페이스이며, 몇 가지 차이가 있습니다.

- 헤더의 호스트에 서버 이름이 표시되고, 옆에 [[ui:app.server]] 표시가 붙습니다.
- 서버가 액세스 토큰을 요구하면 한 번 로그인하며, 헤더의 [[ui:app.signOut]] 버튼으로 세션을
  끝냅니다.
- 페이지가 서버와의 연결을 잃으면 연결이 돌아올 때까지 [[ui:app.connectionLost]] 막대가
  표시되며, 콘솔에 두 가지 모두 기록됩니다.
- 실행 보고서, 내보낸 파일, 인스펙터 캡처는 경로로 표시되는 대신 브라우저가 다운로드합니다.
- Signal Lab 정보에 업데이트 항목이 없습니다. 서버는 이미지와 함께 업데이트됩니다.

서버 페이지에서 하는 모든 일은 서버에서 일어납니다. 트래픽은 서버에서 출발하고, 모니터는 서버의
포트에서 수신하며, 파일은 서버의 데이터 폴더에 저장됩니다. [개념](concepts.md#desktop-and-server)을
참고하십시오.

## 언어 {#languages}

헤더의 국기는 현재 언어와 그 두 글자 코드를 보여 줍니다. 클릭하면 모든 언어가 국기와 그 언어 자체의
이름으로 표시된 목록이 열리며, 여기서 하나를 고릅니다. 목록에서 <kbd>↑</kbd>, <kbd>↓</kbd>,
<kbd>Home</kbd>, <kbd>End</kbd>로 이동하고, 글자를 누르면 그 글자로 시작하는 다음 언어로
건너뜁니다. 언어 자체의 이름이나 영어 이름 모두 해당되므로 <kbd>g</kbd>를 누르면 Deutsch를
찾습니다. <kbd>Enter</kbd>로 선택하고 <kbd>Esc</kbd>로 닫습니다.

인터페이스는 다시 시작하지 않아도 즉시 바뀝니다. 모든 화면, 툴팁, 오류, 그리고 콘솔의 이전 줄까지
바뀝니다. Signal Lab을 처음 시작하면 시스템 언어 중 지원하는 첫 번째 언어를, 없으면 영어를 고르며,
그 뒤로는 사용자의 선택을 유지합니다. 브라우저에서는 그 브라우저에 대해 유지합니다.

아랍어를 선택하면 창 전체가 오른쪽에서 왼쪽 방향으로 바뀝니다. 데이터에 해당하는 주소, hex 덤프,
코드, 실험 캔버스는 쓰인 그대로 왼쪽에서 오른쪽 방향을 유지합니다.
