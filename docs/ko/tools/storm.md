# 스톰

[[ui:nav.storm]] 화면은 부하 원천입니다: 하나의 대상으로 UDP 데이터그램을 보내거나 TCP 연결을
열되, 요청한 만큼 빠르게, 요청한 동안 하며, 실제로 나간 것을 측정합니다. 자신의 서버, 장치,
링크가 폭주 속에서 어떻게 버티는지 — 계속 응답하는지, 패킷을 버리는지, 쓰러지는지 — 보려면
사용하십시오.

::: danger 책임 있는 사용
스톰은 실제 호스트로 실제 트래픽을 보냅니다. 소유했거나 테스트가 허용된 호스트와 네트워크에만
향하십시오. 높은 속도는 그 위의 모든 사람을 위해 링크를 포화시킬 수 있고 침입 탐지를 건드릴 수
있습니다. 엔진은 스톰의 속도를 제한하지 않습니다: 0은 이 컴퓨터가 보낼 수 있는 만큼 빠르게를
뜻합니다.
:::

## 스톰 시작하기 {#start}

1. [[ui:common.target]]을 설정합니다: 보낼 `IP:port` 또는 `host:port`이며, `127.0.0.1:9000`이나
   `test-rig.local:9000` 같은 것입니다. 호스트 이름은 시작할 때 조회되며, IPv4 주소가 있으면
   그것을 씁니다.
2. [[ui:common.protocol]]을 고릅니다: [[ui:st.udp]] 또는 [[ui:st.tcp]].
3. [[ui:st.payloadSize]], [[ui:st.rate]], [[ui:st.duration]]을 설정합니다.
4. [[ui:st.launch]]를 누릅니다.

스톰은 작업으로 실행됩니다: 콘솔 표시줄에 나타나며, 지속 시간이 끝나거나, [[ui:st.stop]]을
누르거나, [[ui:app.stopAll]]로 중지됩니다. 실행 중에는 필드가 고정됩니다.

| 필드 | 내용 | 기본값 |
| --- | --- | --- |
| [[ui:common.target]] | 대상의 `IP:port` 또는 `host:port`. | `127.0.0.1:9000` |
| [[ui:common.protocol]] | [[ui:st.udp]]: 분리된 데이터그램. [[ui:st.tcp]]: "패킷"마다 새 TCP 연결. | [[ui:st.udp]] |
| [[ui:st.payloadSize]] | 각 데이터그램 또는 연결의 바이트, 1–65 507. 더 크거나 작은 값은 그 범위로 맞춰집니다. | 512 |
| [[ui:st.rate]] | 목표로 할 초당 패킷(또는 연결) 수. 0: 가능한 한 빠르게. | 1000 |
| [[ui:st.duration]] | 실행할 초. 0: 멈출 때까지. | 10 |

### UDP 폭주 {#udp}

Signal Lab은 페이로드 크기의 데이터그램을, 모든 바이트 `0x55`로, 자신의 포트 하나에서 대상으로
보냅니다. 시스템이 거부한 전송은 오류로 셉니다 — 예를 들어 대상이 그 포트에서 아무것도 수신하지
않는다고 답한 뒤입니다.

### TCP 연결 폭주 {#tcp}

"패킷"마다 Signal Lab은 대상으로 TCP 연결을 열고, 페이로드를 쓰고, 닫습니다. 연결은 동시가 아니라
차례대로 만들어지므로, TCP 스톰이 내는 속도는 대상이 그것들을 얼마나 빨리 받아 주는지에
제한됩니다. 거부되었거나 500 ms 안에 받아들여지지 않은 연결은 오류로 세고, 페이로드를 받아간
연결은 패킷으로 셉니다.

### 속도를 지키는 방식 {#pacing}

속도는 일정표입니다. 첫 패킷은 곧바로 나가고, *n*번째 패킷은 시작 후 *n* ÷ [[ui:st.rate]]초에
예정됩니다. 스톰이 깨어날 때마다 예정된 것을 보내고, 다음 패킷이 예정될 때까지 잡니다. 그래서
초당 50은 초당 50이고 250은 250입니다 — 1초짜리 실행은 대략 그만큼 보냅니다 — 시스템의 타이머
정밀도와 무관하게. [[ui:st.duration]]은 다음 패킷이 더 늦게 예정되어 있더라도 스톰을 제때
끝냅니다.

스톰은 잃은 시간을 만회하려고 자기 속도 위로 보내지 않습니다. 이 컴퓨터, 또는 느리게 받아 주는
TCP 대상이 256패킷 넘게 뒤처지면, 오래된 것은 나중에 한꺼번에 보내지는 대신 일정표에서 버려집니다.
[[ui:st.pps]]가 도달한 것을 보여 줍니다.

[[ui:st.rate]]가 0이면 일정표가 없습니다: 스톰은 이 컴퓨터가 할 수 있는 만큼 빠르게 256패킷을
보내고, 다른 작업이 돌게 하고, 다음 256개를 보냅니다.

## 처리량 읽기 {#metrics}

[[ui:st.throughput]]은 초당 네 번 갱신됩니다:

| 지표 | 내용 |
| --- | --- |
| [[ui:common.packets]] | 시작 이후 보낸 데이터그램, 또는 페이로드를 받아간 연결. |
| [[ui:st.pps]] | 지난 4분의 1초 동안의 초당 패킷. |
| [[ui:st.rateLabel]] | 지난 4분의 1초 동안의 초당 메가비트 페이로드. 헤더(IP, UDP, TCP)는 세지 않습니다. |
| [[ui:common.volume]] | 시작 이후 보낸 페이로드 바이트. |
| [[ui:common.errors]] | 실패한 전송 또는 연결. |

그 아래의 차트는 지난 1분 동안의 [[ui:st.pps]]를 그립니다.

스톰이 끝나면 카운터가 최종 합계를 보여 주고, [[ui:st.pps]]와 [[ui:st.rateLabel]]은 0이 됩니다.

숫자가 알려 주는 것:

- UDP에서 [[ui:st.pps]]가 [[ui:st.rate]]보다 훨씬 낮음: 이 컴퓨터가 더 빠르게 보낼 수 없습니다.
  속도나 페이로드 크기를 낮추십시오.
- UDP에서 [[ui:common.errors]]가 증가함: 대상의 포트가 닫혀 있거나 네트워크가 트래픽을 거부합니다.
- TCP에서 [[ui:common.errors]]가 증가함: 대상이 연결을 거부하거나 받아들이는 데 500 ms보다 오래
  걸립니다 — 한계에 도달했을 수 있습니다.

스톰은 얼마나 나갔는지 말하지, 얼마나 도착했는지 말하지 않습니다. 대상이 받은 것을 보려면
그것을 지켜보십시오: 대상 자체의 로그, [[ui:nav.osc]] 모니터, 또는 그 자리에 둔
[에뮬레이터](emulators.md)입니다.

## 인스펙터에서 {#inspector}

캡처가 켜져 있으면 UDP 스톰은 1초마다 자기 데이터그램 하나를 [인스펙터](inspector.md)에 넣으며,
`sampled 1/s`로 표시됩니다 — 모두 같기 때문입니다. 판정은 이전 것 이후 몇 개가 빠졌는지도
`sampled 1/s · +999 not shown`으로 말합니다. TCP 스톰은 아무것도 넣지 않습니다.
