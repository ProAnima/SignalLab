# Эмуляторы

Эмулятор — это Signal Lab в роли API, устройства или сервиса, с которым говорит ваша
система. Он слушает один адрес и отвечает по правилам: HTTP API — по маршрутам, OSC-,
UDP- или TCP-устройство — по принципу «на это ответить тем-то», MQTT-брокер — как любой
брокер, плюс собственные правила. Он умеет тормозить, сбоить и время от времени
отключаться — так можно проверить, что делает ваша система, когда её зависимость ведёт
себя плохо. Каждый обмен подсчитывается, попадает в список и отправляется в
[Инспектор](inspector.md).

Эмулятор — это один документ. Экран [[ui:nav.emulators]] хранит их библиотеку; тот же
документ работает внутри эксперимента как узел [[ui:exp.node.emulator]], из командной
строки через `signallab emulate`, через [API](../api/commands.md) и
[MCP](../automation/mcp.md) — и везде отвечает одинаково.

## Экран {#screen}

Слева — библиотека ([[ui:emu.library]]): все эмуляторы с протоколом и адресом; у
запущенных — пульсирующая точка и счётчик запросов. Справа — настройки и правила
выбранного эмулятора, а под ними — то, что он получил ([[ui:emu.live]]).

## Создание эмулятора {#create}

1. Нажмите одну из кнопок вверху библиотеки:

   | Кнопка | Создаёт | Слушает | С одним правилом, которое сразу работает |
   | --- | --- | --- | --- |
   | ＋ [[ui:emu.new.http]] | HTTP API | `127.0.0.1:18080` | `GET /health` → 200 `{"status":"ok"}` |
   | ＋ [[ui:emu.new.osc]] | OSC-устройство | `127.0.0.1:9100` | `/ping` → `/pong` со счётчиком в виде int |
   | ＋ [[ui:emu.new.udp]] | UDP-устройство | `127.0.0.1:7100` | датаграмма, содержащая `PING` → `PONG 1`, `PONG 2`, … |
   | ＋ [[ui:emu.new.tcp]] | TCP-устройство | `127.0.0.1:7200` | строка, содержащая `PING` → `PONG` |
   | ＋ [[ui:emu.new.mqtt]] | MQTT-брокер | `127.0.0.1:1883` | публикация в `lab/<name>/set` → то же содержимое, retained, в `lab/<name>/state` |

   Если этот порт уже занят другим эмулятором библиотеки, берётся следующий свободный.
2. Заполните поле [[ui:emu.name]] (не больше 120 символов).
3. В поле [[ui:emu.bind]] укажите `IP:port`. `127.0.0.1` отвечает только этому
   компьютеру; `0.0.0.0` — ещё и сети.
4. Измените правила (см. ниже) и напишите в поле [[ui:emu.note]], что этот эмулятор
   заменяет.

Изменения сохраняются сами. Кнопка [[ui:emu.duplicate]] создаёт копию на следующем
свободном порту. Кнопка [[ui:emu.delete]] переспрашивает ([[ui:emu.confirmDelete]]),
останавливает эмулятор, если он запущен, и удаляет его из библиотеки.

Правила перебираются по порядку, от первого к последнему; отвечает первое подошедшее. В
заголовке каждого правила — его краткое описание в одну строку; щёлкните заголовок, чтобы
раскрыть или свернуть правило. Кнопки ↑ и ↓ перемещают правило, × удаляет его.

## Запуск {#run}

1. Выберите эмулятор и нажмите [[ui:emu.start]]. Его порт открывается раньше, чем кнопка
   снова станет доступна: занятый порт или эмулятор с ошибкой отклоняются тут же, с
   указанием причины.
2. Направьте на него свою систему. Для HTTP API кнопка [[ui:emu.copyUrl]] копирует его
   адрес (`http://127.0.0.1:18080`), а у каждого маршрута есть своя кнопка
   [[ui:emu.copyRouteUrl]] (кроме маршрутов, путь которых содержит шаблон `{{…}}`).
3. Смотрите, как заполняется список [[ui:emu.received]].
4. Нажмите [[ui:emu.stop]] или остановите задачу эмулятора на полосе консоли.

Рядом с кнопками показано состояние: [[ui:emu.notRunning]], адрес, на котором эмулятор
отвечает, или то, что он отключён.

Эмулятор продолжает отвечать по тем правилам, с которыми был запущен. Если изменить его
на ходу, появится кнопка [[ui:emu.restart]]: нажмите её, чтобы запустить эмулятор заново
с текущими правилами. До тех пор счётчики срабатываний у правил скрыты — они относятся к
старым правилам.

Кнопка [[ui:emu.takeDown]] делает запущенный эмулятор недоступным, пока вы не нажмёте
[[ui:emu.bringUp]]: HTTP-запрос получает 503, TCP-устройство и MQTT-брокер рвут
соединения и отказывают новым, OSC- или UDP-устройство ничего не отвечает. См.
[Отключения](#outage).

Два эмулятора одного транспорта не могут делить порт: HTTP-, TCP- и MQTT-эмуляторы
слушают TCP-порты, OSC- и UDP-эмуляторы — UDP-порты. HTTP API и OSC-устройство могут
оба занять порт 8080; два HTTP API — нет. Второй эмулятор на занятом порту отклоняется
при запуске.

::: tip
В браузере, подключённом к [серверу](../server/index.md), эмулятор работает на сервере.
До эмулятора, слушающего `0.0.0.0`, добираются по имени сервера, и [[ui:emu.copyUrl]]
копирует именно этот адрес; эмулятор на `127.0.0.1` отвечает только программам на самом
сервере.
:::

## Что пришло {#received}

Пока эмулятор работает, панель [[ui:emu.live]] считает:

| Счётчик | Что считает |
| --- | --- |
| [[ui:emu.total]] | Всё, что пришло: запросы, сообщения, строки. |
| [[ui:emu.unmatched]] | То, что не взяло ни одно правило. HTTP-запрос без маршрута всё равно получает ответ (см. [Запросы без маршрута](#fallback)); остальные — нет. |
| [[ui:emu.failed]] | Обмены, в которых ответ не удалось составить или отправить. |
| [[ui:emu.down]] | То, что пришло, пока эмулятор был отключён. Показывается, если у него задано отключение или что-то застало его отключённым. Никогда не попадает в [[ui:emu.unmatched]]. |
| [[ui:emu.missed]] | Только MQTT и только если такое случилось: сообщения, которые клиент не смог принять, слишком отстав. |

В заголовке каждого правила видно, сколько раз оно сработало с момента запуска.

Список [[ui:emu.received]] показывает последние 300 обменов, новые сверху:

| Столбец | Что |
| --- | --- |
| [[ui:emu.col.time]] | Когда пришло. |
| [[ui:emu.col.from]] | Адрес клиента. |
| [[ui:emu.col.request]] | Что пришло, в нотации протокола: `GET /users/7`, `/ping 1`, `POWER?`. |
| [[ui:emu.col.rule]] | Правило, которое это взяло (`#2`), или `—`. |
| [[ui:emu.col.reply]] | Что ушло обратно: `200 OK · 37 B`, `/pong 3`, содержимое; [[ui:emu.held]] или [[ui:emu.closed]] при сбое; ошибка, если ответить не удалось; [[ui:emu.wasDown]], если пришло во время отключения. |
| [[ui:emu.col.ms]] | От прихода до отправки ответа, включая задержку. |

Кнопка ⌕ в строке ([[ui:emu.inspectFrame]]) открывает этот обмен в Инспекторе, если
захват был включён. Если за пятую долю секунды приходит больше 200 обменов, список
пропускает часть и пишет, сколько. Движок хранит последние 500 обменов каждого
запущенного эмулятора вместе с тем, что пришло, — для командной строки, API и MCP.

## HTTP API {#http}

Сервер HTTP/1.1. Каждому запросу отвечает первый маршрут, который его берёт.

### Маршруты {#routes}

Маршрут берёт запрос, когда совпадают его метод, путь и все условия.

| Поле | Что |
| --- | --- |
| [[ui:emu.method]] | `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS` или [[ui:emu.methodAny]]. Маршрут `GET` отвечает и на `HEAD`. |
| [[ui:emu.path]] | Начинается с `/`. Сегмент `:name` берёт любой один сегмент и читается как `{{request.params.name}}`; последний сегмент `*` берёт всё, что ниже. Завершающий `/` ничего не меняет; строка запроса в путь не входит. |
| [[ui:emu.conditions]] | Должны выполняться все. Добавьте условие кнопкой ＋ [[ui:emu.addCondition]]. |

Примеры путей:

| Путь | Берёт | Не берёт |
| --- | --- | --- |
| `/health` | `/health`, `/health/` | `/health/db`, `/Health` |
| `/users/:id` | `/users/7` (`params.id` равен `7`), `/users/a%20b` (`a b`) | `/users`, `/users/7/orders` |
| `/files/*` | `/files`, `/files/a`, `/files/a/b/c` | `/file`, `/other/files/a` |

Условие читает одну часть запроса ([[ui:emu.on]]) и сравнивает её:

| [[ui:emu.on]] | Имя | Что читает |
| --- | --- | --- |
| [[ui:emu.on.header]] | Имя заголовка, в любом регистре | Значение заголовка; если заголовок пришёл несколько раз — его значения через `, `. |
| [[ui:emu.on.query]] | Параметр запроса | Его значение, декодированное; если он повторяется — первое. |
| [[ui:emu.on.body]] | — | Всё тело как текст. |
| [[ui:emu.on.json]] | Путь JSON, например `$.user.id` | Это поле тела JSON. |

Сравнения: [[ui:exp.op.eq]], [[ui:exp.op.ne]], [[ui:exp.op.lt]], [[ui:exp.op.le]],
[[ui:exp.op.gt]], [[ui:exp.op.ge]], [[ui:exp.op.contains]], [[ui:exp.op.matches]],
[[ui:exp.op.empty]] и [[ui:exp.op.not_empty]]. Числа сравниваются как числа, текст —
точно. Отсутствующий заголовок, параметр или поле считаются пустыми. Сравнение, которое
невозможно выполнить, — текста с числом — считается невыполненным.

### Ответы {#responses}

У маршрута от одного до 16 ответов ([[ui:emu.responses]]).

| Поле | Что | По умолчанию |
| --- | --- | --- |
| [[ui:emu.status]] | 100–599. | 200 |
| [[ui:emu.fault]] | Что-то иное, чем ответ; см. [Сбои](#faults). | [[ui:emu.fault.none]] |
| [[ui:emu.delay]] | Сколько ждать перед ответом, 0–60 000 мс. | 0 |
| [[ui:emu.jitter]] | Случайная добавка к ожиданию, до этой величины, 0–60 000 мс. | 0 |
| [[ui:emu.weight]] | Доля этого ответа, когда маршрут отвечает случайно. Показывается только в этом случае. | 1 |
| [[ui:emu.headers]] | До 32. В именах можно использовать параметры; значения — [шаблоны](#templates). | нет |
| [[ui:emu.body]] | [Шаблон](#templates), до 256 КиБ в записанном виде. | пусто |

Без заголовка `Content-Type` тело, которое является корректным JSON, уходит как
`application/json`, а любое другое — как `text/plain; charset=utf-8`.

Когда ответов два или больше, поле [[ui:emu.order]] определяет, какой из них получит
запрос:

| [[ui:emu.order]] | Что получают запросы | Для чего |
| --- | --- | --- |
| [[ui:emu.order.sequence]] | Первый, второй, …, а затем всё время последний: 500, 500, 200, 200, 200… | Повторы: два сбоя, потом работает. |
| [[ui:emu.order.cycle]] | После последнего снова первый: 200, 500, 200, 500… | Зависимость, которая регулярно сбоит время от времени. |
| [[ui:emu.order.random]] | Каждый раз выбирается по весу. Веса 8 и 2 дают первый ответ примерно в 80 % случаев. Хотя бы один вес должен быть больше 0. | Реалистичная доля сбоев. |

В списке [[ui:emu.preset]] можно добавить к маршруту готовый ответ:

| Пресет | Что добавляет |
| --- | --- |
| [[ui:emu.preset.ok]] | 200, `{"ok":true}` |
| [[ui:emu.preset.created]] | 201, `{"id":"{{uuid}}"}`, заголовок `Location: {{request.path}}/{{counter}}` |
| [[ui:emu.preset.notFound]] | 404, `{"error":"not found"}` |
| [[ui:emu.preset.error]] | 500, `{"error":"internal"}` |
| [[ui:emu.preset.unavailable]] | 503, `{"error":"unavailable"}`, заголовок `Retry-After: 1` |
| [[ui:emu.preset.slow]] | 200, `{"ok":true}` через 2000 мс |
| [[ui:emu.preset.timeout]] | Сбой [[ui:emu.fault.timeout]] |
| [[ui:emu.preset.reset]] | Сбой [[ui:emu.fault.reset]] |
| [[ui:emu.preset.malformed]] | 200, `{"items":[{"id":1},{"id":2}]}` со сбоем [[ui:emu.fault.malformed]] |

### Сбои {#faults}

| [[ui:emu.fault]] | Что встречает клиент |
| --- | --- |
| [[ui:emu.fault.none]] | Ответ. |
| [[ui:emu.fault.timeout]] | Ничего. Запрос удерживается до 2 минут, затем соединение закрывается — так проверяется собственный тайм-аут клиента. Задержка не применяется. |
| [[ui:emu.fault.reset]] | Соединение закрывается без ответа, после задержки. |
| [[ui:emu.fault.malformed]] | Полный HTTP-ответ с заданными статусом и заголовками, тело которого обрывается на середине: JSON, который не разбирается. Если всё тело было JSON, тип содержимого по-прежнему `application/json`. |

### Запросы без маршрута {#fallback}

Поле [[ui:emu.fallback]] определяет, что получает запрос, который не подошёл ни к одному
маршруту:

- [[ui:emu.fallbackDefault]] — 404 с телом `{"error":"no_route"}`;
- [[ui:emu.fallbackCustom]] — заданный вами ответ со всем, что есть у ответа маршрута.
  Его `{{counter}}` считает запросы, которые не взял ни один маршрут.

В обоих случаях запрос попадает в счётчик [[ui:emu.unmatched]].

### Что может прочитать HTTP-ответ {#http-request}

| Шаблон | Что это |
| --- | --- |
| `{{request.method}}` | `GET`, `POST`, … |
| `{{request.path}}` | Путь, без строки запроса. |
| `{{request.params.id}}` | Сегмент пути с именем `:id`. |
| `{{request.query.page}}` | Параметр запроса, декодированный. |
| `{{request.headers.x-key}}` | Заголовок; имена в нижнем регистре. |
| `{{request.body}}` | Тело как текст: его первые 64 КиБ. |
| `{{request.json.name}}` | Поле тела JSON, если тело — JSON и не больше 64 КиБ. |
| `{{request.from}}` | `IP:port` клиента. |

Запрос с телом больше 1 МиБ получает 413 и попадает в счётчик [[ui:emu.failed]]. Ответ,
который не удалось составить, — шаблон ссылается на то, чего в запросе нет, —
заменяется на 500 с ошибкой в теле и тоже попадает в счётчик [[ui:emu.failed]].

## OSC-устройство {#osc}

Каждому пришедшему сообщению — и каждому сообщению бандла по отдельности — отвечает
первое правило, к которому оно подходит. Датаграмма, которая не является OSC, попадает в
счётчик [[ui:emu.unmatched]].

| Поле | Что |
| --- | --- |
| [[ui:emu.address]] | Шаблон адреса OSC 1.0: `*` — любые символы, `?` — один символ, `[a-z]` — набор, `{a,b}` — любой из вариантов, каждый в пределах одного сегмента (см. [OSC](../protocols/osc.md#patterns)). |
| [[ui:exp.argRules]] | До 16 условий на аргументы, как в узле [[ui:exp.node.wait_osc]] (см. [Узлы](../experiments/nodes.md#node-wait_osc)). |
| [[ui:emu.replyOn]] | Флажок снят: принять сообщение и ничего не отвечать. |
| [[ui:emu.replyAddress]] | Адрес ответа, [шаблон](#templates). |
| [[ui:emu.replyArgs]] | До 16 аргументов, у каждого [[ui:emu.argType]] (`int`, `float`, `str`, `long`, `double`, `bool`, `blob`, `nil`) и [[ui:emu.argValue]] — шаблон. |
| [[ui:emu.to]] | Пусто: обратно на адрес и порт отправителя. Иначе `IP:port`. |
| [[ui:emu.delay]], [[ui:emu.jitter]] | По 0–60 000 мс. |

Значение аргумента читается как его тип после заполнения шаблона: `{{request.args[0]}}`
возвращает первый аргумент числом, если тип числовой. `bool` принимает `true`, `1`,
`yes`, `on` или `false`, `0`, `no`, `off`; `blob` — байты в hex; пустое значение — ноль
этого типа.

Ответы уходят с собственного порта эмулятора, поэтому их слышит клиент, который слушает
тот порт, с которого отправлял.

OSC-ответ может читать `{{request.address}}`, `{{request.args[0]}}` и
`{{request.from}}`.

## UDP-устройство {#udp}

Каждой датаграмме отвечает первое правило, к которому она подходит.

| Поле | Что |
| --- | --- |
| [[ui:emu.match]] | [[ui:exp.mode.any]], [[ui:exp.mode.contains]], [[ui:exp.mode.regex]] или [[ui:exp.mode.hex]]. |
| [[ui:emu.pattern]] | Текст, регулярное выражение или байты, которые нужно найти. |
| [[ui:emu.reply]] | [[ui:emu.replyOff]], [[ui:emu.replyText]] или [[ui:emu.replyHex]], а затем сам ответ — [шаблон](#templates). |
| [[ui:emu.to]] | Пусто: обратно отправителю. Иначе `IP:port`. |
| [[ui:emu.delay]], [[ui:emu.jitter]] | По 0–60 000 мс. |

UDP- или TCP-ответ может читать:

| Шаблон | Что это |
| --- | --- |
| `{{request.text}}` | Содержимое как текст. |
| `{{request.match}}` | Что совпало: текст, первая группа регулярного выражения (или всё совпадение), байты. |
| `{{request.hex}}` | Содержимое в виде hex-байтов, первые 1024. |
| `{{request.bytes}}` | Размер содержимого. |
| `{{request.from}}` | `IP:port` отправителя. |

Текстовый ответ — не больше 65 507 байт.

## TCP-устройство {#tcp}

Устройство, которое обменивается строками по TCP-соединению, как проектор или матричный
коммутатор. Каждому сообщению клиента отвечает первое правило, к которому оно подходит;
ответ уходит обратно по тому же соединению.

| Поле | Что |
| --- | --- |
| [[ui:emu.delimiter]] | Что завершает сообщение и добавляется после каждого ответа и приветствия: [[ui:emu.delimiter.lf]] (`\r` перед ним отбрасывается), [[ui:emu.delimiter.crlf]], [[ui:emu.delimiter.cr]] или [[ui:emu.delimiter.none]]. Пустые строки пропускаются. |
| [[ui:emu.greeting]] | Отправляется, когда клиент подключается; пусто — без приветствия. Может читать `{{request.from}}`. |
| [[ui:emu.match]], [[ui:emu.pattern]], [[ui:emu.reply]] | Как у [UDP-устройства](#udp). |
| [[ui:emu.close]] | Закрыть соединение после ответа этого правила — например, на `QUIT`. |
| [[ui:emu.delay]], [[ui:emu.jitter]] | По 0–60 000 мс. |

Сообщение длиннее 64 КиБ без разделителя берётся как есть.

## MQTT-брокер {#mqtt}

Небольшой брокер MQTT 3.1.1 поверх обычного TCP. Он делает то же, что любой брокер:
клиенты подключаются, подписываются с `+` и `#`, публикуют с QoS 0, 1 и 2,
retained-сообщения и завещания (last will) работают, а второе подключение с тем же id
клиента вытесняет первое. Сессии всегда чистые: клиент, который просит сохранить сессию,
получает новую, и для отсутствующего клиента ничего не копится.

Вдобавок каждое опубликованное на нём сообщение проверяется по правилам: первое
подошедшее ещё и публикует ответ — как устройство, которое сообщает, что сделало.

| Поле | Что |
| --- | --- |
| [[ui:emu.username]], [[ui:emu.password]] | Если имя пользователя задано, клиент должен подключиться с ним и с паролем; пусто — подключиться может кто угодно. Пароль без имени пользователя отклоняется: MQTT 3.1.1 не может его передать. |
| [[ui:emu.retained]] | До 64 сообщений ([[ui:emu.topic]], [[ui:emu.payload]], [[ui:emu.qos]]), которые хранятся с момента запуска, как будто опубликованы с retain: подписавшийся клиент получает их первыми. |
| [[ui:emu.topicFilter]] | Какие топики берёт правило: `+` — один уровень, `#` — все остальные, например `lab/+/set`. |
| [[ui:emu.match]], [[ui:emu.pattern]] | Условие на содержимое, как у [UDP-устройства](#udp). |
| [[ui:emu.replyOn]] | Флажок снят: принять сообщение и больше ничего не публиковать. |
| [[ui:emu.replyTopic]], [[ui:emu.replyPayload]] | [Шаблоны](#templates). В топике не может быть `+` или `#`. |
| [[ui:emu.qos]], [[ui:emu.retain]] | Для ответа. |
| [[ui:emu.delay]], [[ui:emu.jitter]] | По 0–60 000 мс. |

MQTT-ответ может читать `{{request.topic}}`, `{{request.levels[1]}}` (уровни топика,
начиная с 0), `{{request.payload}}`, `{{request.json.state}}`, `{{request.match}}`,
`{{request.qos}}`, `{{request.retain}}`, `{{request.client}}` (id клиента) и
`{{request.from}}`.

## Шаблоны в ответах {#templates}

Ответы пишутся на том же [языке шаблонов](../experiments/data.md#templates), что и
эксперименты, поэтому поле значит одно и то же и здесь, и там. Ответ может читать:

- `request` — то, что пришло, как перечислено выше для каждого протокола;
- `{{counter}}` — сколько сообщений взяло это правило с момента запуска эмулятора,
  включая текущее;
- [генераторы](../experiments/data.md#generators) — `{{uuid}}`, `{{now.iso}}`, случайные
  значения и остальные; случайные значения берутся из seed эмулятора;
- параметры — когда эмулятор работает в эксперименте или запущен через
  `signallab emulate --param`.

Секреты ответ не читает никогда, а неизвестное имя — это ошибка, а не пустой текст.

Некоторые поля фиксируются при запуске эмулятора, ещё до того, как что-то придёт: путь,
условие, шаблон адреса, шаблон содержимого, фильтр топика, [[ui:emu.to]], имя заголовка,
retained-сообщения и учётные данные брокера. Они принимают только текст и параметры —
без `request` и без генераторов.

Seed управляет случайным порядком ответов, разбросом задержки и случайными генераторами.
На экране [[ui:nav.emulators]] каждый запуск получает новый seed; эксперимент использует
seed запуска, а `signallab emulate --seed` берёт тот, что вы укажете.

## Отключения {#outage}

Чтобы проверить, что делает ваша система, когда зависимость то пропадает, то появляется,
установите флажок [[ui:emu.outage]]:

| Поле | Что | По умолчанию |
| --- | --- | --- |
| [[ui:emu.outageUp]] | Сколько эмулятор отвечает, 10–3 600 000 мс. | 10 000 |
| [[ui:emu.outageDown]] | Сколько он отключён, 10–3 600 000 мс. | 3000 |
| [[ui:emu.outageFault]] | Только HTTP: что встречает запрос, пока эмулятор отключён. | [[ui:emu.outageFault.unavailable]] |

Расписание начинается с запуска эмулятора и повторяется: работает, отключён, работает,
отключён… Пока он отключён:

| Эмулятор | Что встречает клиент |
| --- | --- |
| HTTP | [[ui:emu.outageFault.unavailable]]: 503 с `Retry-After`, равным числу секунд до возвращения (не меньше 1). [[ui:emu.outageFault.reset]]: соединение закрывается без ответа. [[ui:emu.outageFault.timeout]]: запрос удерживается до 2 минут, затем соединение закрывается. |
| TCP-устройство | Открытые соединения рвутся в течение 0,1 с; новые закрываются сразу при подключении. |
| MQTT-брокер | Все соединения рвутся; новые отклоняются (код возврата CONNACK 3, сервер недоступен). |
| OSC-, UDP-устройство | Ничего не отвечает. |

То, что приходит во время отключения, попадает в счётчик [[ui:emu.down]], а не в
[[ui:emu.unmatched]], и правила при этом не опрашиваются.

Кнопка [[ui:emu.takeDown]] делает то же самое по требованию, что бы ни говорило
расписание, пока вы не нажмёте [[ui:emu.bringUp]]; HTTP тогда встречает 503 без
`Retry-After`. В эксперименте то же самое на нужном шаге запуска делает узел
[[ui:exp.node.emulator_state]] (см. [Узлы](../experiments/nodes.md#node-emulator_state)
и [Сбои](../experiments/faults.md)).

## Ошибки в эмуляторе {#problems}

Пока вы редактируете, эмулятор проверяется через мгновение после каждого изменения, и
ошибка показывается под его кнопками ещё до того, как вы нажмёте [[ui:emu.start]].
Ошибка указывает место — правило, ответ или retained-сообщение и поле — и что не так:
путь без `/`, регулярное выражение, которое не компилируется, шаблон ответа, который
ссылается на что-то кроме `request`, параметров и генераторов, значение вне допустимого
диапазона. Кнопка [[ui:emu.start]] не запустит эмулятор с ошибкой.

## Ограничения {#limits}

| Что | Ограничение | При достижении |
| --- | --- | --- |
| Маршрутов или правил на эмулятор | 64 | Эмулятор отклоняется при проверке. |
| Ответов на маршрут | 16 | Отклоняется. |
| Условий на маршрут | 16 | Отклоняется. |
| Заголовков на ответ | 32 | Отклоняется. |
| Условий на аргументы, аргументов ответа (OSC) | по 16 | Отклоняется. |
| Retained-сообщений (MQTT) | 64 | Отклоняется. |
| Тело, ответ или приветствие в записанном виде | 256 КиБ | Отклоняется. |
| Задержка или разброс | 60 000 мс | Отклоняется. |
| Тело HTTP-запроса | 1 МиБ | 413. |
| HTTP-соединений одновременно | 512 | Лишние закрываются сразу при подключении. |
| Строка и заголовки HTTP-запроса | 30 с | Клиент должен прислать их за это время. |
| TCP-соединений одновременно | 256 | Лишние закрываются сразу при подключении. |
| OSC- и UDP-ответов, ожидающих своей задержки | 1024 | Лишние отбрасываются и попадают в счётчик [[ui:emu.failed]]. |
| MQTT-клиентов одновременно | 256 | Лишние закрываются сразу при подключении. |
| MQTT-пакет | 256 КиБ | Соединение клиента разрывается. |
| MQTT-подписок на клиента | 100 | Лишние отклоняются. |
| Retained-топиков MQTT | 1000 топиков, 16 МиБ | Новое retained-сообщение доставляется, но не сохраняется. |
| MQTT-сообщений в очереди одного медленного клиента | 1024 сообщения, 8 МиБ | Клиент их пропускает; они попадают в счётчик [[ui:emu.missed]]. |

## Эмулятор из ответа {#mock-this}

Чтобы сделать эмулятор из ответа, который сработал:

1. На экране [[ui:nav.http]] отправьте запрос и получите ответ — или нажмите
   [[ui:exp.sendNow]] на HTTP-узле эксперимента.
2. Нажмите ⧉ [[ui:http.mockThis]] рядом с ответом. Окно [[ui:http.mockTitle]] покажет
   маршрут, который будет создан.
3. В поле [[ui:http.mockInto]] выберите один из своих HTTP-эмуляторов или
   [[ui:http.mockNew]].
4. Нажмите [[ui:http.mockAdd]]. Откроется экран [[ui:nav.emulators]] на этом эмуляторе.

Маршрут отвечает на метод и путь запроса (без строки запроса) статусом, заголовками и
телом ответа. Заголовки, которые относятся только к тому обмену (`Content-Length`,
`Date`, `Server`, `ETag` и подобные), не переносятся, а тело отправляется как было, даже
если в нём есть `{{`. Новый эмулятор содержит только этот маршрут. При добавлении в
существующий эмулятор маршрут встаёт первым, чтобы отвечать раньше более общего
маршрута; запущенный эмулятор подхватит его, когда вы нажмёте [[ui:emu.restart]].

Если ответ взят из эксперимента, URL, записанный с шаблонами, превращается в шаблон пути:
его основа (`{{api}}`) отбрасывается, сегмент, который целиком является шаблоном
(`/orders/{{order_id}}`), становится `:order_id`, а сегмент, лишь частично состоящий из
шаблона, завершает путь звёздочкой `*`.

## Стартовый набор {#starter-set}

Впервые не найдя библиотеку эмуляторов, Signal Lab записывает пять эмуляторов, все на
этом компьютере. Их названия и заметки пишутся на языке, выбранном в интерфейсе в этот
момент.

| Эмулятор | Слушает | Что делает |
| --- | --- | --- |
| [[ui:seed.emu.demo-api.name]] | `127.0.0.1:8080` | `GET /health` → `{"status":"ok","time":…}`; `GET /users/:id` → пользователь с этим id; `POST /users` → 201 с `Location`; `GET /slow` → ответ через 1500 мс; `/flaky` → 503, 503, а дальше всё время 200. |
| [[ui:seed.emu.osc-device.name]] | `127.0.0.1:9100` | `/ping` → `/pong` со счётчиком; `/fader/*` → `/ack` с полученным адресом; `/cue/*` принимается без ответа. |
| [[ui:seed.emu.udp-device.name]] | `127.0.0.1:7100` | `PING` → `PONG` и счётчик; всё остальное → `ACK` и его размер в байтах. |
| [[ui:seed.emu.tcp-device.name]] | `127.0.0.1:7200` | Строки, оканчивающиеся на CR LF. Приветствует `READY`; `POWER?` → `POWER=ON`; `POWER ON` или `POWER OFF` → `OK ON` / `OK OFF`; `QUIT` → `BYE`, затем разрывает соединение. |
| [[ui:seed.emu.mqtt-broker.name]] | `127.0.0.1:1883` | Хранит retained `online` в `lab/status`; `ON` или `OFF`, опубликованные в `lab/<name>/set` → то же самое, retained, в `lab/<name>/state`. |

Стартовый сигнал [[ui:seed.http-reachable.name]] из
[библиотеки сигналов](signals.md#starter-set) запрашивает `http://127.0.0.1:8080/` —
адрес эмулятора [[ui:seed.emu.demo-api.name]]: маршрута для `/` у того нет, поэтому сигнал получает
404.

## Файл библиотеки {#file}

Библиотека — это файл `emulators.json` в папке данных (см.
[Файлы](../reference/files.md)); наведите указатель на счётчик под списком, чтобы увидеть
его путь. Файл записывается целиком через 0,7 с после последнего изменения, через
временный файл, так что неудачная запись оставляет прежний. Если файл не читается,
список показывает ошибку с путём, строкой и столбцом, а сам файл остаётся как есть:
исправьте его и нажмите [[ui:emu.reload]]. Нажмите [[ui:emu.reload]] и после того, как
отредактировали файл вручную. Если файла нет, стартовый набор записывается снова.

```json
{
  "version": 1,
  "emulators": [
    {
      "id": "orders-api",
      "note": "Stands in for the orders service.",
      "emulator": {
        "name": "Orders API",
        "bind": "127.0.0.1:18080",
        "protocol": "http",
        "routes": [
          { "method": "GET", "path": "/orders/:id",
            "responses": [{ "body": "{\"id\":\"{{request.params.id}}\",\"state\":\"open\"}" }] },
          { "method": "POST", "path": "/orders", "order": "sequence",
            "responses": [{ "status": 503 }, { "status": 201, "body": "{\"id\":\"{{uuid}}\"}" }] }
        ],
        "outage": { "up_ms": 20000, "down_ms": 2000, "fault": "unavailable" }
      }
    }
  ]
}
```

Объект `emulator` сам по себе — тоже документ, который читает `signallab emulate`.

## В экспериментах и скриптах {#elsewhere}

- В эксперименте узел [[ui:exp.node.emulator]] открывает свой эмулятор до первого шага и
  отвечает, пока запуск не закончится; то, что он получил, подсчитывается в отчёте.
  HTTP-эмулятор там же — это и есть то, что слушает узел [[ui:exp.node.wait_http]]
  ([Узлы](../experiments/nodes.md#node-wait_http)), а OSC- или UDP-эмулятор делит свой
  порт с ожиданиями запуска. Два эмулятора одного транспорта в одном эксперименте не
  могут делить порт. См. [Узлы](../experiments/nodes.md#node-emulator) и
  [Сбои](../experiments/faults.md).
- `signallab emulate` запускает эмуляторы из файлов или из этой библиотеки до
  <kbd>Ctrl</kbd>+<kbd>C</kbd> или до истечения `--for` и печатает, что они отвечают; см.
  [Командная строка](../automation/cli.md#cli-emulate).
