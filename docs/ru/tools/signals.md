# Сигналы

Сигнал — это сообщение, которому вы дали имя и которое сохранили: OSC-сообщение, сырая
датаграмма UDP, HTTP-запрос или публикация MQTT вместе с адресатом. Вы создаёте его один
раз — на экране [[ui:nav.signals]] или сохранив то, что только что отправили с другого
экрана, — и отправляете снова, когда нужно, байт в байт так же.

Библиотека — это файл JSON, который можно читать, править вручную, копировать на другой
компьютер или коммитить рядом с проектом. Экран [[ui:nav.signals]] показывает её слева как
дерево папок, а справа — поля выбранного сигнала.

## Что может отправлять сигнал {#transports}

Выберите вид в поле [[ui:sig.transport]]. У каждого вида свои поля:

| [[ui:sig.transport]] | Поля | Что уходит |
| --- | --- | --- |
| [[ui:sig.tr.osc]] | [[ui:common.target]], [[ui:common.address]], [[ui:common.arguments]] | Одно OSC-сообщение на один `IP:port` или `host:port` с нового порта UDP. Типы аргументов — на странице [OSC](../protocols/osc.md#types). |
| [[ui:sig.tr.udp]] | [[ui:common.target]], [[ui:sig.payloadKind]] ([[ui:sig.payloadText]] или [[ui:sig.payloadHex]]), [[ui:sig.payload]] | Одна датаграмма ровно с этими байтами. Текст уходит как написан, без терминатора; hex — это пары цифр вроде `de ad be ef` (пробелы и префикс `0x` допустимы). |
| [[ui:sig.tr.http]] | [[ui:sig.method]], [[ui:sig.url]], [[ui:sig.timeout]], [[ui:sig.headers]], [[ui:field.auth]], [[ui:sig.body]] | Один HTTP-запрос. См. [HTTP](../protocols/http.md). |
| [[ui:sig.tr.mqtt]] | [[ui:mq.broker]], [[ui:mq.topic]], [[ui:mq.qos]], [[ui:mq.retain]], [[ui:sig.payload]] | Одна публикация. См. [MQTT](../protocols/mqtt.md). |

У каждого сигнала есть и поля [[ui:sig.name]], [[ui:sig.group]] и [[ui:sig.note]]; в заметке
можно записать, что сигнал должен вызвать и что должно совпасть на другом конце.

Адресаты OSC- и UDP-сигналов — это `IP:port` или `host:port` (например, `127.0.0.1:9000`);
имя хоста разрешается при каждой отправке сигнала. Брокер MQTT-сигнала — `host:port`;
без порта это `1883`.

Когда вы меняете вид сигнала, его сообщение начинается заново со значений по умолчанию для
нового вида. Сохраняется только адресат, и только при переходе между [[ui:sig.tr.osc]] и
[[ui:sig.tr.udp]], где адресат значит одно и то же.

## Отправка сигнала {#send}

Чтобы отправить сигнал с экрана [[ui:nav.signals]], сделайте любое из этого:

- Выберите его и нажмите [[ui:sig.fire]].
- Нажмите <kbd>Ctrl</kbd>+<kbd>Enter</kbd>, пока работаете в его полях.
- Дважды щёлкните его в дереве.

Каждая отправка пишет в консоль строку: что и куда ушло, сколько байт, а для HTTP — статус и
затраченное время. Ошибка (отказ в соединении, недоступный хост) — красная строка с
причиной. Время последней отправки показано рядом с кнопками.

Сигнал уходит через те же команды, что и экраны его протокола, поэтому
[Инспектор](inspector.md) показывает его под тем инструментом, который его отправил, а
другой конец не отличит его от набранного вручную.

Как отправляется каждый вид:

| Вид | Как уходит |
| --- | --- |
| [[ui:sig.tr.osc]] | Так же, как отправляет сообщение экран [[ui:nav.osc]]. |
| [[ui:sig.tr.udp]] | Одна датаграмма на адресата. |
| [[ui:sig.tr.http]] | Так же, как отправляет запрос экран [[ui:nav.http]], — с его банкой cookie, пока там включён параметр [[ui:http.keepCookies]]. Отказ в соединении или тайм-аут считается ошибкой, а не статусом. |
| [[ui:sig.tr.mqtt]] | Пока экран [[ui:nav.mqtt]] подключён к брокеру сигнала — по этому соединению, с его id клиента и учётными данными. Иначе — если соединения нет или оно с другим брокером — Signal Lab подключается к брокеру сигнала ради этой одной публикации, со своим id клиента, без имени пользователя и с чистой сессией, затем отключается. |

Соединение считается соединением с брокером сигнала, когда хост тот же (без учёта регистра)
и порт тот же, причём `1883` подразумевается для брокера, записанного без порта. Имена не
разрешаются: `localhost` и `127.0.0.1` здесь — два разных брокера, поэтому сигнал, который
называет один из них, не отправляется по соединению с другим.

::: tip
MQTT-сигнал не хранит пароль. Чтобы публиковать на брокер, который его запрашивает, сначала
подключитесь к этому брокеру на экране [[ui:nav.mqtt]]; сигнал пойдёт по этому соединению.
:::

## Отправка с любого экрана {#palette}

Нажмите <kbd>Ctrl</kbd>+<kbd>K</kbd> на любом экране, чтобы открыть палитру, введите
несколько букв имени сигнала, его папки, адресата или сообщения и нажмите
<kbd>Enter</kbd>. Палитра закроется, сигнал будет отправлен, а вы останетесь на экране, за
которым наблюдали.

| Клавиша | Что делает |
| --- | --- |
| <kbd>Ctrl</kbd>+<kbd>K</kbd> | Открывает палитру или закрывает её. |
| <kbd>↑</kbd> <kbd>↓</kbd> | Перемещает выбор. |
| <kbd>Enter</kbd> | Отправляет выбранный сигнал. |
| <kbd>Esc</kbd> | Закрывает палитру без отправки. |

Палитра показывает не больше 12 сигналов: пока вы ничего не набрали — первые 12 из
библиотеки, затем первые 12 подходящих. Щелчок по строке отправляет сигнал; щелчок вне
палитры закрывает её.

## Создание сигналов {#create}

### На экране сигналов {#create-here}

1. Выберите папку, в которой должен лежать сигнал (см. [текущую папку](#current-folder)).
2. Нажмите [[ui:sig.new]]. В этой папке появится новый OSC-сигнал на `127.0.0.1:9000` с
   адресом `/hello`, он будет выбран.
3. Измените [[ui:sig.name]], [[ui:sig.transport]] и поля сообщения.

Каждое изменение сохраняется само; кнопки сохранения на этом экране нет. Пока файл
библиотеки нельзя прочитать, ничего не сохраняется, а поля доступны только для чтения (см.
[Файл библиотеки](#file)).

Кнопка [[ui:sig.duplicate]] помещает копию сразу после выбранного сигнала, добавляя к его
имени `·`. Кнопка [[ui:sig.delete]] спрашивает ещё раз ([[ui:sig.confirmDelete]]): второй
щелчок удаляет сигнал из файла. Его папка остаётся, даже если теперь пуста.

### С экранов HTTP, OSC и MQTT {#save-from-screens}

Отправляющая часть трёх экранов — [[ui:http.request]] на экране [[ui:nav.http]],
[[ui:osc.sender]] на экране [[ui:nav.osc]], [[ui:mq.publish]] на экране [[ui:nav.mqtt]] —
может сохранить то, что отправила бы, как сигнал.

1. Настройте сообщение и отправляйте, пока оно не станет делать то, что нужно.
2. Нажмите [[ui:sig.saveNew]] (или <kbd>Ctrl</kbd>+<kbd>S</kbd> в этой части экрана).
   Откроется диалог [[ui:sig.saveTitle]].
3. Проверьте [[ui:sig.name]]: оно предлагается по тому, что отправляется.
4. Выберите или введите [[ui:sig.group]]. Подставляется папка, которой вы пользовались в
   прошлый раз; путь вроде `Venue/Stage`, которого ещё нет, будет создан.
5. Нажмите [[ui:sig.saveConfirm]].

С этого момента экран связан с этим сигналом. Плашка рядом с кнопками сообщает, где он лежит
(`❖ Folder / Name`); щёлкните её, чтобы увидеть сигнал на экране [[ui:nav.signals]].

| Что вы видите | Что это значит | Что можно сделать |
| --- | --- | --- |
| ✓ [[ui:sig.savedState]] (серым) | Библиотека хранит ровно то, что отправил бы экран. | Сохранять нечего. |
| [[ui:sig.save]] и [[ui:sig.changed]] на плашке | Сообщение экрана отличается от сигнала. | [[ui:sig.save]] или <kbd>Ctrl</kbd>+<kbd>S</kbd> записывает сообщение экрана в этот сигнал; его имя, папка и заметка остаются. |
| [[ui:sig.saveAs]] | — | Снова открывает диалог, заполненный именем и папкой сигнала, и сохраняет новый сигнал. Экран после этого связан с новым. |

Сравнение смотрит на сообщение, а не на то, как оно записано: порядок ключей JSON и
последние цифры OSC float сверх 32-битной точности изменением не считаются.

Экраны [[ui:nav.http]] и [[ui:nav.osc]] сохраняют связь при перезапуске Signal Lab; экран
[[ui:nav.mqtt]] — до закрытия приложения.

::: warning
HTTP-сигнал хранит содержимое поля [[ui:field.auth]] — имя пользователя и пароль или токен —
в файле библиотеки открытым текстом. Кто может прочитать файл, тот может прочитать и их.
:::

### Открытие сигнала на его экране {#open-in-screen}

У выбранного HTTP-, OSC- или MQTT-сигнала есть кнопка, которая открывает его на экране его
протокола ([[ui:nav.http]], [[ui:nav.osc]] или [[ui:nav.mqtt]]). Поля экрана заполняются из
сигнала, и экран связывается с ним, как описано выше: правьте там, отправляйте, затем
[[ui:sig.save]]. У сырого UDP-сигнала собственного экрана нет.

### Из кадра или топика {#capture}

- В [Инспекторе](inspector.md#save-as-signal) выберите кадр и нажмите [[ui:sig.fromFrame]].
  Датаграмма становится сырым UDP-сигналом с точными байтами этого кадра; публикация MQTT —
  MQTT-сигналом с теми же брокером, топиком, QoS, флагом retain и содержимым. Другие кадры
  сохранить нельзя.
- На экране [[ui:nav.mqtt]] выберите топик и нажмите [[ui:sig.fromFrame]]. Получится
  MQTT-сигнал, который публикует последнее значение топика, с его QoS и флагом retain, на
  брокер, к которому вы подключены.

Оба попадают в папку [[ui:sig.capturedFolder]] и называются по тому, что было захвачено.

### В эксперименте {#in-experiments}

Когда вы добавляете узел в эксперимент, меню [[ui:exp.addNode]] показывает и ваши сигналы в
группе [[ui:exp.group.signals]]. Выбрав один, вы добавляете узел OSC, HTTP, MQTT или UDP с
тем же сообщением. Сырой UDP-сигнал с hex-содержимым не предлагается: UDP-узел отправляет
текст. См. [Узлы](../experiments/nodes.md).

## Папки {#folders}

Папка — это путь из имён, соединённых через `/`: `API/Auth` — папка `Auth` внутри `API`.
Поле [[ui:sig.group]] сигнала хранит путь к его папке; пустое значение означает верхний
уровень ([[ui:sig.topLevel]]). Когда вы выходите из поля, имена обрезаются от пробелов, а
пустые части отбрасываются, так что ` API / Auth/ ` превращается в `API/Auth`.

Папки сортируются по имени, числа — в числовом порядке (`Cue 2` перед `Cue 10`); сигналы
остаются в порядке файла. Каждая папка показывает, сколько сигналов она содержит, включая
вложенные папки. Пустая папка сохраняется, пока вы её не удалите.

### Текущая папка {#current-folder}

Текущая папка — та, по которой вы щёлкнули последней, или папка выбранного сигнала:
[[ui:sig.new]] и [[ui:sig.newFolder]] создают новое в ней. Плашка над деревом называет её;
щёлкните плашку, чтобы вернуться на верхний уровень.

### Работа с папками {#folder-tasks}

| Чтобы | Сделайте так |
| --- | --- |
| Создать папку | Нажмите ＋ [[ui:sig.newFolder]]. Она создаётся внутри текущей папки с именем [[ui:sig.newFolderName]] (с номером после него, если имя занято), и вы сразу же её переименовываете. |
| Открыть или закрыть папку | Щёлкните её или нажмите <kbd>→</kbd> / <kbd>←</kbd>, пока она в фокусе. Signal Lab запоминает, какие папки закрыты. |
| Открыть или закрыть все | Кнопки ⊞ и ⊟ над деревом ([[ui:sig.expandAll]], [[ui:sig.collapseAll]]). |
| Переименовать папку | Нажмите ✎ ([[ui:sig.renameFolder]]) или <kbd>F2</kbd> на ней, введите имя, затем <kbd>Enter</kbd>; <kbd>Esc</kbd> отменяет. |
| Переместить сигнал или папку | Перетащите на папку или на пустое место дерева — на верхний уровень. |
| Переместить сигнал вводом | Измените его поле [[ui:sig.group]]. |
| Удалить папку | Нажмите × ([[ui:sig.removeFolder]]), затем [[ui:sig.confirmRemoveFolder]], или дважды нажмите <kbd>Delete</kbd> на ней. |

Переименование никогда не сливает две папки: имя с `/` внутри или имя, которое уже есть у
соседней папки, отклоняется, о чём сообщает консоль. Папку нельзя перетащить в неё саму или
в папку внутри неё. Если перетащить папку в папку, где уже есть папка с тем же именем, они
сливаются.

Удаление папки удаляет только саму папку: её сигналы и вложенные папки поднимаются на один
уровень. Ничто не удаляется.

### Поиск сигнала {#filter}

Введите текст в поле над деревом ([[ui:sig.search]]). Он сопоставляется с именем, папкой,
заметкой, адресатом и сообщением. Пока вы фильтруете, каждая папка с совпадением открыта, а
остальные скрыты.

## Стартовый набор {#starter-set}

Когда Signal Lab в первый раз не находит файла библиотеки, он записывает девять примеров,
каждый — про то, в чём легко ошибиться. Их имена и заметки пишутся на языке интерфейса в
этот момент; дальше вы вольны их менять. Все они нацелены на этот компьютер.

| Папка | Сигнал | Что отправляет |
| --- | --- | --- |
| `OSC` | [[ui:seed.osc-fader.name]] | `/fader/1` с float `0.75` на `127.0.0.1:9000` |
| `OSC` | [[ui:seed.osc-types.name]] | `/types` с int `-7`, float `1.5`, строкой `hi`, bool true, int64 `4294967296`, double `0.125` и nil |
| `OSC` | [[ui:seed.osc-id-and-value.name]] | `/tag` со строками `reader-1` и `04a1b2c3` |
| `OSC` | [[ui:seed.osc-trigger.name]] | `/cue/go` без аргументов |
| `MQTT` | [[ui:seed.mqtt-publish.name]] | `1` в `lab/example/value` на `127.0.0.1:1883`, QoS 0 |
| `MQTT` | [[ui:seed.mqtt-retained.name]] | `night` в `lab/example/config`, QoS 1, retained |
| `MQTT` | [[ui:seed.mqtt-clear-retained.name]] | Пустое retained-содержимое в `lab/example/config`, QoS 1 |
| `HTTP` | [[ui:seed.http-reachable.name]] | `GET http://127.0.0.1:8080/`, тайм-аут 4000 мс |
| [[ui:seed.folder.Raw]] | [[ui:seed.udp-raw.name]] | Байты `de ad be ef` на `127.0.0.1:9000` |

Чтобы вернуть стартовый набор, переместите или переименуйте `signals.json` и нажмите
[[ui:sig.reload]]: если файла нет, он записывается заново.

## Файл библиотеки {#file}

Библиотека — это `signals.json` в папке данных: `Documents/SignalLab` в вашей домашней
папке на настольном компьютере или папка данных сервера (см.
[Файлы и папки](../reference/files.md)). Наведите указатель на число сигналов под деревом,
чтобы увидеть полный путь.

- **Сохраняется само.** Каждое изменение записывается через 0,7 с после последнего, сразу
  всем файлом, через временный файл в той же папке, который затем занимает место файла, —
  оборванная запись оставляет прежний файл. Пока запись ждёт, внизу дерева написано
  [[ui:sig.saving]]; затем — [[ui:sig.saved]]. Запись, которая ещё ждёт, выполняется до того,
  как обновление перезапустит приложение.
- **Правка вручную.** Signal Lab не замечает, что файл изменился у него под ногами. После
  правки или замены файлом с другого компьютера нажмите [[ui:sig.reload]]. Перечитывание
  читает файл заново и отбрасывает изменение, которое ещё ждало записи.
- **Сломанный файл никогда не заменяется.** Если файл — не корректный JSON или не
  библиотека сигналов, дерево показывает ошибку с путём к файлу, строкой и столбцом, и
  консоль сообщает то же самое. Файл остаётся как есть, и ничто не записывает библиотеку,
  пока она снова не прочитается: [[ui:sig.new]], переименование, перемещение и удаление
  сигналов и папок, перетаскивание, поля сигнала, [[ui:sig.saveNew]], [[ui:sig.save]] и
  [[ui:sig.saveAs]] на экранах HTTP, OSC и MQTT, а также [[ui:sig.fromFrame]] в Инспекторе и
  на экране MQTT — всё это отключено, а подсказка объясняет, что не так. Исправьте файл или
  удалите его и нажмите [[ui:sig.reload]]: как только он прочитается, всё снова заработает.
- **Файл, который ломается во время работы приложения.** Если вы превратили файл во что-то
  нечитаемое, а приложение затем сохраняет изменение, сохранение отклоняется с той же
  ошибкой, файл остаётся таким, каким вы его сделали, и приложение перестаёт записывать,
  пока вы не исправите файл и не нажмёте [[ui:sig.reload]]. Файл, который вы правили и
  оставили корректным, при следующем сохранении заменяется списком приложения, как описано
  выше: сначала перечитайте.

Короткий пример файла:

```json
{
  "version": 2,
  "signals": [
    {
      "id": "fader-value",
      "name": "Fader value",
      "group": "Venue/Stage",
      "note": "Main fader of desk A.",
      "body": {
        "transport": "osc",
        "target": "127.0.0.1:9000",
        "address": "/fader/1",
        "args": [{ "type": "float", "value": 0.75 }]
      }
    }
  ],
  "folders": ["Venue/Stage", "Venue/Empty for now"]
}
```

| Ключ | Что это |
| --- | --- |
| `version` | `2`. Файл версии 1 (до папок) читается так же, но без пустых папок. |
| `signals[].id` | Составляется из имени при создании сигнала (`fader-value`, `fader-value-2`, …) и никогда не меняется при переименовании. По нему сигнал находит `signallab fire`. |
| `signals[].group` | Путь к папке; `""` — верхний уровень. |
| `signals[].body` | Сообщение. `transport` — `osc`, `udp`, `http` или `mqtt`; остальные ключи — поля этого вида. |
| `folders` | Все папки, чтобы пустая сохранялась. Опускается, если папок нет. `group`, которого нет ни в одной записи, — тоже папка. |

## Из командной строки {#cli}

`signallab fire` отправляет сигнал из библиотеки через те же команды, что и приложение:

```bash
signallab fire "Fader value"
signallab fire fader-value --library ./show/signals.json
```

Сначала он ищет сигнал по id, затем по имени без учёта регистра. Если у нескольких сигналов
такое имя, он называет их id и ничего не отправляет. Без `--library` он читает собственный
`signals.json` приложения; файл он никогда не записывает. См.
[Командная строка](../automation/cli.md#cli-fire).
