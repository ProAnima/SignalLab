# Установка и обновление

Signal Lab выпускается на GitHub: в каждом выпуске есть настольное приложение для Windows
и Linux, отдельная командная строка `signallab` и список контрольных сумм. Чтобы вместо
этого запустить его на сервере и пользоваться им из браузера, см. [Сервер](../server/index.md).

## Что скачать {#downloads}

Откройте [последний выпуск](https://github.com/ProAnima/SignalLab/releases/latest) и
выберите файл для своей системы. `<version>` — версия выпуска, например `[[version]]`.

| Файл | Для чего |
| --- | --- |
| `Signal.Lab_<version>_x64-setup.exe` | Windows 10 и 11, x64 — установщик, который нужен большинству |
| `Signal.Lab_<version>_x64_en-US.msi` | Windows, развёртывание силами ИТ-отдела (Intune, групповая политика): устанавливает для всех пользователей |
| `Signal.Lab_<version>_amd64.deb` | Linux x86_64: Debian, Ubuntu и родственные им дистрибутивы |
| `Signal.Lab-<version>-1.x86_64.rpm` | Linux x86_64: Fedora, RHEL, openSUSE и родственные им дистрибутивы |
| `Signal.Lab_<version>_amd64.AppImage` | Linux x86_64, любой дистрибутив, без установки |
| `signallab-<version>-windows-x64.zip` | только командная строка, для Windows |
| `signallab-<version>-linux-x64.tar.gz` | только командная строка, для Linux |
| `SHA256SUMS.txt` | контрольная сумма SHA-256 каждого файла выше |

Файлы `.sig` и `latest.json` рядом с ними нужны встроенному механизму обновления
приложения; вам они не понадобятся.

## Windows {#windows}

Signal Lab работает в Windows 10 и 11, x64. Он использует среду выполнения WebView2,
которая входит в обе системы.

### Установка с помощью установщика {#windows-setup}

1. Запустите `Signal.Lab_<version>_x64-setup.exe`.
2. Если Windows SmartScreen сообщит, что защитил ваш компьютер, выберите **Подробнее**, а
   затем **Выполнить в любом случае** (см. [SmartScreen](#smartscreen) ниже).
3. Выберите язык установщика. Он предлагает те же 11 языков, что и приложение.
4. Выберите, для кого установка:
   - Только для вас: программа устанавливается в `%LOCALAPPDATA%\Signal Lab`, права
     администратора не нужны.
   - Для всех пользователей этого компьютера: программа устанавливается в
     `C:\Program Files\Signal Lab`, установщик запросит права администратора.
5. Подтвердите папку и установите.
6. На последней странице можно сразу запустить Signal Lab и создать ярлык на рабочем
   столе.

Если запустить установщик новой версии поверх установленной, установленная версия
обновится на месте.

### Что ещё добавляет установщик {#windows-setup-adds}

Кроме самого приложения, установщик ставит ещё две вещи, а программа удаления убирает
обе:

- **Командную строку.** `signallab.exe` кладётся рядом с приложением, а его папка
  добавляется в `PATH` — в ваш собственный `PATH` при установке только для вас, в
  системный при установке для всех, — так что `signallab` работает в каждом терминале,
  открытом после этого. См. [Командная строка](../automation/cli.md).
- **Правило брандмауэра** — только при установке для всех. Брандмауэр Защитника Windows
  пропускает к программе другие машины, только если это разрешает правило, и спрашивает
  человека у экрана, когда программа впервые начинает слушать; если там нажать
  *Отмена*, всё, что присылают другие машины, будет молча отбрасываться. Установка для
  всех, у которой есть права администратора, добавляет разрешающее правило для входящих
  подключений к `signal-lab.exe` (приложение) и ещё одно — к `signallab.exe` (командная
  строка), для частных сетей и сетей домена. Установка только для вас менять брандмауэр
  не может: это предлагает сделать само приложение, через стандартный запрос прав
  администратора Windows, когда что-то впервые начинает слушать, — см.
  [уведомление о брандмауэре](interface.md#firewall-notice).

Трафик внутри самого компьютера (`127.0.0.1`) никогда не фильтруется, поэтому всё, что
вы делаете на loopback, работает без всяких правил.

### Установка без участия пользователя {#windows-unattended}

Установщик принимает в командной строке такие ключи:

| Ключ | Что делает |
| --- | --- |
| `/S` | Устанавливает молча, ничего не спрашивая. |
| `/P` | Устанавливает с индикатором хода выполнения и без вопросов. |
| `/ALLUSERS` | Устанавливает для всех (нужна командная строка с повышенными правами). |
| `/CURRENTUSER` | Устанавливает только для текущего пользователя. |
| `/NS` | Не создаёт ярлыков. |
| `/D=C:\Tools\Signal Lab` | Устанавливает в эту папку. Ключ должен идти последним и пишется без кавычек. |
| `/NOPATH` | Не трогает `PATH`: `signallab` устанавливается, но в `PATH` не попадает. |
| `/NOFIREWALL` | Не добавляет правил брандмауэра. |

Например, тихая установка для всех без правил брандмауэра из командной строки с
повышенными правами:

```powershell
.\Signal.Lab_[[version]]_x64-setup.exe /S /ALLUSERS /NOFIREWALL
```

### MSI {#windows-msi}

`Signal.Lab_<version>_x64_en-US.msi` предназначен для развёртывания силами ИТ-отдела.
Он устанавливает программу для всех пользователей, кладёт `signallab.exe` рядом с
приложением и добавляет эту папку в системный `PATH`, но правил брандмауэра не добавляет:
это остаётся на совести того, кто развёртывает (например, через групповую политику).
Приложение всё равно предложит правило, когда впервые начнёт слушать. Тихая установка:

```powershell
msiexec /i "Signal.Lab_[[version]]_x64_en-US.msi" /qn
```

### SmartScreen {#smartscreen}

Установщики пока не подписаны сертификатом разработчика, поэтому Windows SmartScreen не
знает их издателя и может остановить установку предупреждением. Выберите **Подробнее**,
убедитесь, что это тот самый файл, который вы скачали со страницы выпусков, и выберите
**Выполнить в любом случае**. Чтобы быть уверенным, что файл не изменён, сначала
[сверьте его с `SHA256SUMS.txt`](#checksums).

Собственные обновления приложения подписаны и проверяются отдельно; см.
[Обновления](#updates).

## Проверка загруженного файла {#checksums}

В `SHA256SUMS.txt` перечислены контрольные суммы SHA-256 всех файлов выпуска, по одной на
строку, за каждой следует имя файла. Скачайте его рядом с файлом и сравните.

В Windows, в PowerShell:

```powershell
Get-FileHash .\Signal.Lab_[[version]]_x64-setup.exe -Algorithm SHA256
Select-String "Signal.Lab_[[version]]_x64-setup.exe" .\SHA256SUMS.txt
```

Два хеша должны совпасть (`Get-FileHash` выводит его заглавными буквами; регистр не
важен).

В Linux, в папке, где лежат оба файла:

```bash
sha256sum --check --ignore-missing SHA256SUMS.txt
```

Команда печатает `OK` после каждого найденного файла. Всё остальное значит, что
скачанный файл — не тот, что был выпущен: скачайте его заново.

## Linux {#linux}

Приложение для Linux собрано для x86_64 (на Ubuntu 22.04) и требует WebKitGTK 4.1 —
веб-движок, которым оно рисует своё окно. Сборки для процессоров Arm нет; на машине с
Arm запустите вместо этого [сервер](../server/index.md).

### Пакет .deb {#linux-deb}

```bash
sudo apt install ./Signal.Lab_[[version]]_amd64.deb
```

`apt` заодно установит всё, что нужно пакету. Пакет также кладёт командную строку в
`/usr/bin/signallab`.

### Пакет .rpm {#linux-rpm}

```bash
sudo dnf install ./Signal.Lab-[[version]]-1.x86_64.rpm
```

В openSUSE используйте `sudo zypper install` с тем же файлом. Как и `.deb`, пакет кладёт
командную строку в `/usr/bin/signallab`.

### AppImage {#linux-appimage}

AppImage запускается без установки:

```bash
chmod +x Signal.Lab_[[version]]_amd64.AppImage
./Signal.Lab_[[version]]_amd64.AppImage
```

Командной строки `signallab` в нём нет; если она нужна, возьмите её из
[архива с командной строкой](#cli-archives).

### Брандмауэр в Linux {#linux-firewall}

В Linux приложение не показывает уведомление о брандмауэре: `ufw` и `firewalld`
работают с портами, а не с программами. Если один из них включён и другие машины должны
достучаться до монитора, слушателя, эмулятора или реле, откройте там его порт, например:

```bash
sudo ufw allow 9000/udp
```

Трафика через loopback это не касается.

## Отдельная командная строка {#cli-archives}

Настольные установщики приносят `signallab` с собой. Для машины без приложения — агента
сборки, сервера, лабораторного ПК — в каждом выпуске есть и отдельная командная строка:

- `signallab-<version>-windows-x64.zip` содержит `signallab.exe` и лицензию.
- `signallab-<version>-linux-x64.tar.gz` содержит `signallab` и лицензию.

Распакуйте его в папку из вашего `PATH`. В Linux:

```bash
tar -xzf signallab-[[version]]-linux-x64.tar.gz signallab
sudo install signallab /usr/local/bin/
signallab version
```

В образе Docker для сервера она тоже есть. Как ею пользоваться — в разделе
[Командная строка](../automation/cli.md).

## Обновления {#updates}

### Настольное приложение {#updates-desktop}

Настольное приложение обновляет себя только из опубликованных выпусков и только когда вы
скажете.

- **Оно проверяет раз в день.** Когда флажок [[ui:update.auto]] установлен (а по
  умолчанию это так), приложение вскоре после старта ищет новый выпуск, если с прошлой
  проверки прошли сутки или больше, и затем снова — каждый раз, когда за время работы
  проходят очередные сутки. Снимите флажок в окне «О программе», чтобы оно перестало
  проверять само.
- **Проверить можно прямо сейчас.** Откройте «О программе» — значок **?** в шапке — и
  нажмите [[ui:update.check]] в разделе [[ui:update.title]].
- **Что отправляет проверка.** Она спрашивает у сервиса обновлений студии
  (`hub.proanima.net`), какой выпуск положен этой установке, и обращается к последнему
  выпуску на GitHub, только если этот сервис недоступен. В запросе — версия
  приложения, система и тип процессора, а также случайное число, созданное для этой
  установки: благодаря ему новый выпуск сначала может дойти лишь до части установок.
  Ничего, что указывало бы на вас или этот компьютер, не отправляется.
- **Когда выпуск найден**, об этом пишет консоль, а в шапке появляется кнопка
  обновления, которая открывает «О программе». Там кнопка [[ui:update.notes]] показывает
  описание выпуска.
- **Ничего не устанавливается, пока вы не нажмёте.** Нажмите [[ui:update.install]] (если
  запущены задачи, кнопка предупредит, что остановит их). Signal Lab сохраняет всё, что
  ещё не записано, останавливает все запущенные задачи, скачивает обновление и сверяет
  его подпись с ключом, встроенным в приложение, — обновление, не подписанное процессом
  выпуска, отклоняется, — затем устанавливает его и перезапускается уже новой версией.

В Windows обновление запускает установщик без вопросов и сохраняет вашу папку, `PATH` и
правила брандмауэра. В Linux оно заменяет AppImage или устанавливает новый пакет `.deb`
или `.rpm`; в случае пакета система сначала спросит ваш пароль.

Предварительные выпуски и черновики не предлагаются никогда. Чтобы ни одна установка на
машине не проверяла обновления сама — например, когда ИТ-отдел сам развёртывает
обновления, — задайте переменную окружения `SIGNALLAB_NO_UPDATE_CHECK` с любым
значением; кнопка [[ui:update.check]] при этом по-прежнему работает. Сборки для
разработки сами не проверяют никогда.

### Сервер {#updates-server}

Сервер — а с ним и страница, которую браузер получает от него, — обновляется вместе со
своим образом Docker и никогда сам по себе: так и написано в окне «О программе». Как
обновить сервер — в разделе [Сервер](../server/index.md).

## Удаление {#uninstall}

**Windows.** Откройте *Параметры → Приложения → Установленные приложения*, найдите
Signal Lab и выберите *Удалить*. Программа удаления убирает `signallab.exe` из `PATH`, а
если она запущена с правами администратора (как при установке для всех), удаляет все
правила брандмауэра для входящих подключений к приложению и командной строке, включая
созданные по запросу Windows. Она предлагает флажок, чтобы удалить заодно и данные
приложения: это его собственные настройки — язык, размеры панелей, экран, на котором вы
были, значения, введённые на экранах последними, — а не ваши файлы. Установка из MSI
удаляется так же; она забирает с собой свою запись в `PATH` и оставляет брандмауэр тому,
кто её развёртывал.

**Linux.** Удалите пакет тем же менеджером пакетов, которым устанавливали, или удалите
файл AppImage.

Ни то ни другое не трогает вашу **папку данных**: эксперименты, библиотеки сигналов и
эмуляторов, отчёты о запусках и экспорт остаются в `Documents/SignalLab` в вашей
домашней папке. Если они больше не нужны, удалите эту папку сами.

## Где хранятся ваши данные {#data}

Всё, что вы создаёте, хранится в виде обычных файлов в одной папке —
`Documents/SignalLab` в вашей домашней папке, одинаково в Windows и Linux: текущий
эксперимент, библиотека сигналов, библиотека эмуляторов, отчёты о запусках, экспорт и
захваты Инспектора. Каждый файл и его формат описаны в разделе
[Файлы и папки](../reference/files.md).

## Запуск в виде сервера {#server}

Чтобы пользоваться Signal Lab из браузера — на лабораторном ПК рядом с оборудованием,
на Linux-компьютере, в Docker, — см. [Сервер](../server/index.md). На машине с Linux и
Docker его устанавливает и запускает одна команда.
