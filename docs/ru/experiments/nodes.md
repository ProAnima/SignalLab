# Справочник узлов

Все виды узлов, которые могут быть в эксперименте, — по группам меню добавления:
[действия](#actions), [ожидания](#waits), [эмуляция](#emulation), [сбои](#faults),
[данные](#data), [проверки](#checks) и [сценарий](#flow). Как их добавлять и
соединять, описано в разделе [Редактор](index.md); `signallab nodes` выводит тот же
каталог в виде JSON — для скриптов и ассистентов ([Командная
строка](../automation/cli.md)).

## Как читать эту страницу {#reading}

У каждого узла есть таблица его полей:

- **Поле** — название на панели свойств; **В файле** — ключ в JSON эксперимента.
- **По умолчанию** — то, что узел получает при добавлении в редакторе. Если файл
  вправе опустить ключ, значение, которое тогда принимается, указано как *если ключа
  нет*; остальные ключи в файле обязательны.
- **Шаблоны**: *да* — поле принимает `{{templates}}`: параметры, переменные,
  заданные раньше, секреты и генераторы, которые разрешаются в момент выполнения
  шага ([Данные и шаблоны](data.md)). *Только параметры* — поле открывается до
  первого шага, когда известны лишь параметры. *Нет* — значение берётся как
  написано.

Время указывается в миллисекундах. Пределы проверяются до начала запуска; поле вне
диапазона не даёт эксперименту запуститься и отмечается на узле.

## Узел в файле {#file-shape}

В файле эксперимента узел — это объект с `id` (уникальным в эксперименте), его
`type`, местом на холсте (`x`, `y`, ноль и больше), его полями и используемыми им
настройками (`retry`, `repeat`, `load`; если выключены, их нет). Связь — это ребро от
выхода одного узла (`port`; если его нет — `next`) к другому узлу:

```json
{
  "nodes": [
    { "id": "start", "type": "start", "x": 40, "y": 80 },
    { "id": "ping", "type": "udp", "x": 270, "y": 80, "target": "127.0.0.1:9000", "text": "PING",
      "retry": { "attempts": 3, "delay_ms": 500, "backoff": "fixed" } },
    { "id": "end", "type": "end", "x": 500, "y": 80 }
  ],
  "edges": [
    { "from": "start", "to": "ping", "port": "next" },
    { "from": "ping", "to": "end", "port": "next" }
  ]
}
```

В примерах ниже показано по одному узлу — так, как его хранит файл.

## Настройки, общие для многих узлов {#settings}

Они включаются в нижней части свойств узла. Какой узел какие принимает, указано у
каждого узла.

| Настройка | Кто её принимает | Что делает |
| --- | --- | --- |
| [Повтор при ошибке](#retry) | Узлы, которые отправляют или слушают: [[ui:exp.node.http]], [[ui:exp.node.tcp]], [[ui:exp.node.osc]], [[ui:exp.node.udp]], [[ui:exp.node.mqtt]], [[ui:exp.node.ws_connect]], [[ui:exp.node.ws_send]] и любое ожидание | Пробует снова, если шаг завершился ошибкой |
| [Серия отправок](#repeat) | Узлы, которые отправляют: [[ui:exp.node.http]], [[ui:exp.node.tcp]], [[ui:exp.node.osc]], [[ui:exp.node.udp]], [[ui:exp.node.mqtt]], [[ui:exp.node.ws_send]] | Отправляет снова и снова — заданное число раз или в течение заданного времени |
| [Нагрузка](#load) | [[ui:exp.node.http]] | Отправляет запрос по профилю нагрузки, измеряет его и оценивает порогами |
| [Ожидание ответа](#reply) | [[ui:exp.node.osc]], [[ui:exp.node.udp]] | Отправляет и ждёт ответа на том же шаге |

### Повтор при ошибке {#retry}

Флажок [[ui:exp.retryOn]]: если шаг завершился ошибкой — нет соединения, истёк
таймаут, ожидание ничего не нашло, — он делает паузу и выполняется снова. Каждая
неудачная попытка — строка в ленте; шаг завершается ошибкой, когда ею завершается
последняя попытка. Шаблон, который не удаётся разрешить, не повторяется. Кнопка
[[ui:common.stop]] тоже прерывает паузу.

| Поле | В файле | Что это | По умолчанию и пределы |
| --- | --- | --- | --- |
| [[ui:exp.attempts]] | `retry.attempts` | Всего попыток, включая первую | 3; 2–10 в редакторе (в файле можно указать и 1) |
| [[ui:exp.retryDelay]] | `retry.delay_ms` | Пауза перед второй попыткой | 500; 0–60 000 |
| [[ui:exp.backoff]] | `retry.backoff` | [[ui:exp.backoff.fixed]] (`fixed`): каждый раз одна и та же пауза; [[ui:exp.backoff.exponential]] (`exponential`): после каждой неудачи вдвое длиннее | `fixed` (и если ключа нет) |

Ни одна пауза не бывает длиннее 60 секунд, как бы она ни удваивалась. Ожидание, у
выхода которого [[ui:exp.portTimeout]] есть связь, по таймауту не завершается ошибкой
— оно уходит по этому выходу, — поэтому в таком случае не повторяется.

### Серия отправок {#repeat}

Флажок [[ui:exp.repeatOn]]: узел отправляет снова и снова — сигнал «жив», опрос,
ровный поток — без цикла в схеме. Каждая отправка разрешает шаблоны заново
(`{{counter}}` — её номер, `{{now}}` — её время), а повтор при ошибке, если он
включён, применяется к каждой отправке. Шаг проходит, когда прошла каждая отправка;
отправка, окончательно завершившаяся ошибкой, приводит к ошибке шага. Лента сообщает
о ходе не чаще раза в секунду.

| Поле | В файле | Что это | По умолчанию и пределы |
| --- | --- | --- | --- |
| [[ui:exp.repeatBy]] | `repeat.until` | [[ui:exp.repeatBy.count]] (`count`) или [[ui:exp.repeatBy.duration]] (`duration`) | `count` (и если ключа нет) |
| [[ui:exp.repeatCount]] | `repeat.count` | Всего отправок, включая первую | 10 (и если ключа нет); 2–10 000 |
| [[ui:exp.repeatDuration]] | `repeat.duration_ms` | Как долго отправлять, считая от первой отправки | 10 000 (и если ключа нет); 1–300 000 |
| [[ui:exp.repeatInterval]] | `repeat.interval_ms` | Пауза между двумя отправками | 1 000; 10–60 000; в файле обязательно |
| [[ui:exp.repeatJitter]] | `repeat.jitter_ms` | Каждая пауза длиннее не более чем на это значение, оно берётся из seed запуска | 0 (и если ключа нет); 0–60 000 |

Серии должны укладываться в 300 секунд запуска, а серия *на время* должна требовать
менее 10 000 отправок (её время, делённое на интервал).

### Нагрузка {#load}

Флажок [[ui:exp.loadOn]], только у узла [[ui:exp.node.http]]: запрос отправляется по
профилю — ровному темпу, росту, ступеням, всплеску или случайным приходам, — причём
одновременно в пути может быть до 512 запросов (по умолчанию 32), и измеряется:
задержки, ошибки, достигнутый темп. Пороги решают, проходит ли шаг. Нагрузка заменяет
серию и повтор при ошибке (неудавшийся запрос подсчитывается, а не отправляется
заново) и не оставляет ответа для проверок после неё. Её поля и результаты описаны в
разделе [Нагрузочное тестирование](load.md).

### Ожидание ответа {#reply}

Флажок [[ui:exp.expectReply]], у узла [[ui:exp.node.osc]] или [[ui:exp.node.udp]]:
сообщение отправляется с порта, на котором ждут ответ, поэтому устройство, отвечающее
отправителю, будет услышано, а шаг проходит, только если подходящий ответ пришёл
вовремя. Нет ответа — шаг завершается ошибкой, а повтор при ошибке отправляет снова.
Ответ сохраняется в переменной, как и у ожидания.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.replyOn]] | `reply.bind` | `IP:port`, с которого отправляют и на котором слушают; порт 0 означает любой свободный порт | `0.0.0.0:0` | Нет |
| [[ui:exp.replyAddress]] (OSC) | `reply.address` | Шаблон адреса ответа, как у узла [[[ui:exp.node.wait_osc]]](#node-wait_osc) | `/*` | Да |
| [[ui:exp.argRules]] (OSC) | `reply.args` | Условия на аргументы, как у узла [[ui:exp.node.wait_osc]] | нет; не более 16 | Значения: да |
| [[ui:exp.replyMode]] (UDP) | `reply.mode` | `any`, `contains`, `regex` или `hex` — см. [Сопоставление содержимого](#payload-matching) | `any` (и если ключа нет) | Нет |
| [[ui:field.pattern]] (UDP) | `reply.pattern` | Что ответ должен содержать или чему соответствовать | пусто; обязательно, кроме `any` | Да |
| [[ui:exp.waitTimeout]] | `reply.timeout_ms` | Сколько ждать | 2 000 (и если ключа нет); 1–120 000 | Нет |
| [[ui:exp.replyVariable]] | `reply.variable` | Переменная, в которую сохраняется ответ | `reply` (и если ключа нет) | Нет |

Порт ответа открывается до первого шага, как и у ожидания.

## Действия {#actions}

Узлы, которые отправляют. Ожидание после действия учитывает сообщения с момента
начала этого действия.

### HTTP-запрос {#node-http}

Отправляет один HTTP-запрос и сохраняет ответ для проверок, ветвлений и узлов
[[ui:exp.node.extract]] после него.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.method]] | `request.method` | GET, HEAD, POST, PUT, PATCH, DELETE или OPTIONS (в файле можно указать любой метод) | `GET` | Нет |
| URL | `request.url` | URL с `http://` или `https://` | `http://127.0.0.1:8080/` | Да |
| [[ui:common.timeoutMs]] | `request.timeout_ms` | На весь обмен | 4 000 (10 000, если ключа нет); 1–120 000 | Нет |
| [[ui:exp.headers]] | `request.headers` | `[[name, value], …]`; строка с пустым именем пропускается | нет | Да, имена и значения |
| [[ui:exp.body]] | `request.body` | Текст или `null`, если тела нет | `null` | Да |
| [[ui:field.auth]] | `request.auth` | [[ui:http.auth.none]], [[ui:http.auth.basic]], [[ui:http.auth.bearer]] или [[ui:http.auth.digest]], с полями [[ui:field.username]] и [[ui:field.password]] или [[ui:field.token]] | нет | Да |

- Любой ответ засчитывает шаг, включая 404 и 500: статус проверяйте узлом
  [[[ui:exp.node.assert_status]]](#node-assert_status) или ветвитесь по нему узлом
  [[[ui:exp.node.branch_status]]](#node-branch_status). Запрос, на который нет
  ответа — отказ в соединении, таймаут, имя, которое не разрешается, недоверенный
  сертификат, — завершает шаг ошибкой.
- Перенаправления выполняются, не более десяти. Сертификаты `https://` проверяются.
- Тело ответа сохраняется для проверок до 256 КиБ; более крупное обрезается на этой
  границе (проверки сообщают об этом, когда то, что они ищут, может оказаться за
  обрезкой).
- Digest отвечает на запрос 401 от сервера и отправляет запрос снова. Учётные данные
  попадают только в запрос: шаги, отчёты и Инспектор никогда не показывают
  заголовок `Authorization`. Пишите пароль как `{{secret.NAME}}`.
- Пока эксперимент хранит cookie (по умолчанию включено, в разделе
  [[ui:exp.params]]), то, что установили серверы, отправляется им обратно в
  последующих запросах запуска.

Выход: [[ui:exp.outputPort]]. Настройки: повтор при ошибке, серия, нагрузка.

```json
{ "id": "cue", "type": "http", "x": 270, "y": 80,
  "request": { "method": "POST", "url": "{{api}}/cue", "headers": [["Content-Type", "application/json"]],
               "body": "{\"cue\": 1}", "timeout_ms": 5000,
               "auth": { "scheme": "bearer", "token": "{{secret.API_TOKEN}}" } } }
```

См. также [HTTP](../protocols/http.md).

### TCP-сообщение {#node-tcp}

Подключается к хосту по TCP, записывает данные, ждёт до 250 мс первых байтов ответа
(читает не более 1 024 байт, один раз) и закрывает соединение. Размер ответа
сообщается, но не проверяется.

В [Инспекторе](../tools/inspector.md) шаг — это два кадра `tcp` с источником
`experiment`: записанные данные и, если ответ пришёл, прочитанный ответ. Используемые
секреты в обоих замаскированы, как в любом кадре.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.host]] | `host` | Имя хоста или IP-адрес | `127.0.0.1` | Да |
| [[ui:exp.port]] | `port` | | 9000; 1–65 535 | Нет |
| [[ui:common.timeoutMs]] | `timeout_ms` | На подключение, запись и ответ вместе | 4 000 (и если ключа нет); 1–120 000 | Нет |
| [[ui:exp.payload]] | `payload` | Текст, записываемый после подключения, в UTF-8 | `hello` | Да |

Шаг завершается ошибкой, если в соединении отказано, имя не разрешается или время
истекло. Выход: [[ui:exp.outputPort]]. Настройки: повтор при ошибке, серия. Кнопка
[[ui:exp.sendNow]] подключается и записывает данные один раз, а результат узла
показывает, сколько байтов отправлено и сколько вернулось.

```json
{ "id": "go", "type": "tcp", "x": 270, "y": 80, "host": "127.0.0.1", "port": 5000, "payload": "GO\r\n", "timeout_ms": 2000 }
```

### OSC-сообщение {#node-osc}

Отправляет одно сообщение OSC 1.0 по UDP.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:common.target]] | `target` | `IP:port` или `host:port`; имя хоста разрешается в момент отправки шага, берётся его адрес IPv4, если он есть | `127.0.0.1:9000` | Да |
| [[ui:common.address]] | `address` | Начинается с `/` | `/test` | Да |
| [[ui:exp.arguments]] | `args` | `[{ "type", "value" }, …]` — `int`, `float`, `str`, `long`, `double`, `bool`, `blob` (байты), `nil` (без значения) | нет | Текстовые (`str`) значения: да |
| [[ui:exp.expectReply]] | `reply` | Необязательно: отправить и дождаться ответа — см. [Ожидание ответа](#reply) | выкл. | |

Выход: [[ui:exp.outputPort]]; если ожидается ответ, по нему идут, только когда ответ
пришёл. Настройки: повтор при ошибке, серия, ожидание ответа. Кнопка ⚡
[[ui:exp.routeThrough]] в свойствах узла ставит перед ним узел
[[[ui:exp.node.impairment]]](#node-impairment).

```json
{ "id": "fader", "type": "osc", "x": 270, "y": 80, "target": "{{device}}", "address": "/fader/1",
  "args": [{ "type": "float", "value": 0.75 }] }
```

См. также [OSC](../protocols/osc.md).

### UDP-датаграмма {#node-udp}

Отправляет текстовое содержимое одной UDP-датаграммой на одну или несколько целей.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:common.target]] | `target` | `IP:port` или `host:port`; если их несколько, через запятую, точку с запятой или с новой строки, датаграмму получает каждая. Имя хоста разрешается в момент отправки шага, берётся его адрес IPv4, если он есть | `127.0.0.1:9000` | Да |
| [[ui:exp.payload]] | `text` | Содержимое в UTF-8 | `hello`; не более 65 507 байт | Да |
| [[ui:exp.expectReply]] | `reply` | Необязательно: отправить и дождаться ответа — см. [Ожидание ответа](#reply) | выкл. | |

Шаг завершается ошибкой, если какая-либо цель недоступна. Выход:
[[ui:exp.outputPort]]. Настройки: повтор при ошибке, серия, ожидание ответа.

```json
{ "id": "ping", "type": "udp", "x": 270, "y": 80, "target": "{{device}}", "text": "PING {{run.id}}",
  "reply": { "bind": "0.0.0.0:0", "mode": "contains", "pattern": "PONG", "timeout_ms": 1000, "variable": "pong" } }
```

### Публикация MQTT {#node-mqtt}

Подключается к брокеру MQTT, публикует одно сообщение и отключается. Соединение —
MQTT 3.1.1 по обычному TCP, с чистой сессией, без имени пользователя и пароля.
Подключение, публикация и подтверждение брокера должны уложиться в 15 секунд.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.broker]] | `host` | Имя хоста или адрес брокера | `127.0.0.1` | Да |
| [[ui:exp.port]] | `port` | | 1883; 1–65 535 | Нет |
| [[ui:exp.topic]] | `topic` | Без подстановочных символов (`+`, `#`) | `lab/test` | Да |
| [[ui:exp.payload]] | `payload` | Сообщение в виде текста | `hello` | Да |
| QoS | `qos` | 0, 1 или 2 | 0 | Нет |
| [[ui:exp.retain]] | `retain` | `true`: брокер сохраняет его как значение топика | `false` | Нет |

Все шесть ключей в файле обязательны. Шаг завершается ошибкой, если брокер недоступен
или отказывает в соединении либо в сообщении. Выход: [[ui:exp.outputPort]].
Настройки: повтор при ошибке, серия.

```json
{ "id": "light", "type": "mqtt", "x": 270, "y": 80, "host": "{{broker}}", "port": 1883,
  "topic": "lab/light/1/set", "payload": "on", "qos": 1, "retain": false }
```

См. также [MQTT](../protocols/mqtt.md).

### Подключение WebSocket {#node-ws_connect}

Открывает WebSocket до конца запуска или до узла
[[[ui:exp.node.ws_close]]](#node-ws_close). Всё, что приходит с этого момента,
сохраняется для шагов [[[ui:exp.node.wait_ws]]](#node-wait_ws) на нём. URL и заголовки
разрешаются, когда шаг выполняется, поэтому в них может быть токен, извлечённый
раньше. Если узел выполняется снова — в узле [[ui:exp.node.loop]], — он сначала
закрывает прежнее соединение и открывает новое. Когда запуск заканчивается, как бы это
ни произошло, его соединения закрываются кадром закрытия.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| URL | `url` | URL с `ws://` или `wss://` | `ws://127.0.0.1:9001/` | Да |
| [[ui:exp.headers]] | `headers` | `[[name, value], …]`, отправляются с запросом upgrade | нет | Да, имена и значения |
| [[ui:exp.wsProtocols]] | `protocols` | Подпротоколы, которые предлагаются в порядке предпочтения; сервер выбирает один | нет | Нет |
| [[ui:common.timeoutMs]] | `timeout_ms` | На подключение и upgrade | 5 000 (10 000, если ключа нет); 1–120 000 | Нет |

`wss://` доверяет тем же сертификатам, что и `https://`. Шаг завершается ошибкой,
если не удалось подключиться или выполнить upgrade; статус сервера указан в причине.
Выход: [[ui:exp.outputPort]]. Настройки: повтор при ошибке (серии нет).


## Ожидания {#waits}

Группа [[ui:exp.group.observe]]: узлы, которые ждут, пока что-нибудь придёт. У них
общие правила:

- **Слушают с начала запуска.** Порт ожидания или подписка на брокере открываются до
  первого шага, поэтому устройство, которое отвечает быстрее, чем начинается
  следующий шаг, не будет пропущено. Два ожидания на одном адресе используют один
  сокет.
- **Считают от последнего действия в своей ветке.** Сообщение, пришедшее до
  последнего запроса ветки, не считается ответом на него; до любого действия
  учитывается всё, что пришло с начала запуска.
- **Берётся первое подходящее сообщение.** Сообщение, которое взяло одно ожидание,
  другое не увидит.
- **[[ui:exp.portMatched]] или [[ui:exp.portTimeout]].** При совпадении сообщение
  сохраняется в переменной ожидания, и запуск идёт по выходу
  [[ui:exp.portMatched]]. Когда время истекает, он идёт по выходу
  [[ui:exp.portTimeout]], если у того есть связь; иначе шаг завершается ошибкой,
  сообщая, сколько других сообщений пришло.
- Каждый сокет хранит последние 1 024 сообщения (и 64 МиБ); более старые
  отбрасываются, а таймаут сообщает, сколько их было.
- Кнопка [[ui:exp.listenNow]] слушает только на этом шаге — с текущего момента.

Выходы: [[ui:exp.portMatched]] (обязателен), [[ui:exp.portTimeout]] (необязателен).
Настройки: повтор при ошибке.

### Сопоставление содержимого {#payload-matching}

Узлы [[ui:exp.node.wait_udp]], [[ui:exp.node.wait_mqtt]], [[ui:exp.node.wait_ws]] и
ответ UDP выбирают, как должно выглядеть содержимое:

| Вариант | В файле | Подходит, когда содержимое |
| --- | --- | --- |
| [[ui:exp.mode.any]] | `any` | любое |
| [[ui:exp.mode.contains]] | `contains` | прочитанное как текст UTF-8, содержит шаблон (с учётом регистра) |
| [[ui:exp.mode.regex]] | `regex` | прочитанное как текст UTF-8, соответствует регулярному выражению |
| [[ui:exp.mode.hex]] | `hex` | содержит байты, записанные парами hex: `de ad be ef`, `deadbeef`, `0xde,0xad`, `DE:AD` |

Найденное сообщение сохраняется как объект. Последующие шаги читают его поля как
`{{reply.text}}` (вместо `reply` подставляется имя переменной):

| Поле | Что это |
| --- | --- |
| `text` | Содержимое как текст |
| `hex`, `bytes` | Содержимое в hex (его первые 1 024 байта) и его размер в байтах |
| `match` | Что совпало: текст, первая группа регулярного выражения (или всё совпадение) либо байты |
| `from` | `IP:port` отправителя |
| `ms` | Миллисекунды от последнего действия ветки (или от начала запуска) до сообщения |
| `topic` | [[ui:exp.node.wait_mqtt]]: топик, в который оно опубликовано |
| `json`, `kind` | [[ui:exp.node.wait_ws]]: сообщение, разобранное как JSON (`null`, если это не JSON), и `text` или `binary` |

### Ждать OSC {#node-wait_osc}

Ждёт сообщение OSC, адрес которого соответствует шаблону, а аргументы удовлетворяют
всем условиям. Из пакета (bundle) берётся первое подходящее сообщение.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.listenOn]] | `bind` | `IP:port`, на котором слушать; `0.0.0.0` — на всех сетевых картах | `127.0.0.1:9001` | Нет |
| [[ui:exp.addressPattern]] | `address` | `*` — любые символы, `?` — один, `[0-9]` — набор (`[!0-9]` — вне него), `{ping,pong}` — любое из двух; подстановки не выходят за пределы одного сегмента `/` | `/pong`; не более 512 символов | Да |
| [[ui:exp.argRules]] | `args` | `[{ "index", "op", "value" }, …]`: аргумент `index` сравнивается со значением `value` операцией `op` ([Сравнения](#comparisons)); должны выполняться все | нет; не более 16, индекс 0–63 | Значения: да |
| [[ui:exp.waitTimeout]] | `timeout_ms` | | 2 000 (и если ключа нет); 1–120 000 | Нет |
| [[ui:exp.replyVariable]] | `variable` | Где сохраняется сообщение | `reply` (и если ключа нет) | Нет |

Аргумент сравнивается как текст: числа — как записаны, строки — без кавычек,
`true`/`false`, blob — в hex. Условие на аргумент, которого нет в сообщении, не
выполняется. В сохранённом сообщении есть `address`, `args` (`{{reply.args[0]}}`),
`from` и `ms`.

```json
{ "id": "status", "type": "wait_osc", "x": 500, "y": 80, "bind": "0.0.0.0:9001", "address": "/status",
```

## Эмуляция {#emulation}

### Эмулятор {#node-emulator}

Изображает зависимость — HTTP API, устройство OSC, UDP или TCP, брокер MQTT — на весь
запуск. Он открывается до первого шага и отвечает, пока запуск не закончится; в ходе
запуска шаг проходит сразу. Всё, что он получил, подсчитывается по правилам в отчёте
о запуске.

| Поле | В файле | Что это | По умолчанию |
| --- | --- | --- | --- |
| [[ui:emu.edit]] | `emulator` | Эмулятор: `name`, `bind` (`IP:port`), `protocol` (`http`, `osc`, `udp`, `tcp`, `mqtt`), его маршруты или правила и необязательный `outage` | HTTP API с именем *API* на `127.0.0.1:18080`, отвечающий на `/health` |

Свойства показывают одной строкой, что он изображает. Кнопка [[ui:emu.edit]]
открывает его правила — тот же редактор, что и на экране
[[[ui:nav.emulators]]](../tools/emulators.md); кнопка [[ui:emu.toLibrary]] сохраняет
копию в библиотеке эмуляторов, а [[ui:emu.fromLibrary]] заменяет этот эмулятор копией
из неё. Правила — маршруты, ответы, сбои, отключения — описаны там.

- HTTP-эмулятор — это ещё и то, что читает узел
  [[[ui:exp.node.wait_http]]](#node-wait_http) на его адресе; эмулятор OSC или UDP
  делит свой порт с ожиданиями запуска на нём.
- Два эмулятора одного транспорта в запуске не могут делить порт.
- Узел [[[ui:exp.node.emulator_state]]](#node-emulator_state) отключает его и
  возвращает обратно.

Выход: [[ui:exp.outputPort]]. Настроек нет.

```json
{ "id": "api", "type": "emulator", "x": 270, "y": 80,
  "emulator": { "name": "Orders API", "bind": "127.0.0.1:18080", "protocol": "http",
    "routes": [{ "method": "GET", "path": "/orders/:id", "order": "sequence",
                 "responses": [{ "status": 503 }, { "status": 200, "body": "{\"id\":\"{{request.params.id}}\"}" }] }] } }
```

## Сбои {#faults}

Узлы, которые ломают всё по сигналу. Ветка из узлов [[ui:exp.node.delay]] и этих узлов
рядом с трафиком читается как расписание; как это сделать, показывает страница [Сбои
по расписанию](faults.md).

### Сетевые помехи {#node-impairment}

Реле помех на весь запуск: тестируемая система отправляет данные (или подключается)
не на настоящую цель, а на адрес из поля [[ui:exp.relayListen]]; реле пересылает их на
адрес из поля [[ui:exp.relayTarget]], ответы возвращаются тем же путём, ухудшенные
профилем. Оно открывается до первого шага и закрывается, когда запуск заканчивается,
как бы это ни произошло, так что ничего не остаётся ухудшенным; в ходе запуска шаг
проходит сразу. Каждое решение берётся из seed запуска: один и тот же seed и один и
тот же трафик получают одну и ту же судьбу.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.relayListen]] | `listen` | `IP:port`, на который отправляет тестируемая система | `127.0.0.1:9010` | Только параметры |
| [[ui:exp.relayTarget]] | `target` | `IP:port` настоящего адресата или `host:port` — имя хоста разрешается при старте запуска, а имя, которое не найдено, останавливает запуск на этом узле | `127.0.0.1:9000` | Только параметры |
| [[ui:ns.protocol]] | `protocol` | UDP (`udp`): у каждой датаграммы своя судьба; TCP (`tcp`): каждое соединение связывается с собственным соединением к цели, и оба потока ухудшаются | UDP (`udp`, если ключа нет) | Нет |
| [[ui:ns.preset]] и значения под ним | `profile` | Что реле делает с трафиком — см. [Профиль](#impair-profile) | [[ui:ns.preset.lan]] (без помех, если ключа нет) | Нет |

Адрес, на котором слушает реле, не может быть другим сокетом запуска, а реле не могут
пересылать друг другу по кругу. Цель, заданная именем, прослеживается после того, как
имя разрешено, поэтому круг через имя останавливает запуск при его старте. Отчёт
считает каждую фазу реле отдельно.

Выход: [[ui:exp.outputPort]]. Настроек нет.

```json
{ "id": "relay", "type": "impairment", "x": 270, "y": 80, "listen": "127.0.0.1:9010", "target": "{{device}}",
  "profile": { "name": "lan", "latency_ms": 1, "jitter_ms": 1 } }
```

#### Профиль {#impair-profile}

Плашка пресета — [[ui:ns.preset.lan]], [[ui:ns.preset.wifi]], [[ui:ns.preset.4g]],
[[ui:ns.preset.satellite]], [[ui:ns.preset.intermittent]], [[ui:ns.preset.offline]] —
заполняет все значения; любое из них можно потом изменить. Реле читает только значения
своего протокола; в файле любой ключ можно опустить (ноль, выкл.).

| Поле | В файле | Что это | Пределы | Протокол |
| --- | --- | --- | --- | --- |
| — | `name` | Подпись для ленты и отчёта: ключ пресета (`lan`, `wifi`, `4g`, `satellite`, `intermittent`, `offline`) или ваша собственная | не более 60 символов | оба |
| [[ui:ns.offline]] | `offline` | Ничего не проходит | `true` / `false` | оба |
| [[ui:ns.latency]] | `latency_ms` | Задержка, добавляемая к каждому пакету или куску потока | 0–60 000 (ползунок доходит до 1 000) | оба |
| [[ui:ns.jitter]] | `jitter_ms` | Случайная добавочная задержка до этого значения; поток TCP сохраняет порядок | 0–60 000 (ползунок доходит до 500) | оба |
| [[ui:ns.rate]] | `rate_kbps` | Ограничение полосы, 0 — без ограничения. UDP: сверх секунды очереди датаграммы отбрасываются как превысившие ограничение; TCP: отправитель замедляется, ничего не отбрасывается | 0 или 8–10 000 000 | оба |
| [[ui:ns.loss]] | `loss` | Вероятность того, что датаграмма отброшена | 0–1 (ползунок показывает %) | UDP |
| [[ui:ns.burst]], [[ui:ns.burstLength]] | `burst_start`, `burst_length` | Вероятность начала пачки потерь и сколько датаграмм она длится в среднем | 0–1; 1–1 000, когда пачки включены | UDP |
| [[ui:ns.duplicate]] | `duplicate` | Вероятность того, что датаграмма отправлена дважды | 0–1 | UDP |
| [[ui:ns.corrupt]] | `corrupt` | Вероятность того, что один бит датаграммы перевёрнут | 0–1 | UDP |
| [[ui:ns.reorder]] | `reorder` | Вероятность того, что датаграмма задержана и более поздние её обгоняют | 0–1 | UDP |
| [[ui:ns.reset]] | `reset` | Вероятность того, что кусок потока вместо передачи сбрасывает соединение — обе стороны получают сброс | 0–1 | TCP |
| [[ui:ns.stall]] | `stall` | Вероятность того, что кусок оставляет соединение полуоткрытым: больше ничего не проходит ни в одну сторону, и ни одна сторона об этом не узнаёт | 0–1 | TCP |

Подробнее о реле, пресетах и о том, что они моделируют, — на странице
[[[ui:nav.netsim]]](../tools/impairment.md).

### Сменить помехи {#node-impairment_change}

Переключает одно из реле запуска — узлов [[ui:exp.node.impairment]] — на другой
профиль начиная с этого шага, не отпуская порт. Фаза, что шла до этого, закрывается и
подсчитывается в отчёте.

| Поле | В файле | Что это | По умолчанию | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.relay]] | `relay` | Идентификатор узла [[ui:exp.node.impairment]] этого эксперимента | первый | Нет |
| [[ui:ns.preset]] и значения под ним | `profile` | Чем оно ухудшает трафик с этого момента — см. [Профиль](#impair-profile); реле читает значения своего протокола | [[ui:ns.preset.offline]] (без помех, если ключа нет) | Нет |

Шаг завершается ошибкой, если реле не работает — например, оно не смогло пересылать.
Выход: [[ui:exp.outputPort]]. Настроек нет.

```json
{ "id": "cut", "type": "impairment_change", "x": 730, "y": 200, "relay": "relay",
  "profile": { "name": "offline", "offline": true } }
```

### Эмулятор: выкл./вкл. {#node-emulator_state}

Отключает один из эмуляторов запуска или снова включает его. Пока он отключён,
HTTP-эмулятор отвечает так, как сказано в поле [[ui:exp.downFault]]; устройство TCP и
брокер MQTT обрывают соединения и отказывают новым; устройства OSC и UDP ничего не
отвечают. Включённый снова, эмулятор следует собственному расписанию отключений, если
оно у него есть.

| Поле | В файле | Что это | По умолчанию |
| --- | --- | --- | --- |
| [[ui:exp.emulatorNode]] | `emulator` | Идентификатор узла [[ui:exp.node.emulator]] этого эксперимента | первый |
| [[ui:exp.emulatorDownState]] | `down` | [[ui:exp.emulatorGoesDown]] (`true`) или [[ui:exp.emulatorComesUp]] (`false`) | отключён (`false`, если ключа нет) |
| [[ui:exp.downFault]] | `fault` | Только HTTP: [[ui:emu.outageFault.unavailable]] (`unavailable`), [[ui:emu.outageFault.reset]] (`reset`: соединение закрывается без ответа) или [[ui:emu.outageFault.timeout]] (`timeout`: запрос удерживается, пока клиент не сдастся, но не дольше 120 с) | `unavailable` (и если ключа нет) |

Выход: [[ui:exp.outputPort]]. Настроек нет. Шаблоны нигде не применяются.

```json
{ "id": "down", "type": "emulator_state", "x": 500, "y": 200, "emulator": "api", "down": true, "fault": "unavailable" }
```

## Данные {#data}

### Извлечь значение {#node-extract}

Сохраняет часть последнего HTTP-ответа на своём пути как переменную — для последующих
полей (`{{token}}`), проверок и ветвлений. На каждом пути перед ним должен стоять
HTTP-запрос. Щелчок по значению в ответе на [[ui:exp.sendNow]] добавляет такой узел за
вас.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.variable]] | `variable` | Имя: буквы, цифры и `_`, не начинается с цифры, не зарезервированное слово и не имя параметра | `token` | Нет |
| [[ui:exp.extractFrom]] | `from` | [[ui:exp.from.json]] (`json`), [[ui:exp.from.header]] (`header`), [[ui:exp.from.status]] (`status`), [[ui:exp.from.body]] (`body`) или [[ui:exp.from.regex]] (`regex`) | `json` | Нет |
| [[ui:exp.jsonPath]], [[ui:exp.headerName]] или [[ui:exp.pattern]] | `expr` | JSON-путь (`$.data.token`, `$.items[0]`, `$["first name"]`), имя заголовка (в любом регистре) или регулярное выражение — его первая группа либо всё совпадение | `$.token`; для статуса и тела не используется | Нет |

Шаг завершается ошибкой, если брать нечего: тело не JSON, пути или заголовка нет,
выражение не совпало или — для поля JSON либо всего тела — тело было длиннее
сохранённых 256 КиБ. Статус сохраняется как число; остальное — как текст или как
найденное значение JSON. Выход: [[ui:exp.outputPort]]. Настроек нет.

```json
{ "id": "token", "type": "extract", "x": 500, "y": 80, "variable": "token", "from": "json", "expr": "$.data.token" }
```

Подробнее о переменных — в разделе [Данные и шаблоны](data.md).

## Проверки {#checks}

Проверка либо проходит, либо проваливает запуск. Четыре проверки ответа читают
последний HTTP-ответ на своём пути, поэтому на каждом пути перед ними должен стоять
HTTP-запрос — не под нагрузкой.

### Статус HTTP {#node-assert_status}

Проходит, когда статус последнего ответа в точности равен заданному.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.expectedStatus]] | `status` | | 200; 100–599 | Нет |

Выход: [[ui:exp.outputPort]]. Настроек нет.

```json
{ "id": "ok", "type": "assert_status", "x": 500, "y": 80, "status": 200 }
```

### Текст ответа {#node-assert_body}

Проходит, когда тело последнего ответа содержит этот текст точно (с учётом регистра).
Сохраняются только первые 256 КиБ тела: если текст не найден в обрезанном теле,
проверка проваливается именно с этой причиной.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.contains]] | `contains` | | `ok`; обязательно | Да |

Выход: [[ui:exp.outputPort]]. Настроек нет.

```json
{ "id": "ready", "type": "assert_body", "x": 500, "y": 80, "contains": "ready" }
```

### Заголовок ответа {#node-assert_header}

Проходит, когда в последнем ответе есть заголовок и его значение содержит этот текст.
Имя заголовка сопоставляется в любом регистре, значение — точно.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.headerName]] | `name` | | `content-type`; обязательно | Да |
| [[ui:exp.contains]] | `contains` | Что должно содержать его значение; пусто — достаточно, чтобы заголовок был | `application/json` | Да |

Выход: [[ui:exp.outputPort]]. Настроек нет.

```json
{ "id": "json", "type": "assert_header", "x": 500, "y": 80, "name": "Content-Type", "contains": "json" }
```

### Время ответа {#node-assert_latency}

Проходит, когда последний ответ занял не больше этого времени — от отправки запроса
до конца его тела.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.maxLatency]] | `max_ms` | | 1 000; 1–120 000 | Нет |

Выход: [[ui:exp.outputPort]]. Настроек нет.

```json
{ "id": "fast", "type": "assert_latency", "x": 500, "y": 80, "max_ms": 250 }
```

### Проверка значения {#node-assert_value}

Сравнивает значение — обычно переменную, записанную шаблоном, — с ожидаемым и
проходит, когда сравнение выполняется.

| Поле | В файле | Что это | По умолчанию | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.value]] | `value` | Что сравнивается: `{{token}}`, `{{reply.args[0]}}` | `{{token}}` | Да |
| [[ui:exp.operator]] | `op` | См. [Сравнения](#comparisons) | [[ui:exp.op.not_empty]] | Нет |
| [[ui:exp.expected]] | `expected` | Не используется условиями [[ui:exp.op.empty]] и [[ui:exp.op.not_empty]] | пусто (и если ключа нет) | Да |

Выход: [[ui:exp.outputPort]]. Настроек нет.

```json
{ "id": "state", "type": "assert_value", "x": 730, "y": 80, "value": "{{state}}", "op": "eq", "expected": "ready" }
```

### Сравнения {#comparisons}

Узлы [[ui:exp.node.assert_value]] и [[ui:exp.node.branch_value]], условие выхода узла
[[ui:exp.node.loop]], условия на аргументы OSC и условия HTTP сравнивают одинаково:

| Вариант | В файле | Выполняется, когда значение |
| --- | --- | --- |
| [[ui:exp.op.eq]] | `eq` | равно ожидаемому — как числа, когда оба числа (`200` = `200.0`), иначе как точный текст |
| [[ui:exp.op.ne]] | `ne` | не равно ему по тому же правилу |
| [[ui:exp.op.lt]], [[ui:exp.op.le]], [[ui:exp.op.gt]], [[ui:exp.op.ge]] | `lt`, `le`, `gt`, `ge` | меньше, не больше, больше, не меньше — оба должны быть числами: иначе проверка, ветвление или узел [[ui:exp.node.loop]] завершает шаг ошибкой, а условие на аргумент или условие HTTP не выполняется |
| [[ui:exp.op.contains]] | `contains` | содержит ожидаемый текст |
| [[ui:exp.op.matches]] | `matches` | соответствует ожидаемому регулярному выражению |
| [[ui:exp.op.empty]], [[ui:exp.op.not_empty]] | `empty`, `not_empty` | пусто (пробелы считаются пустотой) / не пусто |

## Сценарий {#flow}

Узлы, которые решают, куда пойдёт запуск. Подробнее о ветках, слияниях и циклах — в
разделе [Как идёт запуск](flow.md).

### Старт {#node-start}

Здесь начинается запуск; в каждом эксперименте ровно один такой узел. У него нет ни
входа, ни полей. Первая строка ленты показывает seed запуска.

Выход: [[ui:exp.outputPort]], обязателен. Несколько связей от него сразу запускают
параллельные ветки.

```json
{ "id": "start", "type": "start", "x": 40, "y": 80 }
```

### Финиш {#node-end}

Здесь запуск завершается; в каждом эксперименте ровно один такой узел, и выходов у
него нет. К нему могут вести несколько веток: запуск проходит один раз, после того
как закончила последняя ветка, и только если ни одна не завершилась ошибкой. Запуск,
который так и не дошёл до узла [[ui:exp.node.end]], проваливается.

```json
{ "id": "end", "type": "end", "x": 960, "y": 80 }
```

### Пауза {#node-delay}

Ждёт заданное время перед следующим шагом.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.delayMs]] | `ms` | | 300; 0–60 000 | Нет |

Выход: [[ui:exp.outputPort]]. Настроек нет. Для более долгого ожидания поставьте
несколько таких узлов подряд или в узел [[ui:exp.node.loop]].

```json
{ "id": "pause", "type": "delay", "x": 500, "y": 80, "ms": 500 }
```

### Ветвление по статусу {#node-branch_status}

Выбирает выход [[ui:exp.yes]], когда последний HTTP-ответ имеет этот статус, иначе —
[[ui:exp.no]]. На каждом пути перед ним должен стоять HTTP-запрос.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.expectedStatus]] | `status` | | 200; 100–599 | Нет |

Выходы: [[ui:exp.yes]] и [[ui:exp.no]], оба обязательны. Настроек нет.

```json
{ "id": "branch", "type": "branch_status", "x": 500, "y": 80, "status": 200 }
```

### Ветвление по значению {#node-branch_value}

Выбирает выход [[ui:exp.yes]], когда сравнение выполняется, иначе — [[ui:exp.no]]. Его
поля и [сравнения](#comparisons) те же, что у узла
[[[ui:exp.node.assert_value]]](#node-assert_value); сравнение, которое нельзя
выполнить (`lt` для текста), завершает шаг ошибкой.

| Поле | В файле | Что это | По умолчанию | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.value]] | `value` | Что сравнивается | `{{token}}` | Да |
| [[ui:exp.operator]] | `op` | | [[ui:exp.op.eq]] | Нет |
| [[ui:exp.expected]] | `expected` | | пусто (и если ключа нет) | Да |

Выходы: [[ui:exp.yes]] и [[ui:exp.no]], оба обязательны. Настроек нет.

```json
{ "id": "ok", "type": "branch_value", "x": 730, "y": 80, "value": "{{reply.args[0]}}", "op": "eq", "expected": "ok" }
```

### Параллельный запуск {#node-fork}

Выполняет то, что следует за выходами [[ui:exp.branch1]] и [[ui:exp.branch2]],
одновременно, причём у каждой ветки своя копия переменных. У каждого выхода может быть
больше связей — для большего числа веток. Полей нет.

Выходы: [[ui:exp.branch1]] и [[ui:exp.branch2]], оба обязательны.

```json
{ "id": "split", "type": "fork", "x": 270, "y": 80 }
```

### Слияние потоков {#node-join}

Ждёт, пока будет достигнута каждая ведущая в него связь, затем продолжает один раз,
слив переменные веток — если две ветки задают одну переменную, побеждает та, чья связь
в файле идёт позже, — и последний HTTP-ответ из последней из них, у которой он был.
Полей нет.

Здесь встречаются только ветки, которые выполняются все вместе: узел
[[ui:exp.node.join]], стоящий за узлом [[ui:exp.node.branch_status]] (его выходы
[[ui:exp.yes]] и [[ui:exp.no]] никогда не срабатывают оба сразу), никогда не
продолжит; если ни один другой путь не достигает [[ui:exp.node.end]], запуск
завершается ошибкой на этом узле, сообщая, скольких веток он всё ещё ждал.

Выход: [[ui:exp.outputPort]], обязателен.

Любой другой узел, в который ведёт несколько связей, выполняется по разу при каждом
приходе.

```json
{ "id": "joined", "type": "join", "x": 730, "y": 80 }
```

### Цикл {#node-loop}

Снова и снова выполняет шаги на выходе [[ui:exp.portBody]], которые ведут обратно к
нему: не более заданного числа раз и, если у него есть условие выхода, пока оно не
выполнится.

| Поле | В файле | Что это | По умолчанию и пределы | Шаблоны |
| --- | --- | --- | --- | --- |
| [[ui:exp.loopMax]] | `max` | Наибольшее число итераций | 5; 1–1 000 | Нет |
| [[ui:exp.loopUntilOn]] | `until` | Необязательное условие выхода `{ "value", "op", "expected" }`, как у узла [[[ui:exp.node.assert_value]]](#node-assert_value) | выкл. | Значение и ожидаемое: да |

- Тело всегда выполняется хотя бы один раз. Условие выхода читается после каждой
  итерации, поэтому тело может задать то, что оно проверяет.
- Выход [[ui:exp.portDone]] выбирается, когда условие выполняется — или, без условия,
  после последней итерации.
- Выход [[ui:exp.portLimit]] выбирается, когда итерации кончились раньше, чем
  выполнилось условие. Без связи на нём это завершает шаг ошибкой.
- Внутри тела `{{counter}}` — номер итерации.
- Тело выполняется как одна ветка: у каждого выхода внутри него одна связь; в нём нет
  узлов [[ui:exp.node.start]], [[ui:exp.node.end]], [[ui:exp.node.fork]],
  [[ui:exp.node.join]] и других узлов [[ui:exp.node.loop]]; в него входят только
  через [[ui:exp.portBody]]; и каждая связь в нём ведёт дальше в теле или обратно к
  циклу.

Выходы: [[ui:exp.portBody]] и [[ui:exp.portDone]] (обязательны), [[ui:exp.portLimit]]
(необязателен). Настроек нет.

```json
{ "id": "poll", "type": "loop", "x": 270, "y": 80, "max": 10,
  "until": { "value": "{{status.args[0]}}", "op": "eq", "expected": "ready" } }
```
